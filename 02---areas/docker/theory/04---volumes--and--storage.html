04 · Volumes & Storage

← 🐳 Docker MOC

1. Tại sao cần Volumes?

Container có ephemeral storage (writable layer) — bị xóa khi container bị remove.

Giải pháp: Volumes và Bind Mounts — lưu data ngoài container lifecycle.

2. Ba loại Storage

LoạiLưu ở đâuQuản lý bởiUse case
Named VolumeDocker area trên hostDockerDatabases, persistent data
Bind MountBất kỳ đường dẫn nào trên hostUserDevelopment, config files
tmpfsRAM (memory)DockerSecrets, temp data
Host filesystem
├── /var/lib/docker/volumes/  ← Named Volumes (Docker managed)
│   ├── myvolume/
│   └── pgdata/
│
├── /home/user/myapp/        ← Bind Mount (user path)
│
└── RAM                      ← tmpfs

3. Named Volumes (Khuyên dùng cho Production)

Tạo và sử dụng

Volume Management

Ưu điểm Named Volumes

  • ✅ Docker quản lý vị trí lưu trữ
  • ✅ Dễ backup và migrate
  • ✅ Hoạt động tốt trên mọi OS (kể cả Windows/Mac)
  • ✅ Volume drivers cho cloud storage (NFS, S3, etc.)
  • ✅ Không bị vấn đề permissions như bind mount

5. tmpfs Mounts (In-Memory)

Data lưu trong RAM — mất khi container stop:

Use cases:

  • Secrets/tokens tạm thời (không ghi ra disk)
  • Cache temp files hiệu năng cao
  • Session storage in-memory

6. VOLUME trong Dockerfile

Hạn chế VOLUME trong Dockerfile

  • Tạo anonymous volume nếu không chỉ định volume khi run
  • Anonymous volumes khó quản lý (tên random)
  • Nên dùng named volume khi docker run thay vì dựa vào VOLUME directive
