1. Container vs Virtual Machine

Tiêu chíContainerVirtual Machine
KernelDùng chung kernel hostKernel riêng biệt
Kích thước~MB~GB
Khởi độngVài giây / msVài phút
IsolationProcess-level (namespaces)Full hardware emulation
OverheadRất thấpCao

Container = Process, không phải VM.

Container dùng chung kernel host OS, chỉ cô lập via namespaces + cgroups.

Host OS (Linux Kernel)
├── namespaces: PID, Network, Mount, UTS, IPC, User
└── cgroups: CPU, Memory, I/O
    ├── Container 1 (Process tree)
    ├── Container 2 (Process tree)
    └── Container 3 (Process tree)

Podman trên Fedora

Podman là drop-in replacement cho Docker, chạy rootless và SELinux-aware.
podman run hello-world — hoạt động giống docker run hello-world.

                                  │                         │

3. PID 1 — Process đặc biệt

Process PID 1 trong container có trách nhiệm:

  1. Reap zombie processes — thu gom child processes đã kết thúc
  2. Handle signals — SIGTERM, SIGINT, SIGKILL
  3. Không thể bị kill bằng SIGKILL từ bên ngoài (trừ force)

Shell Form vs Exec Form

Giải pháp zombie processes: Init system nhỏ gọn

Khi nào cần init system?

  • App spawn nhiều child processes
  • Shell scripts fork nhiều commands
  • App không handle signals tốt

4. Process Signals

SignalSốÝ nghĩa
SIGTERM15Yêu cầu tắt graceful

Graceful Shutdown Flow

docker stop mycontainer
       │
  SIGTERM → Container
       │
  App cleanup (max 10s default)
  - Finish current requests
  - Close DB connections
  - Flush logs
       │
  process.exit(0)
       │
  Nếu timeout → SIGKILL (force)

5. Stateless Design

Nguyên tắc vàng

Container phải stateless — có thể kill/restart bất kỳ lúc nào mà không mất data.

Tại sao quan trọng:

  • Container có thể bị kill/restart bất cứ lúc nào
  • Horizontal scaling (nhiều instances)
  • Rolling updates không mất data
  • High availability
