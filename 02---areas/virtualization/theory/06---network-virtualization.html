← 🖥️ Virtualization MOC

1. Bài toán cốt lõi

Mỗi VM cần network connectivity: giao tiếp với VM khác, host, và thế giới bên ngoài. Nhưng chỉ có hữu hạn NIC vật lý.

Câu hỏi:

  • Làm sao nhiều VM chia sẻ 1-2 NIC vật lý?
  • Làm sao cô lập traffic giữa các VM?
  • Làm sao kết nối VM xuyên host (cross-host networking)?

2. Virtual Network Interface Card (vNIC)

2.1. Emulated vs Paravirtual

LoạiCơ chếPerformanceVí dụ
EmulatedHypervisor giả lập NIC phần cứng cũChậm (mỗi packet = VM Exit)Intel e1000, Realtek RTL8139
ParavirtualGuest biết nó ảo hoá, dùng driver tối ưuNhanh (batch I/O, giảm VM Exit)virtio-net, VMXNET3
PassthroughNIC vật lý gán trực tiếp cho VMNative speedSR-IOV VF, PCI passthrough
Emulated NIC:
  Guest packet → emulated e1000 → VM Exit → hypervisor → pNIC
  Mỗi packet = ít nhất 1 VM Exit = ~1000 cycles overhead

Paravirtual (virtio-net):
  Guest packet → virtio ring buffer → hypervisor batch process → pNIC
  Batch nhiều packets = ít VM Exit hơn nhiều lần

Luôn dùng paravirt NIC

  • KVM/Proxmox: virtio-net (cần virtio driver trong guest)
  • VMware: VMXNET3 (cần VMware Tools)
  • Hyper-V: netvsc (tự động với Linux Integration Services)

Windows guest trên KVM: cài virtio-win drivers trước khi chuyển sang virtio.

3. Virtual Switch (vSwitch)

3.1. Khái niệm

vSwitch = switch Layer 2 trong phần mềm, chạy trên hypervisor host. Kết nối vNICs của VMs với nhau và với pNIC.

┌──────────────────────────────────────────────┐
│                   Host                       │
│                                              │
│  VM1──vNIC──┐                                │
│             │                                │
│  VM2──vNIC──┼──► vSwitch ──► Uplink ──► pNIC │──► Physical Network
│             │       │                        │
│  VM3──vNIC──┘       │                        │
│                     │                        │
│              Internal Port                   │
│              (host management)               │
└──────────────────────────────────────────────┘

3.2. Các loại vSwitch

vSwitchPlatformFeatures
Linux BridgeKVM, LXCĐơn giản, built-in kernel, STP, VLAN
Open vSwitch (OVS)KVM, OpenStack, nhiều platformSDN-ready, OpenFlow, VXLAN, GRE, DPDK
VMware vSwitch (VSS)ESXiCơ bản, per-host configuration
VMware VDSvCenterDistributed, consistent policy across hosts
Hyper-V Virtual SwitchHyper-VExtensible, SDN integration

3.3. Linux Bridge (chi tiết)

    br0 (Linux Bridge)
    ├── enp1s0 (physical NIC) → uplink ra mạng vật lý
    ├── vnet0 (VM1 tap device)
    ├── vnet1 (VM2 tap device)
    └── vnet2 (VM3 tap device)

4. Network Modes

4.1. Các chế độ kết nối VM

┌─────────────────────────────────────────────────────────┐
│  Bridged Mode                                           │
│  VM ←→ vSwitch ←→ pNIC ←→ Physical Network             │
│  VM có IP cùng subnet với host, "thấy" trên mạng LAN   │
├─────────────────────────────────────────────────────────┤
│  NAT Mode                                               │
│  VM ←→ NAT ←→ Host IP ←→ Physical Network              │
│  VM dùng private IP, host NAT ra ngoài                  │
├─────────────────────────────────────────────────────────┤
│  Host-Only Mode                                         │
│  VM ←→ vSwitch ←→ Host (only)                           │
│  VM chỉ nói chuyện được với host, không ra ngoài        │
├─────────────────────────────────────────────────────────┤
│  Internal Mode                                          │
│  VM ←→ vSwitch ←→ VM (only)                             │
│  VM chỉ nói chuyện với nhau, không với host hay ngoài   │
├─────────────────────────────────────────────────────────┤
│  Passthrough / Macvtap                                  │
│  VM ←→ pNIC (trực tiếp)                                │
│  Hiệu năng cao nhất, nhưng pNIC bị chiếm bởi 1 VM     │
└─────────────────────────────────────────────────────────┘
ModeInternetVM↔VMVM↔HostIP subnet
Bridged✅✅✅Cùng subnet host
NAT✅ (qua NAT)✅ (cùng NAT net)✅Private (192.168.x.x)
Host-Only❌✅✅Private
Internal❌✅❌Private
Passthrough✅❌ (qua physical)⚠️Cùng subnet host

Chọn mode nào?

  • Lab/Homelab: Bridged (dễ truy cập từ mạng LAN)
  • Dev/Test isolation: NAT hoặc Host-Only
  • Production VM: Bridged + VLAN tagging
  • High-performance (NFV, storage): SR-IOV passthrough

6. Overlay Networks

6.1. Tại sao cần overlay?

Khi VM trên host khác nhau cần nằm cùng L2 network:

Underlay (Physical network):
  Host A (10.0.0.1) ─── Router ─── Host B (10.0.0.2)
                    L3 routed

Overlay (VXLAN tunnel):
  VM1 (192.168.1.10)              VM2 (192.168.1.20)
      │                               │
      └── VXLAN Tunnel ───────────────┘
          (L2 frame encapsulated in UDP/IP)
          
→ VM1 và VM2 "thấy" nhau ở L2 dù host khác subnet

6.2. VXLAN

VXLAN (Virtual Extensible LAN) — encapsulate L2 frame trong UDP (port 4789):

Original L2 Frame:
[Dst MAC][Src MAC][EtherType][Payload]

VXLAN Encapsulated:
[Outer Ethernet][Outer IP][Outer UDP:4789][VXLAN Header (VNI)][Original L2 Frame]
                                              │
                                        24-bit VNI
                                        = 16 million segments
                                        (vs VLAN chỉ 4096)
FeatureVLANVXLAN
Max segments4,096~16 million
ScopeSame L2 domainCross L3 (qua tunnel)
Overhead4 bytes (802.1Q tag)50+ bytes (full encapsulation)
MTU requirementBình thườngCần MTU ≥ 1550 trên underlay
Use caseTruyền thống, nhỏCloud, data center, multi-tenant

6.3. Các overlay khác

ProtocolEncapsulationSử dụng bởi
VXLANL2 over UDPVMware NSX, OpenStack, Linux
GREL2/L3 over GREOpenStack, general purpose
GeneveL2 over UDP (extensible)OVN, next-gen standard

7. SR-IOV — Hardware Network Virtualization

7.1. Khái niệm

SR-IOV (Single Root I/O Virtualization) — chia 1 NIC vật lý thành nhiều Virtual Functions (VF), mỗi VF gán trực tiếp cho VM.

Physical NIC (SR-IOV capable)
├── PF (Physical Function) — quản lý bởi host driver
├── VF 0 → VM1 (passthrough, native speed)
├── VF 1 → VM2 (passthrough, native speed)
├── VF 2 → VM3 (passthrough, native speed)
└── VF 3 → (available)

VM không đi qua vSwitch → latency cực thấp

7.2. So sánh

AspectvSwitch (virtio/VMXNET3)SR-IOV VF Passthrough
Latency~50-100 μs~10-20 μs
Throughput10-25 Gbps (tuỳ CPU)Line rate (25-100 Gbps)
CPU overheadCao (hypervisor xử lý packet)Gần zero (hardware)
Live Migration✅ Dễ (vNIC là ảo)⚠️ Phức tạp (phải detach/attach VF)
FlexibilityCao (security policies, monitoring)Thấp (bypass hypervisor)
Use caseĐa số workloadsNFV, HPC, storage traffic

SR-IOV yêu cầu

  1. NIC phải support SR-IOV (Intel X710, Mellanox ConnectX-5, …)
  2. BIOS: enable SR-IOV
  3. IOMMU: enable VT-d/AMD-Vi
  4. Host OS: driver support + VF allocation

8. Network Security trong môi trường ảo hoá

8.1. Microsegmentation

Truyền thống (perimeter firewall):
  Internet → [Firewall] → [All VMs in same network]
  → VM1 compromise → lateral movement dễ dàng

Microsegmentation:
  Internet → [Firewall] → [VM1] ←firewall→ [VM2] ←firewall→ [VM3]
  → Mỗi VM có firewall rule riêng
  → Lateral movement bị chặn
SolutionPlatform
VMware NSXvSphere
Security GroupsOpenStack
nftables / iptablesKVM/Linux
Proxmox FirewallProxmox VE

8.2. Anti-spoofing
