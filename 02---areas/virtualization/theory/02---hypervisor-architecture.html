1. Hypervisor là gì?

Hypervisor (hay Virtual Machine Monitor — VMM) là lớp phần mềm nằm giữa phần cứng vật lý và các máy ảo (VM). Nhiệm vụ:

  1. Trừu tượng hoá phần cứng — tạo ra phần cứng ảo cho mỗi VM
  2. Phân bổ tài nguyên — chia CPU, RAM, I/O cho các VM
  3. Enforce isolation — đảm bảo VM không xâm phạm lẫn nhau
  4. Intercept & emulate — xử lý các instruction đặc quyền từ guest OS

Popek & Goldberg (1974) — 3 tiêu chí của VMM

  1. Equivalence (Fidelity): chương trình chạy trên VM phải cho kết quả giống hệt bare-metal
  2. Resource control (Safety): VMM phải kiểm soát hoàn toàn mọi tài nguyên vật lý
  3. Efficiency: đa số instruction của guest phải chạy trực tiếp trên CPU, không cần emulation

KVM — Type 1 hay Type 2?

Tranh cãi phân loại KVM

KVM thường bị nhầm là Type 2 vì chạy “trên Linux”. Nhưng thực tế:

  • KVM là kernel module (kvm.ko) — Linux kernel trở thành hypervisor
  • Khi load KVM module, Linux kernel chạy ở VMX root mode (Ring -1)
  • Guest OS chạy ở VMX non-root mode
  • Linux kernel vẫn quản lý scheduling, memory, I/O → đóng vai trò hypervisor

→ KVM là Type 1 biến thể: kernel = hypervisor, không phải app chạy trên OS.

Trước khi load KVM:
  Linux = OS bình thường

Sau khi load KVM:
  Linux kernel + kvm.ko = Hypervisor (Type 1)
  ├── Host processes (Linux userspace) ← một "guest" đặc biệt
  ├── VM 1 (QEMU process + guest kernel)
  └── VM 2 (QEMU process + guest kernel)

5.2. KVM/QEMU Architecture (chi tiết)

KVM/QEMU là kiến trúc hybrid đặc biệt quan trọng vì là nền tảng của Proxmox, OpenStack, và nhiều cloud provider.

┌─────────────────────────────────────────────────────────┐
│                    User Space                           │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │  QEMU (VM1)  │  │  QEMU (VM2)  │  │   libvirt    │  │
│  │  ┌────────┐  │  │  ┌────────┐  │  │  (virsh,     │  │
│  │  │ vCPU   │  │  │  │ vCPU   │  │  │   virt-mgr)  │  │
│  │  │ vRAM   │  │  │  │ vRAM   │  │  └──────────────┘  │
│  │  │ vDisk  │  │  │  │ vDisk  │  │                     │
│  │  │ vNIC   │  │  │  │ vNIC   │  │                     │
│  │  └────┬───┘  │  │  └────┬───┘  │                     │
│  └───────┼──────┘  └───────┼──────┘                     │
│          │ ioctl           │ ioctl                       │
├──────────┼─────────────────┼────────────────────────────┤
│          ↓     Kernel Space          ↓                  │
│  ┌─────────────────────────────────────────────────┐    │
│  │                KVM Module (kvm.ko)              │    │
│  │  ┌─────────────┐  ┌──────────────────────────┐  │    │
│  │  │ kvm-intel.ko│  │ VM scheduling (CFS)      │  │    │
│  │  │ kvm-amd.ko  │  │ Memory management (EPT)  │  │    │
│  │  └─────────────┘  │ Interrupt injection       │  │    │
│  │                    └──────────────────────────┘  │    │
│  └─────────────────────────────────────────────────┘    │
├─────────────────────────────────────────────────────────┤
│                    Hardware                             │
│            VT-x / AMD-V + EPT/NPT + VT-d               │

Phân công vai trò:

ComponentVai trò
KVM kernel moduleTạo /dev/kvm, quản lý VMX transitions, EPT, interrupt injection
QEMUUserspace process mô phỏng hardware (disk controller, NIC, GPU, USB…)
libvirtAPI layer chuẩn hoá — virsh, virt-manager, Proxmox, OpenStack đều gọi qua đây
virtioParavirtual drivers cho I/O hiệu năng cao (thay vì emulate hardware cũ)

QEMU có thể chạy không cần KVM

  • QEMU + KVM: hardware acceleration → gần native speed
  • QEMU thuần: full software emulation → rất chậm, nhưng có thể emulate CPU khác architecture (ARM trên x86)

VMkernel là proprietary microkernel của VMware — KHÔNG phải Linux:

  • Viết từ đầu để tối ưu cho ảo hoá
  • Hỗ trợ VMFS (filesystem cho datastore)
  • Tích hợp vMotion, HA, DRS trong kernel level
  • Driver model riêng → chỉ support hardware trong HCL (Hardware Compatibility List)

7. Nested Virtualization

Nested virtualization = chạy hypervisor bên trong VM → tạo VM trong VM.

Physical Host
└── Hypervisor L0 (KVM / ESXi)
    └── VM (L1 Guest) — chạy hypervisor L1
        └── Nested VM (L2 Guest)
AspectMô tả
Use caseLab, testing, CI/CD, training (ví dụ: lab Morpheus trên Fedora KVM)
Yêu cầuCPU phải support VMCS shadowing (Intel) hoặc SVM nesting (AMD)
Hiệu năngL2 chậm hơn L1 đáng kể (thêm 1 layer trap)
EnableKVM: echo "options kvm_intel nested=1" > /etc/modprobe.d/kvm.conf

Không dùng nested virt cho production

Nested chỉ phù hợp cho lab/testing. Production luôn dùng L1 trực tiếp (bare-metal hypervisor).
