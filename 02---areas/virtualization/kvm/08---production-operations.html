Tuning Priority (từ cao đến thấp)

Impact cao ──────────────────────────────── Impact thấp
  │                                            │
  ▼                                            ▼

1. NUMA pinning        → giảm memory latency 2x
2. CPU pinning         → giảm scheduling jitter
3. Hugepages           → giảm TLB miss, đặc biệt DB VMs
4. I/O scheduler       → none cho NVMe, mq-deadline cho HDD
5. Disk cache=none     → data safety + stable performance
6. IOThreads           → tách I/O khỏi vCPU threads
7. tuned profile       → one-shot optimization bundle
8. KSM                 → tiết kiệm RAM nhưng trade security

2.2. NUMA Pinning

NUMA pinning = performance boost lớn nhất

VM nên nằm trọn trong 1 NUMA node (vCPU + RAM). Cross-NUMA access tốn latency gấp đôi (~80ns vs ~150ns). Đặc biệt quan trọng cho database VMs.

3.2. KSM (Kernel Same-page Merging)

KSM: performance vs security tradeoff

KSM tiết kiệm RAM (nhiều VM cùng OS → share kernel pages). Nhưng có side-channel attack risk. Cho multi-tenant cloud: disable. Cho homelab/private: enable.

5.4. Security Checklist

  • SELinux = Enforcing
  • sVirt labels per VM
  • QEMU chạy dưới user qemu (không phải root)
  • seccomp sandbox enabled
  • nwfilter cho anti-spoofing
  • VNC/SPICE có TLS
  • Không expose QEMU monitor ra network
  • Firmware UEFI + Secure Boot cho VMs quan trọng
  • Regular security updates (sudo dnf5 upgrade -y qemu-kvm libvirt)
