Vậy QEMU cụ thể làm gì? Phần tiếp theo đi sâu vào QEMU — component chịu trách nhiệm emulate hardware cho VM.

2. QEMU Deep Dive

2.1. QEMU là gì?

QEMU (Quick EMUlator) là phần mềm emulation đa năng:

ModeMô tảTốc độ
Full system emulationEmulate toàn bộ máy tính (CPU + devices) bằng softwareChậm (10-100x)
Full system + KVMCPU chạy native qua KVM, QEMU chỉ emulate devicesGần native
User-mode emulationChạy binary của architecture khác (ARM binary trên x86)Trung bình

Trong ngữ cảnh KVM, QEMU chạy ở mode Full system + KVM.

2.2. QEMU command line (raw)

Khi không dùng libvirt, bạn chạy QEMU trực tiếp:

Giải thích từng option:

OptionÝ nghĩa
-enable-kvmBật KVM acceleration (QUAN TRỌNG)
-machine q35Machine type: Q35 chipset (modern, PCIe native)
-cpu hostExpose host CPU features cho guest (tốt nhất cho performance)
-smp 4,...4 vCPU: 1 socket, 4 cores, 1 thread
-m 8G8GB RAM
-drive ...Virtual disk: qcow2, virtio controller, no cache
-netdev bridgeNetwork: bridged mode qua br0
-device virtio-net-pciNIC: virtio paravirt
-vnc :0VNC server on display :0 (port 5900)
-monitor stdioQEMU monitor console trên terminal

2.3. Machine Types

QEMU emulate nhiều loại machine/chipset:

Machine TypeChipsetPCIeKhi nào dùng
pc (i440fx)PIIX4❌ PCI onlyLegacy VMs, compatibility
q35ICH9✅ PCIe nativeMặc định nên dùng, modern
microvmMinimal❌Firecracker-style microVM
virt (ARM)GIC + SMMU✅ARM VMs

Luôn dùng q35 cho VM mới

q35 hỗ trợ PCIe (cần cho NVMe passthrough, nhiều devices hơn), IOMMU, và advanced features. i440fx chỉ để backward compatibility.

2.4. CPU Models

CPU ModelUse case
hostProduction: expose tất cả host CPU features
Skylake-Server / EPYCMigration cluster: tất cả hosts cùng CPU model
maxTesting: bật tất cả features
qemu64Maximum compatibility (chậm nhất)

Live migration yêu cầu CPU model tương thích

Nếu host A có Skylake và host B có Ice Lake, dùng -cpu host sẽ KHÔNG migration được. Phải dùng CPU model chung thấp nhất (ví dụ Skylake-Server).

3. libvirt Deep Dive

3.1. Tại sao cần libvirt?

QEMU command line rất dài và phức tạp. libvirt giải quyết:

Vấn đề QEMU thuầnlibvirt giải quyết
Command line hàng trăm optionsXML definition → libvirt generate command
Không có lifecycle managementstart/stop/reboot/migrate API
Không track VM statePersistent VM definitions, autostart
Không quản lý networkVirtual network definitions, DHCP, DNS
Không quản lý storageStorage pool/volume abstraction
Không có remote managementSSH/TLS remote connection
Không có event monitoringEvent callbacks, watchdog

3.2. libvirtd Daemon

Modular daemons là tương lai

Fedora/RHEL 9+ dùng modular daemons thay vì monolithic libvirtd. Mỗi subsystem chạy riêng → restart virtnetworkd không ảnh hưởng VMs đang chạy.

3.3. Connection URI

libvirt dùng URI để xác định kết nối tới hypervisor:

URIScopeVMs visibleNetworkStorage
qemu:///systemSystem-wideTất cả VMsBridged, NAT, isolatedSystem pools
qemu:///sessionPer-userChỉ VMs của userUser-mode (SLiRP NAT)User dirs

Luôn dùng qemu:///system

qemu:///session bị giới hạn: không có bridge networking, không có shared storage pools, VMs tắt khi user logout. Chỉ dùng cho development cá nhân không cần network.

    └── myvm.pid               # PID file per VM

5.2. Hooks

libvirt hỗ trợ hook scripts chạy tự động khi VM lifecycle thay đổi:

/etc/libvirt/hooks/
├── daemon       # Khi libvirtd start/stop
├── qemu         # Khi VM start/stop/migrate
└── network      # Khi network start/stop

Hook use cases thực tế

  • Tự động thêm/xoá firewall rules khi VM start/stop
  • Gửi notification (Telegram, Slack)
  • Mount/unmount shared storage
  • Update DNS records
  • Backup VM trước khi shutdown

Điều cuối cùng để quản lý VM hiệu quả: giao tiếp với bên trong guest OS. QEMU Guest Agent là cầu nối.

6. QEMU Guest Agent (qemu-ga)

6.1. Khái niệm

qemu-ga là daemon chạy bên trong guest OS, giao tiếp với host qua virtio-serial channel:

Host (QEMU/libvirt)                 Guest OS
       │                                │
       │  virtio-serial channel          │
       │  (unix socket ↔ /dev/virtio0)   │
       ├────────────────────────────────►│
       │                                │  qemu-guest-agent daemon
       │  Commands:                     │
       │  - freeze/thaw filesystem      │
       │  - get IP addresses            │
       │  - set password                │
       │  - shutdown/reboot             │
       │  - execute commands            │
       │  - get disk/memory info        │
       └────────────────────────────────┘

6.2. Cài đặt và sử dụng

Guest agent = application-consistent snapshots

Không có guest agent, snapshot chỉ crash-consistent (như rút điện). Với guest agent, filesystem được freeze trước snapshot → data consistent.
