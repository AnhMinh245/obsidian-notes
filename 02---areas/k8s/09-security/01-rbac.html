🔐 RBAC Là Gì?

Định Nghĩa

RBAC = Phương thức quản lý quyền truy cập dựa trên vai trò (Role). Thay vì gán quyền cho từng user, bạn gán quyền cho Role, rồi bind Role cho user.

Giải Thích Bằng Ví Dụ

🏢 CÔNG TY CÓ NHIỀU PHÒNG BAN

Phòng Development (Role: developer):
├── Xem Pods ✓
├── Tạo Deployments ✓
├── Xem Logs ✓
├── XÓA namespace ✗
└── Truy cập Secrets ✗

Phòng Operations (Role: operator):
├── Quản lý Nodes ✓
├── Xem tất cả resources ✓
├── Scale Deployments ✓
├── XÓA namespace ✓ (với approval)
└── Backup cluster ✓

Nhân viên mới:
├── Thuộc phòng Dev → Được gán Role "developer"
├── Tự động có tất cả quyền của developer
└── Không cần configure từng permission riêng lẻ

🏗️ RBAC Architecture

4 Objects Chính

┌─────────────────────────────────────────────────────────┐
│                    RBAC SYSTEM                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  WHO? (Subjects)                                        │
│  ├── User (người dùng)                                 │
│  ├── Group (nhóm users)                                │
│  └── ServiceAccount (identity cho Pods)                │
│                                                         │
│  WHAT? (Permissions)                                    │
│  ├── Role (namespace-scoped permissions)               │
│  └── ClusterRole (cluster-wide permissions)            │
│                                                         │
│  BIND (Kết nối WHO + WHAT)                             │
│  ├── RoleBinding (bind Role → Subject, in namespace)   │
│  └── ClusterRoleBinding (bind ClusterRole → Subject)   │
│                                                         │
│  Flow:                                                  │
│  Subject → RoleBinding → Role → Resources             │
│  "dev-user" → "dev-binding" → "dev-role" → "pods"     │
│                                                         │
└─────────────────────────────────────────────────────────┘

Role vs ClusterRole

Role:
├── Namespace-scoped
├── Permissions chỉ apply trong 1 namespace
├── Ví dụ: "dev team chỉ xem Pods trong namespace 'development'"
└── Dùng cho: Application-level access

ClusterRole:
├── Cluster-wide
├── Permissions apply toàn cluster
├── Ví dụ: "ops team quản lý tất cả Nodes"
└── Dùng cho: Infrastructure-level access, non-namespaced resources (Nodes, PVs)

👤 ServiceAccount

Tại Sao Cần?

User Account: Cho CON NGƯỜI (dev, ops, admin)
ServiceAccount: Cho PODS và APPLICATIONS

Mọi Pod đều chạy dưới 1 ServiceAccount.
Default: "default" ServiceAccount (quyền rất hạn chế).
Custom SA: Khi Pod cần permissions cụ thể (ví dụ: đọc Secrets).

💡 Best Practices

🎯 Key Takeaways

  1. RBAC = Who + What + Where — Subject + Role + Namespace
  2. Role = namespace-scoped, ClusterRole = cluster-wide
  3. RoleBinding kết nối Subject → Role
  4. ServiceAccount = identity cho Pods, mỗi app nên có SA riêng
  5. Default = denied — không có Rule = không có quyền
  6. Test trước apply — kubectl auth can-i
