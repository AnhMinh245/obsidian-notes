    rect rgb(255, 230, 230)
        Note over AUTHN: Phase 1: WHO ARE YOU?
        API->>AUTHN: Authenticate request
        AUTHN->>AUTHN: Check authenticators (in order):<br/>1. Client Certificate → CN=minh, O=dev-team ✅<br/>2. Bearer Token<br/>3. OIDC Token<br/>4. ServiceAccount Token
        AUTHN-->>API: Identity: user=minh, groups=[dev-team]
    end

        Note over AUTHZ: Phase 2: WHAT CAN YOU DO?

        AUTHZ->>AUTHZ: Check RoleBindings in "production":<br/>1. Find: dev-binding binds Role "developer"<br/>   to Group "dev-team" ✅<br/>2. Check Role "developer" rules:<br/>   - resources: ["pods"]<br/>   - verbs: ["get", "list", "watch"] ✅

        AUTHZ-->>API: ✅ ALLOWED
    end

    API->>ETCD: Read pods from production namespace
    ETCD-->>API: [pod-1, pod-2, pod-3]
    API-->>U: 200 OK + Pod list

RBAC Key Rules

  1. Default = DENY — không có Rule = không có quyền
  2. RBAC chỉ ADD permissions — không có “deny” rule, chỉ có “allow”
  3. Role = namespace-scoped, ClusterRole = cluster-wide
  4. ClusterRole + RoleBinding = grant ClusterRole permissions chỉ trong 1 namespace

🔄 Workflow 3: Network Policy Evaluation

Scenario: Default deny + selective allow rules

Default Deny → Allow Logic

flowchart TD
    PACKET["📨 Packet arrives<br/>src: Pod A (ns: frontend)<br/>dst: Pod B (ns: backend, port 8080)"]

    PACKET --> NP_EXISTS{"NetworkPolicy<br/>selecting Pod B<br/>exists?"}

    NP_EXISTS -->|"No NetworkPolicy"| ALLOW_DEFAULT["✅ ALLOW<br/>(K8s default: all traffic allowed)"]

    NP_EXISTS -->|"Yes, has ingress rules"| EVAL["Evaluate ALL matching<br/>NetworkPolicies"]

    EVAL --> MATCH{"Packet matches<br/>ANY allow rule?"}

    MATCH -->|"✅ Matches rule"| ALLOW["✅ ALLOW traffic"]
    MATCH -->|"❌ No match"| DENY["❌ DROP packet<br/>(implicit deny)"]

NetworkPolicy Gotchas

  1. No NetworkPolicy = ALL traffic allowed (dangerous!)
  2. NetworkPolicy rules are additive (UNION of all matching policies)
  3. Ingress and Egress are independent — must configure both
  4. NetworkPolicy requires a CNI plugin that supports it (Calico, Cilium — NOT Flannel!)
  5. Policy applies to Pods selected by podSelector, not to Services

🔄 Workflow 4: Pod Security Admission Pipeline

Scenario: Pod spec evaluated against Pod Security Standards

flowchart TD
    POD_REQ["📨 Create Pod Request<br/>spec includes:<br/>securityContext:<br/>  runAsNonRoot: false<br/>  privileged: true"] --> NS_LABEL{"Check namespace<br/>labels"}

    NS_LABEL --> ENFORCE{"pod-security.kubernetes.io/<br/>enforce = ?"}

    ENFORCE -->|"privileged"| PRIV["✅ ALLOW all<br/>(no restrictions)<br/><i>kube-system namespace typical</i>"]

    ENFORCE -->|"baseline"| BASELINE_CHECK{"Pod spec<br/>violates baseline?"}
    BASELINE_CHECK -->|"privileged: true ❌"| BASELINE_DENY["❌ REJECT Pod<br/>Error: privileged containers<br/>not allowed"]
    BASELINE_CHECK -->|"No violations"| BASELINE_OK["✅ ALLOW"]

    ENFORCE -->|"restricted"| RESTRICT_CHECK{"Pod spec<br/>violates restricted?"}
    RESTRICT_CHECK -->|"runAsNonRoot: false ❌<br/>privileged: true ❌<br/>no seccomp profile ❌"| RESTRICT_DENY["❌ REJECT Pod<br/>Multiple violations"]
    RESTRICT_CHECK -->|"No violations"| RESTRICT_OK["✅ ALLOW"]

    end

    subgraph "Layer 6: Network Security"

    end

    NETPOL --> RUNNING["✅ Secure Pod Running<br/>All 6 layers passed!"]

Câu 1: RBAC Troubleshooting

Tình huống: User dev1 chạy kubectl logs pod-1 -n staging → Error: forbidden. Làm sao debug?

Xem đáp án

pods/log là sub-resource riêng! pods permission không include pods/log.

Tình huống: Namespace production có default-deny NetworkPolicy. Pod api cần gọi database Pod (port 5432) trong cùng namespace. Viết NetworkPolicy.

Xem đáp án

NetworkPolicy chọn destination Pod (podSelector), rồi define allowed sources (from).
