6.1. ConfigMaps - External Configuration

Tách biệt configuration khỏi application code — nguyên tắc 12-Factor App

🎯 Mục Tiêu Học

Sau khi học xong phần này, bạn sẽ:

  • ✅ Hiểu ConfigMap là gì và TẠI SAO cần tách config khỏi code
  • ✅ Tạo ConfigMaps từ literals, files, directories, YAML
  • ✅ Consume ConfigMaps as env vars, volumes, command args
  • ✅ Hiểu hot-reload mechanism và immutable ConfigMaps
  • ✅ Biết cách dùng SubPath mount và specific key projection
  • ✅ Best practices và troubleshoot ConfigMap issues

📦 ConfigMap Là Gì?

Định Nghĩa

ConfigMap = Kubernetes object lưu trữ non-sensitive configuration data dưới dạng key-value pairs, cho phép tách biệt configuration khỏi container images.

Giải Thích Bằng Ví Dụ Thực Tế

ConfigMap giống như bảng cấu hình trung tâm của công ty:

🏢 CÔNG TY CÓ 3 CHI NHÁNH

Bảng cấu hình trung tâm (ConfigMap):
├── Giờ làm việc: 8:00 - 17:00
├── Số lượng nhân viên tối đa: 100
├── Chính sách nghỉ phép: 12 ngày/năm
└── Log level: info

Chi nhánh HN (Pod 1): Đọc cùng bảng cấu hình
Chi nhánh HCM (Pod 2): Đọc cùng bảng cấu hình
Chi nhánh ĐN (Pod 3): Đọc cùng bảng cấu hình

→ Thay đổi cấu hình 1 lần = Apply cho tất cả chi nhánh!
→ Không cần "xây lại" chi nhánh (rebuild image)!

🔄 Hot-Reload: Tự Động Cập Nhật

Volume Mount = Hot-Reload ✅

ConfigMap thay đổi
    ↓ (~30-60s)
kubelet phát hiện
    ↓
Files trong mounted volume được update
    ↓
Application cần WATCH file changes để reload
(K8s KHÔNG tự restart Pod!)

Environment Variables = KHÔNG Hot-Reload ❌

ConfigMap thay đổi
    ↓
Env vars trong container KHÔNG đổi!
    ↓
Cần restart Pod để nhận config mới:
kubectl rollout restart deployment/webapp

🔒 Immutable ConfigMaps

Tại Sao Cần?

Lợi ích:

✓ Bảo vệ khỏi thay đổi ngẫu nhiên (accidental changes)
✓ Performance tốt hơn (kubelet không cần watch)
✓ Giảm load trên API Server
✓ Cluster có >10,000 ConfigMaps → performance impact nếu không immutable

Strategy:
├── Tạo ConfigMap với version trong tên: app-config-v1
├── Cần update? Tạo mới: app-config-v2
├── Update Deployment reference → triggers rolling update
└── Delete old ConfigMap khi không còn dùng

🎓 Kiểm Tra Hiểu Biết

Câu Hỏi Tự Kiểm Tra

1. ConfigMap và Secret khác nhau thế nào?

Xem đáp án
  • ConfigMap: Non-sensitive data, plain text, không mã hóa
  • Secret: Sensitive data (passwords, tokens), base64-encoded, có thể encrypted at rest
  • Rule: Không bao giờ đặt passwords/tokens vào ConfigMap!

2. Hot-reload hoạt động với pattern nào?

Xem đáp án
  • ✅ Volume mount (không SubPath) → Hot-reload sau ~60 giây
  • ❌ Environment variables → Cần restart Pod
  • ❌ SubPath mount → Cần restart Pod
  • ❌ Command arguments → Cần restart Pod

3. Khi nào nên dùng immutable ConfigMap?

Xem đáp án
  • Cluster có nhiều ConfigMaps (>1000) → Performance improvement
  • Config KHÔNG thay đổi frequently
  • Muốn bảo vệ khỏi accidental changes
  • Strategy: Version trong tên (app-config-v1, v2, v3)

4. SubPath mount giải quyết vấn đề gì?

Xem đáp án

Volume mount bình thường sẽ overwrite toàn bộ directory. SubPath cho phép mount 1 file cụ thể mà không ảnh hưởng các files khác trong directory. Nhưng trade-off: mất hot-reload capability.

🎯 Key Takeaways

Ghi Nhớ 5 Điều Quan Trọng

  1. ConfigMap = External, Non-Sensitive Config

    • Tách config khỏi code
    • Same image, different configs per environment
    • 12-Factor App principle

  2. 4 Cách Tạo: Literals, Files, Directories, YAML

    • Production: Luôn dùng YAML manifest (declarative, version control)

  3. 3 Cách Consume: Env Vars, Volumes, Args

    • Env vars: Đơn giản nhưng không hot-reload
    • Volumes: Hot-reload nhưng phải watch file changes
    • SubPath: Không overwrite nhưng không hot-reload

  4. Hot-Reload chỉ với Volume Mount (không SubPath)

    • Delay ~60 giây
    • App cần tự detect file changes

  5. Immutable ConfigMaps cho production

    • Performance improvement
    • Prevent accidental changes
    • Versioned naming strategy
