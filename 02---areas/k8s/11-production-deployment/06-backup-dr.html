📐 RTO & RPO — Xác Định Targets

Definitions

Recovery Time Objective (RTO):
├── "Mất bao lâu để system hoạt động lại?"
├── Thời gian tối đa chấp nhận downtime
├── Ảnh hưởng: Architecture, automation level
└── Ví dụ: RTO = 1h → Phải restore trong 1 giờ

Recovery Point Objective (RPO):
├── "Mất bao nhiêu data tối đa?"
├── Khoảng thời gian data loss chấp nhận được
├── Ảnh hưởng: Backup frequency
└── Ví dụ: RPO = 15 min → Backup mỗi 15 phút

Timeline:
  Last backup    Disaster    Recovery complete
      ↓              ↓              ↓
  ────|──────────────|──────────────|────
      ←── RPO ──→   ←──── RTO ────→
      (data loss)    (downtime)

Xác Định RTO/RPO Theo Business Impact

TierỨng dụngRTORPOStrategy
Tier 1Payment, Auth< 5 minNear-zeroActive-Active, real-time replication
Tier 2Core APIs, Databases< 1 hour< 15 minActive-Passive, frequent backups
Tier 3Internal tools, CMS< 4 hours< 1 hourScheduled backups, manual recovery
Tier 4Dev/test, Archives< 24 hours< 24 hoursDaily backups, best-effort

Cost vs Recovery Tradeoff

         Cost
          ↑
          │    ●  Active-Active (real-time)
          │
          │         ●  Active-Passive (warm standby)
          │
          │              ●  Pilot Light (minimal standby)
          │
          │                   ●  Backup & Restore
          │
          └──────────────────────────────────→ RTO
         Fast                              Slow

→ Chọn strategy phù hợp với business requirements VÀ budget

💾 Velero — Cluster-Level Backup

Velero Là Gì?

Velero = Kubernetes backup tool (by VMware/Broadcom)
├── Backup K8s resources (YAML manifests)
├── Backup Persistent Volumes (PV snapshots)
├── Schedule automated backups
├── Restore to same or different cluster
├── Migrate between clusters
└── Disaster recovery

🗄️ etcd Backup & Restore

Tại Sao etcd Backup Quan Trọng?

etcd = Brain of Kubernetes cluster
├── Stores ALL cluster state
│   ├── Pods, Deployments, Services definitions
│   ├── Secrets, ConfigMaps
│   ├── RBAC rules
│   ├── Namespace configurations
│   └── Custom Resources
├── Mất etcd = Mất TOÀN BỘ cluster config
└── Velero backup K8s resources, nhưng etcd backup là "deeper" level

🌍 Multi-Region DR

Architecture Patterns

Active-Passive (phổ biến nhất):
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  Primary Region (us-central1)                          │
│  ├── Production cluster (full capacity)                │
│  ├── Continuous Velero backups → S3                    │
│  ├── Database replication → DR region                  │
│  └── Active traffic                                    │
│                                                         │
│  DR Region (us-east1)                                  │
│  ├── Standby cluster (minimal nodes)                   │
│  ├── Database replica (read-only)                      │
│  ├── Latest Velero backups available                   │
│  └── Scale up on failover                             │
│                                                         │
│  Failover:                                              │
│  1. Promote DB replica → primary                       │
│  2. Restore K8s resources from backup                  │
│  3. Scale up DR cluster                                │
│  4. Switch DNS → DR region                             │
│  5. Verify applications healthy                        │
│                                                         │
└─────────────────────────────────────────────────────────┘

🧪 DR Drill — Quy Trình Test

Tại Sao Cần DR Drill?

"A backup that hasn't been tested is not a backup."

DR Drill kiểm tra:
├── Backups có thể restore thành công?
├── Team biết quy trình?
├── RTO/RPO targets có đạt được?
├── Monitoring/alerting hoạt động?
└── Documentation đúng và up-to-date?

Frequency: Ít nhất mỗi quý (quarterly)

💡 Best Practices

🎓 Key Takeaways

  1. RTO/RPO xác định backup strategy — define TRƯỚC khi build
  2. Velero cho cluster-level backup (K8s resources + PV snapshots)
  3. etcd backup cho control plane — backup riêng, restore khi cluster corruption
  4. Application backup cho databases — logical dumps + PV snapshots
  5. Multi-region DR cho business-critical apps — Active-Passive phổ biến nhất
  6. DR Drill mỗi quý — “A backup not tested is not a backup”
  7. 3-2-1 rule: 3 copies, 2 types, 1 offsite
  8. Automate backup AND verification
