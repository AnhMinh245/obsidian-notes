11.7. Cost Optimization

Giảm chi phí K8s mà vẫn đảm bảo performance và reliability

🎯 Mục Tiêu

  • ✅ Hiểu FinOps framework cho Kubernetes
  • ✅ Triển khai Resource right-sizing (VPA, actual usage analysis)
  • ✅ Tối ưu với Spot/Preemptible instances và PDB
  • ✅ Setup Cost monitoring với Kubecost/OpenCost
  • ✅ Implement Dev/test scheduling (scale to zero off-hours)
  • ✅ Áp dụng Multi-tenancy cost allocation
  • ✅ Tối ưu Storage và Network costs

💰 FinOps Framework

FinOps Là Gì?

FinOps = Financial Operations for Cloud
= Collaboration giữa Engineering ↔ Finance ↔ Business

Kubernetes FinOps challenges:
├── Shared clusters → khó allocate cost per team
├── Dynamic scaling → cost unpredictable
├── Over-provisioning → waste (phổ biến nhất!)
├── Under-provisioning → performance issues
└── Lack of visibility → không biết money đi đâu

FinOps Lifecycle

┌─────────────────────────────────────────────────────────┐
│                   FinOps LIFECYCLE                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. INFORM (Visibility)                                │
│  ├── Allocate costs per team/namespace/app             │
│  ├── Dashboard: Who spends what?                       │
│  ├── Showback/Chargeback reports                       │
│  └── Tools: Kubecost, OpenCost                         │
│                                                         │
│  2. OPTIMIZE (Efficiency)                              │
│  ├── Right-size resources (VPA recommendations)        │
│  ├── Use spot instances                                │
│  ├── Schedule dev/test environments                    │
│  ├── Remove unused resources                           │
│  └── Optimize storage tiers                            │
│                                                         │
│  3. OPERATE (Governance)                               │
│  ├── Set budgets per team                              │
│  ├── Alert on cost anomalies                           │
│  ├── Enforce resource requests/limits                  │
│  ├── Regular cost reviews                              │
│  └── Continuous improvement                            │
│                                                         │
│  → Repeat: INFORM → OPTIMIZE → OPERATE                 │
│                                                         │
└─────────────────────────────────────────────────────────┘

📊 Cost Monitoring

Kubecost (Feature-rich, K8s-specific)

Kubecost cung cấp:

├── Cost per namespace, deployment, pod
├── Idle resource detection (→ wasted spend)
├── Right-sizing recommendations
├── Savings opportunities
├── Cost trends and forecasting
├── Network cost allocation
├── Shared cost allocation
└── Alerts on anomalies

OpenCost (Open source, CNCF)

Key Cost Metrics

Metrics to track:
├── Total cluster cost (monthly)
├── Cost per namespace (team/project)
├── Cost per deployment
├── Idle cost (requested nhưng không dùng)
├── CPU/Memory efficiency (actual / requested)
├── Cost per request (application-level)
└── Cost trend (month-over-month)

Typical waste:
├── 30-60% of requested CPU unused (idle)
├── 20-40% of requested memory unused
├── 15% of PVs không attached
└── Dev environments run 24/7 (dùng 8 giờ/ngày)

Common Over-Provisioning Patterns

🚨 Pattern 1: "Just to be safe" — requests = limits = high values
   ❌ cpu: 2, memory: 4Gi (nhưng thực tế dùng 100m CPU, 200Mi memory)
   ✅ Dùng VPA recommendations, set requests = actual + 20% buffer

🚨 Pattern 2: Copy-paste từ StackOverflow
   ❌ Mọi service đều 500m CPU, 512Mi memory (one-size-fits-all)
   ✅ Profile từng service riêng

🚨 Pattern 3: Never review after initial setup
   ❌ Set once, forget forever
   ✅ Review monthly, adjust seasonally

🎰 Spot / Preemptible Instances

Cách Hoạt Động

On-Demand instances: Full price, guaranteed availability
Spot instances:      60-91% cheaper, can be terminated with 2-min warning!

Strategy:
├── Stateless workloads → Spot instances ✅
├── Stateful workloads → On-Demand ❌ (don't put databases on spot!)
├── Batch jobs → Spot instances ✅
└── Critical APIs → Mix (on-demand base + spot for burst)

ResourceQuota Per Team

Showback vs Chargeback

Showback: "Here's what your team costs"
├── Informational — no actual billing
├── Encourages awareness
├── Monthly reports
└── Dùng khi: Internal teams, shared budget

Chargeback: "Your team pays for this"
├── Actual billing to team budget
├── Incentivizes optimization
├── Accurate allocation needed
└── Dùng khi: Large organizations, separate P&L

📈 Cost Savings Examples

Scenario 1: Resource Right-Sizing

Before: 20 pods × (1 CPU, 2Gi) = 20 CPU, 40Gi requested
Actual usage: 20 pods × (200m CPU, 400Mi) = 4 CPU, 8Gi used
Waste: 80% CPU, 80% Memory!

After right-sizing: 20 pods × (300m CPU, 512Mi) = 6 CPU, 10Gi
Savings: 70% CPU, 75% Memory
Monthly savings: ~$500-1000 (depends on provider)

Scenario 2: Spot Instances

Before: 10 on-demand nodes × $200/month = $2,000/month
After:  3 on-demand + 7 spot nodes = 3×$200 + 7×$60 = $1,020/month
Savings: 49% ($980/month)

Scenario 3: Dev/Test Scheduling

Before: Dev cluster 24/7 = $1,500/month
After:  Dev cluster 10h/day × 5 days/week = $450/month
Savings: 70% ($1,050/month)

Scenario 4: Combined Optimizations

💡 Cost Optimization Checklist

✅ Quick Wins (Implement Today)

□ Delete unused PVs, ConfigMaps, Secrets
□ Stop dev/test during off-hours
□ Remove :latest tags (unnecessary pulls)
□ Set resource requests based on actual usage
□ Install Kubecost/OpenCost for visibility

✅ Medium-Term (This Month)

□ Implement VPA recommendations
□ Setup spot node pools for non-critical workloads
□ Configure PDB for spot resilience
□ Add cost labels to all resources
□ Setup cost alerts (budget thresholds)

✅ Long-Term (This Quarter)

□ Implement ResourceQuota per team
□ Setup showback/chargeback reporting
□ Optimize storage tiers
□ Review HPA/VPA configurations
□ Regular cost review meetings (monthly)
□ Evaluate Reserved Instances vs On-Demand

🎓 Key Takeaways

  1. FinOps = Inform → Optimize → Operate (continuous cycle)
  2. Right-sizing giảm 40-70% waste — dùng VPA recommendations
  3. Spot instances giảm 60-91% compute cost — dùng cho stateless workloads
  4. Dev/test scheduling giảm 60-70% cost — scale to zero off-hours
  5. Cost allocation bằng labels + ResourceQuota — accountability per team
  6. Monitor costs liên tục — Kubecost/OpenCost dashboards
  7. Storage tiers — standard cho logs/archives, SSD chỉ cho databases
  8. Quick wins → Medium term → Long term: progressive optimization
