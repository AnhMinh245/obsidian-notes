6. EC2 – Solutions Architect Associate Level

Cách đọc note này: Đây là 4 khái niệm networking/hardware nâng cao của EC2, thường ra thi dưới dạng “chọn kiến trúc phù hợp” chứ không hỏi định nghĩa suông. Đọc kỹ 2 bảng so sánh (Placement Groups, EBS liên quan ở 07 - EC2 Instance Storage) — đề thi rất thích hỏi dạng “công ty cần X, chọn Placement Group nào?”.

Private IP vs Public IP vs Elastic IP

Slide gốc chỉ nói IPv4 ([0-255].[0-255].[0-255].[0-255]) — IPv6 (dạng 3ffe:1900:4545:3:200:f8ff:fe21:67cf) mới hơn, giải quyết vấn đề thiếu địa chỉ IoT, nhưng khoá này (và phần lớn câu hỏi SAA-C03) chỉ tập trung IPv4.

Phân biệt Public IP và Private IP

Company A và Company B dùng CHUNG dải private 192.168.0.1/22 mà không xung đột — vì private IP chỉ cần unique trong nội bộ 1 mạng, không cần unique toàn cầu. Chỉ Internet Gateway (public IP) mới cần unique trên toàn Internet.

Public IPPrivate IP
Phạm viTruy cập được từ InternetChỉ trong mạng nội bộ (VPC)
Tính duy nhấtUnique toàn cầuUnique trong private network
Khi EC2 stop/startCó thể thay đổiGiữ nguyên
Địa chỉBất kỳ IP công cộng10.x, 172.16–31.x, 192.168.x.x
Kết nối InternetTrực tiếpQua NAT + Internet Gateway

Mặc định khi launch EC2:

  • Private IP: cố định cho internal AWS network.
  • Public IP: phân công tạm thời, thay đổi khi stop/start.

SSH vào EC2:

  • Từ mạng ngoài → phải dùng Public IP (không dùng được Private IP).
  • Khi EC2 stop rồi start lại → Public IP có thể đổi → SSH sẽ fail nếu đang dùng IP cứng.

Elastic IP — IP công cộng cố định

Elastic IP là địa chỉ IPv4 public bạn sở hữu và giữ cho đến khi tự xóa.

  • Gắn được vào 1 instance tại một thời điểm.
  • Có thể gán lại nhanh sang instance khác khi instance cũ fail → dùng cho failover thủ công.
  • Mỗi account mặc định tối đa 5 Elastic IP (có thể xin tăng).

Tại sao nên tránh dùng Elastic IP?

  • Thường phản ánh thiết kế kiến trúc kém.
  • Chi phí phát sinh khi không gắn vào instance đang chạy.
  • Giải pháp tốt hơn:
    • Dùng DNS (Route 53) trỏ vào Public IP ngẫu nhiên → tự cập nhật khi đổi.
    • Đặt Load Balancer phía trước → không cần IP cố định.

Placement Groups — Chiến lược đặt EC2

Placement Group cho phép kiểm soát cách AWS đặt các EC2 instance lên phần cứng vật lý. Có 3 chiến lược:

1. Cluster — Độ trễ thấp nhất

graph LR
    subgraph AZ1 ["Availability Zone 1"]
        subgraph Rack1 ["Cùng 1 rack vật lý"]
            EC1["EC2 #1"]
            EC2["EC2 #2"]
            EC3["EC2 #3"]
        end
    end
  • Tất cả instance trong cùng 1 AZ, cùng rack vật lý.
  • Băng thông network giữa instances: tối đa 10 Gbps (Enhanced Networking).
  • Ưu điểm: Latency cực thấp → phù hợp cho HPC, distributed computing.
  • Nhược điểm: Nếu AZ hoặc rack fail → tất cả instances fail cùng lúc.

Dùng cho:

  • Big Data job cần xử lý xong thật nhanh.
  • App yêu cầu extremely low latency + high network throughput.

2. Spread — Cách ly tối đa

    subgraph AZ1 ["AZ 1"]
        R1["Rack 1\nEC2 #1"]
        R2["Rack 2\nEC2 #2"]
    end
    subgraph AZ2 ["AZ 2"]
        R3["Rack 3\nEC2 #3"]
    end
    subgraph AZ3 ["AZ 3"]
        R4["Rack 4\nEC2 #4"]
    end
  • Mỗi instance trên hardware riêng → không bao giờ cùng rack.
  • Trải đều qua nhiều AZ.
  • Giới hạn: tối đa 7 instances/AZ per placement group.
  • Ưu điểm: Giảm rủi ro nhiều instance fail cùng lúc tối đa.
  • Nhược điểm: Giới hạn số lượng.

Dùng cho:

  • App yêu cầu High Availability tối đa.
  • Critical application cần mỗi instance độc lập về failure.

3. Partition — Tách nhóm rack

graph LR
    subgraph AZ1 ["AZ 1"]
        subgraph P1 ["Partition 1"]

            EC2["EC2 #2"]
        end

            EC4["EC2 #4"]

            EC5["EC2 #5"]
        end

  • Chia instances thành các partition (nhóm rack), các partition không chia sẻ phần cứng với nhau.
  • Tối đa 7 partitions/AZ, có thể trải qua nhiều AZ trong cùng region.
  • Có thể chứa hàng trăm EC2 instances.
  • Mỗi instance có quyền truy cập metadata về partition của nó.
  • Một partition fail → ảnh hưởng instances trong partition đó, không ảnh hưởng partition khác.

Dùng cho: Big Data frameworks — Hadoop, Cassandra, Kafka, HBase, HDFS.

Elastic Network Interfaces (ENI)

ENI là gì?

ENI (Elastic Network Interface) là card mạng ảo trong VPC — component logic đại diện cho một network card.

Mỗi ENI có thể có:

Thuộc tínhMô tả
Primary Private IPv41 địa chỉ chính
Secondary IPv4Một hoặc nhiều địa chỉ phụ
Elastic IP (IPv4)1 per private IPv4
Public IPv41 địa chỉ
Security GroupsMột hoặc nhiều
MAC Address1 địa chỉ MAC cố định

ENI và Failover

graph LR
    ENI["ENI\n(chứa Private IP, SG, MAC)"]
    EC2_A["EC2 Instance A\n(healthy)"]
    EC2_B["EC2 Instance B\n(failover target)"]

    ENI -->|"gắn vào"| EC2_A
    EC2_A -->|"fail!"| EC2_A
    ENI -->|"tháo và gắn sang"| EC2_B
  • ENI có thể tạo độc lập và attach/detach từ EC2 instances — linh hoạt cho failover.
  • Khi EC2 fail → tháo ENI gắn sang EC2 mới → Private IP không đổi → app tiếp tục hoạt động.
  • Bound to AZ: ENI chỉ gắn được cho instance trong cùng AZ.

Use cases:

  • Failover nhanh mà không cần đổi IP.
  • Management network riêng (1 ENI cho traffic, 1 ENI cho management).
  • Dual-homed instance (instance kết nối 2 subnet khác nhau).

EC2 Hibernate

EC2 Hibernate hoạt động thế nào?

flowchart LR
    Running["EC2 đang chạy\n(RAM: 8GB data)"]
    Hibernate["Hibernate signal"]
    Save["RAM state → ghi vào\nroot EBS volume (encrypted)"]
    Stop["Instance dừng\n(EBS vẫn có full state)"]
    Resume["Start lại\nRAM được restore từ EBS"]
    Fast["Boot cực nhanh\nApp tiếp tục ngay"]

    Running --> Hibernate --> Save --> Stop
    Stop --> Resume --> Fast

Điều kiện áp dụng Hibernate:

Điều kiệnYêu cầu
Instance familiesC3, C4, C5, I3, M3, M4, R3, R4, T2, T3…
RAM sizePhải < 150 GB
Instance sizeKhông hỗ trợ bare metal
OSAmazon Linux 2, Ubuntu, RHEL, CentOS, Windows
Root VolumePhải là EBS (không phải Instance Store) + Encrypted
PurchasingOn-Demand, Reserved, Spot
Max durationTối đa 60 ngày

Use cases:

  • Long-running processing — không muốn khởi động lại từ đầu.
  • Service cần warm-up lâu (cache warm-up, connection pooling).
  • Lưu trạng thái RAM giữa các session.

Bảng từ khoá đề thi

Từ khoá trong đềChọn
”Big Data job cần chạy xong thật nhanh, low-latency, HPC”Placement Group – Cluster
”Critical app, mỗi instance phải độc lập khi có sự cố”Placement Group – Spread (tối đa 7 instance/AZ)
“Hadoop/Cassandra/Kafka/HDFS, hàng trăm node”Placement Group – Partition
”Cần fixed public IP để failover thủ công sang instance khác”Elastic IP (nhưng cân nhắc LB/Route 53 trước)
“Cần failover mà không đổi private IP”ENI — tháo khỏi instance fail, gắn sang instance mới cùng AZ
”Không muốn khởi động lại từ đầu, giữ nguyên RAM”EC2 Hibernate (root EBS phải encrypted, RAM < 150 GB)
“SSH vào EC2 từ máy cá nhân”Phải dùng Public IP, không dùng được Private IP

Đào sâu thêm về ENI/Private IP trong bối cảnh VPC → 1.3 - VPC Security - SG, NACL, NAT. Về lựa chọn compute nói chung → 3.2 - Compute - EC2, Lambda, Fargate.

Điểm hay ra thi

  • Elastic IP nên tránh — thay bằng Load Balancer + Route 53.
  • Placement Group Cluster — cùng 1 AZ, latency thấp nhất, nhưng AZ fail → tất cả fail.
  • Placement Group Spread — tối đa 7 instances/AZ per group.
  • Placement Group Partition — Hadoop/Cassandra/Kafka, tối đa 100s instances.
  • ENI bound to AZ — không di chuyển sang AZ khác.
  • EC2 Hibernate yêu cầu root EBS phải encrypted.
  • Hibernate tối đa 60 ngày.
  • Hibernate: RAM < 150 GB, không hỗ trợ bare metal.

Takeaway cá nhân

  • Elastic IP là anti-pattern — architecture chuẩn dùng Load Balancer + DNS thay vì IP cố định.
  • 3 Placement Group: Cluster (speed/latency), Spread (max isolation), Partition (big data frameworks).
  • ENI giúp failover không đổi IP bằng cách tháo và gắn sang instance mới trong cùng AZ.
  • EC2 Hibernate = “ngủ đông” — RAM được lưu xuống EBS, boot nhanh và resume từ chỗ dừng.
