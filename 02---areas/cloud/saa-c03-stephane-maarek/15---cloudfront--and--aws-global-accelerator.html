15 – CloudFront & AWS Global Accelerator

Amazon CloudFront là gì?

Amazon CloudFront là dịch vụ CDN (Content Delivery Network) của AWS — đưa content gần user hơn bằng cách cache tại edge locations toàn cầu.

Đặc điểm chính:

  • Cải thiện read performance — content được cache tại edge, user không phải đi hết về Region gốc mỗi lần.
  • Có hàng trăm Points of Presence (PoP) / edge locations.
  • Bảo vệ DDoS nhờ mạng phân tán toàn cầu; tích hợp AWS Shield và AWS WAF.
  • Phục vụ cả static (ảnh, CSS, JS, video) và dynamic (API, HTML sinh động).

CloudFront hoạt động thế nào?

sequenceDiagram
    participant User as User gần edge
    participant Edge as CloudFront Edge
    participant Origin as Origin S3 hoặc ALB

    User->>Edge: GET /logo.png
    alt Cache HIT
        Edge->>User: Trả file từ cache edge
    else Cache MISS
        Edge->>Origin: Forward request
        Origin->>Edge: Response + Cache-Control / TTL
        Edge->>Edge: Lưu vào cache
        Edge->>User: Trả content
    end

Ý chính: User luôn kết nối tới edge gần nhất. Chỉ khi cache miss (hoặc content không cache được) CloudFront mới gọi về origin.

CloudFront – Origins

Origin = nguồn gốc mà CloudFront lấy content để phục vụ (và cache khi phù hợp).

Loại OriginDùng khiBảo mật / ghi chú
S3 bucket (REST endpoint)Phân phối file static, cache tại edge; upload lên S3 qua CloudFrontDùng Origin Access Control (OAC) — bucket không public
VPC OriginApp trong VPC private subnetPrivate ALB / NLB / EC2 — không cần expose Internet
Custom Origin (HTTP)Backend HTTP công khaiS3 website endpoint (phải bật static website hosting), Public ALB, HTTP server bất kỳ

1. S3 làm Origin + Origin Access Control (OAC)

Mục tiêu: User chỉ truy cập file qua CloudFront, không vào thẳng S3 URL công khai.

graph LR
    User["User"] -->|"HTTPS"| CF["CloudFront"]
    CF -->|"OAC ký request"| S3["S3 Bucket<br/>(private)"]
    User -.->|"❌ bị chặn bởi Bucket Policy"| S3
  • OAC thay thế cơ chế cũ OAI (Origin Access Identity) — OAC hỗ trợ SSE-KMS, PUT/DELETE qua CloudFront, mọi Region mới hơn.
  • Cần Bucket Policy cho phép CloudFront service principal (kèm điều kiện AWS:SourceArn của distribution).
  • Phân biệt 2 endpoint S3:
    • REST API (bucket.s3.amazonaws.com / regional) → dùng với OAC.
    • Website endpoint (bucket.s3-website-...) → là Custom Origin, không dùng OAC; bucket phải public (hoặc có cơ chế khác).

Điểm thi: Muốn S3 private + chỉ CloudFront đọc được → OAC + Bucket Policy. Không chọn “làm bucket public”.

2. Custom Origin (HTTP)

  • Bất kỳ origin nói HTTP/HTTPS: Public ALB, EC2 có public IP, on-prem HTTP, S3 website.
  • CloudFront kết nối tới origin theo Origin Protocol Policy: HTTP only / HTTPS only / Match Viewer.
  • Origin phải reachable từ Internet (trừ khi dùng VPC Origin).

3. VPC Origin — ALB / NLB / EC2 private

VPC Origins cho phép CloudFront lấy content từ app trong private subnet, không cần expose ALB/EC2 ra Internet.

Traffic có thể tới private:

  • Application Load Balancer
  • Network Load Balancer
  • EC2 Instances
graph LR
    User["User"] --> CF["CloudFront"]
    CF -->|"VPC Origin"| ALB["Private ALB"]
    ALB --> EC2["EC2 private subnet"]

Trước đây (không VPC Origin): ALB thường phải Internet-facing để CloudFront gọi được → bề mặt tấn công rộng hơn.

Với VPC Origin: ALB/NLB/EC2 giữ private → chỉ CloudFront (qua cơ chế VPC Origin) tới được.

Điểm thi: “Serve app private subnet qua CDN, không public ALB” → CloudFront + VPC Origin.

CloudFront vs S3 Cross Region Replication

Hai giải pháp giảm latency đọc nhưng cơ chế khác hẳn — hay bị đề thi trộn.

Tiêu chíCloudFrontS3 Cross Region Replication (CRR)
Cơ chếCache tại Global EdgeCopy object sang bucket ở region khác
Setup1 distribution, cover toàn cầuPhải setup từng cặp region cần replicate
Độ “tươi” của dataTheo TTL (có thể vài phút → cả ngày)Gần real-time (async, thường vài giây)
Ghi / cập nhậtOrigin vẫn là nguồn truth; edge có thể staleDestination nhận bản sao; model read tại region đích
Phù hợpStatic (và một phần dynamic) cần sẵn sàng mọi nơiDynamic / data cần low latency đọc ở vài region cụ thể

Ví dụ chọn:

  • Website ảnh/CSS/JS cho user toàn cầu → CloudFront.
  • Object phải đọc được ngay ở eu-west-1 và ap-southeast-1 với data gần real-time → S3 CRR (hoặc kết hợp cả hai).

Điểm thi: CloudFront = cache toàn cầu theo TTL. CRR = replicate gần real-time sang region cụ thể — không thay thế nhau.

CloudFront – Cache & TTL

CloudFront quyết định giữ object bao lâu dựa trên:

Nguồn TTLÝ nghĩa
Header origin (Cache-Control, Expires)Origin “bảo” edge cache bao lâu
CloudFront Minimum / Maximum / Default TTLGiới hạn / mặc định phía distribution
Object không cacheableVí dụ response có Cache-Control: no-cache / cookie / một số dynamic request

Hệ quả:

  • TTL còn hiệu lực → user nhận bản cũ dù origin đã update.
  • Muốn content mới ngay → Invalidation, hoặc dùng versioned filename (app.v2.js) để URL mới → cache miss tự nhiên.

CloudFront Geo Restriction

Giới hạn ai được truy cập distribution theo quốc gia:

Chế độHành vi
AllowlistChỉ user ở các nước trong danh sách mới được truy cập
BlocklistChặn user ở các nước trong danh sách bị cấm
  • Quốc gia xác định qua Geo-IP database bên thứ 3 (không phải GPS chính xác 100%).
  • Độ chi tiết: cấp quốc gia, không phải thành phố/IP range tùy ý.
  • Use case: tuân thủ luật bản quyền (copyright) theo vùng địa lý — ví dụ chỉ phát video ở EU.

Phân biệt với Route 53 Geolocation: Route 53 chọn DNS answer theo vị trí; CloudFront Geo Restriction chặn/cho phép HTTP request tại edge.

CloudFront – Cache Invalidations

Khi cập nhật origin, CloudFront không tự biết — vẫn phục vụ bản cache cũ đến khi TTL hết.

Muốn làm mới ngay (bỏ qua TTL) → dùng CloudFront Invalidation:

  • Invalidate tất cả: /* hoặc *
  • Invalidate theo path: /images/*, /index.html

CáchƯuNhược
InvalidationForce refresh ngay path cũCó thể tốn phí; không phải best practice dài hạn
Versioned objects (style.a1b2.css)Không cần invalidate; cache hit URL mớiPhải đổi URL / build pipeline

Thực hành tốt: Deploy static với tên file có hash/version; giữ Invalidation cho emergency hoặc HTML entrypoint.

Bài toán: User toàn cầu truy cập app

Bạn deploy một application, user toàn cầu muốn truy cập trực tiếp.

  • Đi qua public Internet → nhiều hop, peering kém → latency cao, jitter lớn.
  • Mục tiêu: vào mạng nội bộ AWS sớm nhất có thể (tại edge gần user) rồi đi private backbone tới Region.

Đây là bài toán mà AWS Global Accelerator giải quyết (khác CloudFront — GA không cache content).

AWS Global Accelerator

Global Accelerator tận dụng mạng nội bộ AWS để route traffic tới application — cải thiện hiệu năng TCP/UDP bằng cách proxy tại edge, không phải CDN cache.

graph LR
    User["User toàn cầu"] -->|"2 Anycast IP"| Edge["Edge Location"]
    Edge -->|"AWS private network"| EG["Endpoint Group<br/>(Region)"]
    EG --> EP["Endpoint<br/>ALB / NLB / EIP / EC2"]

Anycast IP là gì?

  • Global Accelerator cấp 2 static Anycast IP (IPv4) cho accelerator của bạn.
  • Cùng 1 IP được advertise từ nhiều edge → user được route tới edge gần nhất.
  • IP không đổi khi bạn failover Region → client / firewall whitelist không bị vỡ vì DNS TTL.

Endpoint được hỗ trợ

  • Elastic IP
  • EC2 instances
  • ALB, NLB
  • Public hoặc private (tùy cấu hình)

Ba nhóm lợi ích

NhómChi tiết
Consistent PerformanceRouting tới latency thấp nhất; failover region nhanh; IP cố định → không bị client cache DNS cũ; traffic đi internal AWS network sau khi vào edge
Health ChecksGA health-check endpoint; failover < 1 phút khi unhealthy; hữu ích cho Disaster Recovery multi-region
SecurityFirewall chỉ cần whitelist 2 external IP; DDoS nhờ AWS Shield

Ví dụ DR: Primary ALB us-east-1 unhealthy → traffic chuyển sang ALB eu-west-1 trong vòng dưới 1 phút, cùng Anycast IP.

AWS Global Accelerator vs CloudFront

Cả hai đều dùng AWS global network + edge locations, và đều tích hợp AWS Shield (DDoS).

Tiêu chíCloudFrontGlobal Accelerator
Vai tròCDN — cache & serve contentNetwork layer accelerator — proxy packets
ProtocolChủ yếu HTTP/HTTPSTCP và UDP
Content ở edge?✔ Có thể serve từ cache tại edge❌ Không cache app content; forward về Region
IPDomain CloudFront (DNS), IP có thể đổi2 static Anycast IP
Use case nổi bậtStatic + dynamic web, API acceleration, videoGaming (UDP), IoT (MQTT), VoIP; HTTP cần static IP; failover region nhanh, deterministic

Cách chọn nhanh (hay ra thi)

Tình huống đề bàiChọn
Cache ảnh/video/static gần userCloudFront
API/website HTTP cần CDN + WAFCloudFront
Cần static IP cố định cho whitelistGlobal Accelerator
Gaming / IoT / VoIP (UDP hoặc non-HTTP)Global Accelerator
Failover multi-region < 1 phút, không phụ thuộc DNS TTLGlobal Accelerator
App private subnet, serve qua CDN HTTPCloudFront + VPC Origin
Data object phải có bản sao gần real-time ở vài RegionS3 CRR (không phải CloudFront)

Công thức nhớ: CloudFront = cache content. Global Accelerator = tối ưu đường đi mạng + IP tĩnh.

Điểm hay ra thi

  • CloudFront = CDN, cache theo TTL tại edge; origin update ≠ edge update ngay.
  • S3 private + CloudFront → OAC + Bucket Policy (không public bucket).
  • S3 website endpoint = Custom Origin, khác S3 REST + OAC.
  • Private ALB/EC2 làm origin → VPC Origin.
  • Geo Restriction = Allowlist / Blocklist theo quốc gia (Geo-IP).
  • Invalidate /* hoặc path cụ thể để bypass TTL; ưu tiên versioned filenames.
  • CloudFront ≠ S3 CRR: edge cache toàn cầu vs replicate gần real-time vài region.
  • Global Accelerator: 2 Anycast IP, health check, failover < 1 phút, Shield.
  • Cần static IP / UDP / failover nhanh → Global Accelerator; cần CDN cache → CloudFront.

Takeaway cá nhân

  • CloudFront tối ưu đọc content gần user; Global Accelerator tối ưu đường đi mạng tới app.
  • VPC Origin = front được app private mà không mở Internet-facing ALB.
  • Invalidation = cứu cháy khi TTL còn dài; lâu dài nên version file name.
  • Câu hỏi “static IP + multi-region failover” gần như luôn là Global Accelerator, không phải CloudFront.
