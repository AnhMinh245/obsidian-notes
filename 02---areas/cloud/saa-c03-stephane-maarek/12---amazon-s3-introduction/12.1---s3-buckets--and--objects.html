12.1 – S3 Buckets & Objects

Cách đọc note này: Đây là bài nền tảng của cả 3 section S3 (12/13/14) — nắm chắc khái niệm Bucket/Object/Key ở đây trước khi sang Storage Classes (Section 13) hay Encryption (Section 14). Đối chiếu thêm ở 3.1 - Storage Solutions - S3, EBS, EFS, FSx.

S3 là gì?

Amazon S3 là dịch vụ object storage của AWS — lưu trữ file dưới dạng đối tượng (objects), dung lượng gần như vô hạn, độ bền 99.999999999% (11 số 9).

Các Use Case thực tế

Use CaseMô tả
Backup & StorageBackup file, DB, app — 11 số 9 durability
Disaster RecoveryCross-Region Replication — phục hồi khi region fail
ArchiveS3 Glacier — lưu dài hạn giá cực rẻ
Hybrid Cloud StorageKết nối on-prem qua S3 Storage Gateway
Application HostingỨng dụng lưu ảnh, video, logs trực tiếp vào S3
Data Lakes & AnalyticsNơi chứa dữ liệu thô cho Athena, Glue, EMR
Static WebsiteS3 + CloudFront = website tĩnh giá rẻ, uptime cao
Software DeliveryPackage, game assets, firmware phân phối qua CloudFront

Buckets — Khái niệm và Quy tắc đặt tên

Bucket là “thư mục gốc” để chứa objects.

graph TD
    Account["AWS Account"] --> BucketA["Bucket: my-app-data<br/>(us-east-1)"]
    Account --> BucketB["Bucket: my-backups<br/>(ap-southeast-1)"]
    BucketA --> Obj1["Object: images/photo.jpg"]
    BucketA --> Obj2["Object: logs/2026-07-19.log"]

Đặc điểm bucket:

  • Mỗi bucket thuộc một region cụ thể — S3 trông như global service nhưng bucket luôn được tạo trong 1 region.
  • Tên bucket phải toàn cầu duy nhất — không chỉ trong account của bạn mà trên toàn bộ AWS thế giới.

2 kiểu Namespace — hay bị nhầm

Slide gốc phân biệt rõ 2 khái niệm namespace, dễ gây hiểu lầm nếu bỏ qua:

NamespaceÝ nghĩa
Shared Global NamespaceTên bucket phải unique trên toàn AWS — across mọi region, mọi account
Account Regional NamespaceCho phép tái sử dụng cùng 1 tên bucket ở các region khác nhau, miễn là cùng account

→ Nói cách khác: bạn KHÔNG thể tạo 2 bucket tên my-data ở 2 account khác nhau (dù khác region), nhưng CÓ THỂ tạo my-data ở us-east-1 và my-data ở eu-west-1 nếu cả 2 đều thuộc cùng 1 account.

Quy tắc đặt tên (quan trọng trong exam):

Quy tắcMô tả
✔ Độ dài3–63 ký tự
✔ Bắt đầu bằngChữ cái thường hoặc số
❌ Không dùngChữ hoa, dấu gạch dưới _
❌ Không được làDạng IP (vd: 192.168.1.1)
❌ Không bắt đầu bằngPrefix xn--
❌ Không kết thúc bằngSuffix -s3alias

Tại sao quy tắc nghiêm vậy? Vì S3 phải tạo endpoint DNS dạng https://my-bucket.s3.amazonaws.com — tên kỳ lạ sẽ làm DNS không hoạt động.

Objects — Cách S3 lưu trữ dữ liệu

Trong S3, mọi thứ đều là object (không có “folder” thật sự).

Mỗi object gồm:

Thành phầnMô tả
DataNội dung file (bytes)
KeyĐường dẫn đầy đủ (FULL PATH)
MetadataSystem metadata (Content-Type…) + User metadata (tự đặt)
TagsTối đa 10 tags (dùng cho lifecycle, security, billing)
Version IDNếu bật Versioning

Key = Full Path của Object

my_file.txt
my_folder/my_file.txt
my_folder/another_folder/my_file.txt

Prefix + Object name:

  • Key: my_folder/another_folder/my_file.txt
  • Prefix: my_folder/another_folder/
  • Object name: my_file.txt

Prefix quan trọng để tối ưu performance — xem S3 Performance.

S3 KHÔNG có thư mục thật

graph LR
    subgraph realWorld ["Thực tế bên trong S3 — flat list"]

        K2["Key: folder/sub/file2.jpg"]

    subgraph uiView ["Giao diện Console hiển thị"]

UI Console hiển thị folder, nhưng đó chỉ là object có key chứa dấu / — được giả lập. S3 thật sự chỉ lưu flat list of objects với key dài.

Kích thước Object

  • Tối đa: 5 TB per object
  • Upload > 5 GB → bắt buộc dùng Multipart Upload
  • Nên dùng Multipart khi file > 100 MB (song song, resume được)

Bảng từ khoá đề thi

Từ khoá trong đềChọn
”Bucket name đã bị người khác dùng ở account khác”Bình thường — tên bucket là Shared Global Namespace
”Dùng lại đúng tên bucket ở region khác, cùng account”Được phép — Account Regional Namespace
”Bucket có phải service theo region không?”Có — mỗi bucket thuộc 1 region, dù S3 trông như global
”File > 5 GB upload thế nào?”Bắt buộc Multipart Upload
”Muốn tối ưu tốc độ đọc/ghi hàng nghìn request/s”Phân bổ nhiều prefix khác nhau
”S3 có folder thật không?”Không — chỉ là key chứa dấu /, UI giả lập folder

Điểm hay ra thi

  • Tên bucket phải globally unique — trên toàn thế giới, không chỉ trong account.
  • Bucket thuộc một region cụ thể — không phải global.
  • Phân biệt Shared Global Namespace (tên bucket) vs Account Regional Namespace (cùng tên, khác region, cùng account thì được).
  • S3 không có thư mục thật — chỉ là key với dấu /.
  • Object tối đa 5 TB; upload > 5 GB bắt buộc Multipart.
  • Prefix ảnh hưởng đến performance (baseline 3.500 PUT + 5.500 GET per prefix/sec).

Takeaway cá nhân

  • S3 là flat key-value store — “folder” chỉ là prefix trong key.
  • Bucket = container theo region; Object = file với full path key.
  • Hiểu prefix là cơ sở để tối ưu performance và lifecycle rules.
  • 2 loại namespace (Shared Global vs Account Regional) là chi tiết nhỏ nhưng dễ bị hỏi dạng “tại sao lại…” — nhớ: tên là global, nhưng “chỗ chứa” (region) là account-scoped.
