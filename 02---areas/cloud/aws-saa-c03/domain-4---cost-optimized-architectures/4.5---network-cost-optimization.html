Task 4.4: Design Cost-Optimized Network Architectures

📊 Tiến độ học tập: Network Cost Optimization

Status: Đã hoàn thành chuyên sâu
Tầm quan trọng: Cao (Thường xuyên gặp các cạm bẫy về Data Transfer và VPC Endpoint trong bài thi)

Phí truyền tải dữ liệu (Data Transfer) thường là một “chi phí ẩn” khủng khiếp nếu không được thiết kế kỹ lưỡng. Nắm vững luật tính phí mạng của AWS là chìa khóa để xử lý bài thi và quản trị thực tế. Đôi khi tiền Data Transfer Out (DTO) còn cao hơn tiền thuê EC2!

1. Lý Thuyết Chuyên Sâu: Luật chung của AWS Data Transfer Costs

Bảng sau tổng hợp các nguyên tắc tính phí truyền dữ liệu cốt lõi trong AWS:

Loại TrafficPhí Data TransferGiải thích chi tiết & Tối ưu
Data IN (Từ Internet vào AWS)MIỄN PHÍ ($0.00)AWS muốn bạn mang dữ liệu vào hệ sinh thái của họ. Tải lên 100 PB vào S3 hay EC2 đều miễn phí tiền mạng (vẫn tính phí API PUT và Storage).
Data OUT (Từ AWS ra Internet)Đắt ($0.09/GB)Tính theo GB (tiered pricing - dùng càng nhiều càng rẻ dần). Dùng Amazon CloudFront để giảm chi phí này vì Data Transfer ra Internet từ CloudFront rẻ hơn EC2/S3 trực tiếp.
Data giữa 2 Regions (Inter-Region)Tính phí ($0.02/GB)VD: EC2 Region A gọi RDS Region B, hoặc S3 Cross-Region Replication. Thiết kế Multi-Region rất đắt đỏ do phí này.
Data giữa 2 AZ (Inter-AZ)Tính phí ($0.01/GB in/out)Dù cùng Region, traffic chạy qua lại giữa 2 Availability Zones (cùng VPC) vẫn bị tính phí cả chiều gửi và nhận.
Data cùng AZ (Cùng VPC)MIỄN PHÍ ($0.00)Bắt buộc phải sử dụng Private IP. Nếu dùng Public IP hoặc Elastic IP để gọi máy cùng AZ, lưu lượng sẽ chạy ra public network và bị tính phí!

Chú ý khi thiết kế High Availability (Exam Trap)

Mặc dù Multi-AZ là “Best Practice” cho High Availability, nhưng nếu bạn có một cụm phân tán Big Data (Hadoop/Cassandra) cần trao đổi Terabytes dữ liệu liên tục giữa các nodes, bạn nên đặt chúng trong CÙNG MỘT AZ thông qua Cluster Placement Group. Nếu để chúng tản mạn ở 2 AZ, phí mạng liên AZ có thể khiến dự án phá sản.

2. Limits, Quotas & Constraints Cần Nhớ

  • NAT Gateway: Hỗ trợ băng thông từ 5 Gbps lên đến 100 Gbps. Dù scale tự động, chi phí sẽ rất cao do thu thêm “Data Processing fee” ($0.045 cho mỗi GB đi qua nó).
  • VPC Peering: Không hỗ trợ Transitive Peering (Bắc cầu). Nếu A nối B, B nối C, thì A không thể trực tiếp gọi C thông qua B. Phải tạo kết nối trực tiếp A-C.
  • AWS Direct Connect: Có các gói vật lý Port Speed 1Gbps, 10Gbps, 100Gbps, hoặc kết nối qua Partner (Hosted connection) từ 50Mbps.
  • Transit Gateway (TGW): Hỗ trợ kết nối lên tới 5000 VPCs. Băng thông tối đa 50 Gbps trên mỗi VPC Attachment.

3. Tối ưu NAT Gateway vs NAT Instance vs VPC Endpoints

NAT Gateway & NAT Instance

Khi các EC2 nằm trong Private Subnet cần ra Internet (Ví dụ tải OS patch, kết nối 3rd party API), chúng phải đi qua NAT ở Public Subnet.

  • NAT Gateway (Managed): Được AWS quản lý, Highly Available trong 1 AZ. Tính phí theo giây hoạt động (Hourly charge) + số lượng GB được xử lý (Data Processing charge).
  • NAT Instance (EC2 tự cấu hình): Máy ảo Amazon Linux tự cấu hình iptables. Rẻ hơn cho băng thông thấp (chỉ tốn tiền EC2 t3.micro), nhưng không tự động HA và bị thắt cổ chai bởi Network Bandwidth của chính EC2 đó. Không khuyến khích cho Production.

Thần chú tiết kiệm: VPC Endpoints (Gateway vs Interface)

Đây là “Chén Thánh” (Holy Grail) của tiết kiệm mạng trong bài thi SAA-C03. Khi Private EC2 cần gọi Amazon S3 hoặc DynamoDB:

  • Cách đắt tiền (NAT Gateway): Data đi qua NAT Gateway, bị tính phí $0.045/GB (Data processing). Upload 10TB log lên S3 mỗi ngày tốn hàng ngàn đô/tháng.
  • Cách siêu tiết kiệm (Gateway Endpoint): Tạo VPC Gateway Endpoint cho S3. AWS tiêm (inject) Prefix List vào Route Table của subnet. Traffic từ EC2 đến S3 đi qua mạng Backbone của AWS. MIỄN PHÍ 100% (Không phí hourly, không phí data processing).
  • Interface Endpoint (AWS PrivateLink): Dùng cho các service khác ngoài S3/DynamoDB (như Kinesis, SNS, SSM, ECR). Nó nhét một Elastic Network Interface (ENI) với Private IP vào subnet của bạn. Lưu ý: Interface Endpoint CÓ TÍNH PHÍ Hourly + Data Processing, nhưng vẫn rẻ và bảo mật hơn NAT Gateway.

4. Tối ưu Data Transfer Out với Amazon CloudFront

CloudFront là Content Delivery Network (CDN) của AWS.

  • Phí truyền dữ liệu (Data Transfer Out - DTO) từ Origin (EC2, S3, ALB) đến các CloudFront Edge Locations là Hoàn toàn miễn phí.
  • DTO từ CloudFront Edge ra ngoài Internet thì rẻ hơn do AWS có các hợp đồng chiết khấu volume khổng lồ trên toàn cầu.
  • Nếu ứng dụng (hình ảnh, video, html) thường xuyên bị truy xuất nhiều lần, bộ nhớ cache của CloudFront chặn hầu hết request, giảm tải hoàn toàn lượng Read vào hệ thống gốc → Tiết kiệm thêm tiền Compute.

5. Mạng Lai (Hybrid Network): VPN vs Direct Connect

Khi cần nối mạng doanh nghiệp (On-premises) với AWS:

  • AWS Site-to-Site VPN: Chạy qua Internet mã hóa IPSec. Triển khai trong 5 phút. Rẻ ban đầu. Tuy nhiên, giới hạn 1.25 Gbps/tunnel, độ trễ không ổn định, và phí Data Transfer Out từ AWS về On-premise tính ngang giá Internet đắt đỏ.
  • AWS Direct Connect (DX): Kéo đường cáp quang dùng riêng bypass Internet. Cần nhiều tuần để thiết lập (nhà mạng đối tác). Tốn phí thuê Port vật lý hàng tháng khá cao. BÙ LẠI: Phí Data Transfer Out qua DX cực kì rẻ (0.02/GBsovới0.09/GB Internet). Nếu công ty chuyển Petabytes dữ liệu mỗi tháng, ROI của DX là cực lớn.

6. Case Study: Kiến trúc VPC Peering vs Transit Gateway (TGW)

Bối cảnh: Tập đoàn có 50 VPCs. Các VPC cần nói chuyện với nhau.

  • VPC Peering (Mesh): 50 VPC cần (50×49)/2=1225 kết nối Peering. Rất phức tạp để quản lý cấu hình. Tuy nhiên, chi phí mạng rất rẻ vì Peering không có cước phí cố định (hourly) hay phí xử lý dữ liệu (data processing), chỉ tính tiền nếu data đi qua lại giữa 2 AZ khác nhau.
  • Transit Gateway (Hub-Spoke): 50 VPC chỉ cần 50 kết nối (Attachments) đâm vào 1 Transit Gateway ở giữa. Dễ quản lý Route Tables vô cùng. Nhưng AWS tính phí 1 Attachment (0.05/giờ)+Phıˊxửlyˊ​dữliệuđiquaTGW(0.02/GB).

Quyết định (Cost Optimization): Nếu chỉ có 2-3 VPC, luôn chọn VPC Peering vì nó miễn phí. Nếu có hàng chục VPC, TGW là lựa chọn thực tế duy nhất, nhưng bạn phải chấp nhận “trade-off” (đánh đổi) tăng chi phí mạng để mua lấy sự đơn giản trong vận hành (Operational Excellence).

9. Cảnh Báo & Mẹo Thi (Exam Tips)

Mẹo từ khóa SAA-C03

  • “Cost-effective connectivity to S3 from private subnet” → Chọn Gateway Endpoint. (Tuyệt đối không chọn NAT Gateway hay Interface Endpoint cho S3 nếu chỉ ưu tiên giá).
  • “Predictable network performance and reduce bandwidth cost to on-premises” → Chọn AWS Direct Connect.
  • “Peering between 50 VPCs, reduce management overhead” → Transit Gateway (Mặc dù tốn tiền hơn nhưng là best practice cho mô hình mạng lớn).
  • “Static files, reduce load on EC2 and network transfer cost” → CloudFront.

Exam Trap: Gateway Endpoint vs Interface Endpoint

S3 và DynamoDB hỗ trợ Gateway Endpoint (MIỄN PHÍ).
S3 gần đây cũng hỗ trợ Interface Endpoint (CÓ TÍNH PHÍ, dùng cho AWS Client VPN hoặc On-premise chọc lên S3 qua Direct Connect).
Nếu đề bài chỉ đơn thuần là “EC2 trong VPC gọi S3 rẻ nhất”, chọn GATEWAY Endpoint.

10. Checklist Ôn Tập Cuối Cùng

  • Hiểu quy tắc Traffic: Inbound = Miễn phí, Cùng AZ bằng Private IP = Miễn phí, Inter-AZ = Mất phí.
  • Phân biệt được cơ chế tính tiền của NAT Gateway (giây + volume) so với VPC Gateway Endpoint (miễn phí).
  • Sự khác biệt lớn về chi phí Data Out giữa Internet vs CloudFront vs Direct Connect.
  • Phân biệt Use Case của VPC Peering (Rẻ, ít mạng) vs Transit Gateway (Tốn phí, nhiều mạng).
  • Nắm rõ lỗi hay mắc phải: dùng Public IP trong cùng VPC gây phát sinh phí mạng.
