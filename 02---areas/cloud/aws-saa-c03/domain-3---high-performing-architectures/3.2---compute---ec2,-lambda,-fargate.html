Compute: EC2, Lambda, Fargate & More

Compute là trái tim của mọi ứng dụng. Kiến trúc hiệu năng cao trong Compute đòi hỏi sự am hiểu về định cỡ máy chủ (sizing), chiến lược sắp xếp vật lý (placement), và khả năng co giãn linh hoạt (elasticity/serverless).

1. Amazon EC2 (Elastic Compute Cloud)

EC2 cung cấp máy chủ ảo (Virtual Machines) trên đám mây. Để đạt High Performance, cần chọn đúng Instance Family.

1.1. EC2 Instance Families

Cách đọc tên instance, ví dụ m5.xlarge:

  • m: Family class (General purpose).
  • 5: Thế hệ (Generation). Thế hệ càng cao thì CPU càng mới, networking mạnh hơn.
  • xlarge: Kích thước (Size). Cho biết số lượng vCPU và Memory.
FamilyĐặc trưng cốt lõiUse Case
General Purpose (M, T)Cân bằng giữa CPU, RAM và Network.Web servers thông thường, môi trường dev/test. T instances (T2, T3) là dạng Burstable.
Compute Optimized (C)Tỉ lệ vCPU so với RAM rất cao. CPU mạnh mẽ.Batch processing, game servers, machine learning inference, High Performance Web Servers.
Memory Optimized (R, X, z)Tỉ lệ RAM cực lớn (có thể lên tới hàng TB RAM).In-memory databases (Redis, Memcached, SAP HANA), Apache Spark, Big data analytics.
Storage Optimized (I, D, H)Gắn kèm Local NVMe Storage dung lượng lớn, tốc độ I/O cực cao.NoSQL databases (Cassandra, MongoDB), Data Warehouses, Kafka.
Accelerated Computing (P, G, Inf, Trn)Trang bị phần cứng chuyên dụng: GPUs, AWS Inferentia, AWS Trainium.Machine Learning training (P4, Trn1), Đồ họa, Video transcoding, 3D rendering (G4, G5).

Mẹo thi - T Instances (Burstable Performance)

Instances dòng T (như t2.micro, t3.large) sử dụng cơ chế CPU Credits. Khi idle, máy tích lũy credits. Khi có tải đột xuất (spike), máy xài credits để burst lên 100% CPU. Nếu hết credits, hiệu năng sẽ bị bóp nghẹt cực chậm. Để khắc phục, hãy bật chế độ Unlimited Mode (tự động trả thêm tiền nếu xài lố credits thay vì bị bóp hiệu năng).

1.2. Placement Groups (Nhóm vị trí triển khai)

Bạn có quyền kiểm soát vị trí vật lý mà các EC2 instances được AWS đặt vào hạ tầng vật lý của họ để tối ưu hiệu năng mạng hoặc tăng cường khả năng chịu lỗi.

1.3. Networking Interfaces (ENI, ENA, EFA)

  • ENI (Elastic Network Interface): Card mạng ảo mặc định.
  • ENA (Elastic Network Adapter): Nâng cấp của ENI, hỗ trợ tốc độ mạng lên tới 100 Gbps. Bắt buộc để đạt Enhanced Networking.
  • EFA (Elastic Fabric Adapter): Đỉnh cao nhất của networking, bypass OS kernel (OS bypass) giúp cung cấp độ trễ siêu thấp (ultra-low latency). Rất quan trọng cho HPC (High Performance Computing) và MPI (Message Passing Interface).

1.4. Các kỹ năng EC2 quan trọng khác

  • AMI (Amazon Machine Image): Bản clone của EC2 chứa OS, cài đặt phần mềm. AMI bị giới hạn trong Region. Muốn dùng ở Region khác phải copy (Cross-Region Copy). Golden AMI pattern: Đóng gói toàn bộ source code vào AMI để khi Auto Scaling boot lên, instance có thể phục vụ traffic ngay lập tức thay vì tốn thời gian tải code.
  • User Data: Script (bash, powershell) được chạy MỘT LẦN DUY NHẤT ở lần boot đầu tiên của EC2. Dùng để cài cắm ban đầu (cloud-init).
  • IMDS (Instance Metadata Service): Truy cập thông tin nội tại của EC2 (IP, tags, role credentials) qua địa chỉ 169.254.169.254. IMDSv2 sử dụng session-oriented requests (bắt buộc gọi PUT lấy token trước), an toàn hơn nhiều so với v1 (phòng chống SSRF attack).
  • EC2 Hibernate: Đóng băng trạng thái. Lưu toàn bộ nội dung RAM vào EBS root volume. Khi khởi động lại, bật lên ngay lập tức trạng thái cũ. EBS volume phải được mã hóa và đủ dung lượng chứa RAM. Dùng để boot nhanh các ứng dụng tốn thời gian khởi tạo in-memory cache lớn.
  • Dedicated Instances vs Dedicated Hosts:
    • Dedicated Instances: Chạy trên phần cứng dành riêng cho một tài khoản AWS (không chia sẻ vật lý với người khác).
    • Dedicated Hosts: Bao trọn gói một server vật lý, cho phép bạn nhìn thấy và can thiệp vào các sockets/cores của CPU. Rất cần thiết cho các loại license phần mềm dựa trên socket (vd: Windows Server BYOL, SQL Server).

1.5. EC2 Limits, Troubleshooting & Common Errors

  • Limits & Quotas:
    • Elastic IPs (EIP): Giới hạn mặc định là 5 EIPs trên mỗi Region.
    • vCPU Limits: Mặc định bạn không bị giới hạn số instance, mà bị giới hạn bởi tổng số vCPU bạn có thể chạy trong một Region.
  • Troubleshooting: EC2 Instance Status Checks Fails:
    Đây là concept cực kỳ hay hỏi trong bài thi:
    1. System Status Check Fails: Lỗi xảy ra ở tầng hạ tầng vật lý của AWS (hypervisor, power, network switch fail).
      → Giải pháp: Phải Stop và Start lại instance. Việc này buộc AWS phải khởi động EC2 của bạn trên một server vật lý MỚI hoàn toàn khỏe mạnh. (Lưu ý: Reboot sẽ không có tác dụng vì máy vẫn ở nguyên host cũ).
    2. Instance Status Check Fails: Lỗi do hệ điều hành OS bên trong, thiếu RAM, CPU quá tải, sai cấu hình network.
      → Giải pháp: Reboot instance hoặc thay đổi cấu hình OS, tăng RAM.

2. Serverless Compute: Lambda & Fargate

Kiến trúc hiệu năng cao hiện đại ưu tiên Serverless để tối đa hóa khả năng co giãn (elasticity) và loại bỏ chi phí quản trị server (No Ops).

2.1. AWS Lambda

Lambda cho phép chạy code mà không cần cung cấp hay quản lý máy chủ. Trả tiền theo thời gian chạy (tính bằng mili giây).

  • Đặc tính: Tự động scale từ 0 lên hàng ngàn concurrent executions. Dưới mui xe, nó chạy các microVM (Firecracker) siêu tốc.
  • Ngôn ngữ hỗ trợ: Node.js, Python, Java, C#, Go, Ruby… Custom runtime cho các ngôn ngữ khác (Rust).
  • Giới hạn (Limits) QUAN TRỌNG:
    • Thời gian chạy tối đa: 15 phút. (Đề thi yêu cầu tác vụ chạy 30 phút → loại Lambda, dùng ECS/Fargate/Batch).
    • RAM: 128MB đến 10GB. Tăng RAM thì CPU và Network ảo cũng tự động tăng theo tỷ lệ thuận. Nếu Lambda chạy chậm → Hãy tăng RAM!
    • Dung lượng ổ tạm (Ephemeral Storage /tmp): Cấu hình được từ 512MB đến 10GB. Rất hữu ích cho các hàm cần tải file lớn về giải nén.
    • Deployment package: 50MB (zip upload trực tiếp), 250MB (unzipped). Nếu lớn hơn có thể dùng Container Image lưu ở ECR (hỗ trợ tới 10GB).
    • Concurrency limit: Mặc định 1000 concurrent executions trên toàn Region. Cần xin tăng nếu chạy ứng dụng lớn.
  • Under the Hood: Synchronous vs Asynchronous Invocation:
    • Synchronous: Gọi từ API Gateway, ALB. Chờ kết quả trực tiếp. Lỗi thì API trả lỗi luôn.
    • Asynchronous: Gọi từ S3, SNS. Lambda nhận event bỏ vào queue ngầm. Nếu chạy lỗi, tự động retry 2 lần. Sau đó có thể đẩy vào Dead-Letter Queue (DLQ).
  • Khởi động lạnh (Cold Start): Lần chạy đầu tiên mất vài giây khởi tạo môi trường (nhất là Java, VPC). Khắc phục bằng Provisioned Concurrency (giữ một lượng Lambda luôn warm để phản hồi < 10ms).
  • Tích hợp VPC: Lambda có thể nằm trong VPC để truy cập RDS riêng tư. Dùng công nghệ AWS Hyperplane ENI nên cold start do VPC gần như bị loại bỏ hoàn toàn trong các kiến trúc mới.

2.2. Troubleshooting Lambda

  • Timeout Error: Lỗi do script chạy quá thời gian cấu hình (hoặc quá 15 phút). Thường do kết nối db treo. Phải tách nhỏ workload hoặc tối ưu code, tăng Timeout settings, hoặc dùng Fargate nếu việc quá dài.
  • Throttling Error (429 Too Many Requests): Vượt quá quota 1000 concurrency. Các request dư thừa sẽ bị từ chối thẳng thừng. Giải pháp: Request tăng quota hoặc cấu hình Reserved Concurrency.
  • OutOfMemoryError: RAM không đủ. Giải pháp: Tăng cấu hình Memory trong setting.

2.3. AWS Fargate (Serverless Containers)

  • Khi dùng Docker containers (quản lý bởi ECS hoặc EKS), nếu dùng kiểu EC2 Launch Type, bạn vẫn phải quản lý hệ điều hành, cập nhật bảo mật của dàn server nền, tự scale cluster.
  • Nếu dùng Fargate Launch Type, bạn không cần quan tâm đến server. Chỉ định nghĩa vCPU, RAM cho container (Task Definition) và AWS sẽ tự chạy.
  • Vô cùng thích hợp cho ứng dụng web microservices thay đổi tải liên tục hoặc các job batch kéo dài vài tiếng (khắc phục điểm yếu 15 phút của Lambda).

3. Các Công cụ Xử lý Chuyên biệt

3.1. AWS Batch

  • Chuyên biệt để chạy hàng ngàn job xử lý hàng loạt (batch computing).
  • Có thể dùng EC2 (On-Demand, Spot) hoặc Fargate làm Compute Environment.
  • Có tính năng Job Queues và Job Definitions (chỉ định bao nhiêu RAM/vCPU, script gì).
  • Tự động scale hạ tầng lên xuống theo số lượng job trong queue. Rất hay dùng chung với Spot Instances để giảm giá thành tới 90%.

3.2. Amazon EMR (Elastic MapReduce)

  • Hadoop, Apache Spark, Presto dưới dạng managed service. Rất mạnh cho xử lý Big Data.
  • Cấu trúc Cluster EMR:
    • Master node: Quản lý cluster (chạy EC2 On-Demand).
    • Core node: Xử lý task VÀ lưu trữ data (HDFS). (Nên chạy EC2 On-Demand/Reserved).
    • Task node: CHỈ xử lý task, không lưu data. (Nên dùng Spot Instances để tiết kiệm, lỡ node mất thì data HDFS không bị ảnh hưởng).

3.3. AWS Elastic Beanstalk

  • Dịch vụ PaaS (Platform as a Service) giúp dev deploy web app nhanh chóng.
  • Deployment Policies:
    • All at once: Nhanh nhất, nhưng có downtime.
    • Rolling: Update từng phần, công suất giảm trong lúc update.
    • Rolling with additional batch: Khởi tạo batch mới để update, đảm bảo 100% công suất luôn duy trì.
    • Immutable: Tạo một dàn Auto Scaling Group hoàn toàn mới để deploy, nếu OK mới chuyển traffic. Rất an toàn, dễ rollback.
    • Blue/Green: Swap URL, zero downtime.

3.4. Điện toán Biên (Edge Computing)

  • AWS Outposts: Đem tủ rack máy chủ thực sự của AWS đặt vào trung tâm dữ liệu on-premise của bạn. Trải nghiệm APIs EC2/EBS ngay trong mạng LAN của công ty với độ trễ siêu nhỏ.
  • AWS Wavelength: Triển khai hạ tầng AWS bên trong trung tâm dữ liệu mạng viễn thông 5G. Nhắm mục tiêu ứng dụng ultra-low latency cho mobile (xe tự lái, AR).
  • AWS Local Zones: Các mini-region nằm gần các thành phố lớn chưa có Region chính.

4. Case Study Thực Tế

Case Study: Kiến trúc Event-Driven Image Processing

Bài toán: Khi người dùng tải ảnh avatar lên S3, hệ thống tự động sinh ra 3 phiên bản ảnh (thumbnail, medium, large) và lưu đường dẫn vào cơ sở dữ liệu. Tất cả phải tự động scale.

Giải pháp: Sử dụng S3 Event Notifications kích hoạt AWS Lambda. Lambda chạy code nén ảnh, thả file kết quả lại vào S3, và ghi siêu dữ liệu vào DynamoDB. Đây là chuẩn mực của Serverless.

5. Checklist Thực Hành / Đánh giá

  • Chạy một EC2, dùng user data để cài apache web server.
  • Bật EC2 tiết kiệm bằng Spot Instance và handle Spot Interruption (2 phút cảnh báo).
  • So sánh Cold Start của Lambda vs Provisioned Concurrency Lambda.
  • Cấu hình một Cluster Placement Group và dùng iperf test băng thông mạng.

Important

Lựa chọn đúng Compute sẽ mở khóa 50% câu hỏi về High Performance. Quy tắc vàng: Nếu là code event-driven chạy chớp nhoáng → Lambda. Nếu là Docker → ECS Fargate. Nếu cần toàn quyền tùy chỉnh OS, custom phần cứng GPU → EC2.

Tài liệu liên quan:

  • Để EC2 truy cập S3 một cách an toàn: dùng IAM Role gắn vào EC2.
  • Kết hợp với Load Balancing: 3.5 - Networking - VPC, Route 53, Direct Connect > Elastic Load Balancing
  • Xử lý dữ liệu luồng trước khi gọi Lambda: 3.6 - Data Ingestion - Kinesis, Glue, Athena
