Các Dịch Vụ Bảo Mật Chuyên Sâu Của AWS

AWS cung cấp một bộ công cụ mạnh mẽ để bảo vệ nhiều tầng (Defense in Depth) từ Network Edge, Application Layer đến Data Layer.

1. Bảo Vệ Ứng Dụng Web và Biên Mạng (Edge)

AWS WAF (Web Application Firewall)

Bảo vệ ứng dụng web khỏi các cuộc tấn công khai thác lỗ hổng phổ biến (Layer 7).

  • Core Features: Chặn SQL Injection, Cross-Site Scripting (XSS).
  • Quy tắc (Rules):
    • Rate-based rules: Chặn IP nếu gửi quá nhiều request (VD: > 100 req/5 phút). Dùng để chống bot/DDoS nhẹ.
    • Geo-match rules: Chặn toàn bộ traffic đến từ một quốc gia cụ thể.
    • IP Set: Chặn/Cho phép một list IP cụ thể (Blacklist/Whitelist).
  • Managed Rule Groups: Các bộ quy tắc được AWS hoặc đối tác (F5, Fortinet) viết sẵn bảo vệ theo chuẩn OWASP Top 10.
  • Tích hợp: Bạn CHỈ CÓ THỂ gắn WAF vào:
    • Application Load Balancer (ALB).
    • Amazon API Gateway.
    • Amazon CloudFront.
    • AWS AppSync.
      (Lưu ý: Không thể gắn WAF vào NLB hay trực tiếp vào EC2).

AWS Shield (Chống DDoS)

Bảo vệ cơ sở hạ tầng khỏi các cuộc tấn công Từ chối Dịch vụ Phân tán (DDoS).

2. Phát Hiện Mối Đe Dọa (Threat Detection)

Amazon GuardDuty

Dịch vụ phát hiện mối đe dọa (Intelligent Threat Detection) sử dụng Machine Learning để phân tích hành vi bất thường.

  • Dữ liệu đầu vào (Không cần cài agent): Đọc từ VPC Flow Logs, AWS CloudTrail Logs, và DNS Logs.
  • Phát hiện gì (Findings):
    • Reconnaissance: Kẻ tấn công dò quét port, đào bới tài nguyên.
    • Instance Compromise: EC2 đang bị cài mã độc đào Bitcoin (Cryptocurrency mining), liên lạc với máy chủ C&C (Command & Control).
    • Account Compromise: Đăng nhập từ vị trí bất thường, thao tác tắt CloudTrail.
  • Tính năng: Có thể tích hợp với AWS EventBridge để chạy Lambda tự động cô lập (quarantine) EC2 bị nhiễm.

Amazon Inspector

Dịch vụ đánh giá lỗ hổng bảo mật (Vulnerability Management).

  • Mục tiêu quét: Amazon EC2, Amazon ECR (Container images), và AWS Lambda functions.
  • Tính năng chính: Tự động phát hiện các CVE (Common Vulnerabilities and Exposures) nổi tiếng, đánh giá EC2 có mở cổng ra internet không kiểm soát hay không.

Amazon Macie

Dịch vụ phân loại dữ liệu và bảo vệ quyền riêng tư sử dụng AI/Machine Learning.

  • Mục tiêu độc quyền: Amazon S3.
  • Dùng để quét nội dung files trong S3 nhằm tìm kiếm PII (Passport, Credit Card) hay khóa bí mật bị đẩy nhầm lên S3.
  • Phát ra cảnh báo (Alert) nếu S3 bucket chứa dữ liệu PII bị chuyển thành Public.

3. Điều Tra (Investigation)

Amazon Detective

Công cụ hỗ trợ phân tích và điều tra sâu nguồn gốc (root cause) của một sự cố bảo mật (thường sau khi nhận cảnh báo từ GuardDuty/Macie).

  • Sử dụng mô hình đồ thị (Graph Model) trực quan.
  • Kết hợp VPC Flow Logs, CloudTrail, và GuardDuty findings.

4. Quản Lý và Tuân Thủ Tập Trung (Central Management & Compliance)

AWS Security Hub

  • Là bảng điều khiển bảo mật trung tâm (Centralized Dashboard) gom tất cả cảnh báo (findings) từ GuardDuty, Inspector, Macie, WAF, Firewall Manager về một nơi.
  • Hỗ trợ đánh giá liên tục môi trường theo các tiêu chuẩn Compliance Standards phổ biến như:
    • CIS AWS Foundations Benchmark.
    • PCI DSS (Thanh toán thẻ).

AWS Firewall Manager

  • Được dùng trong môi trường Multi-Account.
  • Trình quản lý cho phép admin thiết lập các rules bảo mật một lần và ép buộc (enforce) chúng trên hàng trăm tài khoản AWS.
  • Quản lý tập trung các rules của: WAF, Shield Advanced, Security Groups (vd: bắt buộc toàn bộ EC2 trong tổ chức cấm cổng 22 ra internet).

AWS Audit Manager

  • Dành cho bộ phận Kiểm toán (Auditing) của công ty.
  • Tự động thu thập bằng chứng (evidence) một cách liên tục (continuous) để chứng minh kiến trúc AWS của bạn tuân thủ các frameworks quản lý rủi ro pháp lý (GDPR, HIPAA, SOC 2).

AWS Artifact

  • Cổng thông tin trung tâm miễn phí để tải xuống (download) các báo cáo kiểm toán bảo mật và tuân thủ của chính AWS.
  • Ví dụ: Sếp bạn yêu cầu giấy chứng nhận ISO 27001 của hạ tầng AWS để trình cho cơ quan chính phủ → Bạn vào AWS Artifact tải bản PDF về.

6. Under the Hood: AWS WAF và GuardDuty

  • Sự thật về GuardDuty và VPC Flow Logs: Rất nhiều người nghĩ rằng để GuardDuty hoạt động, bạn BẮT BUỘC phải bật tính năng VPC Flow Logs (và trả tiền cho S3/CloudWatch để lưu log). Điều này là sai. GuardDuty đọc luồng dữ liệu thô trực tiếp từ hypervisor của AWS. Việc bạn bật hay tắt VPC Flow Logs không ảnh hưởng đến khả năng phát hiện của GuardDuty.
  • WAF Rule Evaluation: Các rule trong WAF được đánh giá theo thứ tự (Priority). Action có thể là: Allow, Block, Count (chỉ ghi log chứ không chặn - dùng để test rule mới), hoặc CAPTCHA (Bắt giải mã Captcha nếu nghi là Bot).

7. Troubleshooting & Lỗi thường gặp

Lỗi / Vấn đềPhân tích & Khắc phục
WAF chặn người dùng thật (False Positives)Thường do Managed Rules (đặc biệt là SQLi rules) chặn các request có chứa ký tự đặc biệt. Khắc phục: Đổi rule đó sang chế độ Count, xem log (WAF Logs), sau đó viết một rule Exception (Exclude rule) cho URI đó.
GuardDuty cảnh báo UnauthorizedAccess:EC2/SSHBruteForce liên tụcAi đó trên mạng Internet đang scan cổng 22. Đây là chuyện thường ngày ở Cloud. Khắc phục: Đảm bảo Security Group của bạn KHÔNG mở cổng 22 ra 0.0.0.0/0. Cảnh báo sẽ tự hết hoặc không gây hại.
Không gắn được WAF vào NLBBắt buộc đổi kiến trúc. WAF chỉ hoạt động ở Layer 7. NLB hoạt động ở Layer 4. Nếu vẫn muốn dùng NLB, bạn phải dùng AWS Network Firewall hoặc tự dựng Firewall Appliance (Fortinet/Palo Alto).

9. Case Study: GuardDuty Auto-Remediation

Đây là một mô hình bảo mật tự động nổi tiếng và rất hay xuất hiện trong bài thi SAA.
Ngữ cảnh: GuardDuty phát hiện một EC2 instance đang liên tục bị kết nối bởi một IP độc hại đã biết (Threat Intel). Thay vì đợi con người xử lý, hệ thống tự động khóa IP đó ở mức VPC NACL.

sequenceDiagram
    participant Attacker as Bad IP (Attacker)
    participant EC2 as Target EC2
    participant GD as GuardDuty
    participant EB as EventBridge (CloudWatch Events)
    participant Lambda as Auto-Remediation Lambda
    participant NACL as VPC NACL

    Attacker->>EC2: SSH Brute Force
    Note over GD: Quét luồng mạng từ Hypervisor
    GD->>EB: 1. Tạo Finding (Event)
    EB->>Lambda: 2. Kích hoạt Lambda Rule
    Note over Lambda: Trích xuất Bad IP từ Event JSON
    Lambda->>NACL: 3. API CreateNetworkAclEntry<br>(Action: DENY Bad IP)
    Attacker--xEC2: 4. Bị chặn hoàn toàn tại viền Subnet

Chi tiết kỹ thuật:

  1. GuardDuty tạo ra một Finding định dạng JSON.
  2. EventBridge Rule bắt (catch) event có detail-type là “GuardDuty Finding”.
  3. EventBridge trigger AWS Lambda function.
  4. Lambda script gọi thư viện boto3 để cập nhật NACL (chèn Rule Number thấp nhất, cấu hình DENY cho địa chỉ IP độc hại lấy từ payload).

Tóm Tắt & Tips Luyện Thi

Cheat Sheet cho Câu hỏi Tình Huống

  • Chặn IP cụ thể (hoặc theo quốc gia) cho một ứng dụng web → AWS WAF.
  • Chống DDoS ở cấp độ ứng dụng phức tạp, có đội phản ứng nhanh DRT → AWS Shield Advanced.
  • Machine Learning phát hiện bất thường trong VPC, không cần cài cắm gì → Amazon GuardDuty.
  • Tìm quét PII / Credit Card trong S3 → Amazon Macie.
  • Quản lý WAF/Security Group cho hàng trăm tài khoản cùng lúc → AWS Firewall Manager.
  • Lấy chứng chỉ Compliance PCI DSS của cơ sở hạ tầng AWS → AWS Artifact.

Checklist Cài Đặt Mặc Định Bắt Buộc

  • Mở GuardDuty trên mọi Regions và mọi Accounts (Rất rẻ và hiệu quả).
  • Kích hoạt Security Hub trong tài khoản Security Tooling và gom findings từ các account khác.
  • Đính kèm AWS WAF với managed rules vào CloudFront/ALB.
  • Thiết lập cảnh báo Billing (Cost Explorer) để đề phòng trường hợp DDoS làm tăng chi phí hạ tầng.
