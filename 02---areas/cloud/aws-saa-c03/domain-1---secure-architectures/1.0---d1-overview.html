Domain 1 — Design Secure Architectures (30%)

Tổng quan

Domain 1 chiếm 30% trọng số trong kỳ thi AWS Certified Solutions Architect — Associate (SAA-C03), tương đương khoảng 19-20 câu hỏi trên tổng số 65 câu. Đây là domain có trọng số cao nhất, phản ánh tầm quan trọng của security trong kiến trúc AWS.

Kỳ thi SAA-C03 yêu cầu bạn không chỉ hiểu các dịch vụ security riêng lẻ mà còn phải biết kết hợp chúng để thiết kế kiến trúc bảo mật toàn diện theo nguyên tắc defense in depth (phòng thủ nhiều lớp).

Trọng số cao nhất

Domain 1 chiếm 30% — nhiều hơn bất kỳ domain nào khác. Đầu tư thời gian học domain này sẽ mang lại ROI cao nhất cho kỳ thi.

Ba Task Statements chính thức

AWS chia Domain 1 thành 3 task statements, mỗi task bao gồm Knowledge (kiến thức cần biết) và Skills (kỹ năng áp dụng):

Task 1.1: Design secure access to AWS resources

Knowledge cần nắm:

  • Access controls và management across multiple accounts
  • AWS federated access và identity services (IAM, AWS IAM Identity Center)
  • AWS global infrastructure (Availability Zones, Regions)
  • AWS security best practices (principle of least privilege)
  • AWS shared responsibility model

Skills yêu cầu:

  • Áp dụng AWS security best practices cho IAM users và root users (MFA, password policies)
  • Thiết kế flexible authorization model: IAM users, groups, roles, policies, RBAC
  • Sử dụng AWS STS cho role switching, cross-account access
  • Thiết kế security strategy cho multiple AWS accounts (AWS Control Tower, SCPs)
  • Xác định resource policies phù hợp cho từng AWS service
  • Tích hợp directory services với IAM roles cho federated access

Exam Tip — Task 1.1

Câu hỏi về Task 1.1 thường yêu cầu bạn chọn giải pháp least privilege nhất. Khi thấy multiple options đều “work”, chọn option có quyền hạn ít nhất mà vẫn đáp ứng yêu cầu.

Dịch vụ trọng tâm:

  • 1.1 - IAM - Identity and Access Management
  • 1.2 - AWS Organizations và Multi-Account
  • 1.6 - Secrets và Credentials Management

Task 1.2: Design secure workloads and applications

Knowledge cần nắm:

  • Application configuration và credentials security
  • AWS service endpoints
  • Control ports, protocols, và network traffic trên AWS
  • Secure application access
  • Security services với use cases phù hợp (Amazon Cognito, Amazon GuardDuty, Amazon Macie)
  • Threat vectors bên ngoài AWS (DDoS, SQL injection)

Skills yêu cầu:

  • Thiết kế VPC architectures với security components (Security Groups, route tables, NACLs, NAT gateways)
  • Xác định network segmentation strategies (public subnets, private subnets)
  • Tích hợp AWS services để bảo vệ applications (AWS Shield, AWS WAF, IAM Identity Center, AWS Secrets Manager)
  • Bảo mật external network connections đến/từ AWS Cloud (VPN, AWS Direct Connect)

Exam Tip — Task 1.2

Câu hỏi VPC luôn xuất hiện nhiều. Nắm vững sự khác biệt giữa Security Groups (stateful, instance-level) và NACLs (stateless, subnet-level) là MUST.

Dịch vụ trọng tâm:

  • 1.3 - VPC Security - SG, NACL, NAT
  • 1.5 - Security Services - WAF, Shield, GuardDuty
  • 1.6 - Secrets và Credentials Management

Task 1.3: Determine appropriate data security controls

Knowledge cần nắm:

  • Data access và governance
  • Data recovery và data retention/classification
  • Data encryption và appropriate key management

Skills yêu cầu:

  • Align AWS technologies để đáp ứng compliance requirements
  • Encryption at rest (AWS KMS)
  • Encryption in transit (AWS Certificate Manager, TLS)
  • Access policies cho encryption keys
  • Data backups và replications
  • Data access, lifecycle, và protection policies
  • Key rotation và certificate renewal

Exam Tip — Task 1.3

KMS là dịch vụ quan trọng nhất trong task này. Hiểu rõ sự khác biệt giữa AWS managed keys, customer managed keys, và AWS owned keys. Envelope encryption cũng thường xuất hiện trong câu hỏi.

Dịch vụ trọng tâm:

  • 1.4 - Data Protection - KMS, ACM, Encryption
  • 1.6 - Secrets và Credentials Management

Shared Responsibility Model

Mô hình trách nhiệm chung là nền tảng của security trên AWS. Hiểu rõ ranh giới giữa trách nhiệm của AWS và của khách hàng là bắt buộc cho kỳ thi.

Nguyên tắc cốt lõi

  • AWS chịu trách nhiệm: Security OF the Cloud — hạ tầng vật lý, hardware, networking, hypervisor, managed services
  • Khách hàng chịu trách nhiệm: Security IN the Cloud — data, IAM, OS patching, network configuration, encryption

Cảnh báo thi

AWS luôn chịu trách nhiệm về hạ tầng vật lý, nhưng encryption và IAM luôn là trách nhiệm của khách hàng — kể cả với managed services. Đây là điểm hay bị nhầm.

Ví dụ cụ thể

Shared Responsibility Examples

  • EC2: Khách hàng phải patch OS, cấu hình Security Groups, encrypt EBS volumes
  • RDS: AWS patch OS/database engine, khách hàng quản lý IAM, encryption, Security Groups
  • S3: AWS quản lý infrastructure, khách hàng quản lý bucket policies, encryption, access control
  • Lambda: AWS quản lý runtime environment, khách hàng quản lý code, IAM roles, encryption

AWS Global Infrastructure và Security

Regions

  • Mỗi Region là một cluster of data centers, hoàn toàn độc lập về data và services
  • Chọn Region dựa trên: compliance (data residency), latency, service availability, pricing
  • Data không tự động replicate giữa các Regions trừ khi bạn cấu hình rõ ràng
  • Một số dịch vụ là global: IAM, Route 53, CloudFront, WAF, Shield

Availability Zones (AZs)

  • Mỗi Region có tối thiểu 3 AZs (thường 3-6)
  • Mỗi AZ = 1 hoặc nhiều data centers với power, networking, connectivity riêng biệt
  • AZs kết nối qua high-bandwidth, low-latency networking
  • Thiết kế multi-AZ cho high availability và fault tolerance

Edge Locations

  • 400+ Points of Presence (PoPs) toàn cầu
  • Dùng cho CloudFront (CDN), Route 53 (DNS), AWS WAF, AWS Shield
  • Edge security: WAF rules đánh giá tại edge trước khi traffic đến origin

Security implication

Hiểu global infrastructure giúp bạn quyết định:

  • Nơi đặt data (data sovereignty)
  • Nơi deploy security controls (edge vs regional)
  • Multi-AZ vs Multi-Region cho disaster recovery

Principle of Least Privilege

  • Chỉ cấp quyền tối thiểu cần thiết để thực hiện công việc
  • Sử dụng IAM Access Analyzer để xác định unused permissions
  • Sử dụng IAM Access Advisor để xem last accessed services
  • Bắt đầu với zero permissions và thêm dần theo nhu cầu
  • Sử dụng Permission Boundaries để giới hạn maximum permissions

Zero Trust Architecture

  • Never trust, always verify — mọi request đều phải authenticated và authorized
  • Sử dụng VPC endpoints thay vì public internet khi có thể
  • Encrypt everything — at rest và in transit
  • Log everything — CloudTrail, VPC Flow Logs, access logs
  • Monitor continuously — GuardDuty, Security Hub, Config Rules

Exam Mindset

Khi gặp câu hỏi security, luôn nghĩ theo thứ tự:

  1. Least privilege — quyền ít nhất có thể
  2. Encryption — mã hóa mọi thứ
  3. Monitoring — giám sát liên tục
  4. Automation — tự động hóa response

Exam Tips tổng hợp Domain 1

Top Exam Tips

  • IAM Policy evaluation: Explicit Deny luôn thắng. Nhớ thứ tự: Deny → Allow → Implicit Deny
  • SG vs NACL: Security Group = stateful (chỉ cần rule 1 chiều), NACL = stateless (cần rule 2 chiều)
  • KMS key types: Phân biệt AWS managed vs Customer managed vs AWS owned
  • Encryption by default: EBS có thể bật account-level default, S3 mặc định SSE-S3 từ 01/2023
  • Cross-account access: Resource-based policy (no assume role needed) vs IAM role (AssumeRole)
  • SCPs: Không ảnh hưởng management account, không grant permissions — chỉ restrict

Lỗi phổ biến

  • Nhầm Security Groups cho phép DENY rules — SG chỉ có ALLOW rules
  • Quên rằng NACLs cần allow ephemeral ports (1024-65535) cho return traffic
  • Nghĩ rằng SCPs ảnh hưởng root user của management account — SAI, SCPs không ảnh hưởng management account
  • Nhầm NAT Gateway cho phép inbound traffic từ internet — NAT Gateway chỉ cho outbound
  • Quên rằng IAM là global service, không phải regional

Keywords trong đề thi

Khi thấy các keywords sau, nghĩ đến service tương ứng:

  • “Least privilege” → IAM policies, Permission Boundaries
  • “Cross-account” → IAM Roles (AssumeRole) hoặc Resource-based policies
  • “DDoS protection” → Shield + WAF + CloudFront
  • “Encrypt at rest” → KMS
  • “Encrypt in transit” → ACM + TLS
  • “Rotate secrets” → Secrets Manager
  • “Private connectivity” → VPC Endpoints / PrivateLink
  • “Centralized security management” → Security Hub + Organizations
  • “Threat detection” → GuardDuty
  • “Data classification” → Macie
  • “Vulnerability scanning” → Inspector

Checklist học tập Domain 1

Task 1.1 — Secure Access

  • Hiểu IAM Users, Groups, Roles — khi nào dùng gì
  • Nắm vững IAM Policy types và JSON structure
  • Hiểu Policy evaluation logic (Deny > Allow > Implicit Deny)
  • Biết cách sử dụng AWS STS và AssumeRole
  • Hiểu IAM Identity Center (SSO) và permission sets
  • Nắm AWS Organizations, OUs, SCPs
  • Hiểu Control Tower, guardrails, Account Factory
  • Biết cross-account access patterns
  • Hiểu MFA types và enforcement
  • Nắm Shared Responsibility Model

Task 1.2 — Secure Workloads

  • Hiểu VPC architecture (subnets, route tables, IGW)
  • Phân biệt Security Groups vs NACLs
  • Nắm NAT Gateway vs NAT Instance
  • Hiểu VPC Endpoints (Gateway vs Interface)
  • Biết Site-to-Site VPN và Direct Connect
  • Nắm AWS WAF (Web ACL, rules, managed rules)
  • Hiểu AWS Shield (Standard vs Advanced)
  • Biết GuardDuty (data sources, findings)
  • Hiểu Network Firewall basics
  • Nắm VPC Flow Logs

Task 1.3 — Data Security

  • Hiểu encryption at rest cho mỗi service (EBS, S3, RDS, DynamoDB)
  • Nắm S3 encryption types (SSE-S3, SSE-KMS, SSE-C)
  • Hiểu KMS key types và key policies
  • Nắm Envelope Encryption flow
  • Biết CloudHSM vs KMS
  • Hiểu ACM (public vs private certificates)
  • Nắm Secrets Manager vs Parameter Store
  • Hiểu Macie cho data classification
  • Biết AWS Backup basics
  • Hiểu S3 Object Lock và Glacier Vault Lock

Review và Practice

  • Làm ít nhất 3 bộ practice questions cho Domain 1
  • Review lại các câu sai — hiểu WHY đáp án đúng
  • Tạo flashcards cho các so sánh quan trọng
  • Vẽ lại VPC architecture diagram từ bộ nhớ
  • Giải thích được Policy evaluation logic cho người khác
