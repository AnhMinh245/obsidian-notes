1. Analytics

ServiceMô tảDomain liên quanMức độ
Amazon AthenaQuery trực tiếp data trong S3 bằng SQL (serverless, pay per query). Dùng cho ad-hoc analysis, log analysis, querying data lakeD3, D4🟡 Important
AWS Data ExchangeMarketplace để subscribe và sử dụng third-party data sets trong AWS. Hỗ trợ S3, Redshift, API-based dataD3🟢 Good to know
AWS Data PipelineOrchestration service để move và transform data giữa AWS compute/storage services. Đang dần bị thay thế bởi Glue/Step FunctionsD3🟢 Good to know
Amazon EMRManaged Hadoop/Spark cluster cho big data processing. Chạy trên EC2 hoặc EKS. Dùng cho ETL, machine learning, log analysis quy mô lớnD3🟡 Important
AWS GlueServerless ETL (Extract, Transform, Load) service. Tự động discover schema (Glue Crawler), tạo data catalog. Tích hợp tốt với Athena, Redshift, S3D3🟡 Important
Amazon KinesisReal-time streaming data platform. 4 services con: Data Streams (custom consumers, shard-based), Data Firehose (auto delivery to S3/Redshift/OpenSearch), Data Analytics (SQL on streams), Video StreamsD3🔴 Critical
AWS Lake FormationXây dựng và quản lý data lake trên S3. Centralized access control, fine-grained permissions, data catalogingD1, D3🟢 Good to know
Amazon MSKManaged Apache Kafka. Dùng khi cần Kafka ecosystem (producers/consumers API, Kafka Connect). So sánh thường gặp với KinesisD3🟢 Good to know
Amazon OpenSearch ServiceManaged OpenSearch (fork từ Elasticsearch). Full-text search, log analytics, real-time application monitoring. Tích hợp với CloudWatch Logs, KinesisD3🟡 Important
Amazon QuickSightServerless BI (Business Intelligence) dashboards. ML-powered insights. Pay-per-session pricing modelD3🟢 Good to know
Amazon RedshiftCloud data warehouse (petabyte-scale). Columnar storage, MPP (Massively Parallel Processing). Dùng Redshift Spectrum để query S3 dataD3, D4🟡 Important

Kinesis vs MSK — phân biệt nhanh

  • Kinesis: AWS-native, tự động scale (Firehose), pay per shard/throughput, dễ dùng
  • MSK: Managed Kafka, dùng khi team đã có Kafka expertise hoặc cần Kafka ecosystem (Connect, Streams API)
  • Trong đề thi, nếu không nói “existing Kafka” → chọn Kinesis

2. Application Integration

ServiceMô tảDomain liên quanMức độ
Amazon AppFlowManaged integration service để transfer data giữa SaaS apps (Salesforce, SAP, Slack) và AWS services (S3, Redshift). No-code/low-codeD3🟢 Good to know
AWS AppSyncManaged GraphQL và Pub/Sub API service. Real-time data sync cho mobile/web apps. Tích hợp DynamoDB, Lambda, HTTP datasourcesD3🟡 Important
Amazon EventBridgeServerless event bus. Route events giữa AWS services, SaaS apps, custom apps. Event-driven architecture. Rules-based routing, schema registryD2, D3🔴 Critical
Amazon MQManaged message broker cho Apache ActiveMQ và RabbitMQ. Dùng khi migrate existing apps dùng standard messaging protocols (AMQP, MQTT, STOMP)D2🟡 Important

3. Cloud Financial Management (Cost Management)

ServiceMô tảDomain liên quanMức độ
AWS BudgetsSet custom cost, usage, reservation budgets. Alert khi vượt threshold (email, SNS). Có thể auto-execute actions (stop EC2, apply SCP)D4🔴 Critical
AWS Cost and Usage Report (CUR)Report chi tiết nhất về AWS spending. CSV/Parquet to S3. Dùng Athena/Redshift để analyze. Granularity: hourly/daily/monthlyD4🟡 Important
AWS Cost ExplorerVisualize, understand, manage AWS costs & usage over time. Built-in forecasting (12 months). Right-sizing recommendations cho EC2D4🔴 Critical
Savings PlansFlexible pricing model — commit spend $/hour for 1 or 3 years. Compute SP (áp dụng mọi compute: EC2, Fargate, Lambda) vs EC2 Instance SP (specific instance family + region, giảm nhiều hơn)D4🔴 Critical

So sánh Cost tools

  • Cost Explorer: xem retrospective + forecast → “Tôi đã/sẽ chi bao nhiêu?”
  • Budgets: set threshold + alerts → “Báo tôi khi vượt X USD”
  • CUR: raw data chi tiết → “Tôi cần analyze spending patterns”
  • Trusted Advisor: recommendations → “AWS gợi ý tôi tiết kiệm ở đâu?“

Amazon EKS AnywhereChạy Kubernetes clusters trên on-premises infrastructure (bare metal, VMware). Dùng EKS API/toolingD2🟢 Good to know
Amazon EKS DistroOpen-source Kubernetes distribution giống EKS. Self-managed, deploy ở bất kỳ đâuD2🟢 Good to know

ECS vs EKS — khi nào chọn cái nào?

  • ECS: AWS-native, đơn giản hơn, không cần Kubernetes expertise → chọn khi “least operational overhead”
  • EKS: Kubernetes ecosystem, portable, community tools → chọn khi “already using Kubernetes” hoặc “need portability”
  • Cả 2 đều support Fargate (serverless containers)

6. Database

ServiceMô tảDomain liên quanMức độ
Amazon AuroraMySQL/PostgreSQL-compatible relational DB. Up to 5x throughput MySQL, 3x throughput PostgreSQL. Auto-scaling storage (10GB → 128TB). 6 copies data across 3 AZs. Aurora Serverless v2, Global Database, Multi-MasterD2, D3🔴 Critical
Amazon Aurora ServerlessOn-demand auto-scaling Aurora. Scale to zero khi không dùng. Dùng cho infrequent/unpredictable workloads. v1 (scale to 0) vs v2 (instant scaling, production-ready)D3, D4🟡 Important
Amazon DocumentDBMongoDB-compatible document database. Managed, scalable. Dùng khi migrate MongoDB workloads lên AWS hoặc cần document modelD3🟡 Important
Amazon DynamoDBServerless key-value & document database. Single-digit ms latency at any scale. On-demand vs provisioned capacity. Global Tables (multi-region). DynamoDB Streams, TTL, DAX (caching). Partition key design quan trọngD2, D3, D4🔴 Critical
Amazon ElastiCacheManaged in-memory cache/data store. Redis (complex data types, persistence, replication, pub/sub, geospatial) vs Memcached (simple caching, multi-threaded, no persistence). Dùng cho session store, leaderboards, real-time analyticsD3🔴 Critical
Amazon KeyspacesManaged Apache Cassandra-compatible database. Serverless. Dùng khi migrate Cassandra workloads hoặc cần wide-column storeD3🟢 Good to know
Amazon NeptuneGraph database. Dùng cho social networks, recommendation engines, fraud detection, knowledge graphs. Supports Gremlin, SPARQL, openCypherD3🟢 Good to know
Amazon QLDBQuantum Ledger Database. Immutable, cryptographically verifiable transaction log. Dùng cho audit trail, supply chain, financial transactions cần chứng minh không bị tamperD3🟢 Good to know
Amazon RDSManaged relational database. Engines: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server. Multi-AZ (HA, sync replication), Read Replicas (read scaling, async). Automated backups, snapshotsD2, D3🔴 Critical
Amazon RedshiftCloud data warehouse (listed lại ở Database cho convenience). Petabyte-scale, columnar, MPP. Redshift Spectrum query S3. RA3 instances tách compute/storageD3, D4🟡 Important

RDS Multi-AZ vs Read Replicas — bẫy phổ biến nhất

FeatureMulti-AZRead Replica
Mục đíchHigh AvailabilityRead Scaling
ReplicationSynchronousAsynchronous
FailoverAutomatic (DNS switch)Manual (promote to standalone)
Read traffic❌ Không serve reads✅ Serve read queries
Cross-region❌ Same region✅ Cross-region available
Số lượng1 standbyUp to 5 (MySQL/MariaDB/PostgreSQL), 15 (Aurora)

Database selection decision tree cho đề thi 

Relational + complex queries → RDS / Aurora
Key-value / document + massive scale → DynamoDB
In-memory caching → ElastiCache (Redis/Memcached)
Data warehouse / OLAP → Redshift
MongoDB compatibility → DocumentDB
Cassandra compatibility → Keyspaces
Graph relationships → Neptune
Immutable ledger → QLDB
Full-text search → OpenSearch
Time-series → Timestream (not in scope, but good to know)

12. Migration & Transfer

AWS Database Migration Service (DMS)Migrate databases to AWS. Homogeneous (MySQL → RDS MySQL) & heterogeneous (Oracle → Aurora PostgreSQL, cần SCT). Continuous replication, CDC (Change Data Capture)D2, D3🔴 Critical
AWS DataSyncData transfer service. On-premises ↔ AWS (S3, EFS, FSx). Automated, scheduled, encrypted. Up to 10 Gbps. Online transfer (qua internet hoặc Direct Connect)D2🟡 Important

AWS Snow FamilyOffline data transfer devices. Snowcone (8-14TB, nhỏ, portable), Snowball Edge (80TB, compute + storage), Snowmobile (100PB, xe tải container). Dùng khi bandwidth limited hoặc data > 10TBD2, D4🔴 Critical

Khi nào dùng Snow Family vs DataSync?

  • Data < 10TB + bandwidth tốt → DataSync (online, nhanh hơn)
  • Data > 10TB + bandwidth hạn chế → Snowball Edge
  • Data > 100TB + tight deadline → nhiều Snowball Edge song song
  • Data > 10PB → Snowmobile (literally xe tải)
  • Nhớ: “Nếu transfer qua internet mất > 1 tuần → dùng Snow Family”

Lưu ý về SES

Amazon SES (Simple Email Service) đôi khi xuất hiện trong đáp án về “gửi email notifications”, nhưng không phải in-scope service chính thức. Trong đề thi, SNS thường là lựa chọn đúng cho notifications. SES chỉ đúng khi đề nói cụ thể “send bulk emails” hoặc “transactional emails”.

18. Service Limits, Quotas & Advanced Concepts

Hard Limits vs Soft Limits

AWS có hai loại giới hạn:

  • Soft Limits (Adjustable Quotas): Có thể yêu cầu tăng thông qua Service Quotas console hoặc AWS Support. VD: số lượng EC2 instances tối đa per region (mặc định 20 vCPUs cho On-Demand).
  • Hard Limits (Unadjustable Quotas): Giới hạn vật lý hoặc kiến trúc, không thể tăng. Đề thi rất hay hỏi về cách vượt qua rào cản này bằng kiến trúc thay thế.

18.2. Under the Hood: Control Plane vs Data Plane

Thiết kế kiến trúc Cloud luôn yêu cầu hiểu về 2 mặt phẳng này:

  • Control Plane: Nơi tạo, cấu hình, xóa resource (VD: RunInstances EC2 API, tạo S3 bucket, đổi Route 53 record). Thường có SLA thấp hơn (99.9%) và dễ bị API throttling.
  • Data Plane: Nơi thực tế phục vụ traffic / workload (VD: EC2 instance running, tải file từ S3, DNS query resolution). Data Plane được AWS thiết kế để “always on” (SLA lên đến 99.99% hoặc 100%).

Best Practice

Trong trường hợp DR (Disaster Recovery), đừng phụ thuộc vào Control Plane để phục hồi hệ thống. Hãy “pre-provision” resource hoặc sử dụng Data Plane mechanisms (ví dụ: failover routing) vì Control Plane API có thể bị quá tải trong lúc Region có sự cố.

18.5. Case Study: Hệ sinh thái Serverless (Tương tác giữa các Services)

Để làm quen với cách các services trong danh sách trên tương tác với nhau, đây là mô hình Serverless Data Ingestion pipeline kinh điển.

flowchart TD
    aws["AWS Cloud"]
    api["API Gateway"]
    lambda["Lambda Function"]
    kinesis["Kinesis Data Firehose"]
    s3["S3 Data Lake"]
    athena["Athena"]
    quicksight["QuickSight"]
    api --> lambda
    lambda --> kinesis
    kinesis --> s3
    s3 --> athena
    athena --> quicksight

Luồng dữ liệu:

  1. API Gateway (App Integration) nhận telemetry data từ mobile apps.
  2. Lambda (Compute) được trigger, thực hiện validation, format data.
  3. Kinesis Data Firehose (Analytics) nhận dữ liệu từ Lambda, gộp (batching) và đẩy về S3. (Nếu dùng Kinesis Firehose, quá trình scale hoàn toàn tự động, vượt qua nút thắt cổ chai nếu dùng RDS).
  4. S3 (Storage) làm Data Lake lưu Raw Data theo cấu trúc thư mục dạng year/month/day.
  5. Athena & QuickSight (Analytics) query và visualize biểu đồ trực tiếp từ S3 mà không cần copy data ra ngoài.
