Lab 02 — Tagging Strategy & Organization

⏱️ Thời gian: ~30 phút
📋 Prerequisites: Lab 01 hoàn thành, Storedog đang chạy trên Minikube
🔗 Source: DataDog/storedog

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu tag system: key:value pairs gắn vào mọi telemetry data
  • Biết 6 nguồn tags trong Kubernetes: labels, annotations, Helm values, env vars, Admission Controller, integrations
  • Xem existing tags trên Storedog pods (automatic + custom)
  • Hiểu tag inheritance trong K8s: Cluster → Node → Namespace → Deployment → Pod → Container
  • Áp dụng Unified Service Tagging với tags.datadoghq.com/{env,service,version} labels
  • Filter và group data bằng tags trên Datadog UI

📚 Kiến Thức Nền

Fundamentals

  • Ch.08 — Labels & Context
    → Tags/labels là context cho metrics, logs, traces

Cách học lab này

Tags trong K8s không chỉ là metadata — chúng là cơ chế correlation chính

  • Kubernetes tự sinh rất nhiều tags (kube_namespace, kube_deployment, pod_name…). Việc của bạn là bổ sung unified tags (env, service, version) để Datadog nối được metrics ↔ logs ↔ traces.
  • Lab này hiệu quả nhất khi bạn mở song song terminal (kubectl) và Datadog UI, so sánh tags trên cả hai.
  • Đừng chạy theo số lượng tags. Giá trị nằm ở từ vựng nhất quán — toàn bộ telemetry cùng nói về một service theo cùng một cách.

1. Tags — “Ngôn Ngữ Chung” Của Datadog

1.1. Tag là gì?

Tag = key:value pair gắn vào mọi data point. Tags cho phép:

  • Filter: “Chỉ xem metrics từ kube_deployment:discounts”
  • Group: “Nhóm error rate theo kube_namespace”
  • Correlate: “Tìm logs + traces + metrics có cùng service:store-discounts”
Mọi data trong Datadog đều có tags:
  metric{kube_namespace:storedog, service:discounts, env:dev} = 42
  log{pod_name:discounts-7f8b9c, service:discounts, status:error} = "DB timeout"
  trace{service:discounts, env:dev, version:1.0} = {spans...}

1.2. Quy tắc đặt tên tags

RuleChi tiết
Formatkey:value — lowercase, alphanumeric, underscores, hyphens
Max length80 ký tự (key + value + dấu :)
Key bắt đầu bằngChữ cái (không bắt đầu bằng số hoặc ký tự đặc biệt)
Reservedhost, device, source, service, env, version

Tag max length = 80 chars

Nhiều tài liệu cũ ghi 200 chars — không chính xác. Datadog enforce giới hạn 80 ký tự. Tags dài hơn sẽ bị truncate.

2.2. Host-level tags

  1. Vào Infrastructure → Host Map → click host (Minikube node)
  2. Xem panel Tags:
    • host:minikube — automatic
    • kube_cluster_name:minikube — từ K8s integration
    • Tags từ Helm datadog.tags nếu đã set

2.3. Pod-level tags

  1. Vào Infrastructure → Kubernetes → Pods
  2. Click 1 pod (ví dụ: discounts-*) → xem tags:
    • kube_namespace:storedog
    • kube_deployment:discounts
    • pod_name:discounts-7f8b9c6d-x4k2p
    • kube_app_name:discounts

2.4. Service-level tags (APM)

  1. Vào APM → Services (nếu APM enabled)
  2. Mỗi service có tags từ unified tagging labels:
    • service:store-discounts
    • env:dev
    • version:1.0 (nếu set)

3. Unified Service Tagging — Chuẩn K8s

3.1. Concept

Datadog khuyến nghị 3 reserved tags trên MỌI data:

TagPurposeVí dụ
envEnvironmentenv:dev, env:staging, env:prod
serviceService nameservice:store-discounts, service:frontend
versionDeployment versionversion:1.0, version:2.3.1

3.2. UST trong Kubernetes — 2 lớp

Trong K8s, Unified Service Tagging cần cả labels VÀ env vars:

Lớp 1 — Pod/Deployment labels (cho metrics, infrastructure):

Lớp 2 — Container env vars (cho traces, logs, runtime):

Downward API trick

Env vars đọc từ labels qua Downward API → single source of truth. Đổi label = tự đổi env var khi pod restart.

3.3. Kiểm tra UST trên cluster

3.4. Tại sao cần cả 2 lớp?

Labels (Lớp 1):                    Env Vars (Lớp 2):
  → Agent đọc từ K8s API             → Tracer library đọc runtime
  → Gắn vào infrastructure metrics   → Gắn vào traces, logs
  → Hiện trên Host Map, Pods view    → Hiện trên APM, Log Explorer

Khi CẢ HAI khớp nhau → Unified Service Tagging kích hoạt:
  ✓ APM Deployments tracking
  ✓ Logs correlate đúng service version
  ✓ Metrics filterable theo env/service/version
  ✓ Seamless pivot giữa metrics ↔ traces ↔ logs

4. Tag Inheritance Trong Kubernetes

4.1. Hierarchy

Trong K8s, tags được kế thừa theo hierarchy:

Cluster (kube_cluster_name:minikube)
  └── Node (host:minikube)
        └── Namespace (kube_namespace:storedog)
              └── Deployment (kube_deployment:discounts)
                    └── Pod (pod_name:discounts-7f8b9c6d-x4k2p)
                          └── Container (container_name:discounts)
                                └── Process / Trace / Log
  • Tags ở level cao tự động gắn vào level thấp hơn
  • Pod thuộc kube_namespace:storedog → metrics, logs, traces từ pod đó đều có tag kube_namespace:storedog

4.2. Verify inheritance

  1. Vào APM → Traces → click 1 trace từ store-discounts
  2. Xem span tags → thấy cả service, env, version (từ labels/env) VÀ kube_namespace, pod_name (từ K8s metadata)
  3. Vào Logs → click 1 log cùng service → so sánh tags
  4. Nếu correlation đúng, log có dd.trace_id / dd.span_id

So sánh với Docker

Trong Docker Compose, inheritance là host → container → service. Trong K8s, hierarchy phong phú hơn vì có thêm Cluster, Namespace, Deployment, ReplicaSet — mỗi level đều inject tags.

5. Filter & Group Data Bằng Tags

5.1. Metrics Explorer

  1. Vào Metrics → Explorer
  2. Query kubernetes.cpu.usage.total
  3. Thêm from: kube_deployment:discounts
  4. Thử avg by: kube_namespace → xem CPU per namespace

5.2. Kubernetes Overview

  1. Vào Infrastructure → Kubernetes
  2. Pods tab → filter by kube_namespace:storedog
  3. Xem resource usage per pod, grouped by deployment

5.3. Logs Explorer

  1. Vào Logs → Explorer
  2. Gõ: kube_namespace:storedog service:store-discounts status:error
  3. Chỉ logs từ discounts pods + level error hiện

5.4. APM Traces

  1. Vào APM → Traces
  2. Filter: env:dev + service:store-discounts
  3. Thử group by version → phát hiện version nào có latency cao

6. So Sánh: Datadog Tags vs Dynatrace

FeatureDatadog Tags (K8s)Dynatrace
Formatkey:value (labels + env vars)Tags (key:value) + Properties (auto)
K8s integrationLabels → auto-tags (kube_*)Smartscape tự discover topology
Reservedenv, service, versionKhông có reserved tags
InheritanceCluster → Node → NS → Deploy → PodEntity-based (Smartscape topology)
ScopingTags + RBACManagement Zones
UST mechanismtags.datadoghq.com/* labels + Downward APIKhông có tương đương — dùng Process Group metadata

Datadog’s tagging = explicit, flexible, bạn kiểm soát hoàn toàn. Dynatrace bù lại bằng Smartscape topology (auto-discovery relationships không cần labels).

⚠️ Troubleshooting

Tags không xuất hiện trên UI

UST labels không mapping vào traces

Nếu thiếu env vars → kiểm tra Downward API config trong Deployment manifest hoặc bật Admission Controller trong Helm values:

Tags mất thời gian hiện

  • Tags mới cần 2-5 phút để propagate qua Datadog UI
  • Sau khi thay đổi labels → pod cần restart để Downward API env vars cập nhật
  • Check Infrastructure → Kubernetes → Pods → pod details → Tags tab

  • Pods view có kube_namespace, kube_deployment, pod_name tags

  • env, service, version xuất hiện trên APM Services
