Lab 06 — Dashboards & Visualization

⏱️ Thời gian: ~45 phút
📋 Prerequisites: Lab 05 hoàn thành, Storedog đang chạy trên Minikube
🔗 Source: DataDog/storedog

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Khám phá OOTB dashboards (Kubernetes, Docker, PostgreSQL)
  • Hiểu Dashboard type hiện tại (unified) và khác biệt với Timeboard/Screenboard cũ
  • Tạo custom dashboard cho Storedog trên K8s với nhiều widget types
  • Sử dụng Template Variables (service, env, kube_namespace, kube_deployment)
  • Export/Import dashboard JSON (hữu ích cho account rotation)
  • Thực hành Metric Query với kubernetes.* metrics

Cách học lab này

Dashboard tốt là dashboard trả lời được một câu hỏi vận hành

  • Đừng gom càng nhiều widget càng tốt. Mỗi dashboard nên phục vụ một mục đích rõ ràng: cluster health, service performance, hay release triage.
  • Học từ OOTB dashboards trước — chúng cho bạn biết Datadog nghĩ một integration nên được quan sát theo góc nào. Sau đó hãy chỉnh lại cho đúng bài toán Storedog trên K8s của riêng bạn.
  • Nếu một widget trông “lạ”, hãy kiểm tra lại time range, rollup, split-by, và template variables trước khi nghi metric sai. Phần lớn lỗi đọc dashboard đến từ query semantics hơn là thiếu dữ liệu.

1. Dashboard Types — Unified Model

1.1. Lịch sử: Timeboard vs Screenboard

Exam Tip — Khái niệm cũ nhưng thi vẫn có thể hỏi

Trước ~2020, Datadog có 2 loại dashboard riêng biệt:

  • Timeboard: tất cả widgets share cùng time range, tốt cho investigation (đồng bộ thời gian khi debug)
  • Screenboard: widgets independent, tốt cho status boards (hiển thị trên TV/monitor)

Từ ~2020, Datadog hợp nhất (unified) thành một loại Dashboard duy nhất. Khi tạo mới, bạn chọn layout:

  • Grid-based (ordered) = hành vi như Timeboard cũ — widgets xếp lưới, đồng bộ time
  • Free-form (automatic) = hành vi như Screenboard cũ — kéo thả tự do

Trong UI hiện tại bạn chỉ thấy “New Dashboard” → chọn layout. Nhưng exam có thể dùng thuật ngữ Timeboard/Screenboard.

1.2. So sánh nhanh

Thuộc tínhGrid-based (≈ Timeboard)Free-form (≈ Screenboard)
Time rangeĐồng bộ tất cả widgetsMỗi widget riêng
LayoutLưới cố định, auto-flowKéo thả pixel tự do

Template VariablesCóCó

2. OOTB Dashboards — Out Of The Box

2.1. Xem danh sách

  1. Vào Dashboards → Dashboard List
  2. Tìm dashboards tự tạo bởi integrations:
    • Kubernetes Overview — cluster-level view (nodes, pods, containers)
    • Kubernetes Pods — pod status, restarts, resource usage
    • Kubernetes Containers — container CPU, memory, network
    • Docker — container overview (Minikube dùng containerd, nhưng Docker metrics vẫn có thể hiện nếu Docker integration enabled)
    • PostgreSQL — database performance
    • Host — system metrics overview

2.2. Khám phá Kubernetes Overview dashboard

  1. Click Kubernetes Overview dashboard
  2. Quan sát:
    • Pod count by namespace, node
    • Container states (running, waiting, terminated)
    • CPU/Memory requests vs limits vs actual usage
    • DaemonSet/Deployment/ReplicaSet status

2.3. Khám phá Kubernetes Pods dashboard

  1. Click Kubernetes Pods dashboard
  2. Quan sát:
    • Pods running per namespace
    • Pod restart count (high restarts = CrashLoopBackOff hoặc OOMKilled)
    • Resource usage per pod

2.4. Khám phá PostgreSQL dashboard

  1. Click PostgreSQL Overview (nếu Postgres integration enabled)
  2. Quan sát:
    • Active connections
    • Query throughput (tuples fetched/inserted/updated)
    • Buffer hit rate
    • Lock waits

OOTB dashboards = starting point

Chúng cho bạn visibility ngay lập tức. Custom dashboards (bước tiếp) cho bạn business-specific views phù hợp với Storedog trên K8s.

4. Widget-by-Widget Guide

4.1. Widget: Running Pods (Query Value)

  1. Click + Add Widget → Query Value
  2. Metric: kubernetes.pods.running{kube_namespace:storedog}
  3. Display: Show as raw number
  4. Title: Running Pods (Storedog)

4.2. Widget: Error Rate (Query Value)

  1. + Add Widget → Query Value
  2. Formula:
    • a: trace.flask.request.errors{service:store-discounts}.as_count()
    • b: trace.flask.request.hits{service:store-discounts}.as_count()
    • Formula: a / b * 100
  3. Conditional formatting: Green < 1%, Yellow < 5%, Red ≥ 5%
  4. Title: Error Rate %

4.3. Widget: Request Rate by Service (Timeseries)

  1. + Add Widget → Timeseries
  2. Ưu tiên dùng APM data source / request measure và group by service
  3. Display: Line chart
  4. Title: Request Rate by Service

Tránh dùng một metric kiểu trace.flask.request.hits{*} để đại diện cho toàn bộ Storedog

Prefix trace.<integration>.request.* phụ thuộc framework. Query đó chỉ phản ánh Flask entry spans, không phải Rails/Java/Next.js services.

4.4. Widget: Pod CPU & Memory (Timeseries)

  1. + Add Widget → Timeseries
  2. Metric 1: kubernetes.cpu.usage.total{kube_namespace:storedog} by pod_name (line, blue)
  3. Metric 2: kubernetes.memory.usage{kube_namespace:storedog} by pod_name (line, green)
  4. Title: Pod Resources (Storedog)

kubernetes.* vs system.* vs docker.*

  • kubernetes.cpu.usage.total — CPU usage theo pod/container, từ Kubelet metrics
  • system.cpu.user — CPU usage ở host level (Minikube node)
  • docker.cpu.usage — CPU per container qua Docker/containerd runtime

Trong K8s lab, ưu tiên kubernetes.* vì chúng gắn sẵn K8s tags (pod_name, kube_namespace, kube_deployment).

4.5. Widget: Top Errors (Log Stream)

  1. + Add Widget → Log Stream
  2. Query: status:error kube_namespace:storedog
  3. Columns: timestamp, service, pod_name, message
  4. Title: Recent Errors (Storedog)

4.6. Widget: Slowest Endpoints (Top List)

  1. + Add Widget → Top List
  2. Metric: trace.flask.request.duration{service:store-discounts} → top by resource_name
  3. Limit: Top 5
  4. Title: Slowest Discount Endpoints

4.7. Widget: Pod CPU by Deployment (Top List)

  1. + Add Widget → Top List
  2. Metric: kubernetes.cpu.usage.total{kube_namespace:storedog} → top by kube_deployment
  3. Limit: Top 10
  4. Title: CPU Usage by Deployment

5. Template Variables

5.1. Thêm template variables

  1. Dashboard settings (gear icon) → Template Variables
  2. Click Add Variable:
NameTag groupDefaultDùng cho
serviceservice*Filter by service (store-frontend, store-discounts…)
envenv*Filter by environment
kube_namespacekube_namespacestoredogFilter by K8s namespace
kube_deploymentkube_deployment*Filter by K8s deployment

5.2. Áp dụng vào widgets

  1. Edit widget → thay filter tags bằng template variable syntax $variable
  2. Ví dụ: 
    kubernetes.cpu.usage.total{kube_namespace:$kube_namespace, kube_deployment:$kube_deployment}

    trace.flask.request.hits{service:$service, env:$env}.as_rate()
  3. Dashboard sẽ có dropdowns ở đầu trang: chọn giá trị → tất cả widgets filter đồng bộ

5.3. Template Variables = dashboard cho cả team

1 dashboard, nhiều views:

  • Dev chọn service:store-discounts → thấy chỉ discounts service
  • QA chọn env:staging → thấy staging metrics
  • Ops chọn kube_namespace:storedog + kube_deployment:* → thấy toàn bộ namespace
  • SRE chọn kube_deployment:store-frontend → focus vào frontend pods

6. Dashboard Export/Import

6.1. Export

  1. Dashboard page → gear icon → Export dashboard JSON
  2. Save file (ví dụ: storedog-k8s-dashboard.json)

6.2. Import (khi rotate account)

  1. Trên account mới → Dashboards → Import dashboard JSON
  2. Upload file → dashboard restored

6.3. Account rotation workflow

1. Trial sắp hết → Export dashboard JSON
2. Tạo trial mới
3. Import dashboard JSON → dashboard structure giữ nguyên
4. Data cũ KHÔNG chuyển sang account mới, nhưng layout + queries có sẵn

Dashboard JSON mang theo gì?

  • Widget definitions (type, query, title, formatting)
  • Template variable definitions
  • Layout positions

KHÔNG mang theo: historical metric data, log data, APM traces. Những thứ đó thuộc về account/org gốc.

7. Metric Query Practice

Tự viết trước, rồi mới xem đáp án

Mở Metrics Explorer và thử viết query cho mỗi câu hỏi.

Exercise 1: CPU usage trung bình, group by pod

Đáp án 
avg:kubernetes.cpu.usage.total{kube_namespace:storedog} by {pod_name}

Exercise 2: Error rate (%) cho store-discounts service

Đáp án 
a = sum:trace.flask.request.errors{service:store-discounts}.as_count()
b = sum:trace.flask.request.hits{service:store-discounts}.as_count()
formula: a / b * 100

Exercise 3: Top 5 deployments theo memory usage

Đáp án 
top(avg:kubernetes.memory.usage{kube_namespace:storedog} by {kube_deployment}, 5)

Exercise 4: Network bytes received, chỉ storedog namespace

Đáp án 
avg:kubernetes.network.rx_bytes{kube_namespace:storedog} by {pod_name}

Exercise 5: Số pods đang chạy, group by deployment

Đáp án 
sum:kubernetes.pods.running{kube_namespace:storedog} by {kube_deployment}

⚠️ Troubleshooting

Widget shows “No data”

  • Kiểm tra metric name — dùng autocomplete trong widget editor
  • Kiểm tra time range — đổi sang “Last 1 hour”
  • Kiểm tra tag filters — $service hoặc $kube_namespace có giá trị?
  • Verify Agent đang collect K8s metrics:

Log Stream widget trống

  • Logs phải đang được collected (datadog.logs.enabled=true trong Helm values)
  • Check query syntax — thử bỏ filters để xem có log nào không

Kubernetes metrics không có

  • Kubelet port 10250 (HTTPS) phải accessible từ Agent pod
  • Nếu dùng Minikube, minikube status phải show kubelet: Running

Template Variable dropdown trống

  • Variable tag group phải khớp với tag thực tế trên metrics
  • Verify tags tồn tại: Metrics → Summary → click metric → xem Tags section
  • kube_namespace, kube_deployment chỉ có nếu K8s integration hoạt động
