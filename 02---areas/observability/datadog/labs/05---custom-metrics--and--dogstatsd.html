Lab 05 — Custom Metrics & DogStatsD

⏱️ Thời gian: ~45 phút
📋 Prerequisites: Lab 04 hoàn thành, Datadog Agent chạy trên Minikube
🔗 Source: Datadog DogStatsD Docs

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu DogStatsD — protocol gửi custom metrics đến Agent trong Kubernetes
  • Phân biệt 2 transport: hostPort UDP vs UDS (Unix Domain Socket)
  • Khám phá existing metrics từ Storedog (trace., kubernetes.)
  • Gửi custom metric bằng CLI từ debug Pod (netcat)
  • Hiểu Datadog metric types: COUNT, GAUGE, RATE, HISTOGRAM, DISTRIBUTION
  • Nắm rõ HISTOGRAM sinh 5 metrics mặc định, cấu hình qua histogram_aggregates
  • So sánh: Datadog metric types vs Prometheus equivalents

📚 Kiến Thức Nền

Fundamentals

  • Ch.03 — Metrics
    → Metric types (Counter, Gauge, Histogram), metric naming, push vs pull
  • Ch.05 — Instrumentation
    → Client libraries, StatsD protocol

Cách học lab này

Lab này dạy bạn cách thiết kế metric, không chỉ cách gửi metric

  • Trước khi gửi metric đầu tiên, hãy tự hỏi dữ liệu đó là trạng thái hiện thời, số lần xảy ra, hay phân bố latency. Chọn sai metric type sẽ làm dashboard và alert phía sau trở nên khó hiểu hoặc sai nghĩa.
  • Trong Kubernetes, DogStatsD có 2 transport: hostPort (đơn giản, dùng trong lab) và UDS (recommended cho production vì origin detection tự động tag container metadata). Hiểu cả hai, nhưng lab dùng hostPort cho nhanh.
  • DogStatsD rất dễ dùng nên cũng rất dễ bị lạm dụng. Giá trị của lab này nằm ở chỗ hiểu khi nào một tag là hữu ích, và khi nào bạn đang đẩy cardinality lên chỉ để đổi lấy quá ít insight.

1. DogStatsD trong Kubernetes

1.1. Concept

DogStatsD = StatsD protocol + Datadog extensions, chạy bên trong Agent DaemonSet.

                    Minikube Node
┌─────────────────────────────────────────────────────┐
│                                                     │
│  ┌──────────────┐       ┌─────────────────────────┐ │
│  │  App Pod      │       │  Agent Pod (DaemonSet)  │ │
│  │  (storedog)   │       │                         │ │
│  │               │  UDP  │  DogStatsD              │ │
│  │  DD_AGENT_HOST├──────→│  hostPort: 8125         │ │
│  │  = status.    │       │                         │ │
│  │    hostIP     │       │  ┌─────────────────┐    │ │
│  │               │       │  │ Aggregate (10s) │    │ │
│  └──────────────┘       │  └────────┬────────┘    │ │
│                          │           │ HTTPS       │ │
│  ┌──────────────┐       │           ▼             │ │
│  │  App Pod 2    │  UDS  │  Datadog Cloud          │ │
│  │               ├──────→│  (via Forwarder)        │ │
│  │  /var/run/    │       │                         │ │
│  │  datadog/     │       └─────────────────────────┘ │
│  │  dsd.socket   │                                   │
│  └──────────────┘                                   │
└─────────────────────────────────────────────────────┘

2. Khám Phá Existing Metrics

2.1. Metrics Summary

  1. Vào Metrics → Summary
  2. Gõ filter: trace. → thấy APM-generated metrics
  3. Gõ filter: kubernetes. → thấy K8s metrics (thay vì docker.*)
  4. Gõ filter: system. → thấy host/node metrics

2.2. Metric namespaces trong K8s

NamespaceSourceVí dụ
system.*Agent (node metrics)system.cpu.user, system.mem.used
kubernetes.*Kubernetes integrationkubernetes.cpu.usage.total, kubernetes.memory.rss
kubernetes_state.*KSM (Kube State Metrics)kubernetes_state.deployment.replicas, kubernetes_state.pod.status_phase
trace.*APM trace metricstrace.flask.request.hits, trace.rack.request.duration
postgres.*PostgreSQL integrationpostgres.connections, postgres.rows_fetched
custom.*DogStatsD (user-defined)Bạn sẽ tạo ở bước tiếp

K8s metrics thay thế Docker metrics

Trong Docker labs bạn thấy docker.cpu.usage, docker.mem.rss. Trong K8s, tương đương là kubernetes.cpu.usage.total, kubernetes.memory.rss. Agent lấy metrics từ Kubelet API (port 10250 HTTPS) thay vì Docker socket.

2.3. Xem metric details

  1. Click vào 1 metric (ví dụ: kubernetes.cpu.usage.total)
  2. Xem:
    • Type: COUNT, GAUGE, etc.
    • Tags: kube_namespace, kube_deployment, pod_name
    • Unit: nanocores, bytes, milliseconds
    • Hosts/Tags: Bao nhiêu tag combinations đang gửi metric này

3.2. DogStatsD packet format

<metric_name>:<value>|<type>|@<sample_rate>|#<tag1>,<tag2>
ElementOptionsVí dụ
metric_nameTên metric (dots ok)shop.products.viewed
valueNumber1, 42, 3.14
typec (count), g (gauge), h (histogram), d (distribution), ms (timer)c
sample_rateOptional, @0.5 = 50% sampling@0.1
tagsOptional, prefix ##env:dev,service:shop

Sample rate hỗ trợ những type nào?

Sample rate (@<rate>) hỗ trợ: COUNT, HISTOGRAM, DISTRIBUTION, TIMER. Không hỗ trợ GAUGE (vì gauge là giá trị tức thời, sampling sẽ làm mất ý nghĩa).

4. Metric Types — Deep Dive

4.1. Datadog metric types

TypeWire CodeUse caseVí dụ
COUNT|cĐếm eventsrequests, errors, purchases
GAUGE|gGiá trị hiện tạiqueue size, temperature, active users
RATE—Events/secondDatadog tự tính từ COUNT
HISTOGRAM|hDistribution (client-side)response time, payload size
DISTRIBUTION|dGlobal percentiles (server-side)cross-region latency
TIMER|msDuration (alias cho histogram)function execution time

4.2. HISTOGRAM sinh 5 metrics mặc định

Đây là kiến thức thi quan trọng

Khi gửi 1 histogram metric, Agent tự sinh 5 metrics mặc định:

Generated MetricSuffixÝ nghĩa
<name>.avgAverageGiá trị trung bình trong flush interval
<name>.countCountSố data points nhận được
<name>.medianMedianPercentile 50
<name>.95percentileP95Percentile 95
<name>.maxMaxGiá trị lớn nhất

Cấu hình trong datadog.yaml (hoặc Helm values):

Mỗi percentile/aggregate thêm = thêm custom metric

1 histogram metric name + 2 tag values + 7 aggregates = 14 custom metrics. Cardinality tăng rất nhanh!

4.3. So sánh: Datadog vs Prometheus types

DatadogPrometheusGiống/Khác
COUNTCounterTương tự — monotonically increasing
GAUGEGaugeGiống — current value
HISTOGRAMHistogramKhác — DD client-side aggregate, Prom server-side buckets
DISTRIBUTIONSummaryTương tự — percentiles, nhưng DD server-side aggregation
RATE—DD Agent tự tính rate từ count
TIMER—Alias cho histogram, đo duration

4.4. Chọn type nào?

Q: "Đếm events?"           → COUNT (|c)
   Ví dụ: requests, errors, purchases

Q: "Giá trị hiện tại?"     → GAUGE (|g)
   Ví dụ: queue size, temperature, active users

Q: "Distribution/latency?" → HISTOGRAM (|h) hoặc DISTRIBUTION (|d)
   Ví dụ: response time, payload size
   HISTOGRAM = client-side (5 metrics mặc định)
   DISTRIBUTION = server-side (global percentiles, accurate cross-host)

Q: "Rate (events/second)?" → COUNT + Datadog "as_rate()" function
   Ví dụ: requests/second

🔗 Fundamentals: Ch.03 — Counter, Gauge, Histogram. Cùng concepts, khác naming. Prometheus Counter ≈ Datadog COUNT. Prometheus Histogram ≈ Datadog HISTOGRAM (nhưng aggregation location khác).

5. DogStatsD — Advanced: Flush & UDS

5.1. Flush interval = 10 giây (hardcoded)

App gửi metric          Agent buffer          Datadog Cloud
  t=0  "shop:1|c"  ──→  ┌──────────┐
  t=3  "shop:1|c"  ──→  │ count=3  │
  t=7  "shop:1|c"  ──→  │          │
                         └────┬─────┘
  t=10 (flush)                │  HTTPS POST
                              └──────────→   count=3 (10s bucket)
  • Flush interval là 10 giây, không thể thay đổi
  • Agent tổng hợp tất cả data points trong 10s rồi gửi 1 lần
  • Nếu app gửi shop:1|c 3 lần trong 10s → Agent gửi count=3

6. Metrics Explorer — Advanced Queries

6.1. Query functions

Trong Metrics Explorer, thử các functions:

# Average CPU by Pod
avg:kubernetes.cpu.usage.total{kube_namespace:storedog} by {pod_name}

# Sum memory by Deployment
sum:kubernetes.memory.rss{kube_namespace:storedog} by {kube_deployment}

# Rate of discount requests
avg:trace.flask.request.hits{service:store-discounts}.as_rate()

# Top 5 Pods by memory
top(avg:kubernetes.memory.rss{*} by {pod_name}, 5)

# Custom metric vừa gửi
avg:shop.products.viewed{env:lab}.as_count()

6.2. Aggregation & Rollup

FunctionÝ nghĩa
avgAverage across tags
sumSum across tags
max / minExtremes
countNumber of unique tag combinations
.rollup(avg, 60)Average over 60s buckets
.as_rate()Convert count to rate (per second)
.as_count()Raw count

⚠️ Troubleshooting

Custom metric không hiện trên UI

netcat không gửi được từ debug Pod

Metric hiện nhưng value sai

  • COUNT metrics: Datadog normalize thành rate per second by default
  • Dùng .as_count() để xem raw count
  • Flush interval = 10 giây (hardcoded) — không thể thay đổi
  • HISTOGRAM tạo 5 metrics mặc định — check suffix .avg, .count, .median, .95percentile, .max
