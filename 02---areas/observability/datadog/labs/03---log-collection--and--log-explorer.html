Lab 03 — Log Collection & Log Explorer

⏱️ Thời gian: ~45 phút
📋 Prerequisites: Lab 02 hoàn thành, Storedog + Agent đang chạy trên Minikube
🔗 Source: DataDog/storedog

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu cách Datadog Agent thu thập logs từ Kubernetes Pods qua CRI (containerd)
  • Cấu hình log collection bằng Helm values và Pod annotations
  • Sử dụng Log Explorer để search, filter, analyze logs
  • Hiểu Log Facets — structured fields tự động extracted
  • Tạo Saved Views và Log Patterns
  • Thực hiện Log → Trace correlation bằng dd.trace_id

📚 Kiến Thức Nền

Fundamentals

  • Ch.02 — Logs
    → Log levels, structured logging, log aggregation, correlation IDs
  • Ch.04 — Trace-Log Correlation

Cách học lab này

Trình tự đúng của lab logs: ingest trước, query sau, correlation cuối cùng

  • Nếu logs chưa vào Datadog, việc học search syntax hay facets sẽ không giúp gì. Bước đầu tiên luôn là xác nhận Agent DaemonSet có thực sự collect logs từ đúng Pods hay không.
  • Trong lúc explore, hãy phân biệt rõ 3 thứ: tìm theo raw text, lọc theo parsed attributes, và group/filter bằng facets. Nhiều nhầm lẫn trong Log Explorer đến từ việc dùng đúng field nhưng sai loại field.
  • Khi làm correlation, đừng giả định “có traces + có logs” là đủ. Điều bạn thật sự cần là trace context xuất hiện trong log record, thường qua log injection hoặc structured logging phù hợp.

1. Log Collection — Agent Thu Thập Logs Trên Kubernetes

1.1. Kiến trúc

Pod (store-discounts)
  │ stdout/stderr
  ▼
containerd runtime → writes log files
  │
  ▼
/var/log/pods/<namespace>_<pod>_<uid>/<container>/0.log
  │
  ▼
Datadog Agent DaemonSet (hostPath mount /var/log/pods/)
  │ reads CRI log format, enriches with K8s metadata
  │ (pod name, namespace, labels, annotations)
  ▼ HTTPS
Datadog Cloud → Log Storage
  │
  ▼
Log Explorer (UI) / Log Analytics

Khác biệt cốt lõi so với Docker standalone

  • Docker: Agent đọc logs qua Docker socket (/var/run/docker.sock)
  • Kubernetes: Agent đọc file logs từ /var/log/pods/ — containerd (CRI) ghi stdout/stderr của container ra đây
  • Minikube dùng containerd làm runtime mặc định, không phải Docker Engine

1.4. Log collection bằng Pod Annotations (Autodiscovery)

Khi containerCollectAll: true, Agent thu logs mọi container. Nhưng bạn vẫn muốn gán source và service chính xác để Datadog áp đúng Log Pipeline:

Tên container trong annotation key

ad.datadoghq.com/<container-name>.logs — <container-name> phải khớp chính xác với spec.containers[].name trong Pod spec, không phải Pod name hay Deployment name.

Verify annotation đã được Agent nhận:

💡 Datadog Agent thu thập logs trên K8s bằng cách nào?

  1. Agent DaemonSet chạy 1 Pod/Node, mount hostPath /var/log/pods/
  2. Containerd runtime ghi stdout/stderr của mọi container vào /var/log/pods/<ns>_<pod>_<uid>/<container>/0.log
  3. Agent tail các file log này (CRI log format)
  4. Agent enrich logs với K8s metadata: kube_namespace, kube_deployment, pod_name, labels
  5. Nếu Pod có annotation ad.datadoghq.com/<c>.logs, Agent áp source và service tương ứng
  6. Agent gửi logs lên Datadog Cloud qua HTTPS

🔗 Fundamentals: Ch.02 — Log Collection. Datadog Agent = centralized log collector, tương đương Filebeat/Fluentd nhưng tích hợp sẵn metrics + traces. Trên K8s, nó chạy như DaemonSet để cover mọi Node.

2. Log Explorer — Khám Phá Logs

2.1. Mở Log Explorer

  1. Trên Datadog UI → Logs → Explorer (hoặc Search)
  2. Bạn sẽ thấy live log stream từ các Pods trên Minikube

2.2. 🔍 Quan Sát: Log Stream

ElementMô tả
Search barTìm kiếm logs bằng query
Time rangeChọn khoảng thời gian (top right)
Log entriesDanh sách log lines, mới nhất trên cùng
Facets panelBên trái — structured attributes cho filtering
Live TailToggle xem logs real-time

2.3. Search syntax

Thử các queries:

# Filter theo service
service:store-discounts

# Filter theo log level
status:error

# Filter theo nội dung
"database connection"

# Kết hợp
service:store-discounts status:error

# Wildcard
service:store-*

# Exclude
-status:info

# K8s-specific: filter theo namespace
kube_namespace:storedog

# Filter theo Pod name
pod_name:discounts-*

2.4. Thử từng filter

  1. service:store-discounts → chỉ logs từ Python discounts service
  2. status:error → tìm errors (nếu Log Pipeline đã set status)
  3. service:store-discounts status:error → errors từ discounts
  4. @http.status_code:500 → HTTP 500 errors nếu field đã được parse
  5. kube_namespace:storedog → tất cả logs trong namespace storedog

status:error rất tiện nhưng không phải universal

Với plain-text logs hoặc source chưa có parser phù hợp, bạn có thể phải tìm theo message/text thay vì status. Annotation source: python giúp Datadog áp đúng Log Pipeline → parse status chính xác hơn.

3. Log Facets — Structured Fields

3.1. Hiểu Facets

Datadog phân biệt:

  • Attributes: fields được parse/extract từ log
  • Facets: attributes bạn promote để dễ filter, aggregate, autocomplete và monitor

💡 Structured logs thường được parse thành attributes trước:

  • JSON logs → mỗi field thành 1 attribute
  • Access logs → @http.method, @http.status_code, @http.url
  • Application logs → @duration, @usr.id

Không phải mọi parsed field đều tự động thành facet ở panel bên trái.

3.2. Khám phá existing facets

Trong panel bên trái, expand các groups:

Facet GroupContains
Corehost, service, source, status
Kuberneteskube_namespace, kube_deployment, pod_name, container_name
HTTP@http.method, @http.status_code, @http.url
Network@network.client.ip
CustomBất kỳ fields từ structured logs

💡 K8s-specific facets là lợi thế lớn — bạn có thể filter logs theo kube_deployment, kube_namespace, thậm chí kube_container_name mà không cần config thêm.

3.3. Sử dụng Facets

  1. Click vào status facet → thấy distribution: info, warn, error
  2. Click error → tự filter status:error
  3. Click vào service facet → thấy danh sách services
  4. Click store-discounts → filter thêm
  5. Click kube_namespace → filter theo namespace

3.4. Tạo Custom Facet

Nếu bạn thấy 1 field trong log mà chưa có facet:

  1. Click vào 1 log entry → expand
  2. Tìm field muốn tạo facet (ví dụ: @duration)
  3. Click icon ⚙️ bên cạnh field → Create facet
  4. Đặt path, display name → Save

4. Log Detail & Context

4.1. Xem log detail

  1. Click vào 1 log entry
  2. Bạn sẽ thấy:
    • Message — raw log content
    • Attributes — parsed fields (JSON/structured)
    • Tags — K8s metadata: pod_name, kube_namespace, kube_deployment, image_name
    • Host info — Node name, container
    • Related — correlated traces, metrics

4.2. View in context

  1. Click View in context
  2. Bạn sẽ thấy logs trước và sau log entry hiện tại — cùng source (cùng Pod/container)
  3. Giống kubectl logs <pod> --since=... nhưng với UI tốt hơn

💡 Tại sao “context” quan trọng?

Khi debug error, 1 log line thường không đủ. Bạn cần xem:

  • Trước error: request nào gây ra? Input gì?
  • Sau error: recovery hay cascade failure?

4.3. So sánh với kubectl logs

Datadog Log Explorer bổ sung: parsing, facets, correlation, saved views, và retention vượt xa lifecycle của Pod.

5. Log Processing — Grok Parser

5.1. Grok Parser syntax (exam-relevant)

Datadog dùng Grok để parse unstructured logs thành attributes:

%{MATCHER:ATTRIBUTE_NAME:FILTER}
ComponentVai tròVí dụ
MATCHERPattern để match (regex hoặc built-in)word, ip, number, notSpace
ATTRIBUTE_NAMETên attribute được extracthttp.method, duration, client_ip
FILTERChuyển đổi kiểu dữ liệuinteger, double, array, scale(factor)

FILTER, không phải TYPE

Nhiều tài liệu cũ ghi sai là %{MATCHER:NAME:TYPE}. Đúng là FILTER — nó không chỉ cast type mà còn hỗ trợ transformations như scale(1000) để chuyển đổi đơn vị.

Ví dụ parse access log:

# Rule:
access.common %{ip:client_ip} %{word:http.method} %{notSpace:http.url} %{number:http.status_code:integer} %{number:duration:scale(1000000)}

# Input:
10.0.2.15 GET /api/discounts 200 0.053

# Output attributes:
client_ip = "10.0.2.15"
http.method = "GET"
http.url = "/api/discounts"
http.status_code = 200       (integer, nhờ filter)
duration = 53000             (scaled by 1000000)

5.2. Log Pipelines trên Datadog UI

  1. Vào Logs → Configuration → Pipelines
  2. Tìm pipeline cho source:python — Datadog tự tạo cho sources phổ biến
  3. Trong pipeline, bạn sẽ thấy các processors: Grok Parser, Status Remapper, Date Remapper, v.v.

6. Log → Trace Correlation

6.1. Concept: dd.trace_id

Nếu tracer hỗ trợ log injection và app bật DD_LOGS_INJECTION=true (env var trên Pod), log messages sẽ chứa dd.trace_id và dd.span_id:

Datadog dùng các reserved log attributes này để link log với trace. Correlation ổn định hơn khi service, env, version cũng được align theo Unified Service Tagging (K8s labels tags.datadoghq.com/*).

6.2. Thực hành correlation

  1. Trong Log Explorer, tìm 1 log entry từ service:store-discounts
  2. Click vào log entry
  3. Tìm section Traces hoặc nút View Trace
  4. Click → jump sang APM trace view

🔍 Quan sát: Bạn vừa đi từ log → trace chỉ bằng 1 click. Đây là sức mạnh của correlation.

6.3. Ngược lại: Trace → Logs

  1. Vào APM → Traces → click 1 trace
  2. Trong trace detail, tìm tab Logs
  3. Bạn sẽ thấy logs liên quan nếu correlation fields đã có mặt

🔗 Fundamentals: Ch.02 — Correlation IDs. dd.trace_id = implementation của concept “correlation ID”. Datadog tracer tự inject trace context vào logs khi DD_LOGS_INJECTION=true.

6.4. So sánh: Datadog vs Dynatrace correlation

DatadogDynatrace
Mechanismdd.trace_id field in logsOneAgent code-level correlation
K8s setupPod env DD_LOGS_INJECTION=true + tracer libOneAgent Operator tự inject
TransparencyVisible (thấy trace_id trong log)Invisible (magic correlation)
FlexibilityCần ensure libs compatibleJust works (nếu OneAgent inject OK)

7. Saved Views & Log Patterns

7.1. Saved Views

Lưu filter configuration để dùng lại:

  1. Apply filters: service:store-discounts status:error
  2. Click Save (hoặc ⭐) → đặt tên: Discounts Errors
  3. Lần sau chỉ cần chọn saved view → instant filter

7.2. Log Patterns

  1. Trong Log Explorer, click tab Patterns
  2. Datadog tự nhóm logs có cấu trúc tương tự lại
  3. Ví dụ: 100 logs "GET /api/products 200" → 1 pattern

💡 Patterns giúp giảm noise: Thay vì đọc 10,000 log lines, bạn đọc 30 patterns — mỗi pattern = 1 nhóm logs tương tự.

⚠️ Troubleshooting

Logs không xuất hiện trong Datadog

Logs xuất hiện nhưng thiếu source/service

  • Kiểm tra annotation trên Pod:
  • Annotation key phải khớp container name trong Pod spec
  • Nếu dùng containerCollectAll: true mà không có annotation, source sẽ là containerd thay vì python

Facets không hiện

  • Structured logs (JSON) tự parse thành attributes
  • Chỉ fields được promote thành facet mới hiện ở panel/autocomplete
  • Nếu cần aggregate/filter nhiều, tạo facet thủ công
  • Unstructured logs cần Log Pipeline (Grok Parser) để parse

Correlation không hoạt động

  • Verify tracing library inject trace context vào logs
  • Verify service, env trên logs khớp với traces (Unified Service Tagging)
  • Trace phải được retain trên Datadog (check APM → Traces)

  • Log Explorer hiện logs từ Storedog Pods
  • Filter service:store-discounts hoạt động
  • Filter kube_namespace:storedog hiện đúng logs
  • Filter status:error hoặc text search hiện error logs
  • Facets panel hiện Core + Kubernetes + HTTP facets
  • Log → Trace correlation: click log → jump to trace
  • (Optional) Saved View tạo thành công
