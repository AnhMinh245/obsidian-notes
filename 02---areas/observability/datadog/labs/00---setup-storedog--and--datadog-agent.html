Lab 00 — Setup Storedog & Datadog Agent trên Kubernetes

⏱️ Thời gian: ~45 phút
📋 Prerequisites: Minikube, kubectl, Helm đã cài — chạy được trên bất kỳ máy nào (laptop, VM, cloud instance)
🔗 Source: DataDog/storedog · Datadog Helm Chart

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu kiến trúc Datadog Agent trên K8s: DaemonSet (Node Agent) + Cluster Agent
  • Khởi động Minikube cluster và deploy Storedog (6 services) bằng kubectl apply
  • Cài Datadog Agent qua Helm chart với values.yaml tuỳ chỉnh
  • Verify Agent gửi metrics, traces, logs lên Datadog platform
  • Truy cập Storedog UI qua minikube service hoặc port-forward

Kiến trúc K8s — Khái niệm then chốt

DaemonSet (Node Agent) — 1 Agent Pod per Node, KHÔNG phải per app Pod

  • Tại sao không Sidecar? → 50 Pods × 256MB RAM = 12.8GB overhead, 50× API requests, duplicate node metrics
  • DaemonSet đảm bảo: thêm Node → Agent tự deploy; bớt Node → Agent tự remove
  • Xem chi tiết: Ch.10 §10.2

Cluster Agent — 1 instance (Deployment), giảm tải K8s API

  • 50 Node Agents query K8s API riêng → 50×N queries/giây → API server overload
  • Cluster Agent query 1 lần → cache → Node Agents hỏi Cluster Agent
  • Thu thập: cluster-level events, Kubernetes state metrics, HPA

Autodiscovery — K8s Annotations thay cho Docker Labels

  • Docker: com.datadoghq.ad.* labels trên container
  • K8s: ad.datadoghq.com/<container>.* annotations trên Pod
  • Agent scan Pods trên Node → match annotations → auto-configure checks

hostPort — Cách app Pods gửi data đến Agent

  • App Pod lấy Node IP qua Downward API (status.hostIP) → set DD_AGENT_HOST
  • Gửi traces đến <Node_IP>:8126, custom metrics đến <Node_IP>:8125

CRI (containerd) — Log collection trên Minikube

  • Minikube dùng containerd (CRI) → Agent đọc logs từ /var/log/pods/
  • KHÔNG dùng Docker socket (/var/run/docker.sock) như Docker Compose setup

8. Tìm Hiểu Agent — Khám Phá Sâu Hơn

8.1. Agent status đầy đủ

🔍 Quan sát sections quan trọng:

  • Collector → Running Checks: kubelet, postgres, network…
  • Forwarder → Transactions: Number of transactions: N (N > 0 = đang gửi data)
  • APM Agent → Receiver: traces có đang được nhận? (port 8126)
  • Logs Agent → containers nào đang collect logs?
  • Hostname: resolution order — datadog.yaml → Cloud Provider → Kubelet → OS hostname (KHÔNG có Reverse DNS)

⚠️ Troubleshooting

Pod stuck ở Pending

ImagePullBackOff / ErrImagePull

Storedog images dùng GHCR — nếu vẫn lỗi denied từ ghcr.io:

CrashLoopBackOff

Agent: 403 Forbidden / API key invalid

Agent: RBAC 403 Forbidden từ K8s API

Storedog services không connect được với nhau

Frontend OOMKilled — RESTARTS liên tục

frontend-XXXXX   0/1   OOMKilled   17 (...)

npm run dev + Next.js compiler + dd-trace ngốn RAM nhiều hơn 512Mi. Fix:

Memory requirement

npm run dev cần ~800Mi–1.5Gi. npm run prod (pre-built) chỉ cần ~300Mi nhưng cần thêm bước build.

Frontend SyntaxError: Unexpected token '<' — JSON parse fails

Frontend gọi một Spree API endpoint và nhận HTML thay vì JSON. Nguyên nhân:

  1. /api/v2/storefront/homepage — Route không tồn tại trong Spree 4.3 (được thêm vào phiên bản mới hơn)
  2. /pages, /taxonomies, /products — Frontend gọi qua service-proxy nhưng backend không có custom routes này

Chẩn đoán:

Fix: nginx config đã bao gồm mocks và route redirects (xem ConfigMap ở trên). Nếu update ConfigMap sau khi deploy:

Puppeteer Chrome không launch — Failed to launch the browser

Error: Failed to launch the browser process!

Puppeteer/Chrome cần SYS_ADMIN capability để chạy sandbox trong K8s. Manifest đã bao gồm fix này. Nếu dùng manifest cũ:

Backend products count = 0 sau khi seed

✅ Verify Checklist

Trước khi sang Lab 01, đảm bảo:

  • Minikube cluster đang chạy (kubectl get nodes → STATUS = Ready)
  • Agent DaemonSet Pod đang Running (kubectl get pods -n datadog)
  • Cluster Agent Pod đang Running
  • agent status không có 403 Forbidden, hiện “Running Checks”
  • PostgreSQL integration check active (via Autodiscovery annotations)
  • Host/cluster xuất hiện trên Datadog Infrastructure
  • Tất cả 7 pods trong storedog namespace đang Running
  • Products count > 0: kubectl exec -n storedog deploy/backend -- bundle exec rails runner "puts Spree::Product.count"
  • Frontend trả HTTP 200: kubectl exec -n storedog deploy/service-proxy -- curl -s -o /dev/null -w "%{http_code}" http://frontend:3000/
  • APM traces xuất hiện trên Datadog (store-frontend, store-backend tối thiểu)
