Lab 04 — APM & Distributed Tracing

⏱️ Thời gian: ~60 phút
📋 Prerequisites: Lab 03 hoàn thành, Storedog chạy trên Minikube
🔗 Source: DataDog/storedog

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu cách APM hoạt động trong Kubernetes: DaemonSet Agent + hostPort + Downward API
  • Đọc Service List với RED metrics tự động
  • Khám phá Service Map — dependency visualization với K8s context
  • Phân tích individual traces qua Flame Graph
  • Sử dụng Error Tracking để group và triage errors
  • Thực hiện cross-telemetry navigation: Trace → Log → Metric → Pod
  • So sánh Flame Graph (Datadog) vs PurePath (Dynatrace)

📚 Kiến Thức Nền

Fundamentals

  • Ch.04 — Distributed Tracing
    → Trace, span, propagation, waterfall/flame views
  • Ch.05 — Instrumentation
    → Auto-instrumentation via tracing libraries
  • Ch.03 — RED Method
    → Rate, Errors, Duration

Cách học lab này

Hãy đọc APM theo nhiều tầng, không nhảy thẳng vào trace đẹp nhất

  • Thứ tự học hiệu quả: Service List (bức tranh RED tổng quát) → Service Page (hành vi 1 service) → Trace + Span (chi tiết request cụ thể).
  • Service Map không phải sơ đồ kiến trúc “đúng tuyệt đối”; nó là bản đồ của traffic đã được quan sát. Nếu không có request hoặc không có trace ingestion cho 1 edge, edge đó sẽ không hiện.
  • Trong K8s, APM traces mang thêm context: kube_namespace, kube_deployment, pod_name. Đây là lợi thế lớn khi debug so với Docker standalone.
  • Khi trace thiếu hoặc service map trống, đừng mặc định Datadog UI lỗi. Quay lại kiểm tra tracer config, DD_AGENT_HOST, propagation headers, và traffic đủ chưa.

  2. Bạn sẽ thấy danh sách services Datadog phát hiện từ Storedog traces

2.2. 🔍 Quan Sát: Service Overview

Mỗi service hiện 3 metrics cốt lõi — chính là RED method:

Storedog services bạn sẽ thấy:

3. Service Map — Dependency Graph

3.1. Mở Service Map

  1. Vào APM → Service Map
  2. Bạn sẽ thấy node-and-edge diagram

3.2. 🔍 Quan Sát

                    ┌─────────────────────────────────────┐
                    │        kube_namespace: storedog      │
                    │                                      │
[store-frontend] ───┼──→ [store-backend] ────→ [postgres]  │
       │            │                                      │
       ├────────────┼──→ [store-discounts] ──→ [postgres]  │
       │            │                                      │
       └────────────┼──→ [store-ads]                       │
                    │                                      │
                    └─────────────────────────────────────┘

Mỗi node = 1 service. Mỗi edge = HTTP/gRPC call detected từ traces.

ElementÝ nghĩa
Node sizeThroughput (lớn = nhiều traffic)
Node colorHealth (xanh = OK, vàng = degraded, đỏ = errors)
Edge thicknessCall volume giữa 2 services
Edge colorError rate trên edge

3.3. K8s-specific: Filter theo namespace

  1. Dùng filter kube_namespace:storedog để chỉ hiện app services
  2. Dùng filter kube_deployment:discounts để focus 1 service
  3. Hover node → thấy RED metrics kèm K8s metadata (pod count, deployment)

3.4. Interaction

  1. Hover 1 node → thấy RED metrics
  2. Click 1 node → options: View Service Page, View Traces, View Pods
  3. Hover 1 edge → thấy call volume + error rate

💡 Service Map vs Dynatrace Smartscape:

Datadog Service MapDynatrace Smartscape
Layers1 layer (services only)4 layers (datacenter → host → process → service)
K8s contextTags: kube_namespace, kube_deploymentKubernetes integration: workloads, namespaces
Data sourceObserved APM service interactionsOneAgent + topology inference
DiscoveryTrace propagation + observed requestsCode modules + process/network analysis
InfrastructureSeparate views (Infra → K8s)Integrated in topology

4.3. Resources (Endpoints)

Resource = endpoint cụ thể trong service.

Ví dụ cho store-discounts:

  • GET /discount — lấy discount info
  • POST /discount/apply — áp dụng discount

Click 1 resource → xem latency/error/throughput riêng endpoint đó.

5. Traces — Flame Graph

5.1. Mở Traces search

  1. Vào APM → Traces
  2. Hoặc từ Service Page → click View Traces

5.2. Chọn 1 trace

  1. Click vào 1 trace entry
  2. Bạn sẽ thấy Flame Graph view

5.3. 🔍 Đọc Flame Graph

Timeline (ms) →
0          50         100        150        200        250

store-frontend: GET /products
  ████████████████████████████████████████████████████████  252ms
  │
  ├── store-backend: GET /api/products
  │   ██████████████████████████████████████████           198ms
  │   │
  │   ├── postgres: SELECT * FROM products
  │   │   ██████████████████                               88ms
  │   │
  │   └── store-discounts: GET /discount
  │       ██████████████                                   72ms
  │       │

  │           ████████                                     35ms
  │
  └── store-ads: GET /ad
      ████████                                             40ms

Cách đọc:

  • Mỗi bar = 1 span (unit of work)
  • Chiều dài bar = duration (ms)
  • Nesting = parent-child relationship
  • Màu = service (mỗi service 1 màu)
  • 🔴 Bar đỏ = error

🔗 Fundamentals: Ch.04 — Trace Structure. Mỗi bar trong flame graph = 1 span. Nesting = parent/child span tree. Flame graph = horizontal visualization của tree đó.

5.5. So sánh: Flame Graph vs PurePath

FeatureDatadog Flame GraphDynatrace PurePath
LayoutHorizontal bars (time axis)Vertical waterfall tree
GranularitySpan-level, tùy mức instrumented spansCode/method-level trên supported stacks
K8s contextTags: namespace, deployment, podKubernetes workload + process group
CPU vs Wall timeChủ yếu wall time / span durationTách CPU time + wait time tốt hơn
BottleneckManual readingAuto hotspot analysis

6. Error Tracking

6.1. Mở Error Tracking

  1. Vào APM → Error Tracking (hoặc UX → Error Tracking)
  2. Bạn sẽ thấy grouped errors

6.2. 🔍 Quan Sát

Error Tracking nhóm same errors lại:

  • Cùng exception type + stack trace → 1 error group
  • Count: bao nhiêu lần xảy ra
  • First/Last seen: khi nào bắt đầu/lần cuối
  • Affected services: service nào bị
  • Affected Pods: pod nào bị (K8s context)

6.3. Storedog Intentional Errors

Storedog có intentional bugs trong store-discounts:

  • Discount calculation errors
  • Database connection timeouts

Tìm error groups liên quan → click → xem stack trace + impacted traces + affected Pods.

💡 Error Tracking vs Alert:

  • Alert (Lab 07) = “thông báo khi error rate > threshold”
  • Error Tracking = “nhóm, phân loại, triage errors”

7. Cross-Telemetry Navigation

7.1. Trace → Logs

  1. Mở 1 trace → tab Logs
  2. Thấy logs emitted trong thời gian trace đó
  3. Link bằng dd.trace_id

7.2. Trace → Metrics (Infrastructure)

  1. Mở 1 trace → tab Infrastructure
  2. Thấy infra context liên quan quanh thời điểm trace
  3. Trong K8s: thấy Pod CPU, Pod Memory, Node metrics
  4. Hữu ích: “Pod bị OOMKill lúc request chậm không?“

7.3. Trace → Pod / K8s Resources

  1. Mở 1 trace → click tag pod_name
  2. Jump đến Infrastructure → Kubernetes → Pod detail
  3. Xem Pod events, restarts, resource usage
  4. Hoặc click kube_deployment → xem deployment-level overview

7.4. Trace → Host / Node

  1. Mở 1 trace → click tag host hoặc node_name
  2. Jump đến Infrastructure → Host details
  3. Xem node-level context (CPU, memory, disk, network)

💡 Navigation path thực tế khi debug trên K8s:

1. Nhận alert: "Error rate tăng trên store-discounts"
2. Vào APM → Service Page → thấy error spike at 14:30
3. Filter theo kube_deployment:discounts
4. Click error trace → Flame Graph → thấy postgres span đỏ
5. Click postgres span → thấy sql.query = "SELECT..." timeout
6. Click "View Logs" → lấy error message và context cụ thể
7. Click pod_name tag → K8s Pod detail → kiểm tra restarts, OOM events
8. Click node_name → Node metrics → CPU/memory/disk cùng khung giờ
9. Trace + Logs + Metrics + K8s Events = complete root cause analysis

🔗 Fundamentals: Ch.04 — Cross-Pillar Correlation. Trace (what failed) → Log (why failed) → Metric (infrastructure context) → K8s Events (platform context). 3 pillars + K8s = complete picture.

8. 🔥 Mini Challenge: Debug Một Error Bằng APM trên K8s

Bài tập thực hành

Tự navigate qua toàn bộ debugging workflow trên Kubernetes. Đo thời gian.

Scenario

🔔 “Users phàn nàn trang products load chậm. Đôi khi hiện discount sai. Deployment mới đã rollout 30 phút trước.”

Hướng dẫn

⏱️ Bắt đầu đo thời gian

  1. Bước 1: Mở APM → Services → Filter kube_namespace:storedog → Tìm service nào có error rate cao nhất
  2. Bước 2: Click service đó → Service Page → Xem latency chart:
    • Latency spike bắt đầu khi nào?
    • Correlate với deployment event?
    • Resource (endpoint) nào chậm nhất?
  3. Bước 3: Click resource chậm nhất → View Traces → Chọn 1 trace có error
  4. Bước 4: Trong Flame Graph:
    • Span nào đỏ (error)?
    • Duration bao lâu?
    • Span tags: http.status_code, sql.query, pod_name?
  5. Bước 5: Click tab Logs → Tìm error message cụ thể
  6. Bước 6: Click pod_name → K8s Pod detail → Check restarts, OOM, events
  7. Bước 7: Click tab Infrastructure → Node CPU/memory lúc đó bình thường?

⏱️ Dừng đo thời gian

Tự đánh giá

Thời gianLevel
< 5 phút⭐⭐⭐ Thành thạo — biết navigate Datadog APM + K8s nhanh
5–15 phút⭐⭐ Cơ bản — cần quen UI và K8s context hơn
> 15 phút⭐ Cần ôn lại Labs 01–04

⚠️ Troubleshooting

APM Services trống — không thấy service nào

Traces hiện nhưng thiếu spans

  • Tracing library cần time để send spans (đợi 30–60 giây)
  • Check DD_TRACE_AGENT_URL hoặc DD_AGENT_HOST + DD_TRACE_AGENT_PORT trong Pod env
  • Verify: app container có tracing library (ddtrace Python, dd-trace Ruby/JS, dd-trace-java)
  • Check Pod logs cho tracing errors:

Service Map trống

  • Cần ít nhất 2 services giao tiếp với nhau
  • Cần traces cross-service → propagation headers phải hoạt động
  • Chờ 5–10 phút data + đảm bảo Storedog có traffic (Puppeteer/synthetic traffic chạy)
  • Verify propagation: kiểm tra response headers có x-datadog-trace-id

DD_AGENT_HOST không đúng

APM Agent bị tắt

✅ Verify Checklist

  • APM Agent running: kubectl exec ... agent status | grep APM → Status: Running
  • App Pods có DD_AGENT_HOST = node IP (Downward API hoặc Admission Controller)
  • Service List hiện Storedog services (≥4 services)
  • Service Map hiện dependency graph với kube_namespace:storedog filter
  • Mở 1 trace, thấy Flame Graph với multiple spans + K8s tags
  • Span details hiện pod_name, kube_deployment, kube_namespace
  • Error Tracking hiện grouped errors
  • Trace → Log correlation hoạt động (click log tab)
  • Trace → Pod navigation hoạt động (click pod_name tag)
