Phần 13: Datadog Ports — Giải Thích Chi Tiết

13.1 Tổng Quan: Tại Sao Port Lại Quan Trọng?

Datadog Agent là một tiến trình chạy cục bộ trên host/node của bạn. Nó giao tiếp theo hai hướng:

  • Outbound (ra ngoài): Agent gửi data (metrics, traces, logs) lên Datadog Cloud.
  • Inbound (nhận vào): Agent lắng nghe các kết nối đến từ các tiến trình nội bộ khác trên cùng host (ví dụ: ứng dụng gửi custom metrics qua DogStatsD, hoặc Trace Agent nhận Spans từ thư viện APM).

Hiểu rõ bảng port của Datadog giúp bạn:

  1. Cấu hình Firewall/Security Group chính xác (chỉ mở đúng port cần thiết).
  2. Tránh xung đột port với các dịch vụ khác trên cùng host.
  3. Debug nhanh khi Agent hoạt động sai.

13.3 Giải Thích Chi Tiết Từng Port Quan Trọng

Port 443 (Outbound — Forwarder)

Đây là port quan trọng nhất và duy nhất cần mở ra Internet.

Cách hoạt động:

  • Collector (sub-process thu thập metrics) chuyển dữ liệu sang Forwarder.
  • Forwarder nén (compress bằng gzip) và mã hóa dữ liệu.
  • Forwarder gửi theo batch HTTPS đến Datadog intake endpoint.
  • Nếu mạng tạm thời bị mất, Forwarder buffer data trên disk tối đa 32MB và thử lại.

Không dùng port 10516 nữa:
Trước Agent v6, Agent cũ dùng TCP port 10516 để gửi Logs. Từ Agent v6+ trở đi, tất cả logs cũng được gửi qua HTTPS port 443.

Port 8125 (Inbound — DogStatsD)

DogStatsD là một server StatsD tích hợp sẵn trong Datadog Agent, lắng nghe Custom Metrics từ ứng dụng.

Vì sao dùng UDP chứ không phải TCP?

  • UDP là fire-and-forget: Ứng dụng gửi metric xong không cần chờ xác nhận (ACK). Điều này cực kỳ quan trọng vì nếu dùng TCP, khi Agent bị lỗi hay chậm, nó sẽ làm treo (block) chính ứng dụng của bạn.
  • Hiệu năng cao hơn nhiều khi gửi hàng ngàn metrics/giây.
  • Đánh đổi: Có thể mất một số gói tin metric, nhưng điều đó chấp nhận được vì metric chỉ là dữ liệu thống kê tổng hợp.

Định dạng gói tin DogStatsD (StatsD Protocol):

<metric_name>:<value>|<type>|#<tag1>,<tag2>

Ví dụ thực tế:

web.requests.count:1|c|#env:prod,service:api
api.latency:235|ms|#endpoint:/users,method:GET
queue.depth:42|g|#queue:orders

Port 8126 (Inbound — APM Trace Agent)

Trace Agent là sub-process trong Datadog Agent chịu trách nhiệm nhận, xử lý và gửi Spans (dữ liệu phân tán tracing).

Vì sao dùng TCP (không phải UDP) cho APM?

  • Trace data (Spans) là dữ liệu có cấu trúc phức tạp (JSON, Msgpack), cần đảm bảo toàn vẹn dữ liệu (không được mất gói).
  • Mỗi Span chứa thông tin quan trọng: trace_id, span_id, parent_id, service, resource, duration, error status… nếu mất là không thể reconstruct trace.
  • TCP đảm bảo thứ tự và toàn vẹn của dữ liệu.

Port 5000, 5001, 5002 (Inbound — Agent Internal APIs)

Đây là các port chỉ phục vụ nội bộ, không bao giờ cần mở ra ngoài.

Port 5001 — IPC API:

  • Dùng để các CLI command của Datadog Agent (như datadog-agent status, datadog-agent configcheck) giao tiếp với Agent process đang chạy.
  • Khi bạn chạy datadog-agent status, lệnh này kết nối TCP vào localhost:5001, Agent trả về thông tin trạng thái.
  • Nếu port này bị conflict (bị process khác chiếm), các lệnh CLI của Agent sẽ không hoạt động.

Port 5002 — Web GUI:

  • Datadog Agent có một giao diện web cục bộ (Browser-based GUI).
  • Truy cập http://localhost:5002 để xem trạng thái Agent, danh sách checks đang chạy, errors… mà không cần CLI.
  • Chỉ accessible từ localhost, không expose ra ngoài.

Port 5000 — go-expvar:

  • Agent được viết bằng Go. Go có thư viện expvar để expose các metrics nội bộ (số goroutines, memory usage của Agent…).
  • Port này chủ yếu dành cho developer debugging Agent internals.

Port 6062 & 6162 (Debug & Runtime)

Port 6062 — pprof:

  • Go profiling endpoint. Cho phép lấy CPU profile, heap profile, goroutine dump của Datadog Agent.
  • Chỉ dùng khi Datadog support yêu cầu bạn capture profiling data để debug Agent tiêu tốn quá nhiều CPU/RAM.

Port 6162 — Runtime Settings:

  • Cho phép thay đổi một số cấu hình Agent tại runtime mà không cần restart.
  • Ví dụ: tăng log level của Agent lên DEBUG để troubleshoot mà không restart.

13.6 Unix Domain Socket (UDS) — Thay Thế Hiệu Năng Cao Cho UDP

Trong môi trường Linux, thay vì dùng UDP localhost, bạn có thể cấu hình DogStatsD và APM Trace Agent nhận data qua Unix Domain Socket (UDS) — một file socket thay cho IP + Port.

Ưu điểm so với UDP/TCP:

  • Không có TCP/UDP overhead (không có IP header, port resolution).
  • Không bị giới hạn bởi buffer size của kernel UDP socket.
  • Throughput cao hơn khoảng 20-30% so với UDP.
  • Không cần mở port nào cả, chỉ cần quyền đọc/ghi file socket.

13.7 Tóm Tắt Ôn Thi (Exam Tips)

  • Port 443 (Outbound): Đây là port duy nhất Agent cần để gửi data ra Datadog Cloud (metrics, logs, traces, processes — tất cả đều qua đây).
  • Port 8125 (UDP): DogStatsD — Nhận Custom Metrics từ ứng dụng. Dùng UDP vì fire-and-forget, không block ứng dụng khi Agent gặp sự cố.
  • Port 8126 (TCP): APM Trace Agent — Nhận Spans từ dd-trace library. Dùng TCP vì trace data cần đảm bảo toàn vẹn (không được mất gói).
  • Port 5001 (TCP): IPC API — Dùng bởi CLI commands (datadog-agent status, datadog-agent configcheck).
  • Port 5002 (TCP): Agent Web GUI — Truy cập http://localhost:5002.
  • Chỉ 443 cần ra Internet: Các port 8125, 8126, 5001, 5002 chỉ là internal, không bao giờ expose ra public internet.
  • UDS > UDP: Unix Domain Socket hiệu năng cao hơn UDP 20-30%, là lựa chọn tốt nhất trong môi trường Linux.
  • Kubernetes hostIP: Ứng dụng trong K8s phải dùng status.hostIP (Downward API) để tìm IP của Agent DaemonSet trên cùng Node.
  • DogStatsD non_local_traffic: Mặc định DogStatsD chỉ nhận từ localhost. Muốn nhận từ container/pod khác phải bật dogstatsd_non_local_traffic: true.
