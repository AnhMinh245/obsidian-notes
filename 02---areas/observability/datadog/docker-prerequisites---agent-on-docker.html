🐳 Kiến Thức Docker Cần Biết Trước Khi Học “The Agent on Docker”

Khoá học này dạy gì?

Khoá Agent on Docker hướng dẫn cách chạy và cấu hình Datadog Agent dạng container để thu thập metrics và logs từ các container khác cũng như từ host. Các module bao gồm:

  1. About the Agent Container
  2. Lab: The Agent on Docker
  3. Autodiscovery
  4. Troubleshooting Tips

Sau khi hoàn thành khoá, bạn sẽ có thể:

  • Chạy Agent container cùng các service được orchestrate bằng Docker Compose
  • Cấu hình Agent qua environment variables
  • Kiểm tra Agent health và configuration bằng CLI
  • Gắn Unified Service Tags qua container labels
  • Tìm metrics/logs mà Agent thu thập trong Datadog

1. Container Là Gì? — Khái Niệm Cốt Lõi

1.1 Container vs Virtual Machine

Kích thướcVài chục MBVài GB
IsolationChia sẻ kernel hostCó kernel riêng

1.2 Kiến trúc Docker

┌───────────────────────────────────────────┐
│              Docker Client (CLI)          │
│           docker run, docker ps, ...      │
├───────────────────────────────────────────┤
│              Docker Daemon (dockerd)      │
│         Quản lý containers, images,       │
│         networks, volumes                 │
├───────────────────────────────────────────┤
│              Container Runtime            │
│         containerd → runc                 │
├───────────────────────────────────────────┤
│              Host OS (Linux Kernel)       │
│         namespaces, cgroups, ...          │
└───────────────────────────────────────────┘
  • Docker Daemon (dockerd): service chạy ngầm, quản lý mọi thứ về Docker
  • Docker Client (docker): CLI gửi lệnh tới daemon
  • Docker Socket (/var/run/docker.sock): Unix socket để client giao tiếp với daemon — rất quan trọng vì Datadog Agent cần mount socket này để giám sát các container khác

2. Docker Image & Container

2.1 Image

  • Image = blueprint/template chỉ-đọc để tạo container
  • Được tạo thành từ nhiều layers chồng lên nhau
  • Lưu trữ trong registry (Docker Hub, ECR, GCR, …)
  • Ví dụ image Datadog Agent: gcr.io/datadoghq/agent:7 hoặc datadog/agent:latest

2.2 Container

  • Container = một instance đang chạy từ image
  • Có riêng filesystem, network, process space (nhờ Linux namespaces)
  • Khi container bị xoá → dữ liệu bên trong mất (trừ khi dùng volume)

3. Các Flags Quan Trọng Khi docker run

Khoá học yêu cầu hiểu rõ các flag sau vì chúng được dùng liên tục khi chạy Datadog Agent:

3.1 -d (Detached Mode)

Chạy container ở chế độ nền (background). Terminal không bị chiếm.

3.2 -e (Environment Variables) ⭐

Trong khoá này

Environment variables là cách chính để cấu hình Datadog Agent khi chạy dạng container (thay vì sửa file datadog.yaml như trên host).

Một số biến quan trọng:

BiếnMục đích
DD_API_KEYAPI key bắt buộc để Agent gửi dữ liệu về Datadog
DD_SITESite/region của tài khoản Datadog
DD_LOGS_ENABLEDBật thu thập logs
DD_APM_ENABLEDBật APM (tracing)
DD_PROCESS_AGENT_ENABLEDBật process monitoring
DD_DOGSTATSD_NON_LOCAL_TRAFFICCho phép nhận custom metrics từ container khác

3.3 -v (Volume Mounts) ⭐

Volume mount cho phép container truy cập dữ liệu từ host:

MountMục đích
/var/run/docker.sockCho Agent truy vấn Docker API để biết container nào đang chạy
/proc/Cho Agent đọc thông tin process, CPU, memory của host
/sys/fs/cgroup/Cho Agent đọc cgroup metrics (resource limits)

:ro = Read-Only

Thêm :ro ở cuối để mount chế độ chỉ đọc → an toàn hơn, Agent chỉ cần đọc, không cần ghi.

3.4 -p (Port Mapping)

PortGiao thứcMục đích
8126TCPAPM traces
8125UDPDogStatsD (custom metrics)

Format: -p <host_port>:<container_port>[/protocol]

3.5 --name

Đặt tên cho container thay vì tên ngẫu nhiên → dễ quản lý.

4. Docker Compose ⭐⭐

Bắt buộc phải biết

Khoá học dùng Docker Compose để orchestrate Agent + các service demo. Đây là phần trọng tâm của lab.

4.1 Docker Compose là gì?

  • Tool để định nghĩa và chạy multi-container applications
  • Cấu hình bằng file docker-compose.yml (hoặc compose.yaml)
  • Một lệnh docker compose up → tất cả services khởi chạy

4.2 Cấu trúc file docker-compose.yml

4.3 Lệnh Docker Compose thiết yếu

docker compose vs docker-compose

  • docker compose (có dấu cách): Docker Compose V2 — plugin tích hợp sẵn trong Docker Desktop mới
  • docker-compose (có dấu gạch ngang): V1 — standalone binary, đã deprecated
  • Khoá học có thể dùng cả hai. Nên dùng V2.

5. Docker Exec — Chạy Lệnh Trong Container

Trong khoá này

docker exec được dùng liên tục để kiểm tra Agent status, config, và troubleshoot. Các lệnh Agent CLI quan trọng:

  • agent status — xem tổng quan Agent
  • agent configcheck — kiểm tra cấu hình integration
  • agent health — kiểm tra Agent health

Flags:

  • -i (interactive): giữ stdin mở
  • -t (tty): cấp pseudo-terminal
  • -it: kết hợp cả hai → mở shell tương tác

6. Docker Labels ⭐⭐

Liên quan trực tiếp tới Autodiscovery

Labels là cách chính để cấu hình Autodiscovery và gắn Unified Service Tags trong Docker.

6.1 Labels là gì?

  • Key-value metadata gắn vào container/image
  • Không ảnh hưởng tới runtime behavior — chỉ là metadata
  • Datadog Agent đọc labels này để tự động cấu hình monitoring

6.2 Gắn Labels trong docker-compose.yml

6.3 Unified Service Tags

Ba tag chuẩn của Datadog để link metrics, traces, logs lại với nhau:

8. Docker Networking Cơ Bản

8.1 Default Network trong Compose

  • Docker Compose tự tạo một bridge network cho tất cả services trong cùng file
  • Các service có thể giao tiếp qua tên service (DNS tự động)
  • Ví dụ: Agent muốn connect tới web-app → dùng hostname web-app

8.2 Tại sao cần biết?

Khi cấu hình Autodiscovery, Agent cần biết cách reach tới service khác. Docker Compose network đảm bảo Agent và các service nhìn thấy nhau.

%%host%% là template variable của Datadog — tự động resolve thành IP/hostname của container.

9. Docker Socket (/var/run/docker.sock)

Đây là concept quan trọng nhất để hiểu tại sao Agent cần quyền truy cập host

  • Docker socket là API endpoint của Docker daemon
  • Khi mount vào Agent container → Agent có thể:
    • Liệt kê tất cả container đang chạy
    • Đọc metadata (labels, env vars, …) của từng container
    • Nhận events khi container start/stop
    • Tự động discover services mới → Autodiscovery

10. Autodiscovery — Khái Niệm Tổng Quan

Phần này sẽ được dạy chi tiết trong khoá, nhưng nên hiểu concept trước

Autodiscovery là gì?

Khi môi trường containerized thay đổi liên tục (containers start/stop), việc cấu hình monitoring thủ công là không khả thi. Autodiscovery cho phép Agent:

  1. Phát hiện container mới khi chúng start
  2. Đọc labels trên container để biết cần monitor gì
  3. Tự động apply integration config phù hợp
  4. Tự động remove config khi container stop

Flow hoạt động

Container Start → Agent detect (via Docker socket)
                → Agent đọc labels
                → Agent áp dụng check config
                → Metrics/Logs bắt đầu được thu thập

11. Tóm Tắt Checklist

Trước khi bắt đầu khoá Agent on Docker, hãy đảm bảo bạn thoải mái với:

  • Hiểu Container vs VM
  • Biết Docker image, container, registry là gì
  • Dùng được các lệnh: docker run, docker ps, docker logs, docker exec
  • Hiểu các flag: -d, -e, -v, -p, --name
  • Biết đọc và viết file docker-compose.yml
  • Dùng được docker compose up/down/ps/logs/exec
  • Hiểu Docker labels và cách gán
  • Hiểu bind mount vs named volume
  • Biết Docker socket là gì và tại sao Agent cần nó
  • Hiểu cơ bản Docker networking trong Compose
