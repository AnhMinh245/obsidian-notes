Phần 1: Giới thiệu về Datadog API

1.1. Tổng quan

HTTP REST API của Datadog hỗ trợ tự động hóa rất nhiều tác vụ mà bạn thường phải click chuột trên Datadog UI, bao gồm việc tạo và quản lý:

  • Monitors
  • Dashboards
  • Dashboard widgets
  • SLOs
  • Synthetic tests
  • Notebooks

Đó chỉ là một phần nhỏ. API có thể làm gần như mọi thứ mà một con người có thể làm trên Datadog. Bạn có thể xem toàn bộ các khả năng của API tại Datadog Docs API Reference.

1.2. Use cases (Trường hợp sử dụng)

Nếu có một thao tác nào đó bạn làm nhiều hơn một lần trên Datadog, hãy cân nhắc tự động hóa nó. Dưới đây là một số cách bạn có thể tận dụng sức mạnh của Datadog API để tối ưu hóa quy trình làm việc (workflows) của mình:

  • Viết một shell script nhận tham số (parameterized shell script) để tạo một monitor phổ biến.
  • Viết một công cụ tạo notebooks từ tài liệu nội bộ (internal documentation).
  • Xử lý các nguồn dữ liệu tùy chỉnh (custom data sources) và stream chúng về Datadog logs.
  • Tạo một bộ monitors khi cần thiết, và xóa chúng đi khi không còn dùng nữa.
  • Kích hoạt (fire off) các event để theo dõi tiến độ cấp phát (provisioning) các services mới.
  • Tự động tạo synthetic test khi deploy các API hoặc website mới.
  • Tự động tạo user khi có người mới gia nhập tổ chức/team, và xóa user khi họ nghỉ việc.

Giới hạn duy nhất là trí tưởng tượng của bạn. Bạn có nghĩ ra những tác vụ Datadog lặp đi lặp lại hoặc tốn thời gian nào mà team bạn đang làm có thể được tự động hóa bằng Datadog API không?

1.3. Xác thực (Authentication)

Để giao tiếp với Datadog API, bạn cần xác thực các request của mình. API sử dụng API keys và application keys.

Loại KeyĐịnh nghĩa & Đặc điểm
API keys- Là key duy nhất (unique) cho tổ chức của bạn.
- Datadog Agent bắt buộc phải có API key để gửi metrics và events lên Datadog.
Application keys- Dùng kết hợp với API key của tổ chức để cấp cho user quyền truy cập vào programmatic API của Datadog.
- Application key được gắn với tài khoản user đã tạo ra nó. Mặc định nó sẽ mang các quyền (permissions/scopes) của chính user đó.

IMPORTANT

Việc bảo vệ API keys và application keys là cực kỳ quan trọng. Nếu người khác lấy được API key của bạn, họ có thể gửi dữ liệu “rác” vào Datadog account của bạn. Nếu họ lấy được application key, họ có thể query (truy vấn) dữ liệu từ Datadog của bạn. Hãy tìm hiểu thêm về cách quản lý API and application keys trong tài liệu Datadog.

Có nhiều cách để bạn giao tiếp với Datadog API. Dưới đây là các phương pháp phổ biến nhất:

HTTP clients

Vì Datadog API là một REST API, bạn có thể dùng bất kỳ HTTP client nào. Datadog có bảo trì một bộ Postman collection chứa toàn bộ các endpoint trong Datadog API, đây là cách tuyệt vời để bắt đầu khám phá API.

Datadog provider cho Terraform

Terraform là một open source tool phổ biến dùng để xây dựng và quản lý Infrastructure as Code (IaC). Giống như các IaC tools khác, nó cho phép quản lý infrastructure bằng các công cụ giống hệt như phát triển phần mềm. Datadog Provider cho Terraform giao tiếp với Datadog API khi đang cấp phát hạ tầng, cho phép bạn spin up các service cùng lúc với các tài nguyên Datadog liên quan.

1.5. Nội dung các bài Lab

Trong các bài lab tiếp theo, bạn sẽ làm việc với Datadog API qua nhiều cách khác nhau trong quá trình provisioning một ứng dụng web nhỏ:

  • Sử dụng Postman để:
    • Khám phá Datadog API collection.
    • Post và query log entries.
  • Sử dụng curl để:

    • Publish events lên Datadog để theo dõi tiến độ provisioning.
  • Sử dụng Dogshell để:

    • Cấp phát (provision) một ứng dụng web nhỏ.
    • Đồng thời tạo ra monitor và dashboard cho ứng dụng đó.

Kết thúc các bài lab này, bạn sẽ hiểu cách Datadog API hoạt động, nó làm được những gì và bạn có thể giao tiếp với nó bằng những cách nào.

Phần 2: Lab — Postman

2.1. Giới thiệu Postman và Datadog Collection

Postman là một nền tảng phổ biến để tạo, chia sẻ, test, và tài liệu hóa các HTTP API. Tính năng Collection của Postman cho phép người dùng tạo và chia sẻ các thư viện chứa nhiều HTTP request cho các endpoint khác nhau. Datadog có duy trì một Datadog collection cho Postman, bạn sẽ dùng nó trong bài lab này để khám phá sâu hơn về Datadog API.

Bài lab này yêu cầu một tài khoản Postman miễn phí. Nếu không muốn tạo tài khoản, bạn có thể dùng giải pháp nền web như Hoppscotch. Dù không dùng được Datadog collection làm sẵn, bạn vẫn có thể tự recreate lại nhiều request tương tự.

Khởi tạo Datadog collection trong Postman

Bài lab này hướng dẫn thao tác trên Postman nền web, nhưng bạn hoàn toàn có thể dùng ứng dụng tải về (native application) nếu muốn.

  1. Đăng nhập vào Postman.
  2. Click vào tab API Docs (trong môi trường lab của bạn) để mở trang tài liệu Datadog API Reference.

    Lưu ý: Bạn nên mở sẵn một tab chứa Datadog API Reference trong suốt quá trình làm việc với API.

  3. Click vào nút ▶︎ Run in Postman. Việc này sẽ tạo bản fork của Datadog API collection vào Postman của bạn.
  4. Đặt tên (Fork label) và chọn workspace để lưu collection. Bạn cứ giữ mặc định.
  5. Click nút Fork collections.

Khi quá trình hoàn tất, bạn sẽ thấy cột collection explorer nằm bên trái.

2.2. Khám phá một endpoint

Giờ chúng ta sẽ xem xét kỹ một API endpoint.

  1. Mở rộng Datadog API Collection.
  2. Mở rộng thư mục Events, sau đó click vào Post an event.
  3. Ở góc phải màn hình, click vào icon Documentation. Nó chứa tài liệu API cho endpoint đang chọn. Bạn sẽ thấy URL và phần mô tả ở đầu.
  4. So sánh với tab API Docs (Datadog API Reference). Tìm mục Events ở menu trái, sau đó click Post an event. Đảm bảo bạn đang chọn version v1 ở góc trên bên phải trang tài liệu.

    IMPORTANT

    API v2 cho Post an event hiện chỉ hỗ trợ các event có category là change. Với các event khác, bạn bắt buộc phải dùng v1 API. Postman collection cũng chưa có bản v2.

  5. Đọc mục Body request trong Docs và so sánh với tab Body ở chính giữa workspace của Postman. Bạn sẽ thay đổi JSON placeholder này khi gửi event thật.
  6. Cuộn xuống mục Response trong Docs để thấy các mã phản hồi như 200, 400, 429. Trong Postman, các ví dụ phản hồi này được liệt kê bên dưới “Post an event”.

Hãy dành thời gian tự khám phá các endpoint của Dashboards, Logs, và Metrics trong collection này vì bạn sẽ còn làm việc với chúng sau này.

2.3. Xác thực các API request (Authentication)

Các request gọi tới Datadog API yêu cầu HTTP headers chứa ít nhất một API key. Nếu request thực hiện tác vụ đọc dữ liệu (read) thì nó cần thêm một application key. Chúng được set qua các header DD-API-KEY và DD-APPLICATION-KEY.

Trong Postman, bạn sẽ cấu hình các key này thông qua chức năng Environment Variables.

Bước 1: Lấy API key và App key

Trong terminal của lab, chạy lệnh:

Lưu ý: Bạn cũng có thể lấy key trên Datadog UI bằng cách vào Personal Settings > Organization Settings > API Keys hoặc Application Keys.

Bước 2: Xem biến Collection

Trong Postman, click vào Datadog API Collection, sau đó sang tab Variables. Chú ý hai biến api_key và application_key. Chúng ta sẽ trỏ hai biến này tới biến môi trường (environment variables).

Bước 3: Tạo Postman Environment

  1. Click nút New (góc trên bên trái hoặc góc trên sidebar) và chọn Environment.
  2. Đổi tên thành: Datadog API course
  3. Trong ô Add new variable, tạo biến api_key với type là Secret. Điền API key thực tế của bạn vào ô Current value.

    Lưu ý: Current value chỉ dùng cục bộ trên máy bạn. Initial value sẽ bị lộ ra nếu bạn share collection này cho người khác. Hãy để trống Initial value.

  4. Lặp lại để tạo biến application_key. Sau đó bấm Save.

Bước 4: Liên kết biến

  1. Trở lại tab Variables của Datadog API Collection.
  2. Sửa ô Current value của api_key thành chuỗi {{api_key}}.
  3. Sửa ô Current value của application_key thành {{application_key}}.
  4. Bấm Save.

    IMPORTANT

    Dấu chấm màu cam xuất hiện trên tab Postman báo hiệu bạn chưa Save thay đổi. Hãy luôn Save nhé.

Bước 5: Chọn Environment

Click vào dropdown ở góc trên cùng bên phải (đang ghi No Environment), chọn môi trường Datadog API course vừa tạo.

Nhờ việc set environment variable, bạn có thể dễ dàng switch qua lại giữa production/staging mà không phải sửa cứng key trong từng API request.

2.4. Kiểm tra (Test) các keys

Test API key

Datadog cung cấp endpoint Validate API key để xác nhận authentication của bạn đã cấu hình đúng.

  1. Trong Postman, vào Datadog API Collection > Authentication > Validate API key.
  2. Bấm Send. Bạn sẽ nhận được 200 OK với body { "valid" : true }.

Nếu bạn nhận 403 Forbidden, hãy kiểm tra lại:

  • API key đã nhập đúng chưa?
  • Biến collection đã sửa thành {{api_key}} chưa?
  • Đã bấm Save chưa?
  • Đã chọn đúng Environment ở dropdown chưa?

Test Application key

Datadog API không có endpoint chuyên dụng để verify App key. Bạn chỉ cần gọi thử một endpoint yêu cầu App key, ví dụ như Get a list of events.

  1. Trong Postman, vào Datadog API Collection > Events > Get a list of events. Trong tab Params, tìm thông số filter[from] và filter[to]. Yêu cầu của chúng là thời gian (timestamp) định dạng milliseconds.
  2. Mở terminal của lab, chạy lệnh sau để lấy timestamp tương ứng:

    Lưu ý: Timestamp bắt đầu khoảng 3 phút trước khi session terminal của bạn bắt đầu.

  3. Trong Postman, nhập 2 con số vừa lấy được vào filter[from] và filter[to]. Nhớ uncheck các parameter khác. (Dòng URL phía trên sẽ tự cập nhật khi bạn check/uncheck params).
  4. Bấm Send. Nếu thành công, bạn sẽ nhận được 200 OK kèm theo JSON chứa event lúc lab bắt đầu.

Nếu bị 403 Forbidden, hãy kiểm tra lại biến application key của bạn.

2.6. Sự khác biệt giữa các endpoint (Gửi và Tìm kiếm Logs)

Datadog API thường thiết kế nhất quán, nhưng sẽ có ngoại lệ, ví dụ như Logs endpoints. Khi so sánh Post an event và Send logs, bạn sẽ thấy khác biệt lớn:

  • Gửi event cần trường tags là một array strings. Gửi logs cần trường ddtags là comma-separated string.
  • Gửi event lấy source_type_name. Gửi logs lấy ddsource.
  • Gửi event lấy host. Gửi logs lấy hostname.

Do yếu tố lịch sử nên endpoints của logs sẽ hơi khác biệt. Hãy luôn tham khảo API Reference khi xây dựng queries!

Gửi logs (Post logs)

Chúng ta sẽ gửi một mảng log thông qua Postman:

  1. Vào Datadog API Collection > Logs > Send logs.
  2. Ở tab Params, uncheck ddtags (ta sẽ truyền trong body).
  3. Ở tab Headers, đảm bảo uncheck Content-Encoding.
  4. Sang tab Body, dán vào:
  5. Bấm Send. Nhận được 200 OK kèm một JSON trống là thành công.

    IMPORTANT

    Nếu bị lỗi, hãy đảm bảo bạn đã uncheck header Content-Encoding và API key môi trường của bạn chính xác.

Truy vấn logs (Query logs)

  1. Trong Postman, vào Logs > Search logs (POST).
  2. Sang tab Body. Bạn sẽ thấy cấu trúc chia làm hai:
    • filter: quyết định log nào trả về (thời gian from, index, query). Đổi query thành env:api-course và from thành now-1h.
    • page: quyết định cách trả về (limit, cursor). Chỉnh limit thành 1 và xóa bỏ cursor.
  3. Bấm Send. Kết quả trả về 200 OK chứa các mảng data, meta, và links. Mảng data sẽ có chứa bản ghi log mà bạn tạo khi nãy.

Phân trang (Pagination)

Để ý giá trị meta.page.after. Nếu dữ liệu thực tế lớn hơn biến limit (ví dụ bạn giới hạn 1 log, nhưng hệ thống có nhiều log hơn), API sẽ cung cấp after này.
Ở request tiếp theo, bạn chỉ cần gán nó vào page.cursor để lấy trang dữ liệu kế tiếp. Quá trình lặp lại cho tới khi response không còn trường meta.page.after nữa.

Phần 3: Lab — Command Line (curl)

Trong lab này, bạn sẽ khám phá Datadog API qua command-line scripts:

  1. Bạn sẽ dùng API docs để xây dựng headers, URLs, parameters, và body của API requests.
  2. Cấp phát (provision) một web application nhỏ và dùng Datadog API để phát hiện metric từ Agent của nó.
  3. Post events lên Event Explorer.
  4. Làm tất cả các bước trên nhưng bằng tiện ích Dogshell.

3.1. Giới thiệu và Research the request

Dưới đây là kiến trúc của các Docker service trên lab host của bạn. Ba cái đầu đã chạy, còn redis-search-cache chưa chạy, bạn sẽ khởi chạy nó sau. Môi trường là api-course.

Giả sử một đồng nghiệp đang chuẩn bị rollout redis-search-cache, nhiệm vụ của bạn là phải phát hiện ra ngay thời khắc nó online bằng cách query Datadog API.

Bạn có thể query endpoint Query timeseries points để lấy về danh sách các data points của metric. Nếu mảng dữ liệu này không trống, chứng tỏ service đã gửi metrics về Datadog.

3.2. Xây dựng API URL và truy vấn với curl

Từ tài liệu API, URL sẽ có dạng như sau:

https://api.datadoghq.com/api/v1/query?from=$FROM&to=$TO&query=$QUERY
  • $TO và $FROM là timestamp (cách nhau 60 giây). Lệnh date sẽ giúp bạn lấy cái này.
  • $QUERY sẽ phức tạp hơn. Bạn có thể dùng Metrics Explorer trên giao diện để tự render ra query.
  1. Trong Datadog, mở Integrations, tìm Redis.
  2. Tab Data Collected có liệt kê metric redis.cpu.sys. Nếu Redis dùng CPU hệ thống thì chắc chắn nó đang chạy!
  3. Chuyển sang Metrics Explorer, gõ redis.cpu.sys, thêm tag env:api-course và service:redis-session-cache.
  4. Sao chép lại query string được tạo ra:
    avg:redis.cpu.sys{env:api-course,service:redis-session-cache}
  5. Đổi tên service tag thành mục tiêu của chúng ta là redis-search-cache: 
    avg:redis.cpu.sys{env:api-course,service:redis-search-cache}

Phần 6: Lab — Terraform & Tổng kết khóa học

6.1. Giới thiệu Terraform

Trong lab này, bạn sẽ dùng Terraform để triển khai một web application nhỏ, sau đó tạo metric và dashboard để giám sát ứng dụng đó. Terraform là một công cụ Infrastructure as Code (IaC) vô cùng phổ biến dùng để cấu hình và quản lý tài nguyên trên nhiều cloud provider, bao gồm cả Datadog.

Sử dụng Terraform với Datadog provider cho phép bạn định nghĩa monitor, dashboard dưới dạng code. Nhờ đó, chúng có thể nằm cùng repo với cấu hình hạ tầng của bạn và dễ dàng deploy qua CI/CD pipelines.

6.2. Cấu trúc cấu hình Terraform

Có 3 file Terraform được cung cấp để cấp phát ứng dụng:
Mở thư mục terraform trong IDE và quan sát các file sau:

  • variables.tf: Kéo API keys và Application keys từ biến môi trường.
  • main.tf: Cấu hình Datadog Agent, Redis, và các Python application Docker container. Cấu trúc nó giống file docker-compose.yml. Tất cả container labels, environment variables của Datadog đều đặt ở đây.
  • alert-monitors.tf: Dùng resource datadog_monitor tạo một Datadog alert monitor cho ứng dụng.
  • dashboards.tf: Dùng resource datadog_dashboard tạo Datadog dashboard.

alert-monitors.tf

File này tạo resource datadog_monitor để theo dõi redis.cpu.sys. Monitor sẽ alert nếu average CPU vượt threshold trong khoảng thời gian 5 phút. Monitor này mạnh hơn bản Dogshell trước đó rất nhiều. Cú pháp khai báo gần y hệt như thao tác cấu hình Metric Monitor trên UI của Datadog.

dashboards.tf

Dashboard này chứa nhiều widget. Các widget block được khai báo bám sát theo Datadog API schema. Chúng đi kèm block widget_layout định vị trí đặt của chúng trên dashboard.

Đặc biệt, widget alert_graph có trường alert_id gán với biến datadog_monitor.redis_cpu.id. Biến này tham chiếu trực tiếp đến datadog_monitor vừa tạo. Terraform sẽ biết cách khởi tạo monitor trước, sau đó lấy ID của nó đưa vào dashboard.

6.3. Chạy Terraform (Apply configuration)

Giờ bạn đã sẵn sàng cấp phát các service này.
