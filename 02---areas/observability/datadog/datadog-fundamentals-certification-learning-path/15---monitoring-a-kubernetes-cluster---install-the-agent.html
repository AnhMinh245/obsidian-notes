Phần 1: Giới thiệu

1.1. Tổng quan khóa học

Để giám sát Kubernetes cluster bằng Datadog, bạn cần cài đặt Datadog Agent. Khóa học này hướng dẫn những cách phổ biến nhất để cài đặt Cluster Agent và Node Agent trên Kubernetes: Helm charts và Datadog Operator.

Bạn sẽ bắt đầu với một Kubernetes cluster gồm hai node, đang chạy ứng dụng e-commerce demo tên Storedog để tạo ra metrics. Qua một loạt các bài lab, bạn sẽ:

  • Dùng Helm chart để cài đặt và cấu hình một Cluster Agent và hai Node Agents.
  • Dùng Agent CLI commands để xác nhận các Agents đang chạy đúng.
  • Khám phá Datadog để thấy lượng dữ liệu phong phú từ cluster.
  • Thực hiện các bước trên một lần nữa bằng Datadog Operator.

Sau khi hoàn thành khóa học, bạn sẽ hiểu cách Datadog giám sát một Kubernetes cluster, và có thể chọn phương pháp cài đặt phù hợp nhất cho hạ tầng của mình.

Phần 2: Node Agent và Cluster Agent

2.1. Datadog Agents trong Kubernetes cluster

Datadog Agent có thể được cài đặt trên một Kubernetes node giống như trên bất kỳ host nào. Nó sẽ thu thập các performance metrics tiêu chuẩn về CPU, RAM, disk, network throughput và nhiều thứ khác. Khi phát hiện tiến trình kubelet, nó sẽ thu thập thêm metrics về pods, containers, và cluster metrics từ Kubernetes API.

Trên các cluster với nhiều node và Node Agents, việc thêm một Cluster Agent là một ý tưởng tốt. Cluster Agent sẽ hoạt động như proxy cho Kubernetes API, giảm đáng kể lưu lượng giao tiếp của các Node Agents.

2.2. Node Agents

Datadog Agent có thể được thêm vào Kubernetes cluster theo một số cách.

Một chiến lược là cài đặt Agent như một pod trên mỗi cluster node theo dạng DaemonSet. Trong trường hợp này, mỗi node sẽ chạy một Agent pod. Mỗi Agent sẽ:

  • Giám sát node của nó.
  • Giám sát các pod khác trên node của nó thông qua kubelet.
  • Làm phong phú metrics với cluster metadata bằng cách giao tiếp với Kubernetes API trên control plane.

Node Agents deployed as DaemonSet

2.3. Node Agents + Cluster Agent

Một chiến lược khác là cũng cài đặt thêm Cluster Agent. Trong trường hợp này, một hoặc nhiều Cluster Agent pod sẽ được triển khai trên cluster. Cluster Agent sẽ:

  • Thu thập cluster metadata bằng cách giao tiếp với Kubernetes API.

Còn mỗi Node Agent sẽ:

  • Giám sát node của nó.
  • Giám sát các pod khác trên node của nó thông qua kubelet.
  • Làm phong phú metrics với cluster metadata bằng cách giao tiếp với Cluster Agent (thay vì trực tiếp với Kubernetes API).

Node Agents and Cluster Agent

Điều này giảm đáng kể overhead giao tiếp giữa nhiều Node Agents và Kubernetes API. Nó cũng cho phép bạn thu hẹp phạm vi RBAC của mỗi Node Agent, vì chúng không cần trực tiếp giao tiếp với Kubernetes API nữa.

2.4. Các phương pháp cài đặt

Có ba cách để cài đặt Agent và Cluster Agent trên Kubernetes cluster:

  • Dùng Datadog Operator
  • Dùng Helm
  • Cài đặt thủ công

Datadog Operator

Datadog Operator là một Kubernetes Operator giúp đơn giản hóa việc cài đặt, nâng cấp, và quản lý Datadog trên Kubernetes cluster. Mặc định, Operator sẽ triển khai Agent trên mỗi node trong cluster, và một Cluster Agent.

Operator là dự án mã nguồn mở đạt General Availability (GA) vào năm 2023 và là phương pháp được khuyến nghị để thêm Datadog vào Kubernetes cluster. Đọc thêm tại Datadog Operator documentation.

Helm charts

Trước khi Operator đạt GA, Helm là phương pháp được khuyến nghị để cài đặt Agent trên Kubernetes. Helm charts là mã nguồn mở, mature, và được Datadog tích cực duy trì.

Nếu Datadog Operator không phù hợp với môi trường của bạn, Helm chart cài đặt là lựa chọn không bao giờ sai.

3.4. Universal Service Monitoring (USM) và Software Catalog

Đáng chú ý đặc biệt là Universal Service Monitoring (USM) của Datadog. Ngay cả với giải pháp monitoring tinh vi nhất, việc quản lý đồng thời health và performance của Kubernetes resources lẫn application services vẫn là một thách thức.

USM có thể giúp bạn theo kịp cluster động khi nó scale. USM tự động phát hiện và giám sát các service mới khi chúng được thêm vào Kubernetes cluster. Sau đó bạn có thể dùng Software Catalog để query, tổ chức, và quản lý các service:

Software Catalog

Ngoài việc cung cấp các chỉ số service health và performance realtime, Software Catalog giúp tổ chức của bạn làm phong phú thêm với metadata về mục đích, quyền sở hữu và nhiều thứ khác.

Software Catalog metadata

Tất nhiên, bạn cũng có được toàn bộ công cụ monitoring của Datadog, bao gồm logs, events, traces, monitors, và nhiều hơn nữa!

Khám phá thêm

Bạn có thể tự khám phá dữ liệu trong Datadog, chẳng hạn Logs và APM traces. Bạn sẽ có cơ hội khám phá Datadog thêm ở cuối bài lab tiếp theo.

4.9. Tổng kết Lab (Helm)

Kết luận: Bạn đã cài đặt và cấu hình thành công Datadog Agent và Cluster Agent bằng Helm chart. Bạn đã xác nhận:

  • Các Agents đang chạy đúng.
  • Một Node Agent được deploy trên mỗi node.
  • Các Node Agents đã kết nối với Cluster Agent.
  • Agents đang gửi dữ liệu tới Datadog thông qua việc khám phá Kubernetes dashboards, infrastructure views, và các sản phẩm khác.

Phần 5: Lab — Cài đặt Agent bằng Datadog Operator

5.1. Giới thiệu

Các bước deploy Agent bằng Operator khá tương tự với các bước Helm chart, vì vậy bạn đã có sự khởi đầu về mặt khái niệm!

Datadog Operator sử dụng một Custom Resource Definition (CRD) duy nhất để deploy Node Agent, Cluster Agent, và Cluster Checks Runner. Operator báo cáo deployment status, health, và errors trong CRD status.

5.2. Deploy Datadog Operator

Bước 1: Cài đặt Datadog Operator bằng Helm

Đúng là bạn đang dùng Helm. Nhưng đây chỉ là để cài đặt Operator; Operator mới là thứ sẽ tiếp quản quy trình deploy Agent.

Lưu ý: Flag --version là tùy chọn. Nếu bỏ qua, phiên bản mới nhất của Operator sẽ được cài đặt.

Bước 2: Xác nhận Operator pod đang chạy

Output tương tự:

NAME                                     READY   STATUS    RESTARTS     AGE
my-datadog-operator-858b665ff5-lfxd9     1/1     Running   0            58s

Lưu ý: Bạn có thể dùng flag -w trong kubectl get để tránh phải chạy lại lệnh nhiều lần. Thoát khỏi watch mode bằng Ctrl+C.

Chờ cho đến khi pod đang Running trước khi tiếp tục.

5.3. Cấu hình Datadog Agent (DatadogAgent CRD)

Bây giờ Datadog Operator đang chạy trong cluster, bạn có thể chuẩn bị deploy Agent bằng cách cấu hình một DatadogAgent definition.

Giống như cài đặt Helm chart, bạn phải cung cấp Datadog API key cho Agent. Nhưng có hai điểm khác biệt so với Helm:

  • Helm chart tự động tạo Kubernetes secret để lưu API key, nhưng Operator yêu cầu bạn tự tạo secret.
  • Khi bật USM bằng Operator, bạn cũng phải cung cấp application key, được set trong môi trường lab của bạn là $DD_APP_KEY.

Bước 1: Tạo Kubernetes secret lưu API key và App key

Bước 2: Xem file DatadogAgent definition

Click tab IDE và mở file datadog.yaml. Đây là DatadogAgent definition.

File này tương tự với file custom-values.yaml bạn dùng với Helm chart ở bài lab trước. Các Agent options là như nhau, nhưng cấu trúc khác. Dưới đây là bảng ánh xạ chi tiết:

Tham số Operator (datadog.yaml)Tương đương trong Helm (custom-values.yaml)Ý nghĩa
spec.global.clusterNamedatadog.clusterNameGắn cluster name tag duy nhất
spec.global.kubelet.tlsVerify: falsedatadog.kubelet.tlsVerify: falseTắt xác minh TLS kubelet
spec.global.credentials.apiSecretdatadog.apiKey (qua --set)Tham chiếu Secret chứa API key
spec.global.credentials.appSecretKhông có (helm tự xử lý)Tham chiếu Secret chứa App key
spec.features.logCollection.enabled: truedatadog.logs.enabled: trueBật log collection
spec.features.logCollection.containerCollectAll: truedatadog.logs.containerCollectAll: trueThu log từ tất cả containers
spec.features.apm.hostPortConfig.enabled: truedatadog.apm.portEnabled: trueBật TCP port nhận traces
spec.features.liveProcessCollection.enabled: trueKhông có trong ví dụ HelmBật live process collection
spec.features.usm.enabled: truedatadog.serviceMonitoring.enabled: trueBật Universal Service Monitoring
override.nodeAgent.tolerationsagents.tolerationsCho phép Node Agent chạy trên control plane

5.4. Tổng kết Lab (Operator)

Kết luận: Bạn đã cài đặt và cấu hình thành công Datadog Agent và Cluster Agent bằng Operator. Bạn đã xác nhận:

  • Các Agents đang chạy đúng.
  • Một Node Agent được deploy trên mỗi node.
  • Các Node Agents kết nối với Cluster Agent.
  • Agents đang gửi dữ liệu tới Datadog.

Bây giờ bạn đã quen với cả hai phương pháp Helm chart và Operator để cài đặt Agent trên Kubernetes cluster, bạn sẽ có thể chọn phương pháp phù hợp nhất với nhu cầu của mình.

6.1. Tổng kết khóa học

  • Deploy Node và Cluster Agents bằng Helm chart và Operator.
  • Lưu trữ thông tin nhạy cảm như API key trong Kubernetes Secrets.

  • Xác nhận Node và Cluster Agents đang chạy và gửi dữ liệu về Datadog account.
  • Xem thông tin Kubernetes cluster trong Datadog qua Dashboards, Kubernetes resource views, và các sản phẩm Datadog khác.
  • Khám phá Software Catalog và Service Map để xem cách các ứng dụng kết nối với nhau.
