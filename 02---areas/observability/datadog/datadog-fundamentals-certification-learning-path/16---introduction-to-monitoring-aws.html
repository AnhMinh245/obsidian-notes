Phần 1: Giới thiệu về AWS Integration

1.1. Tổng quan khóa học

Khóa học này sẽ hướng dẫn bạn cài đặt và cấu hình integration AWS của Datadog để thu thập metrics, events, và logs từ các AWS resources.

Bạn sẽ làm việc với một ứng dụng demo để học các nguyên tắc và kỹ năng có thể áp dụng cho môi trường AWS của mình. Bạn sẽ cấu hình integration, sau đó khám phá metrics và logs thu thập được trong Datadog, và một số out-of-the-box dashboards được cung cấp bởi integration. Cuối cùng, bạn sẽ deploy Datadog Agent và bật metric streams.

1.2. Tổng quan về AWS Integration

AWS integration của Datadog bao gồm hơn 100 sub-integrations theo từng loại resource. Hầu hết được tự động cài đặt và cấu hình khi bạn thiết lập main AWS integration.

Có một số cách integration có thể thu thập AWS metrics, events, và logs vào Datadog.

1.3. Các phương pháp thu thập mặc định

AWS integration sử dụng hai phương pháp chính để phát hiện AWS resources và thu thập metrics và logs:

  1. Pulling metrics từ AWS vào Datadog account của bạn.

    • Datadog giả định một IAM role trong AWS account để poll CloudWatch Metrics API. Trung bình, Datadog thu thập metrics mỗi 10 phút.

  2. Pushing logs từ AWS account của bạn lên Datadog.

    • Một Lambda function trong môi trường của bạn chuyển tiếp logs lên Datadog khi được trigger. Nó tự động thu thập logs từ một số loại resource và có thể được cấu hình để hỗ trợ các nguồn bổ sung.

Default methods of pulling metrics from AWS and pushing logs to Datadog

1.4. Các phương pháp thu thập khác

Metric Streams và Amazon Data Firehose

Với cấu hình bổ sung, bạn có thể thu thập low-latency metrics từ AWS bằng cách sử dụng metric streams. Metric streams dùng Amazon Data Firehose để liên tục đẩy metrics lên Datadog account của bạn với độ trễ 3 phút.

Lưu ý: Tìm hiểu thêm trong guide AWS CloudWatch Metric Streams with Amazon Data Firehose.

Gửi logs qua Amazon Data Firehose

Bạn có thể chuyển tiếp AWS service logs được lưu trữ trong CloudWatch Log groups lên Amazon Kinesis Data Stream, sau đó giao hàng qua Amazon Data Firehose đến một hoặc nhiều destinations. Datadog là một trong những default destinations có sẵn cho Amazon Data Firehose Delivery streams.

Lưu ý: Tìm hiểu thêm trong guide Send AWS Services Logs with the Datadog Amazon Data Firehose Destination.

Datadog Agent

Datadog Agent có thể được cài đặt trên hoặc cùng với một số loại AWS resource. Ví dụ:

  • Cài đặt Agent trên EC2 instances, bao gồm cả những cái được dùng bởi RDS và ECS (EC2 launch type)
  • Chạy Datadog Agent container trong cùng task definition với application container
  • Chạy Datadog Agent container trong ECS clusters

Lợi ích của việc thêm Agent vào AWS infrastructure:

  • Low-latency host metrics được lấy mẫu mỗi 15 giây (so với 60-300 giây cho EC2 metrics trong CloudWatch)
  • Hơn 200 checks, nhiều trong số đó chạy tự động
  • Khả năng chạy custom checks
  • Khả năng gửi custom metrics bằng DogStatsD
  • Khả năng thu thập APM traces và profiling data

Datadog khuyến nghị cài đặt Agent ở bất cứ đâu có thể, kết hợp với AWS integration. Sự kết hợp này cung cấp khả năng quan sát toàn diện nhất cho AWS infrastructure của bạn.

  • Lambda

  • DynamoDB

TechStories on AWS architecture diagram

Khám phá metrics, logs, và dashboards

Sau khi integration được thiết lập, bạn sẽ khám phá môi trường AWS qua Datadog UI: out-of-the-box dashboards, phân tích logs, và điều tra metrics liên quan đến ứng dụng TechStories.

Bật Metric Streams

Bạn sẽ bật Amazon CloudWatch Metric Streams để gửi metrics đến Datadog với low latency.

Thêm log triggers

Cuối cùng, bạn sẽ cấu hình thủ công log forwarding triggers trên Datadog Forwarder Lambda function: thêm triggers để forward logs từ CloudWatch log groups và S3 buckets lên Datadog.

Bước 7: Kiểm tra HealthCheck

Trên dòng 288, chú ý GeneratePostsApiTaskDefinition bao gồm property HealthCheck. Cả GeneratePostsApiTaskDefinition và QuotesApiTaskDefinition đều có health checks, nhưng ReferralsServiceTaskDefinition thì không. Bạn sẽ thấy hậu quả của điều này ở các bước lab tiếp theo.

Phần 8: Lab — Cấu hình Log Forwarding thủ công

8.1. Giới thiệu

Trước đó trong lab, bạn đã cấu hình Datadog AWS integration để tự động subscribe Datadog Forwarder Lambda function đến Lambda CloudWatch log groups. Đối với các services không hỗ trợ auto-subscription, bạn có thể thêm triggers thủ công cho Datadog Forwarder. Trong activity này, bạn sẽ thiết lập hai loại trigger:

  1. CloudWatch trigger để chuyển tiếp ECS CloudWatch logs lên Datadog.
  2. S3 event trigger để chuyển tiếp CloudTrail logs lên Datadog.

8.2. Forward logs từ CloudWatch (ECS)

Các ECS services quotes-api, generate-posts-api, và referrals-service gửi container logs đến CloudWatch log group prefix ecs.

Lưu ý: Để xem cách CloudWatch logging được cấu hình cho ECS, tham khảo file techstories-cloudformation/ecs-services.yml trong IDE. Bạn cũng có thể thu thập ECS logs với Datadog Agent. Tìm hiểu thêm trong docs.

AWS CloudTrail logs các API calls và events trên AWS services. Trong lab AWS account, datadog-trail CloudTrail logs tất cả events trong region us-east-1 và ghi vào S3 bucket (tên bắt đầu bằng aws-cloudtrail-logs). Bạn sẽ chuyển tiếp các logs này lên Datadog với Lambda S3 trigger.
