Về Agent Container (The Agent Container)

Datadog Agent là một phần mềm mã nguồn mở chạy trên host cùng với các container của bạn. Nó thu thập các metric và log trước khi gửi chúng đến Datadog để xử lý và hiển thị.

Dù Agent chạy trực tiếp dưới dạng một process (tiến trình) trên host hay chạy trong một container, nó đều có khả năng giám sát các khía cạnh của host, bao gồm: mức sử dụng CPU, các thao tác trên filesystem, mức sử dụng memory (RAM), các process đang chạy, và hoạt động network. Khi Agent hoạt động bên trong một container, nó có thêm khả năng giám sát bản thân container runtime (trình chạy container) và các container khác chạy song song.

Trong môi trường Docker, điều này được thực hiện bằng cách mount (gắn) các resource của host dưới dạng volume vào bên trong Agent container. Trong biểu đồ dưới đây, Agent container được cấp quyền truy cập vào /var/run/docker.sock để giám sát Docker daemon và các container khác. Ngoài ra, nó cũng có quyền truy cập vào /proc và /sys/fs/cgroups để giám sát host nền tảng.


Datadog Agent chạy trong Docker container cùng với các volume được mount.

Agent được thiết kế để tương thích với nhiều nền tảng điều phối container (container orchestration platforms). Ví dụ, nó có thể chạy như một sidecar trong Amazon ECS hoặc như một DaemonSet trong Amazon EKS, Azure AKS, và GKE.

Trong bài lab sắp tới, bạn sẽ deploy (triển khai) Datadog Agent bên trong một Docker container thuộc một ứng dụng thương mại điện tử nhỏ được thiết lập bởi Docker Compose. Dù lab tập trung vào Docker Compose, các nguyên tắc cơ bản vẫn có thể áp dụng cho mọi môi trường container. Dưới đây là những điểm chính cần lưu ý:

  • Agent được cấu hình thông qua các environment variables (biến môi trường) bên trong container của nó.
  • Các tag (thẻ) của service được định nghĩa bằng cách gán label cho các container tương ứng.
  • Agent sẽ thu thập log từ các service được ghi vào standard output (stdout) của container.

    Căn lề (indentation) sao cho ngang hàng với các service khác:

Bạn có thể bôi đen nhiều dòng và ấn Tab để tăng lề, Shift + Tab để giảm lề. IDE sẽ tự lưu thay đổi.

  1. Xem chi tiết service dd-agent mới thêm:
    • image: gcr.io/datadoghq/agent:7.56.0: Chỉ định Docker image của Agent. Bạn cũng có thể dùng tag :latest.
    • environment: Cấu hình Agent qua các biến môi trường trong container của nó.
      Giải thích các Biến Môi Trường (Environment Variables):
      • DD_API_KEY: Bắt buộc để Agent gửi dữ liệu thu thập lên Datadog. Docker Compose sẽ tự kéo giá trị biến này từ biến môi trường DD_API_KEY của host nếu không gán trực tiếp. (Dùng env | grep DD_API_KEY để kiểm tra trên host).
      • DD_HOSTNAME: Cố định tag host gắn vào dữ liệu đo lường gửi lên Datadog. Mặc định Agent sẽ tự nhận dạng hostname.
      • DD_ENV: Set tag env trên dữ liệu gửi lên. Hữu ích cho việc filter dữ liệu trong ứng dụng Datadog.
      • DD_LOGS_ENABLED=true: Kích hoạt tính năng thu thập log.
      • DD_LOGS_CONFIG_CONTAINER_COLLECT_ALL=true: Tự động thu thập log phát ra từ phần log tiêu chuẩn của tất cả container.
      • DD_PROCESS_AGENT_ENABLED=true: Kích hoạt theo dõi process (live process collection).
      • DD_CONTAINER_LABELS_AS_TAGS: Cấu hình để biến custom container label thành custom tag Datadog. Ví dụ: chạy nếu Agent đọc thấy label my.custom.label.team, nó sẽ gán giá trị của nó cho bộ tag team trên Datadog.
      • DD_APM_NON_LOCAL_TRAFFIC=true: Chấp nhận APM traces từ các container khác gởi tới.
      • DD_SYSTEM_PROBE_NETWORK_ENABLED=true: Kích hoạt tính năng giám sát hệ thống mạng qua Cloud Network Monitoring (CNM).
      • DD_SYSTEM_PROBE_SERVICE_MONITORING_ENABLED=true: Kích hoạt theo dõi service bằng hệ thống thăm dò mạng Universal Service Monitoring (USM).
      • HOST_ROOT=/host/root: Cấu hình đường dẫn mount trỏ vào thư mục root của host (tương ứng với cấu hình volume - /:/host/root:ro), là yêu cầu bắt buộc cho USM.
    • ports: Lắng nghe qua port 8126 cho các đoạn APM trace gửi từ Storedog, và port 8125 cho metric APM Runtime & metric của DogStatsD.
    • volumes: Mount các file/thư mục của host vào container. Cho phép Agent query thông tin từ Docker Daemon, cũng như thu thập dữ liệu về process/network từ chính host.
    • cap_add & security_opt: Cấp đặc quyền cao cho container của Agent để theo dõi ở cấp độ Kernel. Bắt buộc để chạy được USM và CNM.

Agent trong bài lab này được cấu hình chạy rất nhiều tính năng (chuông kêu, còi hú). Tài liệu hướng dẫn Docker Agent documentation mô tả một thiết lập gọn nhất cho phép tuỳ chọn theo hệ thống riêng.

Thêm Tags/Labels cho Service Containers

Theo mặc định, Agent dùng một thuật toán khá tối giản cắt cúp bằng tên container con để gán thẻ service. Bạn hoàn toàn có quyền ghi chèn đè giá trị custom khác thông qua việc cấu hình Docker Labels hoặc gán môi trường Environment variables cho container đó.

  • Biến môi trường: Thường dùng kèm với trình giám sát hiệu suất ứng dụng APM nhằm phục vụ bộ định nghĩa kết nối truy ra luồng chéo mang tên Unified Service Tagging (giúp Datadog rà ghim log đi theo trace APM kết nối metric cùng mảng 1 mạch hệ thống trơn tru).
  • Docker Labels: Đủ xài ngon lành với tụi service không cần APM hay đồ rác phần thứ ba bên ngoài (Redis, Database Postgres…). Nhét Labels cho phép ra lệnh cho phần cài đặt trên cấu hình Agent biết đường nhào nhặn metric và log theo dạng Tag của container cấp bên trong.

Cấu hình service “discounts”

Bản thân service discounts code bằng python kia đã được tích hợp bộ đo trace library do Datadog APM support. Cho nên là mình xài Biến môi trường điền form thiết lập tuỳ biến truyền chỉ cho tag service và version. Qua đó Unified Service Tagging sẽ thông suốt. (Tham số thứ tự Tag môi trường env ta không cần nhắc vì con Agent tổng nạp giá trị mặc định cho full toàn cõi rồi, trừ phi ý đồ muốn gán tag nhánh khác).

  1. Quẹo về IDE mở ngỏ file docker-compose.yml.
  2. Add mấy cấu trúc thông số cho discount config box dưới nhãn comment ghi sẵn # paste discounts env variables here:
  • DD_AGENT_HOST: Báo cho APM biết Agent đang nằm ở đâu theo host hostname truy tréo để bắn trace sang ngụ lưu.
  • DD_SERVICE & DD_VERSION: Ghi đè service mặc định tên rút gọn, set phiên bản tương đồng vs version docker image chạy.
  1. Kế tiếp cài Labels thiết lập log dưới dòng comment # paste discounts labels here:
  • my.custom.label.team: Biến thành custom team tag do Datadog Agent nhặt chéo.
  • com.datadoghq.ad.logs: Báo chỉ rõ cho mặt thằng Agent biết là cội source thuộc nguồn python. Làm zậy là format dữ liệu lên app bay nếp sạch bong khỏi trượt đi đâu.
  1. Terminal ấn command start cho tải tái kích hoạt service vừa thêm chữ:
  1. Theo tab Datadog Web panel vọt ngang phần Infrastructure > Containers ngồi rình xem em nó khởi chạy hiện lên box (AGO hiển thị số phút tính từ lúc chạy là One min ago).
  2. Soi box container lab-discounts-1 > Expand dòng ALL TAGS: Mọc ngon ghẻ chuẩn men chùm tags service, team, và version.
  3. Té lặn ngược dòng sang mục Logs.
  4. Filter cái Facet panel > Service: Check cho chọn store-discounts. (Vài mẩu log xách tên discounts rác cũ tí thời gian tự ẩn biến).
  5. Zoom Click vào cái khung thẻ log mới tải lên từ luồng chạy mới ghim Unified Tag chuẩn xác.
    Đập vô tầm mắt liền góc trên phải biểu tượng SOURCE với Logo rắn xanh mướt của Python. Datadog quá thông minh gom gộp trứ danh format đoạn log dạng INFO sạch sành sanh và cực kì quy củ!
    Cách ta vừa sài chèn cho Labels thiết đặt tham số cấu hình mang mác ad.logs chính là Integration cấu hình tích hợp Agent. Mình qua nốt Nginx demo.

Cấu hình tags cho Nginx

Khác hàng trên Nginx làm gì có xài rườm APM vết lần truy dấu, suy ra là dùng tuốt qua cấu hình Docker Labels chơi trò vạn năng ép dòng metrics, logs vô.

  1. Quất vô file docker-compose.yml nhét sau comment Nginx nhé:
  • tags.service & tags.version: Ép vào cho cả luồng Metrics lẫn Logs chung một thể tag đồng điệu.
  • ad.logs: Khớp khớp cho log source biết tỏng là dạng Nginx web format.
  1. Restart nổ súng chùm Nginx compose thôi: docker compose up -d --build nginx
  2. Check lại y hệt bên trên tại Containers và Logs rà soát sẽ thấy ngon lành chùm list tag và logo SOURCE xanh non hình mạng nhện cho cái box Nginx edge!

Autodiscovery (Tự động khám phá)

Khi bạn triển khai hệ thống môi trường một trạm host vật tư ảo chăng nữa, bạn sẽ hiểu gánh nặng của cái trò Monitor khi rải qua nền tảng Container. Nó động như kiến vỡ tổ: nay container spawn ở host A, xám mai di chuyển chạy Host C. Tóm lại thao tác canh me tay gắn thẻ quản config như cơm bụi là sai bét vô phương cứu độ!
Tuyệt nghệ của nền Datadog Agent nó tích góp cái skill mang danh Autodiscovery. Vốn Auto khởi chạy tính năng kèm chung với core Agent.
Khía cạnh cơ bản là bất kể khi nào có container được khởi kích, Agent tự check thăm do và check khớp quy luật config rồi âm thầm ngầm start cấu hình track chuẩn check gom hàng metric tự phát!

Troubleshooting Tips (Mẹo Xử Lý Sự Cố)

Sẽ có lúc cấu hình mớ bòng bong sập sùi cùi chỏ… Cho nên bạn cần đổi mốc thu thiết lập Log và có trò hay để xuất Flare nả lên team kĩ thuật Datadog Support gọi kêu cứu.

Datadog Agent logs

Thiết lập level ngưỡng ghi log cho Agent qua việc chèn trỏ biến DD_LOG_LEVEL. Mặc định ví dụ ta set biến DD_LOG_LEVEL='warn'. Đây là cái bảng cho thấy bạn hứng lượng thông tin Log to nhỏ theo ngưỡng nào là phù hợp nếu chọn option:

OptionCriticalErrorWarnInfoDebugTrace
'OFF'
'CRITICAL'X
'ERROR'XX
'WARN'XXX
'INFO'XXXX
'DEBUG'XXXXX
'TRACE'XXXXXX
  • Agent dùng 6.19+ hoặc 7.19+ có thể chỉnh tại dòng lệnh runtime cho nhẹ đầu (chẳng phiền restart phá bỉnh container) bằng command: agent config set log_level <value>. (Lưu ý: Không dùng lệnh chẻ ngang hông này với mảng Trace Agent do thiết trạm chạy tác rời tiến trình, lúc bấy lại xài cách restart up config môi trường).
  • Gán sang Level DEBUG cung cấp hằng la liệt cái mớ chi tiết li ti găm lỗi của hệ thống. Đây là một mỏ vàng ngầm để team Support rờ ra lỗi cho bạn. Do vậy rào thóp xong xuôi thì bạn nên tháo đi để nhốt lại rác kẻo nghẹt Index lưu trữ Log tiền tỷ.

Gửi “flare” tới Datadog Support

Cái tool có mặt giúp đời đóng bao hàng gom vứt trạm rác bao nhiêu xô log thiết kế từ Datadog Agent nhét chung file zip tên “Flare”. Đặc biệt tool Flare có tính toán tinh khôn lả lượt gạch sạch các lớp nhạy cảm như file code khóa pass, key API, Proxy access.
Mã Source của Datadog thuộc hàng thiết kế Mở nên bạn hoàn toàn dư khả năng chui vào GitHub lùng sục rà check coi bộ tool flare ém dìm cái gì ở bên trong. Tính an ninh nhè nhẹ cho một lần click xác thực đẩy dữ liệu từ phía bạn trên panel cli.
