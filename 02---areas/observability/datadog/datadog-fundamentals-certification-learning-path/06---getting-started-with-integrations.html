Phần 1: Integration là gì?

1.1. Tổng quan

Integration là các gói phần mềm bổ sung cho phép Datadog giám sát từng công nghệ riêng lẻ, chẳng hạn như ứng dụng của bên thứ ba và các dịch vụ cloud. Nhờ có integration, Datadog có thể hợp nhất metric và log được tạo ra bởi nhiều công nghệ khác nhau được triển khai trên toàn bộ infrastructure của bạn. Tại thời điểm viết tài liệu này, đã có hơn 800 integration sẵn sàng sử dụng, và con số này vẫn tiếp tục tăng đều đặn.

1.2. Các loại integration

Có ba loại integration chính: agent-based integration, authentication-based integration, và library integration. Mặc dù hầu hết các integration đều được xây dựng sẵn và chỉ cần cài đặt, bạn cũng có thể tự tạo custom integration cho riêng mình. Tất cả các integration, kèm theo hướng dẫn cài đặt, đều có thể dễ dàng truy cập trên trang Integrations trong Datadog.

LoạiMô tảVí dụ
Agent-basedChạy trên host qua Agent, dùng Python check methoddisk, cpu, Docker, Redis
Authentication-basedKết nối qua API credentials (crawler)AWS, Azure, Slack, PagerDuty
LibraryThư viện trace nhúng vào code ứng dụngdd-trace-py, dd-trace-rb

Phần 2: Agent-based Integration

2.1. Tổng quan

Datadog Agent là một phần mềm quan trọng chạy trên các host của bạn. Nó thu thập các event và metric ở cấp process rồi gửi chúng về Datadog. Các agent-based integration chạy cùng Datadog Agent trên host hoặc trong container, và sử dụng một Python class method có tên check để xác định các metric cần thu thập. Các agent-based integration mặc định của Datadog cung cấp khả năng giám sát các thành phần chính trong infrastructure của tổ chức bằng cách thu thập dữ liệu hiệu suất cho disk, CPU, memory, network throughput, và nhiều thành phần khác.

2.2. Core integration

Datadog Agent đi kèm với một số integration được tích hợp sẵn theo mặc định. Các integration này được Datadog duy trì và cập nhật thường xuyên. Chúng được thiết kế để cung cấp cho bạn những metric quan trọng nhất cho các dịch vụ mà chúng giám sát. Với rất nhiều integration có sẵn, bạn có thể giám sát toàn bộ infrastructure một cách dễ dàng. Một số integration phổ biến bao gồm Docker, Kafka, MySQL, Nginx, và Redis. Danh sách đầy đủ các core integration đi kèm Datadog Agent có thể được tìm thấy tại GitHub repository integrations-core: https://github.com/DataDog/integrations-core

2.3. Community integration

Bạn cũng có thể tự tạo integration của riêng mình. Để bắt đầu tìm hiểu cách tạo integration, hãy xem trang Build an Integration (https://docs.datadoghq.com/developers/integrations/). Bạn có thể chọn gửi custom integration của mình lên Datadog, nơi nó có thể được chia sẻ với những người dùng khác. Các community integration này được cộng đồng duy trì và không được Datadog hỗ trợ chính thức. Chúng được lưu trữ trên GitHub repository integrations-extras: https://github.com/DataDog/integrations-extras

Lưu ý: Community integration không được cài mặc định cùng Agent. Bạn phải cài riêng.

Phần 3: Authentication-based Integration

3.1. Tổng quan

Authentication (crawler-based) integration được cấu hình trong Datadog và yêu cầu bạn cung cấp credentials (thông tin xác thực) để lấy metric và dữ liệu thông qua API. Nhóm này bao gồm các integration phổ biến cho Slack, AWS, Azure, và PagerDuty. Các integration này được gọi là “crawler integration” vì chúng sử dụng credentials mà bạn cung cấp để crawl (quét) qua infrastructure của bạn và thu thập dữ liệu.

Integration AWS là một ví dụ điển hình cho crawler-based integration. Khi bạn cấu hình integration AWS, bạn sẽ tạo một IAM role và policy tương ứng để cho phép tài khoản AWS của Datadog thực hiện các lệnh gọi API vào tài khoản AWS của bạn. Datadog sử dụng các credentials này để truy cập tài khoản AWS của bạn và thu thập metric cùng log từ các dịch vụ AWS.

Sau khi kết nối ban đầu được thiết lập, bạn có thể bật từng integration dịch vụ AWS riêng lẻ phù hợp với môi trường AWS của mình. Chỉ với một cú nhấp chuột, CloudFormation sẽ được sử dụng để cung cấp các tài nguyên cần thiết trong tài khoản AWS của bạn và bắt đầu truy vấn metric cùng event cho các dịch vụ bạn đang sử dụng.

3.2. Kiểm soát dữ liệu thu thập từ cloud provider

Khi bạn cấu hình authentication-based integration cho một cloud provider, bạn có thể kiểm soát dữ liệu mà Datadog thu thập. Ví dụ, bạn có thể bật hoặc tắt các dịch vụ AWS hoặc Azure cụ thể mà bạn muốn giám sát.

Amazon Web Services (AWS)

Sau khi cấu hình integration AWS, bạn có thể bật hoặc tắt các dịch vụ AWS cụ thể mà bạn muốn giám sát. Ví dụ, bạn có thể bật integration EC2 để thu thập metric và log từ các EC2 instance, hoặc bật integration RDS để thu thập metric và log từ các RDS instance.

Việc thêm tag dạng key:value sẽ tạo một allowlist (danh sách cho phép) chỉ thu thập dữ liệu từ các service có tag khớp. Ký tự đại diện (wildcard) như ? (cho một ký tự đơn) và * (cho nhiều ký tự) cũng có thể được sử dụng. Các resource có tag nhất định cũng có thể được loại trừ bằng cách thêm ! trước tag. Loại trừ (exclusion) được ưu tiên hơn bao gồm (inclusion).

Ví dụ: giới hạn EC2 với datadog:monitored, loại trừ RDS staging với !env:staging.

Microsoft Azure

Tương tự với Azure. Tab Metric Collection cho phép bạn bật/tắt các Azure resource provider. Việc thu thập metric có thể được giới hạn cho Hosts, App Service Plans, và Container Apps bằng cách sử dụng tag dạng key:value.

Ví dụ bộ lọc: datadog:monitored,env:production,!plan_tier:basic,instance-type:c1.*


Google Cloud

Tab Metric Collection cho phép bật các dịch vụ Google Cloud cụ thể. Bộ lọc được áp dụng cho GCE, GKE host, và Cloud Run revision. Sử dụng cùng định dạng key:value.

Ví dụ: datadog:monitored, loại trừ staging với !env:staging.


Phần 4: Library Integration

Library integration, thường được gọi là trace library, cho phép bạn giám sát ứng dụng dựa trên ngôn ngữ lập trình mà ứng dụng được viết, chẳng hạn như Node.js hoặc Python. Các thư viện này được cài đặt vào code ứng dụng của bạn và gửi dữ liệu đến Datadog Agent. Sau đó, Agent gửi metric, trace, và log của ứng dụng về Datadog cùng với các tag liên quan.

Dữ liệu được thu thập bởi trace library được gọi là dữ liệu Application Performance Monitoring (APM). Bạn có thể điều hướng đến mục APM trong thanh navigation chính của Datadog để xem các ứng dụng của mình.

Phần 5: Môi trường Lab

Trong lab này, bạn sẽ chạy một ứng dụng ecommerce demo có tên Storedog. Ứng dụng này được xây dựng từ nhiều microservice chạy trong Docker. Lưu lượng truy cập đến Storedog được tạo tự động. Datadog Agent đã được cài đặt sẵn cho bạn trong tất cả các lab.

Trong hoạt động thực hành sau đây, bạn sẽ quan sát:

  • Một agent-based integration đã được cài đặt và đang chạy
  • Các integration đã cài đặt và các OOTB dashboard có sẵn trong Datadog
  • Một vài integration của bên thứ ba và dữ liệu mà chúng thu thập

Phần 6: Lab — Agent Integration (System Checks)

6.1. Giới thiệu

Các agent-based integration được cài đặt cùng với Datadog Agent. Mỗi integration cung cấp một Python method có tên check mà Agent thực thi mỗi 15 giây. Do đó, các agent integration cũng thường được gọi là “check.”

Trong hoạt động này, bạn sẽ chạy các lệnh Agent để quan sát những check mà Agent đang chạy, tập trung vào disk system check. Bạn cũng sẽ học cách xem chính xác các metric mà một check thu thập và cách tìm tài liệu cho chúng.

6.2. Khám phá Storedog

Có khoảng 10 Docker container đang chạy để cung cấp backend, frontend, và các dịch vụ liên quan. Một trong những container đó chính là Datadog Agent.

Lưu ý: Nếu bạn thấy lỗi 502 Bad Gateway khi mở Storedog, hãy đợi vài giây rồi refresh lại trang. Các container có thể cần thêm thời gian để khởi động hoàn toàn.

6.3. Kiểm tra trạng thái check

Một số system check nằm trong số các integration đi kèm Agent. Chúng cung cấp metric từ hệ thống cơ bản của bạn về CPU, IO, load, memory, swap, và uptime.

Bước 1: Chạy lệnh agent status

Lệnh này hiển thị trạng thái tổng quan của Datadog Agent, bao gồm thông tin về các check đang chạy, phiên bản Agent, kết nối đến Datadog, và nhiều thông tin khác.

Giải thích các trường quan trọng trong output:

  • Instance ID: Định danh duy nhất của instance check. Trạng thái [OK] cho biết check đang chạy bình thường.
  • Total Runs: Số lần check đã được thực thi kể từ khi Agent khởi động.
  • Metric Samples: Số lượng metric sample được thu thập — Last Run là lần chạy gần nhất, Total là tổng cộng từ khi Agent khởi động.

Lưu ý rằng Agent không lưu trữ thông tin giữa các lần khởi động lại — tất cả các số liệu như Total Runs và Total metric samples sẽ được reset về 0 khi Agent restart.

Phần 7: Lab — Integration trong Datadog

7.1. Giới thiệu

Đối với Agent, một integration đơn giản chỉ là một hàm check Python khác dùng để thu thập metric, event, log và service check. Trong Datadog, integration còn có thể cung cấp dashboard có sẵn (OOTB), các quy tắc xử lý log đặc biệt gọi là pipeline, cùng nhiều tài nguyên khác.

Agent đi kèm với hàng trăm integration ngoài các system check và có thể được cấu hình để tự động phát hiện (autodetect) và cài đặt nhiều integration trong số đó.

Trong bài lab này, bạn sẽ khám phá một số integration, bao gồm Docker, Nginx, Redis và PostgreSQL.

7.2. Mở trang Integrations

Bước 1: Đăng nhập Datadog

Đăng nhập vào Datadog bằng thông tin tài khoản training. Chạy lệnh show-dd-credentials trong terminal để lấy thông tin đăng nhập.

Bước 2: Xem integration trên trang chủ

Ở giữa trang chủ Datadog, bạn sẽ thấy một danh sách các integration đã được autodetect và cài đặt.

Bước 3: Mở trang Integrations

Điều hướng đến trang Integrations bằng cách click vào Integrations (biểu tượng mảnh ghép) ở cuối thanh điều hướng chính (global navigation).

Các integration được hiển thị dưới dạng tile và phân thành ba nhóm:

  • Autodetected — đã được Agent phát hiện nhưng chưa cấu hình
  • Installed — đã được Agent phát hiện và không cần cấu hình thêm
  • Available — tất cả integration còn lại, bao gồm non-Agent integration

Lưu ý: Bạn có thể cần đợi vài phút để integration được autodetect trước khi phần này xuất hiện.

Bước 4: Xem phần Installed

Nhìn chung, nếu Agent đang chạy check của một integration thành công và integration đó đi kèm dashboard OOTB, log hoặc pipeline, bạn sẽ thấy integration được liệt kê ở đây.

Lưu ý: System check như disk, cpu, io không hiển thị ở đây vì chúng không có dashboard riêng. Tuy nhiên, metric của chúng được tích hợp vào các dashboard khác.

7.3. Tìm hướng dẫn cấu hình

Bước 1: Mở Docker integration

Trên trang Integrations, click vào tile Docker. Mỗi panel integration đều có ít nhất hai tab: Overview và Configuration.

Bước 2: Xem tab Configuration

Click vào tab Configuration. Tab này chứa hướng dẫn cấu hình Docker Integration trên virtual host, đồng thời cung cấp liên kết đến tài liệu containerized Docker Agent.

Lưu ý: Mỗi tab Configuration đều có nút Uninstall Integration ở cuối trang. Nút này chỉ gỡ integration khỏi Datadog (xóa dashboard OOTB, v.v.), không gỡ khỏi Agent. Để gỡ hoàn toàn Agent integration, chạy lệnh agent integration remove.

Bước 3: Xem tab Data Collected

Click vào tab Data Collected. Tại đây bạn sẽ thấy tất cả metric mà integration này thu thập.

Bước 4: Xem PostgreSQL integration

Đóng panel Docker, click vào tile PostgreSQL. Cuộn qua tab Configure để tìm phần hướng dẫn cho Docker.

Bước 5: (Tùy chọn) Xem docker-compose.yml

Click vào tab IDE và mở file docker-compose.yml. Xem các biến môi trường (environment variable) và label được thêm vào các service như nginx, db (PostgreSQL) và redis. So sánh chúng với hướng dẫn cấu hình.

Bước 6: Xem tab Monitoring Resources

Trong panel PostgreSQL, click vào tab Monitoring Resources. Tab này liệt kê các tài nguyên khác được tạo tự động khi integration được cài đặt.

PostgreSQL cung cấp 2 dashboard và 2 recommended monitor.

7.4. Khám phá Dashboard OOTB

Bước 1: Mở Postgres - Overview dashboard

Trong tab Monitoring Resources của panel PostgreSQL, dưới mục Dashboards, click vào Postgres - Overview.

Giống như tất cả dashboard OOTB, dashboard này giúp bạn bắt đầu giám sát ngay lập tức và cung cấp các ví dụ về những kiểu trực quan hóa (visualization) có sẵn.

Bước 2: Xem danh sách Dashboard

Điều hướng đến Dashboards > Dashboards List trong thanh điều hướng chính. Bạn sẽ thấy nhiều dashboard OOTB.

7.5. Tổng kết activity

Kết luận: Bạn đã học cách xem các Agent integration trong Datadog, tìm hướng dẫn cấu hình, xác định metric, dashboard và các tài nguyên khác mà chúng cung cấp, cũng như duyệt qua các dashboard OOTB.

7.6. Quiz: Integration trong Datadog

Câu hỏi: Nhìn vào trang Integrations trong Datadog. Integration nào sau đây chưa được cài đặt?

  • Nginx
  • Redis
  • Tomcat ✅
  • Docker

Giải thích: Tomcat không nằm trong danh sách Installed vì lab không chạy Tomcat. Nginx, Redis và Docker đều đang chạy trong Storedog.

Phần 8: Lab — Authentication & Library Integration

8.1. Giới thiệu

Các integration dựa trên xác thực (authentication-based integration) của Datadog kết nối đến nền tảng bên thứ ba để thu thập metric, log và event. Chúng hoạt động theo hai cách: hoặc kéo (pull) dữ liệu từ các nền tảng đó, hoặc ủy quyền cho các nền tảng đó đẩy (push) dữ liệu vào Datadog.

Library integration (trace library) là các gói phần mềm được import vào mã nguồn ứng dụng. Chúng sử dụng tracing API của Datadog để thu thập metric về hiệu năng, profiling và debugging trong thời gian chạy (runtime).

8.2. Datadog kéo dữ liệu từ bên thứ ba (Pull)

CircleCI integration là ví dụ về integration kéo dữ liệu từ third-party API.

Bước 1: Quay lại trang Integrations

Bước 2: Tìm kiếm circleci

Bước 3: Mở tile Integration (không phải Software License)

Bước 4: Xem tab Configure

Theo hướng dẫn, nếu bạn muốn kết nối với CircleCI, bạn cần đăng nhập vào tài khoản CircleCI và tạo một API token cho Datadog.

Lưu ý: Bạn không cần thực hiện bước này — đây chỉ là minh họa.

Bước 5: Click Add Account

Đây là nơi bạn sẽ dán API key đó.

Lưu ý: Bạn không cần thực hiện bước này — đây chỉ là minh họa.

8.4. Kiểm soát dữ liệu thu thập từ AWS

Một tài khoản AWS với 2 EC2 instance đã được tạo sẵn và AWS integration đã được cấu hình trong tài khoản training.

Bước 1: Mở Infrastructure > Hosts

Điều hướng đến Infrastructure > Hosts. Bạn sẽ thấy hai host với tên dạng i-0a1b2c3d4e5f6g7h8.

Bước 2: Xem chi tiết host

Click vào từng host. Tab Host Info hiển thị các tag được thu thập từ AWS. Một host có tag cho biết nó đang được giám sát (monitored).

Phần system detail ở trên cùng trống vì chưa có Datadog Agent được cài đặt trên host. Kiểm tra tab Metrics để xem các metric hiệu năng được thu thập bởi AWS integration.

Bước 3: Mở Amazon Web Services tile

Điều hướng đến Integrations và click vào tile Amazon Web Services.

Bước 4: Xem tab Metric Collection

Bạn sẽ thấy danh sách các AWS service. Bật hoặc tắt việc thu thập bằng các toggle switch.

Bước 5: Xem phần Limit Metric Collection

Cuộn xuống dưới cùng để tìm phần Limit Metric Collection to Specific Resources.

Lưu ý: Không phải tất cả AWS service đều hỗ trợ filter.

Bước 6: Xem hướng dẫn format tag

Bước 7: Chọn EC2 trong dropdown AWS SERVICE

Bước 8: Nhập tag datadog:monitored

Thao tác này sẽ chỉ bao gồm (include) các EC2 instance có tag này.

Bước 9: Click Save

Bước 10: Mở Dashboard list

Bước 11: Mở AWS EC2 Overview dashboard

Dashboard này trực quan hóa các metric tài nguyên tổng quan từ các EC2 instance của bạn.

Bước 12: Xem phần AutoScaling

Di chuột qua đường biểu đồ (line) để xem số instance đang hoạt động. Bây giờ chỉ còn một EC2 instance hoạt động sau khi áp dụng filter.

IMPORTANT

AWS integration kéo dữ liệu từ CloudWatch theo chu kỳ 10 phút. Thay đổi cấu hình cần thời gian để xuất hiện trong Datadog.

8.5. Library Integration

Loại integration thứ ba là trace library — các gói mã nguồn mở được import vào code ứng dụng. Storedog sử dụng các service viết bằng Ruby và Python, tất cả đã được instrument sẵn.

Bước 1: Mở APM > Instrument a Service

Datadog cung cấp một wizard giúp bạn cài đặt library.

Điều hướng đến APM > Instrument a Service.

Bước 2: Chọn Container-Based

Bước 3: Chọn Docker

Bước 4: Chọn Same host

Bước 5: Chọn Python

Trang sẽ hiển thị hướng dẫn instrument ứng dụng Python, bao gồm wizard để cấu hình container.

Lưu ý rằng bước thứ hai là Run the Agent. Agent phải đang chạy để nhận trace data.

Lưu ý: Bạn không cần thực hiện — mọi thứ đã được cấu hình sẵn.

Bước 6: Thử các ngôn ngữ khác

Click vào các ngôn ngữ khác như Java hoặc Ruby để xem hướng dẫn thay đổi như thế nào.

Bước 7: (Tùy chọn) Xem traces

Điều hướng đến APM > Traces > Explorer. Xóa nội dung query. Chọn một service đơn lẻ. Click vào một số trace.

Đây là các biểu đồ về đơn vị công việc (unit of work) gần như theo thời gian thực. Chúng giúp xác định code nào đã thực thi, mất bao lâu, và code nào khác có liên quan.

8.6. Tổng kết lab

Kết luận: Bạn đã làm quen với ba loại integration của Datadog:

  • Agent integration (check) — thu thập metric, log, event từ các tiến trình hệ thống
  • Authentication integration — kéo hoặc nhận dữ liệu từ API bên thứ ba
  • Trace library — được import vào mã nguồn ứng dụng để gửi trace và profiling data qua Agent

8.7. Quiz: Integration

Câu hỏi: Loại integration nào dựa vào Agent để gửi application trace về Datadog?

  • Agent (checks)
  • Authentication
  • Library ✅

Giải thích: Library integration (trace library) được nhúng vào code ứng dụng và gửi trace data qua Agent về Datadog cho APM.
