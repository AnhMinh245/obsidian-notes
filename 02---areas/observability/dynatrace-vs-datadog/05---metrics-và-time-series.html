Histogram vs Distribution — Trap cho exam

Histogram: percentiles tính per host rồi aggregate → KHÔNG chính xác globally (avg of p95s ≠ real p95)
Distribution: raw data gửi lên server, tính percentile globally → chính xác

Câu hỏi “globally accurate percentiles” → Distribution (không phải Histogram)

Histogram — Chi tiết

  • Agent-side / client-side aggregation
  • DogStatsD nhận raw data → tính locally → gửi pre-aggregated buckets (count, min, max, sum)
  • Percentiles (avg, p50, p95, max) tính per-host only
  • ⚠️ INACCURATE khi aggregate across multiple hosts — avg of p95s ≠ real p95
  • Không thể recalculate percentiles after collection
  • Tạo ra 5 metrics per histogram metric: .avg, .count, .median, .95percentile, .max

Distribution — Chi tiết

  • Server-side aggregation dùng DDSketch algorithm (Datadog proprietary, relative-error guarantees)
  • Agent gửi raw/compressed data → DD backend aggregates
  • Globally accurate percentiles (p50, p75, p90, p95, p99) across BẤT KỲ tag combination và timeframe
  • Enables heatmaps trong dashboard
  • Recommended cho latency metrics cần accuracy across cluster

3. Metric Query — So sánh cú pháp

Dynatrace DQL

// Lấy CPU usage trung bình theo host
timeseries avg(dt.host.cpu.usage), by:{dt.entity.host}
| filter avg > 80

// Lấy request count theo service
timeseries count = sum(dt.service.request.count),
  by:{dt.entity.service}
| fieldsAdd rate = count / 60
  • Một ngôn ngữ cho metrics, logs, traces, entities
  • Pipe-based (|) — kết nối các operations
  • fetch, timeseries, filter, fieldsAdd, summarize

Datadog Metric Query

# Cú pháp: aggregation:metric{scope} by {group}.rollup(method, interval)
avg:system.cpu.user{env:prod} by {host}.rollup(max, 300)

5 thành phần:

  1. Metric name: system.cpu.user
  2. Scope/Filter: {env:prod, service:web} (tags trong {})
  3. Time Aggregation: .rollup(max, 300) — rollup mỗi 300s, lấy max
  4. Space Aggregation: avg: prefix + by {host} grouping
  5. Function: .timeshift(), .forecast(), .rank() (optional)

So sánh cú pháp

ConceptDynatrace DQLDatadog Metric Query
Filter by tagfilter environment == "prod"{env:prod}
Group byby:{dt.entity.host}by {host}
Aggregationavg(), sum(), count()avg:, sum:, max: prefix
Time rollupGrail tự xử lý.rollup(avg, 60)
MathfieldsAdd rate = count / 60Formula queries: a / b
Multi-metricMột query, pipe operationsCombine queries (a, b, c) + formula

4. Cardinality — Vấn đề chung

Khía cạnhDynatraceDatadog
Cách tínhEntities × metrics × dimensionsUnique tag combinations × metric names
Nguy hiểmÍt lo vì Grail scale tốtRẤT LO — mỗi tag combination = 1 time series = tiền
Anti-patternVẫn nên tránh cardinality caoNEVER dùng user_id, request_id, timestamp làm tag
MonitoringDQL query count entitiesMetrics Summary page → cardinality tracking
SolutionOpenPipeline filteringMetrics without Limits™ (tag management server-side)

Ví dụ cardinality bomb (Datadog)

metric: order.processing_time
tags: env(3) × service(10) × region(5) × user_id(100,000)
= 3 × 10 × 5 × 100,000 = 15,000,000 time series 💥

Bỏ user_id ra khỏi tags: 3 × 10 × 5 = 150 time series ✅

Best practice cho cả 2

  • Dùng tag cho dimensions có ít unique values (env, region, service)
  • KHÔNG dùng tag cho high-cardinality data (user_id, order_id, IP)
  • High-cardinality data → ghi vào logs hoặc spans (searchable, không tạo time series)

Metric Retention — Datadog

Datadog giữ metrics ở 15-second granularity trong toàn bộ 15 tháng — KHÔNG có downsampling.
Tương tự behavior của Dynatrace Grail! Khác với nhiều tool khác rollup sau 1-7 ngày.

5. Metric Categories — Datadog-specific

Datadog phân loại metrics theo mục đích:

CategoryMục đíchVí dụ
Work MetricsOutput của system → detect PROBLEMSthroughput, error rate, latency
Resource MetricsSystem resources → diagnose ROOT CAUSECPU%, mem%, disk I/O
EventsDiscrete occurrences → find TRIGGERdeployment, alert, scaling

Dynatrace không phân loại formal như vậy — tất cả metrics đều nằm trong Grail, phân biệt qua metric key prefix (dt.host.*, dt.service.*, dt.process.*).

Metric Events (alerting)→Metric Monitor (Threshold)

❌→Histogram type (per-host percentiles)
❌→Distribution type (global percentiles)
❌→DogStatsD sample rate (@0.1)
