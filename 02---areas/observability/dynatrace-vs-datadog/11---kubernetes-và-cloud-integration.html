Dynatrace K8s Architecture

    DS -->|"collect host/container data"| APP
  • DynakubeSpec CRD = single config cho entire deployment
  • DynaKube API: v1beta1/v1beta2 REMOVED trong Operator 1.7+. v1beta3 removed trong 1.9.0. Hiện tại: v1beta5/v1beta6. Auto-conversion khi upgrade
    • Check command: kubectl get crd dynakubes.dynatrace.com -o jsonpath='{.status.storedVersions}'
  • Namespace phải label: monitoring=enabled (hoặc tương tự) để injection hoạt động
  • 3 deployment modes:
    • classicFullStack — traditional DaemonSet
    • cloudNativeFullStack — recommended (webhook + CSI, non-privileged)
    • applicationMonitoring — app-only, no infra

Datadog K8s Architecture

graph TB
    subgraph "Datadog"
        DS["DaemonSet<br/>(Node Agent per node)"]
        CA["Cluster Agent<br/>(Deployment, 1 instance)"]
    end
    
    subgraph "Node"
        DS -->|"collect"| P1["Pod 1"]
        DS -->|"collect"| P2["Pod 2"]
        DS -->|"autodiscovery"| P3["Pod 3"]
    end
    
    CA -->|"K8s API queries<br/>(cluster events/state)"| API["K8s API Server"]
    DS -->|"proxy queries via"| CA
  • Node Agent (DaemonSet): per-node, collect pod/container/node metrics, autodiscovery
  • Cluster Agent (Deployment): 1 instance, proxy K8s API queries → giảm API Server load, cache pods/nodes/services metadata, collect cluster-level events
  • Admission Controller (optional): inject ddtrace library vào pods
  • Datadog Operator (2026 recommended): CRD-based (DatadogAgent), continuous reconciliation, built-in validation. Helm = legacy hoặc simple setups. Thường dùng Helm để INSTALL Operator

DaemonSet không phải Sidecar

Cả 2 đều dùng DaemonSet (1 agent per NODE). Không dùng Sidecar pattern (1 agent per POD) — tránh overhead ×50 nếu có 50 pods.

Autodiscovery — So sánh

AspectDynatraceDatadog
MethodOneAgent auto-scan processesTemplate-based (annotations/labels)
ConfigZero — auto-detect everythingK8s annotations trên pods
Template❌ Không cầnad.datadoghq.com/<container>.checks
Placeholders❌%%host%%, %%port%%

Dynatrace: OneAgent tự phát hiện Redis process, auto-instrument — không cần annotation.

Unified Service Tagging (Datadog)

  • K8s labels chuẩn: tags.datadoghq.com/env, tags.datadoghq.com/service, tags.datadoghq.com/version
  • Dùng Downward API để inject thành DD_ENV, DD_SERVICE, DD_VERSION env vars
  • Agent ≥6.19/7.19 required
  • Cho phép correlate metrics, traces, logs theo cùng service/env/version
  • Annotation prefix cho Autodiscovery: ad.datadoghq.com/*

4. K8s Anomaly Detection

Dynatrace (cần 2 bước)

  1. Connect Dynatrace to K8s Cluster API
  2. Enable K8s anomaly detection trong Settings

Anomaly types: CPU/Memory request saturation, pod restart anomalies, node availability, cluster events (OOMKill, CrashLoop, FailedScheduling)

Davis AI tự correlate K8s events với application problems.

Datadog

  • Monitors trên K8s metrics (kubernetes.pods.running, kubernetes.cpu.usage)
  • Watchdog auto-detect K8s anomalies
  • Container Map + alerts
  • Cần user tạo monitors cho từng condition

AWS Integration Comparison

StepDynatraceDatadog
1Create IAM RoleCreate IAM Role (read permissions)
2Deploy ActiveGate in VPC❌ Không cần — Datadog assumes role
3Config in Dynatrace SettingsConfig in Datadog Integrations UI
4Select services to monitorSelect services (or auto-discover all)
5Verify in Clouds AppVerify in Infrastructure List

Khác biệt quan trọng

Dynatrace cần ActiveGate trong VPC để pull cloud metrics.
Datadog không cần infrastructure — backend trực tiếp assume IAM role và pull CloudWatch.
