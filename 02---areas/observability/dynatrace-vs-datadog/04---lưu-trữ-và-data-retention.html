Lưu trữ và Data Retention

1. Mô hình lưu trữ — Khác biệt nền tảng

Khía cạnhDynatraceDatadog
Storage modelGrail — Unified Data Lakehouse (1 nơi cho tất cả)Separated stores — DB riêng cho metrics, logs, traces
ArchitectureSchema-on-read, MPP, tách storage & computeTime Series DB (metrics) + Log Index (logs) + Trace Store

2. Dynatrace Grail — Chi tiết

Grail Buckets

graph TD
    OP["OpenPipeline"] --> B1["default_logs<br/>(35 ngày)"]
    OP --> B2["default_spans<br/>(10 ngày)"]
    OP --> B3["default_metrics<br/>(15 tháng)"]
    OP --> B4["default_bizevents<br/>(35 ngày)"]
    OP --> B5["custom_bucket<br/>(1 ngày → 10 năm)"]
  • Mỗi bucket có retention, permissions, query scope riêng
  • Tạo custom bucket cho use cases đặc biệt (compliance = 10 năm, debug = 1 ngày)
  • Schema-on-read: không cần define schema trước — ingest data dạng gì cũng được, query khi cần

Grail Technical Properties

MPPMassively Parallel Processing — hàng trăm server query đồng thời
Storage & compute separationScale storage và compute độc lập
Exabyte-scaleKhông giới hạn capacity thực tế

3. Datadog Storage Model

Metrics — Time Series DB

graph LR
    Agent --> Backend["Datadog Backend"]
    Backend --> TSDB["Time Series DB<br/>(proprietary)"]
    TSDB --> Q["Metric Queries<br/>(avg, sum, max...)"]
  • Mỗi unique tag combination = 1 time series
  • Rollup tự động khi zoom out (aggregation theo time buckets)
  • Custom metrics tính phí per time series

Logs — Index + Archive

graph LR
    Agent --> Pipeline["Log Pipeline"]
    Pipeline --> IDX["Log Index<br/>(searchable, tốn phí)"]
    Pipeline --> ARC["Archive<br/>(S3/GCS, rẻ)"]
    ARC -.->|"Rehydrate"| IDX
  • Index: searchable, filter, facets — tốn phí theo volume
  • Archive: S3/GCS/Azure Blob — rẻ, rehydrate khi cần investigate
  • Exclusion Filters: loại log khỏi index nhưng vẫn generate metrics

Traces — Trace Store

  • Traces lưu riêng trong Trace Store
  • Ingestion: ingest tất cả → Retention Filters giữ lại % cần thiết
  • Default: giữ Error traces + Diverse traces (sampling)

Grail vs Classic

Grail metrics giữ 1-minute granularity suốt 15 tháng — KHÔNG downsampling.
Classic metrics downsampling sau 14 ngày. Đây là upgrade lớn khi chuyển sang Grail.

Datadog Retention

Data TypeDefault RetentionTuỳ chỉnh
Metrics15 tháng (15-second granularity, KHÔNG downsampling!)Không tuỳ chỉnh
Logs (indexed)15 ngày (tuỳ plan)3, 7, 15, 30, 45, 60 ngày per index
Logs (archived)Unlimited (S3/GCS)Tuỳ storage policy
Traces15 ngàyRetention Filters
RUM30 ngàyTuỳ plan

Flex Logs — Warm Storage Tier

  • Warm storage tier — rẻ hơn standard indexed logs
  • Retention: lên đến 15 tháng
  • Hạn chế: không dùng được với Monitors/Alerting — chỉ cho investigation/search
  • Use case: giữ logs lâu hơn để compliance/investigation mà không tốn chi phí index

Flex Frozen (extension):

  • Cold storage, retention lên đến 7 năm
  • Dành cho compliance requirements (PCI-DSS, SOX, HIPAA…)
  • Query chậm hơn Flex Logs (cần warm-up time)

Log Archives — Long-term Storage

  • Archive logs sang S3 / GCS / Azure Blob Storage — unlimited retention
  • Rehydration: kéo archived logs về Datadog để search lại
    • Cost: $0.10 / compressed GB scanned
    • Rehydrate vào Log Explorer trong vài phút đến vài giờ tuỳ volume
  • Archive flow: Logs → Pipeline → Archive (S3/GCS) → Rehydrate khi cần

Exam tip — Storage tiers

Datadog có 3 tiers cho logs:

  1. Standard Index: searchable, monitors, alerts — đắt nhất
  2. Flex Logs: searchable, NO monitors — warm, rẻ hơn, lên đến 15 tháng
  3. Archive: S3/GCS, rehydrate khi cần — rẻ nhất, unlimited

5. Metric Granularity — Khác biệt quan trọng

Khía cạnhDynatrace GrailDatadog
Raw resolution1 phút cho 15 tháng15 giây cho 15 tháng (no downsampling!)
Downsampling❌ KHÔNG (Grail)❌ KHÔNG downsampling storage (rollup chỉ tại query time khi zoom out)
Query-time aggregationMọi aggregation tính tại query timeSpace + Time aggregation (rollup function)

Dynatrace Grail giữ raw data 1-minute → query bất kỳ lúc nào cũng có cùng granularity.
Datadog giữ raw data 15-second suốt 15 tháng. Rollup chỉ xảy ra tại query time khi zoom ra timeframe lớn — data gốc KHÔNG bị mất.

6. Cost Optimization Strategies

Dynatrace

  • Custom Grail buckets với retention ngắn cho debug data
  • OpenPipeline filtering — drop logs/events không cần
  • Host monitoring modes — dùng Discovery thay Full-Stack cho non-critical hosts
  • DPS (Davis Data Units) — pricing model mới

Datadog

  • Logging Without Limits™ — ingest all, index selectively
  • Exclusion Filters — exclude từ index (vẫn generate metrics)
  • Archive + Rehydration — store rẻ, query khi cần
  • Metrics without Limits™ — tag management (chỉ giữ tags cần)
  • Ingestion Controls (APM) — sampling để giảm trace volume

Ghi nhớ cho exam

Câu hỏi “cost optimization for logs” → Datadog answer: Logging Without Limits™ (ingest all, index selectively, archive)
