Điểm mạnh

OpenPipeline là 1 nơi duy nhất để xử lý tất cả data. Không cần config pipeline riêng cho logs, metrics, traces.

OpenPipeline Updates 2025-2026

  • Unified cho logs, metrics, spans, security events, business events
  • Pipeline visibility/observability metrics (theo dõi pipeline performance)
  • DQL-based processing
  • 6-10x faster ingestion so với pipeline cũ

3.2. Logging Without Limits™

Khái niệm QUAN TRỌNG cho exam Datadog

Ingest 100% logs (mọi log đều đi qua pipeline) → Index chỉ % cần thiết (tốn tiền) → Archive tất cả ra S3/GCS (rẻ, rehydrate khi cần)

Ingest ALL (cheap) → Index SOME (expensive, searchable) → Archive ALL (cheap, rehydrate on-demand)
  • Exclusion Filters: loại log khỏi index (vẫn qua pipeline, vẫn generate metrics)
  • Rehydration: lấy logs từ archive về lại Log Explorer khi cần investigate
  • Kết quả: không bao giờ mất data, chỉ trả tiền cho logs cần search thường xuyên
  • Strategy: decouple ingestion khỏi indexing — ingest ALL logs → index có chọn lọc qua inclusion/exclusion filters
  • Điều chỉnh dynamic: thay đổi filters mà KHÔNG cần reconfig application hay redeploy

3.3. DogStatsD Processing (Agent-side)

App gửi UDP packets → DogStatsD aggregate 10s → Flush to Forwarder → Datadog Backend
  • Aggregate tại Agent — giảm network traffic
  • Gauge: gửi giá trị cuối cùng trong 10s
  • Count: gửi tổng trong 10s
  • Histogram: tính avg, count, p50, p95, max per host rồi gửi

3.4. Observability Pipelines Workers (OPW)

Chạy trong user infrastructure (không phải DD cloud) — xử lý data trước khi gửi về Datadog.

  • Capabilities:
    • Grok parsing
    • GeoIP enrichment
    • PII scrubbing
    • OCSF/OTEL/CIM standardization
    • Multi-destination routing (collect once, route many)
    • Metric extraction from logs
  • Throughput: ~1TB/vCPU/day
  • Use case: pre-processing, multi-vendor routing, data sovereignty

So sánh OpenPipeline vs OPW

Khía cạnhDynatrace OpenPipelineDatadog OPW
LocationServer-side (trong Dynatrace SaaS)Client-side (trong user infra)
TimingPost-ingestionPre-ingestion
ControlDynatrace quản lýUser quản lý và deploy
RoutingRoute to Grail bucketsRoute to nhiều destinations (DD, S3, Splunk…)
ScalingManaged by DynatraceUser tự scale (~1TB/vCPU/day)

Facets vs Attributes — Khái niệm Datadog

ConceptMô tảDynatrace equivalent
AttributeField trong log (sau parsing)Log field/attribute
FacetAttribute đã register cho search/filter❌ Không cần — Grail schema-on-read tự query mọi field

Khác biệt cốt lõi

Dynatrace Grail schema-on-read — query bất kỳ field nào mà KHÔNG cần tạo facet trước.
Datadog yêu cầu tạo Facet trước khi có thể filter/group theo field đó trong Log Explorer.

6. Log Patterns — Một tính năng Datadog đáng chú ý

Datadog auto-cluster similar logs thành Patterns:

Ví dụ: 50,000 dòng log → 4 patterns:
Pattern 1: "GET /api/products 200 - 50ms" (40,000 lần)
Pattern 2: "POST /api/orders 201 - 350ms" (8,000 lần)  
Pattern 3: "GET /api/products 500 - 2000ms" (1,500 lần) ← chú ý!
Pattern 4: "POST /api/payments 504 - timeout" (500 lần) ← CRITICAL

Dynatrace equivalent: DQL grouping + OpenPipeline metric extraction, nhưng không có auto-clustering UI tương tự.

Mapping nhanh

Dynatrace→Datadog
OpenPipeline→Log Pipelines + Metrics Processing (riêng biệt)
Parsing rules→Grok Parser
PII masking→Sensitive Data Scanner
Metric extraction from logs→Generate Metrics

Log Events→Log Monitors
Log Metrics→Generate Metrics from logs

Schema-on-read (Grail)→Facets (phải register trước)
