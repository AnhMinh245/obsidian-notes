Log Management

1. Triết lý quản lý Log

Khía cạnhDynatraceDatadog
ApproachIngest → OpenPipeline → Grail (unified)Logging Without Limits™ (ingest all, index selectively)
Default collection✅ OneAgent auto-collect❌ TẮT by default (logs_enabled: true)
Query languageDQL (fetch logs)Log Query syntax (field:value)
Cost driverDPS (Davis Data Units)Indexed log volume (GB/day)
Long-termCustom Grail bucket (1d → 10y)Archive to S3/GCS + Rehydration

Logging Without Limits™ — Strategy

Decouple ingestion khỏi indexing:

  1. Ingest ALL logs (mọi log đều đi qua pipeline processing)
  2. Index selectively qua inclusion/exclusion filters
  3. Archive ALL ra S3/GCS (cheap, rehydrate khi cần)
  • Điều chỉnh dynamic: thay đổi filters mà KHÔNG cần reconfig application
  • Kết quả: không bao giờ mất data, chỉ trả tiền cho logs cần search thường xuyên

3. Log Processing — So sánh chi tiết

Dynatrace OpenPipeline

Ingest → Parse → Mask PII → Enrich → Normalize → Extract metrics → Filter → Route to bucket
  • Một pipeline cho tất cả — không cần tạo pipeline riêng per source
  • Parsing rules, masking rules, enrichment rules
  • Metric extraction: tạo metric từ log pattern tự động

Datadog Log Pipelines

Ingest → JSON Preprocessing → Pipeline Processing → Standard Attributes → Sensitive Data Scanner → Routing

Mỗi pipeline match theo filter query (ví dụ source:nginx):

ProcessorChức năngDT equivalent
Grok ParserExtract fields từ unstructured textParsing rules
Date RemapperDùng timestamp từ log thay ingestion timeNormalization
Service RemapperMap attribute → service fieldAuto-detection
Status RemapperMap attribute → log status (level)Auto-detection
Category ProcessorGroup values (200-299 → “success”)❌ Không có trực tiếp
Arithmetic ProcessorTính toán giữa attributesDQL fieldsAdd
String BuilderTạo attribute mới từ templateDQL string functions

Grok Parser — Chi tiết (Datadog)

# Pattern syntax: %{MATCHER:ATTRIBUTE:TYPE}
# Ví dụ parse nginx access log:
%{ip:client_ip} - - \[%{date("dd/MMM/yyyy:HH:mm:ss Z"):timestamp}\] "%{word:method} %{notSpace:url} HTTP/%{number:http_version}" %{integer:status_code} %{integer:bytes}
  • Grok syntax: %{MATCHER:EXTRACT:FILTER} — 3 phần:
    • MATCHER: pattern name (WORD, ip, integer, date…)
    • EXTRACT: tên attribute output
    • FILTER: type filter (optional — int, double, array)
  • Max 10 parsing rules per Grok processor
  • Grok Parser dùng regex internally nhưng syntax readable hơn raw regex

AI Grok Suggestions (2025+)

Datadog tích hợp AI auto-generate Grok rules từ raw log samples trong Log Explorer.
Paste log sample → AI đề xuất parsing rule → review → apply. Giảm thời gian viết Grok thủ công.

Dynatrace KHÔNG dùng Grok — dùng parsing rules trong OpenPipeline (pattern-based nhưng syntax khác).

4. Log Querying — So sánh cú pháp

Dynatrace DQL

// Tìm error logs của service payment trong 1 giờ qua
fetch logs
| filter dt.entity.service == "SERVICE-xxx" 
    AND status == "ERROR"
    AND timestamp > now() - 1h
| fields timestamp, content, log.source
| sort timestamp desc
| limit 100

// Count errors by service
fetch logs
| filter status == "ERROR"
| summarize error_count = count(), by:{dt.entity.service}
| sort error_count desc

Datadog Log Query

# Tìm error logs của service payment
service:payment status:error @http.status_code:>499

# Với facets
@http.method:POST @duration:>1000 service:order-service env:prod

So sánh syntax

Thao tácDynatrace DQLDatadog Log Query
Filter by servicefilter dt.entity.service == "..."service:payment
Filter by statusfilter status == "ERROR"status:error
Filter by fieldfilter http.status == 500@http.status_code:500
Wildcardfilter content matches "timeout*"timeout*
Numeric rangefilter duration > 1000@duration:>1000
Aggregationsummarize count(), by:{...}Analytics tab → group by

Negationfilter NOT status == "INFO"-status:info

Khác biệt UX

Dynatrace: 1 query language (DQL) dùng cho cả logs, metrics, traces, entities — pipe-based, SQL-like.
Datadog: Log Query syntax riêng (Lucene-like, field:value), khác hoàn toàn với Metric Query syntax.

5. Log Features — So sánh đặc biệt

Facets (Datadog-specific)

ConceptMô tảDynatrace equivalent
AttributeField trong parsed logLog field
FacetAttribute đã register — có thể filter/group trong UI❌ Không cần — Grail schema-on-read
MeasureNumeric facet — tính avg, percentileDQL numeric operations

Phải tạo Facet trước mới filter được trong Datadog Log Explorer. Dynatrace Grail cho phép query bất kỳ field nào ngay lập tức.

Facets vs Attributes — EXAM CRITICAL

  • Attributes = raw parsed fields sau khi log đi qua pipeline. Tồn tại nhưng KHÔNG searchable/filterable trong Log Explorer.
  • Để dùng được trong filter/graph/aggregation, phải PROMOTE attribute thành Facet.
  • Không promote = attribute vẫn có trong log JSON nhưng không xuất hiện trong filter sidebar.
  • Measure = numeric Facet — cho phép tính avg, percentile, sum.

Log Patterns (Datadog)

Auto-cluster similar logs:

50,000 logs → 4 patterns:
- "GET /api/products 200 <time>ms" (40,000 lần) ← normal
- "POST /api/orders 201 <time>ms" (8,000 lần) ← normal
- "GET /api/products 500 <time>ms" (1,500 lần) ← investigate!
- "POST /api/payments 504 timeout" (500 lần) ← CRITICAL!

Dynatrace: không có tính năng auto-clustering tương tự trong UI. Dùng DQL grouping để đạt kết quả tương đương.

Standard Attributes (Datadog)

Datadog define standard attribute names để đồng nhất across services:

Standard AttributeMô tả
http.methodHTTP method (GET, POST…)
http.status_codeHTTP status code
http.urlRequest URL
durationRequest duration
usr.idUser ID
network.client.ipClient IP

Dynatrace: tương tự với OTel Semantic Conventions mapping.
