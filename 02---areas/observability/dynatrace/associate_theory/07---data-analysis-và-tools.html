1. DQL (Dynatrace Query Language) ⭐

1.1 DQL Là Gì?

DQL = ngôn ngữ query pipe-based dùng để truy vấn TẤT CẢ data trên Grail.

💡 So sánh cú pháp:

SQL:    SELECT city, AVG(duration) FROM logs WHERE status='ERROR' GROUP BY city
DQL:    fetch logs | filter status == "ERROR" | summarize avg(duration), by: {city}
Shell:  cat logs | grep "ERROR" | awk '{sum+=$3} END {print sum/NR}'

→ DQL giống Unix pipe hơn SQL — mỗi command nhận input từ command trước.

1.4 DQL Pipeline Flow

flowchart LR
    FETCH["fetch logs<br/>from: -1h"] --> FILTER["filter<br/>loglevel == ERROR"]
    FILTER --> FIELDS["fieldsAdd<br/>dur_s = duration/1e9"]
    FIELDS --> SUMMARIZE["summarize<br/>count(), by: host"]
    SUMMARIZE --> SORT["sort count desc"]
    SORT --> LIMIT["limit 10"]
    LIMIT --> RESULT["📊 Result Table"]

TIP

Pipeline order matters! Filter càng sớm → performance càng tốt. Luôn đặt filter ngay sau fetch.

2. USQL (User Session Query Language)

2.1 USQL Là Gì?

USQL = ngôn ngữ SQL-like chỉ dành cho RUM data (user sessions, user actions).

2.2 USQL Data Tables

TableChứa gìVí dụ query
usersessionSession-level dataSession duration, user type, errors
useractionAction-level dataLoad/XHR/Custom actions, timing, Apdex
usereventError events in sessionJS errors, HTTP errors

2.3 DQL vs USQL — Khi Nào Dùng Gì?

DQLUSQL
Query trênGrail (TẤT CẢ data)User session data (RUM only)
Cú phápPipe: fetch | filter | ...SQL: SELECT ... FROM ... WHERE ...
Data sourcesLogs, traces, events, bizevents, metricsUser sessions, user actions
Khi nàoGeneral analysis, multi-data-typeRUM-focused analysis
Nơi dùngNotebooks, Dashboards, Data ExplorerUSQL tile in Dashboards
Cross-app✅ Có thể query across apps✅ Có thể
Session statusQuery bất kỳChỉ completed sessions

⚠️ USQL chỉ query sessions đã completed (🔗 03 - Digital Experience - RUM > 4.4 USQL)

💡 Rule of thumb: Cần RUM data? → USQL. Cần gì khác? → DQL.

📝 Câu thi: “Visualize conversion funnel từ RUM data?” → USQL + Funnel chart

3. Data Explorer ⭐

3.1 Data Explorer Là Gì?

Data Explorer = visual metric builder — không cần viết DQL, kéo thả metrics:

flowchart LR
    SEARCH["Search metric<br/>dt.host.cpu.usage"] --> FILTER["Apply filters<br/>Host group, MZ"]
    FILTER --> SPLIT["Split by dimension<br/>Host, OS, region"]
    SPLIT --> VIS["Choose visualization<br/>Line, Bar, Table"]
    VIS --> PIN["Pin to Dashboard"]

3.2 Key Features

FeatureMô tả
Metric searchTìm theo tên, category, source
Dimension splitGroup metrics theo host, service, etc.
Aggregationavg, min, max, sum, count, percentile
Time frameCustom time range, relative time
ThresholdsVisual threshold lines trên chart
Pin to Dashboard1-click pin chart → Dashboard

3.3 Giới Hạn Cần Nhớ

LimitGiá trị
Metrics per visualization10
Thresholds per chart3

📝 Câu thi kiểu classic: “Bao nhiêu metrics trên một chart?” → 10
📝 Câu thi: “How many threshold values can you set in Data Explorer?” → 3

3.4 Data Explorer vs DQL vs USQL

flowchart TB
    Q{"Bạn cần gì?"}
    Q -->|"Metrics visualization<br/>no coding"| DE["Data Explorer<br/>Kéo thả, visual builder"]
    Q -->|"Cross-data query<br/>logs + traces + events"| DQL["DQL<br/>Pipe-based, Grail"]
    Q -->|"RUM session analysis<br/>user behavior"| USQL["USQL<br/>SQL-like, RUM only"]

3.5 Multidimensional Analysis vs USQL

📝 Câu thi (scenario): “Xem visually complete time + user action time, filter by property + geolocations, xem user actions across multiple apps?”
→ USQL (User Session Query Language) — vì yêu cầu là xem across multiple apps và filter theo user action property + geolocation.

  • ❌ Multidimensional analysis for user actions → không hỗ trợ cross-app view
  • ❌ Data Explorer → metrics, không phải user action detail
  • ❌ Dashboards / Notebooks → visualization tools, không phải query language

📖 Ref: Data Explorer

4. Notebooks vs Dashboards ⭐

4.1 So Sánh Chi Tiết

NotebooksDashboards
Mục đíchInvestigation, analysisReal-time monitoring
Use casePostmortem, deep-dive, researchDaily monitoring, status board, TV screen
ContentDQL + Markdown + Code (mixed)Tiles: Data, Markdown, Code
Collaboration✅ Comment, share findings✅ Share, management zone scoping
DataResults retained (saved snapshot)Real-time (live query on view)
Time contextSnapshot at time of executionLive, auto-refresh
AnalogieGoogle Docs / Jupyter NotebookGrafana Dashboard

📝 Câu thi: “Retain DQL results cho later analysis?” → Notebooks

  • ❌ Dashboards → real-time, results change on each view
  • ❌ Data Explorer → explore, não save long-term analysis

4.2 Dashboard Tiles

TileMô tảInput
Data tileDQL query → auto-visualizationDQL query
Markdown tileText, links, descriptionsMarkdown text
Code tileCode snippets, DQL examplesCode block

Health Tiles (Hexagon):

Một số Dashboard tiles dùng hexagon đỏ/xanh để hiển thị health status:

  • ✅ Service health — trạng thái services
  • ✅ Application health — trạng thái applications
  • ✅ Synthetic monitor health — trạng thái synthetic monitors
  • ❌ Problems → hiển thị danh sách, không dùng hexagon
  • ❌ Web applications → không phải health tile kiểu hexagon

📝 Câu thi: “Dashboard Tiles dùng Red/Green Hexagons?” → Service health, Application health, Synthetic monitor health

4.3 Dashboard Variable & Filtering

Dashboards hỗ trợ:

  • Management Zone filter — scope dashboard theo MZ (🔗 06 - Configuration và Management > 1. Management Zones)
  • Time frame selector — global time cho tất cả tiles
  • Variables — dynamic parameters cho DQL queries
  • Auto-refresh — configurable refresh interval

4.4 Notebooks Sections

DQLQuery + visualization trong 1 section

📝 Câu thi (scenario): “Postmortem analysis — document investigation steps + retain data snapshots + share with team?”
→ Notebooks — kết hợp DQL queries + Markdown narrative + retained results

5. Tình Huống Giả Định (Exam Scenarios) ⭐

Scenario 1: Daily Monitoring Board

📝 “Team cần TV screen hiển thị real-time CPU, error rate, Apdex.”
→ Dashboard — real-time, auto-refresh, Management Zone scoping

Scenario 2: Incident Investigation

📝 “App chậm lúc 2AM hôm qua. Cần analyze logs + traces + metrics cùng lúc.”
→ Notebook — DQL across data types, retain results, add Markdown analysis

Scenario 3: Quick Metric Exploration

📝 “Muốn xem CPU usage trend, không biết DQL.”
→ Data Explorer — visual metric builder, no coding needed

Scenario 4: Session Funnel Analysis

📝 “Marketing muốn biết % users hoàn thành checkout flow.”
→ USQL + Funnel visualization — query user actions across sessions

Scenario 5: Cross-app Performance

📝 “So sánh Visually Complete giữa Mobile App và Web App.”
→ USQL — supports cross-application queries
