1.2 4 Components Chính

ComponentTypeChức năng
Dynatrace OperatorDeploymentWatch CRD, manage lifecycle
OneAgent (classicFullStack)DaemonSet1 pod/node, host + container metrics, eBPF network
Admission WebhookMutatingWebhookConfigurationIntercept pod CREATE, inject code modules
CSI DriverDaemonSetMount code modules vào pods (non-privileged)

📝 Câu thi: “How does Dynatrace instrument K8s workloads?” → Admission Webhook injects init container + CSI Driver mounts code modules

📝 Câu thi (MC): “Data sources available khi K8s cluster đang được monitored?”

  • ✅ Infrastructure level metrics — node CPU/memory/disk
  • ✅ Prometheus metrics — scrape app endpoints
  • ✅ Kubernetes specific events and metrics — pod events, deployments
  • ❌ Code level insights → cần OneAgent trên app pod (không tự động có từ cluster monitoring)
  • ❌ OpenKit monitoring data → custom device SDK, không liên quan K8s

2.3 K8s Anomaly Detection ⭐

📝 Câu thi: “Tự động detect CPU-request saturation trên K8s node?”

Steps cần thiết:

  1. ✅ Connect Dynatrace to Kubernetes Cluster API — cấp quyền Dynatrace đọc K8s data
  2. ✅ Enable Kubernetes anomaly detection — bật feature trong Settings

Steps KHÔNG cần:

  • ❌ Enable Dynatrace RUM → cho web users, không phải K8s infra
  • ❌ Deploy OneAgent as Docker container → sai approach (dùng Operator pattern)

K8s anomaly types:

  • CPU/Memory request saturation — workload cần nhiều hơn limit
  • Pod restart anomalies — pods restart bất thường
  • Node availability — node NotReady
  • Cluster events — OOMKill, FailedScheduling, ImagePullBackOff

🔗 Khi K8s anomaly detected → Davis AI tạo Problem (🔗 02 - Davis AI và Problem Detection)

3.2 Cloud Integration Setup Flow

StepMô tả
1. Create IAM roleAWS: IAM Role + CloudWatch ReadOnly. Azure: Service Principal. GCP: Service Account
2. Deploy Environment AGActiveGate trong VPC/VNet có access tới cloud APIs
3. Configure in DynatraceSettings > Cloud and Virtualization > chọn provider
4. Select servicesChọn services cần monitor (EC2, RDS, Lambda, etc.)
5. Verify dataClouds app → verify metrics flowing

📝 Câu thi: “Multi-cloud unified view?” → Clouds App (🔗 09 - Security và Automation > 3.3)

3.3 Natively Supported Cloud Providers ⭐

📝 Câu thi (MC): “Cloud Providers Dynatrace natively support without extensions?”

  • ✅ Microsoft Azure
  • ✅ Amazon Web Services (AWS)
  • ✅ Google Cloud Platform (GCP)
  • ❌ IBM Cloud → cần extension
  • ❌ DigitalOcean → cần extension

3.4 Cloud Integration — Loại Data Được Ingest

📝 Câu thi: “Cloud integrations (GCP, AWS, Azure) ingest loại data nào?”
→ Metrics (CPU, memory, request count, latency…)

  • ❌ RUM → cần JS tag
  • ❌ Logs → cần log forwarding riêng
  • ❌ Code-level data → cần OneAgent

IMPORTANT

Cloud integration chỉ pull metrics qua CloudWatch/Azure Monitor/GCP Monitoring API. Để có Services (code-level), cần cài OneAgent trên EC2/VM.

📝 Câu thi: “Cloud integration set up for EC2/VM nhưng không thấy Services?” → OneAgent chưa cài trên instance

3.5 VMware Integration

  • VMware vCenter — same pattern: Environment AG → vCenter API
  • Monitor: VMs, ESXi hosts, datastores, clusters
  • Không cần extension — native integration

4. Kubernetes Apps ⭐

📝 Câu thi (MC): “Which apps to analyze K8s/OpenShift cluster data (events, metrics)?”

  • ✅ Kubernetes Classic — classic K8s monitoring views
  • ✅ Kubernetes (mới) — new generation K8s app
  • ✅ Notebooks — DQL queries trên K8s data
  • ❌ Infrastructure & Operations → general infra, không chuyên K8s analysis
  • ❌ Clouds → multi-cloud view, không chuyên K8s cluster data

6. Tình Huống Giả Định (Exam Scenarios) ⭐

Scenario 1: Deploy Dynatrace lên EKS

📝 “Deploy monitoring cho EKS cluster. Cần instrument workloads non-privileged.”
→ Dynatrace Operator + cloudNativeFullStack mode + namespace labeling

Scenario 2: K8s anomaly không detect

📝 “Dynatrace installed nhưng không detect K8s anomalies.”
→ Check: (1) Connect to K8s API enabled? (2) K8s anomaly detection ON?

Scenario 3: Multi-cloud visibility

📝 “Company uses AWS + Azure + GCP. Single pane of glass?”
→ Clouds App — unified view. Each cloud: Environment AG + IAM integration

Scenario 4: Internal app trên K8s cluster

📝 “Internal microservices trên K8s, cần monitor từ bên ngoài.”
→ Private Synthetic Location trên ActiveGate trong cùng cluster/network
