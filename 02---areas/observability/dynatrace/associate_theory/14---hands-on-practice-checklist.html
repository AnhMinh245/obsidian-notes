Chương 14: Hands-on Practice Checklist — Trial Account

NOTE

Checklist 25 tasks cần thành thạo trước khi thi. Tất cả thực hành trên trial account (15 ngày) + EasyTrade app trên ThinkPad T460.

Kỳ thi: Phần 2 yêu cầu hoàn thành tasks thực tế + upload screenshots. Nếu bạn đã làm quen với 25 tasks dưới đây, phần hands-on sẽ không bất ngờ.

🔗 Trial rotation: ../../Labs/02 - Credential Management
🔗 EasyTrade setup: ../Labs/00 - Setup EasyTrade & OneAgent

TIP

Chiến lược trial rotation:

  • Trial Dynatrace = 15 ngày
  • Khi trial hết → đăng ký lại bằng email khác → chạy lại OneAgent installer
  • Giữ EasyTrade trên ThinkPad chạy liên tục → chỉ cần đổi AG/OneAgent config
  • Xem chi tiết credential management tại ../../Labs/02 - Credential Management

A. Infrastructure Observability (4 tasks)

A1 ⬜ — Navigate Host View

Task: Mở Hosts view, tìm ThinkPad T460, xem CPU/Memory/Disk/Network metrics.

Navigation: Infrastructure > Hosts > [your host]

Expected: Thấy đầy đủ host metrics, OneAgent version, process groups running.

Screenshot tip: Chụp Host overview page với metrics visible.

🔗 01 - Kiến trúc Dynatrace > 2. OneAgent | ../Labs/01 - Host Monitoring & Smartscape Topology

A2 ⬜ — Explore Smartscape Topology

Task: Mở Smartscape, navigate qua 4 layers: Datacenter → Host → Process → Service.

Navigation: Observe & Explore > Smartscape Topology

Expected: Thấy ThinkPad host → EasyTrade process groups → services + dependencies giữa chúng.

Screenshot tip: Chụp ở level Service để thấy dependency arrows.

TIP

Smartscape chỉ hiển thị entities active trong 72 giờ gần nhất. Nếu EasyTrade tắt quá 3 ngày, entities có thể biến mất.

🔗 01 - Kiến trúc Dynatrace > 6. Smartscape

A3 ⬜ — Xem Process Groups

Task: Tìm process group của BrokerService. Xem technology detected, instances, và connections.

Navigation: Infrastructure > Technologies & Processes hoặc từ Smartscape filter

Expected: Process Group detail page: technology stack, number of instances, inbound/outbound connections.

🔗 01 - Kiến trúc Dynatrace > 6.4 Process Group

A4 ⬜ — Xem Network Metrics

Task: Mở network view cho host, xem Traffic, Retransmission, Connectivity.

Navigation: Host > [host] > Network

Expected: 3 network metric categories hiển thị.

📝 Câu thi: “3 loại network metrics?” → Traffic, Retransmission, Connectivity

🔗 06 - Configuration và Management > 6. Network Metrics

B. Services & Distributed Tracing (4 tasks)

B1 ⬜ — Service Flow Analysis

Task: Mở 1 EasyTrade service, xem Service flow (dependency graph từ service ra).

Navigation: Services > [BrokerService] > Service flow

Expected: Thấy upstream (who calls me) và downstream (I call whom) services.

🔗 05 - Services và Database Monitoring > 1. Service Detection | ../Labs/02 - Services, PurePath & Database

B2 ⬜ — Đọc PurePath (Distributed Trace)

Task: Tìm 1 PurePath của request chậm (> 1 giây). Đọc waterfall view, tìm bottleneck.

Navigation: Services > [service] > PurePaths > [pick 1 slow request]

Expected: Waterfall view hiển thị mỗi span, duration, DB calls, response time breakdown.

Cần biết:

  • Span xanh = nhanh, span đỏ = chậm
  • Click vào span → xem method details, SQL statements
  • Response time = execution time + wait time + I/O time

🔗 05 - Services và Database Monitoring > 2. PurePath | ../Labs/02 - Services, PurePath & Database

B3 ⬜ — Response Time Hotspots

Task: Mở Response time hotspots cho 1 service. Tìm method consuming most time.

Navigation: Services > [service] > Response time hotspots

Expected: Waterfall analysis cho biết phần nào chiếm nhiều thời gian nhất.

📝 Câu thi: “Hotspots cho biết gì?” → Activities consuming most TIME

🔗 05 - Services và Database Monitoring > 2.1 Response Time Hotspots

B4 ⬜ — Database Statements

Task: Xem top database statements (most frequent, most expensive) cho service gọi database.

Navigation: Services > [service] > Database statements

Expected: Bảng ranked SQL statements theo frequency và latency.

🔗 05 - Services và Database Monitoring > 4. Database Monitoring

C. Digital Experience (3 tasks)

C1 ⬜ — Xem RUM Application

Task: Nếu EasyTrade frontend được RUM-tagged, mở Application → xem User Sessions, Apdex, Key User Actions.

Navigation: Digital Experience > Applications > [EasyTrade Frontend]

Expected: Application overview: Apdex score, top user actions, session count.

NOTE

RUM cần JavaScript tag injection. Nếu EasyTrade frontend không có RUM config, một số data sẽ trống. Trong trường hợp đó, focus vào Synthetic tasks thay thế.

🔗 03 - Digital Experience - RUM

C2 ⬜ — Tạo HTTP Monitor (Synthetic)

Task: Tạo HTTP Synthetic Monitor đơn giản kiểm tra EasyTrade health endpoint.

Navigation: Digital Experience > Synthetic > Create synthetic monitor > HTTP monitor

Steps:

  1. URL: http://<thinkpad-tailscale-ip>:<easytrade-port>/api/health (hoặc tương đương)
  2. Frequency: 5 minutes
  3. Location: Private location (chạy trên Environment AG trên ThinkPad)
  4. Validation: Response code = 200

Expected: Monitor chạy, hiện green/red status theo interval.

🔗 04 - Digital Experience - Synthetic > 1.1 HTTP Monitor | 04 - Digital Experience - Synthetic > 2. Locations

C3 ⬜ — Xem Synthetic Results

Task: Đợi synthetic monitor chạy vài lần, mở xem Availability % và response time trend.

Navigation: Digital Experience > Synthetic > [your monitor] > Results

Expected: Execution history, availability percentage, response time chart.

🔗 04 - Digital Experience - Synthetic

D. Davis AI & Problems (3 tasks)

D1 ⬜ — Trigger và Đọc Problem Card

Task: Trigger 1 problem trong EasyTrade (dùng feature flags) → đợi Davis detect → đọc problem card.

Navigation: Trigger flag → Problems > [new problem]

Steps:

  1. Bật 1 feature flag trong EasyTrade (xem ../Labs/05 - Problem Patterns & Feature Flags)
  2. Đợi 5-10 phút (Davis cần thu thập baseline data)
  3. Mở Problems → xem problem card mới

Problem card cần biết đọc:

  • Impact: affected entities
  • Root cause: highlighted entity
  • Timeline: khi nào bắt đầu/kết thúc
  • Related events

🔗 02 - Davis AI và Problem Detection > 5. Problem Cards

D2 ⬜ — Tạo Maintenance Window

Task: Tạo maintenance window cho ThinkPad host, chọn mode “Detect but Don’t Alert”.

Navigation: Settings > Anomaly detection > Maintenance windows > Create

Expected: Window hiển thị trong calendar, tests confirm no alerts fired during window.

📝 Câu thi: “3 maintenance window options?” → Detect+Alert, Detect but Don’t Alert, Disable Detection

🔗 02 - Davis AI và Problem Detection > 7. Maintenance Windows

D3 ⬜ — Tắt Feature Flag → Verify Recovery

Task: Tắt feature flag → đợi Davis resolve problem → verify problem card shows “Closed”.

Expected: Problem status: CLOSED, Root Cause confirmed.

🔗 ../Labs/05 - Problem Patterns & Feature Flags

E. Configuration & Management (4 tasks)

E1 ⬜ — Tạo Management Zone

Task: Tạo Management Zone “EasyTrade-Production” gồm tất cả EasyTrade services.

Navigation: Settings > Preferences > Management zones > Add

Rule: Entity type = Service, condition = Tag equals “easytrade” (hoặc service name contains “easytrade”)

Expected: MZ filter hoạt động trên mọi view (Hosts, Services, Problems).

📝 Câu thi: “Separate entities + authorized users?” → Management Zones

🔗 06 - Configuration và Management > 1. Management Zones

E2 ⬜ — Gắn Tags

Task: Gắn manual tag team:backend cho BrokerService. Tạo auto-tag rule tier:frontend cho services có tên chứa “frontend”.

Navigation:

  • Manual: Service > [service] > Properties > Tags > Add
  • Auto: Settings > Tags > Automatically applied tags > Create

🔗 06 - Configuration và Management > 2. Tags & Metadata

E3 ⬜ — Tạo Alerting Profile

Task: Tạo Alerting Profile “EasyTrade-Critical” chỉ alert cho AVAILABILITY và ERROR events trong MZ “EasyTrade-Production”.

Navigation: Settings > Alerting > Alerting profiles > Add

🔗 06 - Configuration và Management > 5. Alerting Profiles

E4 ⬜ — Service Naming Rule

Task: Tạo Service Naming Rule để rename services theo pattern {ProcessGroup.Name} - {Host.Name}.

Navigation: Settings > Server-side service monitoring > Service naming rules

📝 Câu thi: “Automatically name services?” → Service Naming Rules

🔗 05 - Services và Database Monitoring > 1.3 Service Naming Rules

  1. Data tile (DQL): Error logs count per service (last 1h)
  2. Data tile (DQL): CPU usage timeseries
  3. Markdown tile: “EasyTrade Monitoring — Updated daily”

Navigation: Observe & Explore > Dashboards > Create dashboard

F2 ⬜ — Tạo Notebook Investigation

Task: Tạo Notebook “Incident Investigation Template” với 3 sections:

  1. Markdown: Incident summary placeholder
  2. DQL: Davis problems last 7 days
  3. DQL: Error logs with parse

Expected: Notebook saved → results retained (khác Dashboard ở chỗ này!)

📝 Câu thi: “Retain DQL results?” → Notebooks

🔗 07 - Data Analysis và Tools > 4.1 So Sánh Chi Tiết

F3 ⬜ — Tạo SLO

Task: Tạo SLO “BrokerService Availability” = 99.5% availability (30-day window).

Navigation: Observe & Explore > Service level objectives > Add

Expected: SLO widget hiển thị current level, error budget remaining, burn rate.

🔗 ../Labs/07 - SLOs, Alerting Profiles & Management Zones

G. Automation & Security (2 tasks)

G1 ⬜ — Tạo Simple Workflow

Task: Tạo Workflow đơn giản: trigger khi Davis detect problem → action: log message (hoặc send HTTP request).

Navigation: Automate > Workflows > Create workflow

Steps:

  1. Trigger: Davis problem
  2. Condition: severity == “ERROR” (optional)
  3. Action: Run JavaScript (log problem title) hoặc HTTP request (webhook)

🔗 09 - Security và Automation > 2. Workflows

G2 ⬜ — Xem Vulnerability List

Task: Navigate đến Security > Vulnerabilities. Xem danh sách third-party vulnerabilities detected.

Navigation: Application Security > Vulnerabilities

Expected: List CVEs detected ở runtime, severity, affected process groups.

🔗 09 - Security và Automation > 1. Application Security

H. Exam Day Preparation (2 tasks)

H1 ⬜ — Practice Screenshot Flow

Task: Thực hành flow: navigate to page → chụp screenshot → lưu file → upload.

Steps:

  1. Mở 1 trang Dynatrace bất kỳ
  2. Chụp screenshot (Print Screen hoặc KDE screenshot tool: spectacle)
  3. Lưu vào Desktop
  4. Mở file, verify ảnh rõ ràng

CAUTION

Ngày thi chỉ được dùng 1 monitor! Chuẩn bị:

  • KDE Display Settings → disable 2 monitors phụ
  • Test lại: tất cả windows fit trong 1 screen
  • Đảm bảo Spectacle (screenshot tool) hoạt động

H2 ⬜ — ProctorU Pre-check

Task: Chạy ProctorU system check + cài Guardian extension.

Steps:

  1. Cài Google Chrome (nếu chưa có)
  2. Cài Guardian extension
  3. Chạy system check
  4. Test webcam, microphone, bandwidth
