﻿# Kiến Trúc Dynatrace

Dynatrace lưu trữ và kết nối tất cả data thu thập được (logs, metrics, traces, events, user interactions) trong một nền tảng gọi là Grail. Hiểu cách Dynatrace kết nối các dữ liệu sẽ giúp chẩn đoán vấn đề nhanh chóng và có insights sâu về ứng dụng.

Mục Tiêu Bài Học

Sau khi hoàn thành, bạn sẽ có khả năng:

  1. Giải thích Dynatrace Apps và Grail là gì, chức năng và cách chúng hỗ trợ observability
  2. Xác định các monitoring modes của OneAgent và mô tả platforms/environments được hỗ trợ

Phần 1: Dynatrace SaaS Platform

SaaS là gì?

SaaS (Software as a Service) = phần mềm chạy trên cloud, truy cập qua internet — không cần cài đặt hay tự vận hành.

Đặc điểmSaaSOn-premise
HostingCloud (nhà cung cấp quản lý)Tự cài trên server riêng
Cập nhậtTự độngTự làm
Bảo trìNhà cung cấp loTự lo
Truy cậpBrowser + internetQua mạng nội bộ

Ví dụ SaaS quen thuộc: Gmail, Google Drive, Spotify web.

Dynatrace SaaS hoạt động tương tự:

  • Không cần cài server nặng
  • Chỉ cần trình duyệt + internet
  • Dynatrace lo mọi thứ: lưu trữ, xử lý, phân tích data

TIP

Vai trò của OneAgent trong mô hình SaaS:
OneAgent chỉ thu thập data rồi gửi lên cloud. Mọi việc xử lý nặng (analysis, AI, visualization) đều do Dynatrace platform trên cloud thực hiện → server của bạn không bị ảnh hưởng hiệu suất.

Grail — Data Lakehouse ⭐

Grail là gì?

“Grail is a causational data Lakehouse with a massively parallel processing (MPP) analytics engine.”
— Dynatrace Blog

Hiểu đơn giản: Grail là hệ thống lưu trữ và phân tích thống nhất cho TẤT CẢ data trong Dynatrace — được thiết kế để xử lý lượng data khổng lồ với tốc độ cực nhanh.

Cách Grail hoạt động

Khi bạn query data trên Grail:

  Request "tìm tất cả error logs trong 24h qua"
      │
      ▼
  ┌───────────────────────────────────────────┐
  │        GRAIL - Massively Parallel          │
  │                                            │
  │  Helper Server 1 → scan chunk 1            │
  │  Helper Server 2 → scan chunk 2            │
  │  Helper Server 3 → scan chunk 3            │
  │  ...                                       │
  │  Helper Server N → scan chunk N            │
  │                                            │
  │  → Gom kết quả → Trả về cho bạn           │
  └───────────────────────────────────────────┘

  Hàng chục đến hàng TRĂM servers làm việc ĐỒNG THỜI
  → Tìm kiếm hàng trăm TB/giây

TIP

Ví von cửa hàng kính thiên văn:

  • Lúc đầu: Bạn tự đóng gói, gửi hàng, trả lời khách hàng — một mình
  • Khi đơn hàng tăng: Quá nhiều việc cho 1 người
  • Giải pháp: Thuê team nhiều người làm song song → nhanh gấp bội

Grail hoạt động tương tự: scale helper servers lên để xử lý song song → query nhanh bất kể data lớn cỡ nào.

Các đặc điểm kỹ thuật quan trọng của Grail

Đặc điểmMô tả
Unified storageTất cả data (logs, metrics, traces, events) lưu cùng một nơi
Schema-on-readKhông cần define schema trước — linh hoạt khi query
Indexless (Datawarping)Không cần tạo index — scan trực tiếp song song
MPPMassively Parallel Processing — hàng trăm servers cùng query
Exabyte-scaleXử lý được lượng data cực lớn

Grail Buckets — Tổ Chức Data ⭐

Buckets là gì?

Tất cả data trong Grail được phân loại và tổ chức vào các buckets khác nhau. Mỗi bucket quản lý:

Thuộc tínhMô tả
RetentionData được giữ bao lâu
PermissionsAi được truy cập
OrganizationData được tổ chức như thế nào

TIP

Ví von tủ hồ sơ:
Buckets giống như ngăn kéo trong tủ hồ sơ. Mỗi ngăn chứa loại thông tin khác nhau, và một số ngăn cần chìa khóa riêng (permissions) mới mở được.

Ví dụ thực tế

Giám sát 2 ứng dụng: App A và App B, quản lý bởi 2 team khác nhau.

Bucket "App_A"                    Bucket "App_B"
┌───────────────────┐            ┌───────────────────┐
│ Data từ App A     │            │ Data từ App B     │
│ Team A truy cập ✅ │            │ Team B truy cập ✅ │
│ Team B truy cập ❌ │            │ Team A truy cập ❌ │
│ Retention: 35 ngày│            │ Retention: 100 ngày│
└───────────────────┘            └───────────────────┘

→ Mỗi team chỉ thấy data LIÊN QUAN đến ứng dụng của mình
→ Mỗi bucket có thể set retention KHÁC NHAU

Tại sao giới hạn retention?

Lý doChi tiết
Chi phíCàng nhiều data giữ lại → càng tốn license
Bảo mậtData nhạy cảm nên tách bucket riêng và giới hạn thời gian lưu

Ví dụ: Logs thường → bucket retention 35 ngày. Logs quan trọng (audit, compliance) → bucket retention 100+ ngày.

Dynatrace Apps

Dynatrace Apps = ứng dụng tương tác chạy bên trong nền tảng Dynatrace, giúp mở rộng chức năng, visualize data, và tạo workflows phù hợp.

LoạiMô tảVí dụ
Prebuilt AppApp có sẵn, dùng ngayAnalyze user sessions, view service performance, explore logs
Custom-Built AppApp team tự build cho nhu cầu riêngDashboard riêng cho business metrics, custom workflow

NOTE

Custom-built apps cho phép bạn kiểm soát hoàn toàn data nào hiển thị và cách trình bày — phù hợp cho yêu cầu business/technical đặc thù.

Phần 2: OneAgent Monitoring Modes ⭐

Ba Chế Độ Giám Sát

OneAgent có 3 monitoring modes chính, mỗi mode thu thập mức độ data khác nhau:

Bảng So Sánh

Khả năngFoundation & DiscoveryInfrastructure OnlyFull-Stack
Host metrics (CPU, RAM, disk)✅✅✅
Host topology & criticality✅✅✅
Process metrics❌✅✅
Log managementThủ công bậtTùy chọn✅
Service-level tracing (PurePath)❌❌✅
Code-level profiling❌❌✅
Application Security❌❌Tùy chọn
Khuyến nghị dùng choKiosks, POS, endpoints kiểm tra availabilityDatabase servers, hạ tầng không cần APMBusiness-critical apps
Chi phí monitoringThấp nhấtTrung bìnhCao nhất

Chi Tiết Từng Mode

Foundation & Discovery — Mode nhẹ nhất

  • Chỉ thu thập metrics cơ bản về host (CPU, RAM, disk, network)
  • Topology data và host criticality
  • KHÔNG thu thập process metrics hoặc traces
  • Use case: Chỉ cần biết host có sống hay không (kiosks, POS systems)

Infrastructure Only — Mode trung gian

  • Thu thập metrics từ host + processes
  • Biết được processes nào đang chạy và resource usage
  • KHÔNG thu thập traces (PurePath)
  • Use case: Database servers, servers không cần code-level analysis

Full-Stack — Mode toàn diện nhất ⭐

  • Thu thập tất cả: host metrics + process metrics + traces + code profiling
  • Auto-instrumentation → tạo PurePath (distributed traces)
  • Hỗ trợ bật thêm: log management, application security
  • Use case: Business-critical applications (default khuyến nghị)

IMPORTANT

Tại sao không luôn dùng Full-Stack?

  • Không phải system nào cũng cần full observability
  • Cost optimization: mode thấp hơn = ít license hơn
  • Cân bằng giữa visibility, performance, và cost

→ Chọn mode phù hợp với mức độ quan trọng của system.

Knowledge Check

Q1: What makes Dynatrace a SaaS platform?

  • A. It requires a powerful on-prem server to run.
  • B. It must be manually updated and managed.
  • C. It runs in the cloud and is accessed through a browser.
  • D. It is only available as a downloadable desktop application.

Đáp án: C — It runs in the cloud and is accessed through a browser (Chạy trên cloud và truy cập qua trình duyệt).

Tại sao C đúng?

SaaS (Software as a Service) là mô hình phần mềm mà nhà cung cấp host mọi thứ trên cloud — bạn chỉ cần trình duyệt + internet là dùng được. Dynatrace SaaS hoạt động hoàn toàn theo mô hình này:

  • Lưu trữ data: Dynatrace cloud lo (Grail data lakehouse)
  • Xử lý & phân tích: Dynatrace cloud lo (Davis AI, DQL engine)
  • Cập nhật phần mềm: Dynatrace tự cập nhật, bạn không cần can thiệp
  • Bảo trì hạ tầng: Dynatrace quản lý toàn bộ servers

Bạn chỉ cần cài OneAgent trên hosts cần giám sát — phần còn lại đều trên cloud.

Giải thích các lựa chọn sai:

  • A. Requires powerful on-prem server: Sai hoàn toàn. SaaS có nghĩa là KHÔNG cần server on-prem. Đây là đặc điểm của Dynatrace Managed (phiên bản on-premise), không phải SaaS.
  • B. Must be manually updated: Ngược lại — lợi thế lớn của SaaS là tự động cập nhật. Bạn không phải lo về patching, upgrade version hay downtime cho maintenance.
  • D. Downloadable desktop application: SaaS truy cập qua web browser, không phải ứng dụng desktop. Giống Gmail hay Google Docs — bạn mở trình duyệt và dùng, không cần cài gì.

💡 Lời khuyên thi: Nhớ keyword SaaS = Cloud + Browser + No maintenance. Bất kỳ đáp án nào nói đến “install on your server”, “manually manage”, “download” đều sai cho câu hỏi về SaaS.

Q2: What is the main role of OneAgent?

  • A. To create dashboards for application teams.
  • B. To gather data from infrastructure, applications, and user activity.
  • C. To store observability data locally.
  • D. To replace the need for cloud platforms.

Đáp án: B — To gather data from infrastructure, applications, and user activity (Thu thập dữ liệu từ hạ tầng, ứng dụng, và hoạt động người dùng).

Tại sao B đúng?

OneAgent là bộ thu thập dữ liệu (data collector) — đây là vai trò duy nhất và cốt lõi của nó. Cụ thể, OneAgent:

  • Infrastructure: Thu thập CPU, RAM, disk I/O, network metrics từ host
  • Applications: Auto-instrument code (Java, .NET, Node.js…) để capture traces, method hotspots, database queries
  • User activity: Inject JavaScript vào web pages để tracking page load, user actions, XHR calls

Sau khi thu thập, OneAgent gửi tất cả data về Dynatrace platform (cloud) qua HTTPS. Mọi việc phân tích, xử lý, visualization đều do platform phía cloud thực hiện — KHÔNG phải OneAgent.

Giải thích các lựa chọn sai:

  • A. Create dashboards: Dashboards được tạo và hiển thị trên Dynatrace platform (web UI), không phải bởi OneAgent. OneAgent chỉ cung cấp raw data — phần trình bày data là việc của platform.
  • C. Store data locally: OneAgent KHÔNG lưu trữ data trên host. Nó buffer tạm thời rồi gửi lên cloud ngay. Data được lưu trữ chính thức trong Grail (trên cloud). Nếu mất kết nối tạm thời, OneAgent chỉ cache rất ngắn.
  • D. Replace cloud platforms: OneAgent là một thành phần của hệ sinh thái Dynatrace, nó cần cloud platform để gửi data lên. Không có platform thì OneAgent thu thập data mà không có chỗ gửi.

💡 Lời khuyên thi: Phân biệt rõ vai trò: OneAgent = Thu thập, Platform = Phân tích + Hiển thị, Grail = Lưu trữ. Câu hỏi về “role of OneAgent” luôn xoay quanh từ khóa gather/collect data.

Q3: Which of the following are Dynatrace apps? (Select all that apply)

  • ✅ Infrastructure & Operations
  • ✅ Problems
  • ✅ Hosts Classic
  • ❌ Time Frame Selector

Đáp án: Infrastructure & Operations, Problems, Hosts Classic

Tại sao 3 đáp án trên đúng?

Dynatrace Apps là các ứng dụng tương tác chạy bên trong nền tảng Dynatrace. Chúng có giao diện riêng, có thể mở, đóng, và tương tác:

  • Infrastructure & Operations: App quản lý và giám sát hạ tầng — hiển thị hosts, network, cloud resources
  • Problems: App hiển thị danh sách các problems mà Davis AI phát hiện — bạn click vào để xem root cause, impact
  • Hosts Classic: App classic view cho hosts — hiển thị host details, performance metrics, processes

Tất cả đều là prebuilt apps có sẵn trong Dynatrace, tìm thấy trong menu navigation hoặc app launcher.

Tại sao Time Frame Selector sai?

Time Frame Selector (bộ chọn khoảng thời gian) chỉ là một UI component — một phần tử giao diện nhỏ nằm trên thanh toolbar. Nó cho phép bạn chọn thời gian hiển thị data (last 2 hours, last 7 days…), nhưng nó KHÔNG phải app vì:

  • Không có giao diện riêng để “mở”
  • Không có functionality độc lập
  • Chỉ là widget hỗ trợ các apps khác

💡 Lời khuyên thi: Phân biệt App (có giao diện đầy đủ, mở từ menu/launcher) vs UI Component (phần tử nhỏ nằm bên trong app khác, như time selector, filter bar).

Q4: What is the main purpose of Grail in Dynatrace?

  • A. To visualize dashboards across multiple environments.
  • B. To store, connect, and analyze observability data in real time.
  • C. To install OneAgent on virtual machines.
  • D. To create alerts for infrastructure outages only.

Đáp án: B — To store, connect, and analyze observability data in real time (Lưu trữ, kết nối, và phân tích dữ liệu observability theo thời gian thực).

Tại sao B đúng?

Grail là data lakehouse — công nghệ lưu trữ thống nhất của Dynatrace. Ba chức năng cốt lõi:

  1. Store (Lưu trữ): Tất cả telemetry data (logs, metrics, traces, events, business events, security events) được lưu vào Grail Buckets với configurable retention
  2. Connect (Kết nối): Data từ nhiều nguồn khác nhau được liên kết — ví dụ: error log ← liên kết → trace ← liên kết → host metrics. Nhờ đó bạn query chéo các loại data
  3. Analyze (Phân tích): MPP (Massively Parallel Processing) engine dùng Datawarping search song song hàng trăm TB/giây — cho phép phân tích real-time trên lượng data khổng lồ

Giải thích các lựa chọn sai:

  • A. Visualize dashboards: Dashboards là tính năng hiển thị data — thuộc về UI/Apps layer. Grail chỉ lưu trữ và query data, việc hiển thị là ở layer trên (Dashboards, Notebooks, Data Explorer sử dụng DQL để query Grail).
  • C. Install OneAgent: Cài đặt OneAgent là quy trình riêng (download installer → chạy trên host). Grail hoàn toàn không liên quan đến việc cài đặt — nó chỉ nhận data sau khi OneAgent đã gửi lên.
  • D. Create alerts for infra only: Grail lưu trữ TẤT CẢ loại data, không chỉ infrastructure. Và việc tạo alerts thuộc về Davis AI và Alerting Profiles, không phải Grail.

💡 Lời khuyên thi: Nhớ 3 keywords: Store + Connect + Analyze + Real-time. Grail là storage engine, không phải visualization tool hay alert system.

Q5: Which of the following best describes a Dynatrace custom-built app?

  • A. An app that runs outside of the Dynatrace platform.
  • B. A preinstalled browser extension.
  • C. An app your team builds to meet specific business or technical needs.
  • D. An app designed only for data storage.

Đáp án: C — An app your team builds to meet specific business or technical needs (App mà team bạn tự build để đáp ứng nhu cầu business hoặc technical riêng).

Tại sao C đúng?

Dynatrace hỗ trợ 2 loại apps:

  • Prebuilt apps: Apps có sẵn (Problems, Hosts Classic, Services…) — dùng ngay không cần code
  • Custom-built apps: Apps mà team tự phát triển bằng Dynatrace App Toolkit

Custom-built apps cho phép:

  • Kiểm soát hoàn toàn data nào hiển thị và cách trình bày
  • Sử dụng DQL để query data từ Grail theo nhu cầu riêng
  • Tạo workflow tùy chỉnh cho business logic cụ thể
  • Ví dụ: Dashboard riêng cho C-level executives chỉ hiển thị business KPIs, hoặc app tự động tạo ticket khi có problem

Giải thích các lựa chọn sai:

  • A. Runs outside the platform: Sai ngược — custom-built apps chạy BÊN TRONG nền tảng Dynatrace. Chúng sử dụng Dynatrace API và DQL để truy cập data, và được host trên Dynatrace platform.
  • B. Preinstalled browser extension: Browser extension là phần mở rộng cho Chrome/Firefox. Custom apps không phải extension — chúng là ứng dụng web chạy trong Dynatrace UI.
  • D. Only for data storage: Custom apps có thể visualize data, tạo workflows, trigger actions, không chỉ lưu trữ. Chức năng storage thuộc về Grail, không phải apps.

💡 Lời khuyên thi: Custom-built app = inside Dynatrace + team builds + specific needs. Nếu đáp án nói “outside”, “preinstalled”, hoặc “only storage” → sai.
