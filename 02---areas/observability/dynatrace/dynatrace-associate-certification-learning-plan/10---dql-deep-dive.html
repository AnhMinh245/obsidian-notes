﻿# DQL Deep Dive — Dynatrace Query Language Chi Tiết

DQL (Dynatrace Query Language) là ngôn ngữ query cho Grail — data lakehouse của Dynatrace. DQL được dùng trong Dashboards, Notebooks, Logs App, Traces App và là phần thiết yếu cho thi (cả phần trắc nghiệm lẫn phần hands-on thực hành).

IMPORTANT

Phần hands-on thực hành trong kỳ thi cho phép open book (tham khảo Dynatrace Documentation). Tuy nhiên, nếu không quen DQL syntax → sẽ mất rất nhiều thời gian tra cứu. Học trước = thi nhanh hơn.

Phần 1: DQL Là Gì? ⭐

Định Nghĩa

DQL = ngôn ngữ query truy vấn trực tiếp Grail để lấy, lọc, biến đổi, và tổng hợp observability data.

Kiến trúc:

  Dashboards ─┐
  Notebooks ──┤
  Logs App ───┤── DQL Query ──→ Grail (Data Lakehouse) ──→ Results
  Traces App ─┤
  API ────────┘

  DQL là "ngôn ngữ giao tiếp" giữa bạn và Grail

DQL vs SQL ⭐

DQLSQL
Data sourceGrail (data lakehouse)Relational database (tables)
SchemaSchema-less — không cần define schema trướcSchema bắt buộc (CREATE TABLE)
ProcessingPipeline (sequential, left → right)Declarative (optimizer tự chọn execution plan)
Syntaxfetch → filter → summarize (pipe |)SELECT → FROM → WHERE → GROUP BY
Bắt đầu bằngfetch (lấy data)SELECT (chọn columns)

So Sánh Cú Pháp Cơ Bản

Thao tácDQLSQL
Lấy tất cảfetch eventsSELECT * FROM events
Lọcfetch events | filter type == "error"SELECT * FROM events WHERE type = 'error'
Chọn fieldsfetch events | fields name, statusSELECT name, status FROM events
Sắp xếpfetch events | sort timestamp descSELECT * FROM events ORDER BY timestamp DESC
Đếmfetch events | summarize count()SELECT COUNT(*) FROM events
Nhómfetch events | summarize count(), by:typeSELECT type, COUNT(*) FROM events GROUP BY type

NOTE

DQL xử lý data tuần tự theo pipeline (bước 1 → bước 2 → bước 3). Mỗi bước nhận output từ bước trước làm input. Giống Unix pipes (cat file | grep error | sort).

Tham khảo: DQL compared to SQL and more

Phần 5: DQL Trong Dashboard & Notebook

Mỗi Dashboard Tile = 1 DQL Query

Dashboard Tile "Error Rate by Service":
  Query:
    fetch logs, from:now()-1h
    | filter loglevel == "ERROR"
    | summarize error_count = count(), by:{dt.entity.service}
    | sort error_count desc
  
  Visualization: Bar Chart

Notebook = DQL + Markdown + Frozen Data

Section 1: [Markdown] "Black Friday 2025 Post-Mortem"

Section 2: [DQL Query]
  fetch events, from:2025-11-28, to:2025-11-29
  | filter event.kind == "DAVIS_PROBLEM"
  | summarize problem_count = count(), by:{ bin(timestamp, 1h) }
  → Chart: Problems per hour during Black Friday
  → Data FROZEN at query time (snapshot)

Section 3: [Markdown] "Root cause analysis..."

Phần 6: Tips & Tricks Cho Thi ⭐

Những Lỗi Hay Gặp

LỗiĐúng
SELECT * FROM logsfetch logs — DQL KHÔNG dùng SELECT/FROM
fetch metricstimeseries avg(dt.host.cpu.usage) — Metrics dùng timeseries
| where status = "ERROR"| filter status == "ERROR" — DQL dùng filter không phải where, dùng == không phải =
| group by host| summarize count(), by:{host} — DQL dùng summarize...by:{} không phải group by

Keywords Cần Nhớ Cho Thi

KeywordGhi nhớ

TIP

Bất kỳ user nào có access vào Dynatrace đều có thể viết DQL (tùy thuộc data access via Management Zones). Không cần quyền Administrator. Đây là điểm hay ra thi.

Knowledge Check

Q1: What does the pipe symbol | do in a DQL query?

  • A. It separates field names in a query.
  • B. It passes the output of one command as input to the next command.
  • C. It indicates the end of a DQL query.
  • D. It creates a new data table in Grail.

Đáp án: B — It passes the output of one command as input to the next command (Chuyển output của command này sang command tiếp theo).

Tại sao B đúng?

DQL sử dụng pipeline model: mỗi command xử lý data → output trở thành input cho command tiếp theo qua pipe |.

Giống Unix pipe: cat access.log | grep ERROR | sort | head -10

Giải thích sai:

  • A. Separates field names: Field names được phân tách bằng dấu phẩy , (VD: fields name, status), không phải pipe.
  • C. End of query: Query kết thúc tự nhiên sau command cuối. Pipe = tiếp tục xử lý, không phải kết thúc.
  • D. Creates data table: Pipe KHÔNG tạo tables. Grail lưu data sẵn. DQL chỉ query data, không modify Grail.

💡 Exam tip: Pipe | = sequential processing = output → input. Keyword: “passes output”, “pipeline”.

Q2: Which command is used to retrieve metric data in DQL?

  • A. fetch metrics
  • B. select metrics
  • C. timeseries
  • D. query metrics

Đáp án: C — timeseries

Tại sao C đúng?

Trong DQL, metrics dùng cú pháp đặc biệt khác với logs/spans/events:

  • Logs/spans/events: fetch logs, fetch spans, fetch events
  • Metrics: timeseries avg(dt.host.cpu.usage) — KHÔNG dùng fetch

timeseries tự động lấy data theo thời gian (time-series) và apply aggregation function (avg, sum, max…).

Giải thích sai:

  • A. fetch metrics: fetch metrics KHÔNG đúng syntax. Data type cho fetch là logs, spans, events, bizevents, dt.entity.* — không có metrics.
  • B. select metrics: DQL KHÔNG dùng select — đó là SQL keyword. DQL dùng fetch hoặc timeseries.
  • D. query metrics: query không phải DQL command.

💡 Exam tip: Logs/spans/events = fetch. Metrics = timeseries. Đây là điểm hay gài bẫy!

Q3: Which DQL command is equivalent to SQL’s WHERE clause?

  • A. fields
  • B. summarize
  • C. filter
  • D. sort

Đáp án: C — filter

Tại sao C đúng?

SQLDQL
WHERE status = 'ERROR'| filter status == "ERROR"

filter lọc records dựa trên conditions — chỉ giữ records thỏa mãn điều kiện. Chính xác tương đương WHERE trong SQL.

Giải thích sai:

  • A. fields: fields = SELECT columns (chọn fields hiển thị), không phải WHERE (lọc records).
  • B. summarize: summarize = GROUP BY + aggregate functions (nhóm + tính toán), không phải lọc.
  • D. sort: sort = ORDER BY (sắp xếp kết quả), không phải lọc.

💡 Exam tip: filter = WHERE, fields = SELECT, summarize = GROUP BY, sort = ORDER BY. Nhớ mapping này cho thi.

Q4: Where does DQL retrieve its data from?

  • A. OneAgent directly
  • B. ActiveGate cache
  • C. Grail data lakehouse
  • D. External SQL databases

Đáp án: C — Grail data lakehouse

Tại sao C đúng?

DQL được thiết kế ĐẶC BIỆT để query data từ Grail — causational data lakehouse của Dynatrace. Flow:

OneAgent → (gom data) → Grail (lưu trữ) ← DQL (query)

Grail chứa TẤT CẢ observability data: logs, metrics, traces, events, business events, security data. DQL query trực tiếp vào Grail, sử dụng MPP (Massively Parallel Processing) engine cho tốc độ cao.

Giải thích sai:

  • A. OneAgent directly: OneAgent thu thập data và gửi về Grail. DQL không query OneAgent trực tiếp — bạn query data đã được ingest vào Grail.
  • B. ActiveGate cache: ActiveGate là proxy relay data, không phải storage. Không có “cache” DQL query được.
  • D. External SQL databases: DQL là ngôn ngữ riêng cho Grail, không query external SQL databases. Muốn monitor external DB → dùng OneAgent/extensions, data sau đó vào Grail.

💡 Exam tip: DQL → Grail. Không gì khác. Grail = data lakehouse (KHÔNG phải data warehouse hay database). Keywords: Grail, lakehouse, MPP.

Q5: True or False — You must be a Dynatrace Administrator to write and run DQL queries.

  • ❌ False

Đáp án: False

Tại sao False?

DQL được thiết kế cho MỌI users — không chỉ admins:

  • Operators dùng DQL để investigate problems
  • Analysts dùng DQL để tạo reports
  • Developers dùng DQL để debug application behavior

Quyền xem data phụ thuộc vào Management Zones và data access permissions — nhưng khả năng viết DQL không require admin rights.

💡 Exam tip: Câu hỏi “must be admin” cho DQL → luôn False. DQL = accessible for everyone.

Q6: What is the correct syntax structure for a basic DQL query?

  • A. SELECT fields FROM logs WHERE condition
  • B. fetch logs | filter condition | fields field1, field2
  • C. query logs filter condition select fields
  • D. logs.fetch().filter().select()

Đáp án: B — fetch logs | filter condition | fields field1, field2

Tại sao B đúng?

DQL syntax = command | command | command (pipe-based pipeline):

  1. fetch logs — lấy data
  2. | filter condition — lọc
  3. | fields field1, field2 — chọn fields

Mọi DQL query bắt đầu bằng fetch (hoặc timeseries cho metrics), sau đó nối bằng |.

Giải thích sai:

  • A: Đây là SQL syntax, không phải DQL.
  • C: query không phải DQL command. DQL dùng fetch.
  • D: Đây giống method chaining kiểu JavaScript, không phải DQL syntax.

💡 Exam tip: DQL pattern: fetch + pipe + commands. Luôn bắt đầu bằng fetch (ngoại trừ metrics dùng timeseries).
