﻿# Extending Dynatrace — Mở Rộng Nền Tảng

Dynatrace out-of-the-box đã thu thập rất nhiều data, nhưng không phải mọi môi trường đều giống nhau. Bài này giới thiệu các cách mở rộng Dynatrace: Hub, Extensions, Cloud Integrations, Workflows, OpenTelemetry, Business Events, API, Application Security, và Kubernetes Monitoring.

Mục Tiêu Bài Học

  1. Xác định các tùy chọn mở rộng Dynatrace
  2. Giải thích từng phương thức mở rộng và lợi ích

Phần 1: Tại Sao Cần Mở Rộng?

Dynatrace giống smartphone: out-of-the-box làm được nhiều việc, nhưng bạn vẫn cài thêm apps cho phù hợp nhu cầu.

Lý do chính:

  • Không phải mọi technology đều được monitor tự động (VD: Tomcat, Kafka cần extensions riêng)
  • Bật mọi thứ mặc định → data thừa, clutter UI
  • Mỗi tổ chức có business logic riêng cần custom tracking

→ Dynatrace cho phép bật những gì cần, khi cần thay vì enable mọi thứ mặc định.

Phần 2: Dynatrace Hub ⭐

Hub là gì?

Dynatrace Hub = “App Store” của Dynatrace — nơi browse, activate, và cài đặt:

LoạiMô tảVí dụ
Pre-Built AppsApps Dynatrace tạo sẵnLearn DQL, Ownership, Site Reliability Guardian
Technology ExtensionsExtensions cho technologies cụ thểTomcat, Kafka, Oracle DB, SAP
Cloud IntegrationsTích hợp cloud providersAWS, Azure, GCP

Technology Extensions chi tiết

Khi activate extension (VD: Tomcat):

  1. OneAgent bắt đầu collect extra metrics riêng cho Tomcat (thread counts, request volumes, session data)
  2. ActiveGate cũng có thể collect metrics remotely
  3. Extension thường kèm pre-made dashboard hiển thị data thu thập
  4. Data xuất hiện dưới dạng custom devices và metrics riêng

NOTE

Nếu technology không có sẵn trong Hub → có thể tạo custom extensions để ingest data từ bất kỳ technology nào.

Phần 3: Cloud Integrations

Monitor Cloud Không Cần OneAgent

Cloud Integrations cho phép monitor AWS, Azure, GCP mà KHÔNG cần cài OneAgent trên từng host.

KHÔNG có Cloud Integration:
  → Phải cài OneAgent trên MỌI EC2/VM
  → Tốn effort + license cho mọi host

CÓ Cloud Integration:
  → Dynatrace connect qua API đến AWS/Azure/GCP
  → Tự động pull: instance names, tags, basic metrics
  → High-level view toàn bộ cloud resources

  Muốn DEEPER visibility (logs, traces, services)?
  → Vẫn cần cài OneAgent — Cloud Integration chỉ cho basic view
Có Cloud IntegrationThêm OneAgent
Instance names, tags✅ + Logs
Basic infrastructure metrics✅ + Process metrics
High-level resource overview✅ + Services, Traces, PurePaths

TIP

Cloud Integrations = great starting point cho hybrid/distributed environments. OneAgent cho deep visibility khi cần.

Phần 4: Workflows ⭐

Workflows là gì?

Workflows = automation builder trong Dynatrace — script builder step-by-step để tự động hóa tasks.

Workflows làm được gì?

Use caseVí dụ
Push data vào DynatraceIngest external logs, metrics từ sources khác
Trigger alertsGửi notification khi threshold bị vượt
Call webhooksGọi external APIs (Slack, PagerDuty, ServiceNow)
Auto-remediationTự restart service khi detect problem
Custom automationBất kỳ thứ gì — “giới hạn là trí tưởng tượng”

NOTE

Workflows cũng là alternative cho Problem Notifications truyền thống — với automation capabilities mạnh hơn (auto-ticketing, auto-scaling, auto-remediation).

Phần 5: Logs Ingestion & Management

Đưa Logs Vào Dynatrace

Ngoài logs tự động thu thập bởi OneAgent, Dynatrace hỗ trợ:

Tính năngChi tiết
Multi-source ingestionIngest logs từ devices KHÔNG có OneAgent (network devices, IoT) qua Dynatrace API
Log filteringChọn logs nào lưu, logs nào bỏ → kiểm soát data volume
Data maskingTự động mask sensitive data (tokens, API keys, passwords) khi ingestion
Access controlRole-based access → team nào xem logs nào
Retention optimizationExclude low-priority logs → tiết kiệm licensing costs

Phần 6: Application Security ⭐

Dynatrace không chỉ monitoring — còn bảo mật!

Dynatrace phân tích code AT RUNTIME (khi đang chạy) — không phải static scan:

Tính năngMô tả
Runtime Vulnerability AnalyticsPhát hiện vulnerabilities trong third-party libraries/frameworks đang được sử dụng
Runtime Application ProtectionChặn attacks real-time: SQL injection, DDoS, code injection
DSS (Dynatrace Security Score)Điểm bảo mật cho mỗi vulnerability — tính bởi Snyk + Davis AI topology understanding

Ưu điểm so với static scanning

Static Scan (truyền thống):
  → Quét CODE → tìm vulnerabilities trong MỌI libraries
  → Báo 500 vulnerabilities
  → Nhưng 450 libraries không thực sự ĐƯỢC SỬ DỤNG → noise!

Dynatrace Runtime Analysis:
  → Monitor code ĐANG CHẠY → chỉ flag libraries THỰC SỰ được dùng
  → Báo 50 vulnerabilities → tất cả đều relevant
  → DSS score giúp prioritize: critical trước, low-risk sau

Phần 7: OpenTelemetry & OneAgent SDK

Khi Nào Cần?

Khi Dynatrace không tự động capture data bạn cần:

  • Technology không được hỗ trợ natively
  • Cần capture custom values (cart total, user tier, transaction ID)
  • Host không thể cài OneAgent

So Sánh 2 Tools ⭐

OpenTelemetry (OTel)OneAgent SDK
Khi dùngTechnology không hỗ trợ, hoặc host không có OneAgentHost ĐÃ có OneAgent, cần thêm data
Capture gìCustom spans/traces từ bất kỳ technologyRequest-level data cụ thể (cart total, headers)
Cài đặtInstrumentation riêng, gửi data đến DynatraceThêm SDK vào code existing
IntegrationData gửi đến Dynatrace → stitched vào existing tracesMerges với OneAgent traces tự động

Kết quả cuối cùng

Dynatrace tự động merge tất cả data (native + OTel + SDK) vào unified traces — mọi thứ trong 1 nơi.

Phần 8: Business Events ⭐

Business Events là gì?

Business Events = cách extract business-critical values từ bên trong logs/spans.

Workflow tạo Business Event

1. XÁC ĐỊNH SOURCE
   → Value nằm trong log hay span? (VD: cart_total trong span)

2. TẠO RULE
   → Nói Dynatrace tìm gì: "Tìm field 'cart_total' trong spans
      của service 'CheckoutService'"

3. EXTRACT VALUE
   → Dynatrace tự trích xuất giá trị (VD: cart_total = $299.99)

4. LƯU BUSINESS EVENT
   → Value lưu dưới dạng Business Event → query bằng DQL:
     fetch bizevents | filter event.type == "checkout.completed"

Ví dụ use cases:

  • Track cart value trung bình → tối ưu pricing strategy
  • Track membership level → phân tích behavior theo tier
  • Track payment method → đánh giá adoption rate

NOTE

Business Events thường do Dynatrace admins tạo, nhưng visible cho mọi users trong dashboards và tools.

Phần 9: Dynatrace API

API làm gì?

Dynatrace API = programmatic access — mọi thứ làm trong UI đều làm được qua API:

Khả năngVí dụ
Tạo/cấu hình dashboardsAutomate dashboard creation cho nhiều environments
Pull logs & metricsExport data sang Power BI, Excel, Grafana
Modify settingsBatch update monitoring configs
Push dataIngest custom metrics, logs, events
MigrateMove dashboards/configs giữa environments

TIP

Khi nào dùng API thay vì UI?

  • Cần automate (thay đổi settings hàng loạt)
  • Cần integrate (push data sang external tools)
  • Cần migrate (move config giữa environments)
  • Cần scale (manage nhiều tenants)

Phần 10: Kubernetes Monitoring

Kubernetes trong Dynatrace

Dynatrace monitor K8s thông qua Dynatrace Operator — cài trên cluster để auto-deploy OneAgent.

Containers in PodNhân viên trong xeMỗi container làm 1 việc cụ thể

Knowledge Check

Q1: What is the Dynatrace Hub for?

  • A. Viewing user behavior recordings.
  • B. Managing Dynatrace licenses.
  • C. Installing extensions and apps to expand functionality.
  • D. Editing Dashboards to customize how monitoring data is displayed.

Đáp án: C — Installing extensions and apps to expand functionality (Cài đặt extensions và apps để mở rộng chức năng).

Tại sao C đúng?

Dynatrace Hub là “App Store” — nơi bạn browse, search, và install:

  • Pre-built apps (Learn DQL, Ownership…)
  • Technology extensions (Tomcat, Kafka, Oracle…)
  • Cloud integrations (AWS, Azure, GCP…)

Hub giúp bạn mở rộng chức năng Dynatrace theo nhu cầu — bật những gì cần, tắt những gì không cần.

Giải thích các lựa chọn sai:

  • A. Viewing user behavior recordings: Đây thuộc về Session Replay (trong DEM), không phải Hub. Hub không liên quan đến xem recordings.
  • B. Managing licenses: License management nằm trong Settings → Subscription hoặc Dynatrace account portal, không phải Hub. Hub là marketplace cho apps/extensions.
  • D. Editing Dashboards: Dashboard editing nằm trong Dashboards app. Hub là nơi cài đặt apps, không phải nơi edit nội dung apps.

💡 Lời khuyên thi: Hub = marketplace/app store cho extensions + apps. Keyword: “install”, “expand”, “activate”.

Q2: True or False — Dynatrace automatically activates all available extensions when OneAgent is installed.

  • ❌ False

Đáp án: False — Dynatrace KHÔNG tự bật tất cả extensions khi cài OneAgent.

Tại sao False?

Đây là thiết kế có chủ đích: không phải mọi extensions đều cần thiết cho mọi environment. Bật tất cả sẽ:

  • Thu thập data thừa → tốn licensing
  • Clutter UI → khó tìm data quan trọng
  • Noise → quá nhiều metrics không liên quan

Thay vào đó, Dynatrace áp dụng nguyên tắc opt-in: bạn chủ động vào Hub → search extension cần → click Install/Activate. Chỉ data bạn thực sự cần mới được thu thập.

💡 Lời khuyên thi: Extensions = opt-in, không phải opt-out. OneAgent install ≠ tất cả extensions activated. Bạn phải chủ động activate từng extension.

Q3: Which of the following best describes the purpose of OpenTelemetry in Dynatrace?

  • A. To reduce CPU usage by OneAgent.
  • B. To visualize user sessions.
  • C. To gather data from technologies Dynatrace doesn’t monitor natively.
  • D. To mask sensitive log data.

Đáp án: C — To gather data from technologies Dynatrace doesn’t monitor natively (Thu thập data từ technologies mà Dynatrace không monitor mặc định).

Tại sao C đúng?

OpenTelemetry (OTel) tồn tại cho 2 tình huống chính:

  1. Technology không hỗ trợ: Dynatrace không auto-instrument technology đó → dùng OTel để tạo custom spans/traces
  2. Không thể cài OneAgent: Host bị restrict → dùng OTel collect data externally → gửi đến Dynatrace

OTel data gửi đến Dynatrace được stitched vào existing traces → unified observability view.

Giải thích các lựa chọn sai:

  • A. Reduce CPU usage: OTel KHÔNG giảm CPU. Thực tế, thêm OTel instrumentation có thể tăng nhẹ overhead. Giảm CPU → dùng monitoring mode thấp hơn.
  • B. Visualize user sessions: User session visualization thuộc RUM/DEM, không phải OpenTelemetry. OTel thu thập traces, không phải user session data.
  • D. Mask sensitive log data: Log masking thuộc Log Ingestion Settings, không phải OTel. OTel collect traces/spans, không xử lý log masking.

💡 Lời khuyên thi: OpenTelemetry = fill gaps mà Dynatrace không cover natively. Keyword: “technologies not monitored”, “custom traces”, “without OneAgent”.

Q4: What can workflows in Dynatrace help you do?

  • A. Add more storage to your environment.
  • B. Schedule and automate tasks in response to specific conditions.
  • C. Create new user roles.
  • D. Delete problem tickets automatically.

Đáp án: B — Schedule and automate tasks in response to specific conditions (Lên lịch và tự động hóa tasks khi có điều kiện cụ thể).

Tại sao B đúng?

Workflows = automation builder. Chúng cho phép tạo quy trình tự động:

  • Trigger: Khi điều kiện xảy ra (problem detected, threshold breached, schedule time)
  • Action: Thực hiện task tự động (gửi alert, call webhook, push data, create ticket)
  • Flexibility: Bất kỳ logic nào — từ đơn giản (gửi email) đến phức tạp (auto-remediation)

VD: Problem detected → Workflow auto-create Jira ticket → Workflow gửi Slack notification → Workflow restart affected service.

Giải thích các lựa chọn sai:

  • A. Add storage: Storage thuộc về Grail Buckets và retention policies, không phải workflows. Workflows automate tasks, không manage infrastructure.
  • C. Create user roles: User role management thuộc IAM (Identity and Access Management) trong Settings, không phải workflows. Workflows automate operational tasks.
  • D. Delete problem tickets: Workflows có thể tạo tickets (Jira, ServiceNow), nhưng phần lớn không “delete” problem tickets. Và đáp án B mô tả purpose chính xác hơn (schedule + automate + conditions).

💡 Lời khuyên thi: Workflows = automate + conditions + actions. Chúng là “if-then” automation builder cho operational tasks.

Q5: Which tool allows Dynatrace to push data to an external platform like Power BI or Excel?

  • A. Dynatrace API
  • B. The Operator
  • C. OneAgent SDK
  • D. Log Viewer

Đáp án: A — Dynatrace API

Tại sao A đúng?

Dynatrace API là cách programmatic để tương tác với Dynatrace. Khi cần push data ra ngoài (export):

  1. Dùng API endpoint (VD: /api/v2/metrics/query) để pull metrics/logs
  2. Transform data (nếu cần)
  3. Push vào external platform: Power BI, Excel, Grafana, custom tool

API cho phép mọi thứ bạn làm trong UI: query data, modify settings, create dashboards — nhưng programmatically, cho phép automation và integration.

Giải thích các lựa chọn sai:

  • B. The Operator: Dynatrace Operator chỉ dùng cho Kubernetes — deploy và manage OneAgent trên K8s clusters. Không export data sang external platforms.
  • C. OneAgent SDK: SDK dùng để capture thêm data (thêm custom spans, request-level values). Nó đưa data VÀO Dynatrace, không push RA NGOÀI.
  • D. Log Viewer: Log Viewer chỉ hiển thị logs trong Dynatrace UI. Không có chức năng export sang external platforms.

💡 Lời khuyên thi: API = programmatic access = mọi thứ UI làm được, API cũng làm được. Push data ra ngoài (Power BI, Excel) → dùng API.
