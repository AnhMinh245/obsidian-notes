﻿# Analyzing Your Observability Data — Phân Tích Dữ Liệu

Bạn đã thu thập data qua OneAgent, lưu trữ trong Grail — giờ là lúc phân tích và hiển thị nó. Bài này giới thiệu các công cụ chính: Dashboards, DQL, Notebooks, Logs & Traces Apps — giúp bạn biến raw data thành actionable insights.

Mục Tiêu Bài Học

  1. Xác định các tính năng phân tích data trong Dynatrace
  2. Tạo và cấu hình Dashboards và Notebooks

Phần 1: Dashboards ⭐

Dashboard là gì?

Dashboard = bảng hiển thị trực quan, biến raw data thành charts, tables, metrics dễ đọc. Dùng để monitor performance real-time.

Cấu trúc Dashboard

Dashboard = tập hợp các TILES (ô hiển thị)

  ┌──────────────────────────────────────────────────┐
  │  Dashboard: "Astroshop Production Overview"       │
  │                                                   │
  │  ┌──────────┐  ┌──────────┐  ┌──────────────────┐│
  │  │ Tile 1   │  │ Tile 2   │  │ Tile 3           ││
  │  │ Host CPU │  │ Error %  │  │ Response Time    ││
  │  │ [Chart]  │  │ [Number] │  │ [Line Graph]     ││
  │  └──────────┘  └──────────┘  └──────────────────┘│
  │  ┌──────────────────────┐  ┌─────────────────────┐│
  │  │ Tile 4              │  │ Tile 5              ││
  │  │ Top 10 Slowest      │  │ Active Problems     ││
  │  │ [Table]             │  │ [List]              ││
  │  └──────────────────────┘  └─────────────────────┘│
  └──────────────────────────────────────────────────┘

  Mỗi tile = 1 DQL query (có thể ẩn hoặc hiện)

Tính năng Dashboard

Tính năngChi tiết
Drag & DropKéo thả tiles, sắp xếp tự do
DQL-poweredMỗi tile chạy DQL query → hiển thị kết quả. Bạn có thể edit query trực tiếp
Time framesSet default time frame (VD: always show last 2 hours)
FiltersApply filters cho toàn dashboard hoặc per-tile
Real-timeData auto-refresh → luôn hiển thị latest data

Sharing & Collaboration

Khả năngChi tiết
Share với teamChia sẻ với members hoặc teams trong Dynatrace
Share externalChia sẻ với người KHÔNG có Dynatrace account — không cần login!
Edit sauUpdate titles, chart formats, filters, rename dashboard bất kỳ lúc nào

TIP

Fun fact cho thi: Dashboards có thể share với người KHÔNG có Dynatrace account. Câu hỏi dạng “can you share dashboards externally?” → Yes.

Phần 2: DQL — Dynatrace Query Language ⭐⭐ RẤT QUAN TRỌNG

DQL là gì?

DQL (Dynatrace Query Language) = ngôn ngữ query để kéo data từ Grail (data lakehouse). Cả Dashboards và Notebooks đều dùng DQL.

Lợi ích DQL

Lợi íchChi tiết
FasterLoad nhanh hơn cho large datasets so với Data Explorer
FlexibleQuery bất kỳ data nào trong Grail: logs, metrics, traces, events, business events
PowerfulFilter, aggregate, join, calculate — toàn bộ trong 1 query

Cấu Trúc DQL Query ⭐

DQL queries gồm các steps nối bằng pipe | (giống Unix pipe):

Giống như cho assistant chỉ thị từng bước:

  1. “Lấy tất cả logs”
  2. “Lọc chỉ giữ logs có từ ‘warning’”
  3. “Sắp xếp mới nhất lên trước”
  4. “Chỉ hiển thị 100 dòng đầu”

Ví Dụ DQL Queries Phổ Biến

Use caseDQL query
Logs có errorsfetch logs | filter loglevel == "ERROR"
Metrics CPU hostsfetch dt.host.cpu.usage | filter host.name == "web-prod-01"
Service response timefetch dt.service.request.response_time
Traces chậmfetch spans | filter duration > 5000000000

NOTE

Không cần viết DQL từ đầu! Dynatrace cung cấp:

  • Autocomplete: Gợi ý khi gõ
  • Templates: Query mẫu cho use cases phổ biến
  • Data Explorer → DQL: Convert visual charts thành DQL → learn by example

DQL có learning curve nhưng không cần là developer để dùng.

WARNING

DQL ảnh hưởng đến licensing — queries consume DDU (Davis Data Units). Lưu ý khi chạy queries lớn hoặc thường xuyên.

Phần 3: Notebooks ⭐

Notebooks là gì?

Notebooks = dashboards có memory — chúng capture data tại một thời điểm cụ thể (snapshot), KHÔNG auto-refresh.

So Sánh Dashboards vs Notebooks ⭐

DashboardsNotebooks
DataReal-time, auto-refreshSnapshot tại thời điểm chạy query
Mục đíchMonitor hiện tạiPhân tích lịch sử, so sánh qua thời gian
Ví dụ”Production đang thế nào?""Black Friday năm nay vs năm ngoái như thế nào?”
Re-run queryAuto-refreshCẢNH BÁO: re-run query = mất snapshot cũ!

Khi nào dùng Notebooks?

Tình huốngCách dùng
Post-incident reviewCapture data liên quan đến sự cố → analysis sau
Seasonal comparisonSnapshot Black Friday 2024 → so sánh với Black Friday 2025
Capacity planningGhi lại metrics hiện tại → so sánh với dự kiến future load
Knowledge sharingDocument analysis kèm queries → share với team

WARNING

Đừng re-run queries trong Notebook nếu bạn muốn giữ snapshot! Re-run = data mới thay thế data cũ → mất historical snapshot.

Phần 4: Logs & Traces Apps

Logs App

App chuyên dụng để explore log data từ Grail. Khác với việc viết DQL thủ công, Logs App cho giao diện UI để:

Tính năngChi tiết
Filter by log levelINFO, WARN, ERROR, FATAL
Search keywordsTìm logs chứa từ khóa hoặc cụm từ cụ thể
Security ContentRestrict access dựa trên user roles
Auto-generate DQLApp tự tạo DQL query từ filters bạn chọn → learn DQL

Traces App

App chuyên dụng để explore distributed traces (PurePaths). Cho phép:

  • Xem full request journey (từ user → services → database)
  • Filter theo duration, status, service name
  • Drill down vào từng span (segment) của trace

NOTE

Cả Logs App và Traces App đều đọc data từ Grail và có thể auto-generate DQL queries — giúp bạn vừa explore data vừa học DQL.

Knowledge Check

Q1: True or False — Dashboard Classic is no longer supported and has been fully replaced in the new Dynatrace platform.

  • ❌ False

Đáp án: False — Dashboard Classic vẫn được hỗ trợ, chưa bị thay thế hoàn toàn.

Tại sao False?

Dynatrace đang chuyển đổi dần từ Dashboard Classic sang Dashboards mới (powered by DQL). Tuy nhiên:

  • Dashboard Classic vẫn tồn tại và vẫn hoạt động trong nền tảng hiện tại
  • Dashboards mới (DQL-based) là hướng phát triển tương lai — nhiều tính năng hơn, flexible hơn
  • Dynatrace không đột ngột loại bỏ Classic — users vẫn có thể dùng cả hai

Đây là quá trình migration dần dần, không phải hard cutover. Nhiều organizations vẫn có Dashboard Classic tiles đang chạy.

💡 Lời khuyên thi: Nếu câu hỏi dùng từ “no longer supported” hoặc “fully replaced” → thường False. Dynatrace thường deprecated gradually, không remove đột ngột.

Q2: Which Dynatrace apps are specifically designed to help you explore raw observability data such as log entries or distributed traces?

  • ❌ Notebooks
  • ❌ Dashboards
  • ✅ Logs
  • ✅ Traces
  • ❌ Grail and DQL

Đáp án: Logs, Traces

Tại sao Logs và Traces đúng?

Câu hỏi nhấn mạnh “specifically designed” và “raw observability data”:

  • Logs App: Thiết kế CHUYÊN DỤNG để explore raw log entries — filter by level, search keywords, view individual log lines
  • Traces App: Thiết kế CHUYÊN DỤNG để explore distributed traces — xem request journey, duration, spans

Hai app này được build đặc biệt cho mục đích explore raw data, với UI tối ưu cho từng loại data.

Tại sao các lựa chọn khác sai?

  • Notebooks: Notebooks là tool phân tích chung (general-purpose analysis) — không “specifically designed” cho raw log/trace exploration. Notebooks CÓ THỂ hiển thị logs/traces qua DQL, nhưng đó không phải purpose chính.
  • Dashboards: Dashboards hiển thị visualized data (charts, graphs, summaries) — không phải raw data exploration. Dashboard cho thấy “overview”, không phải individual log lines.
  • Grail and DQL: Grail là storage engine và DQL là query language — chúng là infrastructure phía sau, không phải “apps designed to explore”. Logs App và Traces App SỬ DỤNG Grail + DQL bên dưới, nhưng câu hỏi hỏi về apps, không phải infrastructure.

💡 Lời khuyên thi: Phân biệt: Apps (Logs, Traces) = UIs để explore raw data. Tools (Dashboards, Notebooks) = general visualization/analysis. Infrastructure (Grail, DQL) = storage + query engine bên dưới.

Q3: Which of the following can you do when editing dashboards in Dynatrace?

  • A. Only rename dashboards but not change tiles.
  • B. Modify chart formats, update tile titles, and add/remove filters.
  • C. View static snapshots of data only.
  • D. Assign dashboards to Grail queries automatically.

Đáp án: B — Modify chart formats, update tile titles, and add/remove filters (Thay đổi format chart, cập nhật tile titles, và thêm/xóa filters).

Tại sao B đúng?

Dashboards trong Dynatrace rất flexible khi editing. Bạn có thể:

  • Modify chart formats: Đổi từ line chart → bar chart → pie chart → table
  • Update tile titles: Đổi tiêu đề tile cho dễ đọc
  • Add/remove filters: Thêm filter (host group, tag, service) hoặc xóa filter không cần
  • Drag & drop: Di chuyển, resize tiles
  • Edit DQL queries: Modify query bên dưới mỗi tile
  • Rename dashboard: Đổi tên toàn bộ dashboard

Giải thích các lựa chọn sai:

  • A. Only rename, not change tiles: Sai — bạn thay đổi rất nhiều thứ ngoài tên: charts, tiles, filters, queries, layout. Dashboards rất customizable.
  • C. Static snapshots only: Đây mô tả Notebooks (snapshots), không phải Dashboards. Dashboards hiển thị real-time data, auto-refresh liên tục.
  • D. Assign to Grail queries automatically: Mỗi tile đã chứa DQL query. Bạn không “assign dashboard to Grail query” — bạn tạo tiles với DQL queries bên trong. Mối quan hệ là ngược: tile chứa query, không phải dashboard được assign cho query.

💡 Lời khuyên thi: Dashboards = fully editable (charts, tiles, filters, queries, layout, names). Cụm từ “only” hoặc “static” trong đáp án về Dashboards → thường sai.

Q4: What makes Notebooks different from Dashboards in Dynatrace?

  • A. They support real-time auto-refresh.
  • B. They are only available on the classic interface.
  • C. They save fixed snapshots of data at a point in time.
  • D. They can only display one metric at a time.

Đáp án: C — They save fixed snapshots of data at a point in time (Lưu snapshot cố định của data tại một thời điểm).

Tại sao C đúng?

Đây là sự khác biệt cốt lõi giữa Notebooks và Dashboards:

DashboardsNotebooks
Data refreshAuto-refresh liên tụcKhông auto-refresh — giữ data tại thời điểm query chạy
Tính chấtReal-time, luôn currentSnapshot — “frozen in time”
Use case”Hiện tại đang thế nào?""Black Friday diễn ra như thế nào?”

Notebooks “freeze” data → cho phép so sánh historical (VD: Cyber Monday 2024 vs 2025). Nếu dashboard auto-refresh → bạn mất data cũ. Notebooks giữ lại.

Giải thích các lựa chọn sai:

  • A. Support real-time auto-refresh: Ngược lại — đặc điểm này thuộc Dashboards, không phải Notebooks. Notebooks KHÔNG auto-refresh — đó chính là lợi thế của chúng (giữ snapshot).
  • B. Only on classic interface: Sai — Notebooks là tính năng mới trên nền tảng Dynatrace hiện đại, không phải classic interface. Classic interface có Dashboard Classic, không phải Notebooks.
  • D. Only one metric at a time: Sai — Notebooks hiển thị nhiều queries, metrics, charts — giống dashboard nhưng không auto-refresh. Không có giới hạn 1 metric.

💡 Lời khuyên thi: Notebooks = snapshot/frozen data. Dashboards = real-time/auto-refresh. Keyword cho Notebooks: “point in time”, “snapshot”, “historical comparison”.

Q5: Which of the following statements about DQL are true? (Select all that apply)

  • ✅ It uses commands like fetch and filter.
  • ❌ You must be a Dynatrace Administrator to use DQL.
  • ✅ It communicates directly with Grail.
  • ❌ It cannot be used on Dashboards.

Đáp án: “It uses commands like fetch and filter” + “It communicates directly with Grail”

Tại sao 2 đáp án trên đúng?

1. “Uses commands like fetch and filter” ✅

  • DQL syntax = fetch (lấy data) + filter (lọc) + pipe | để nối steps
  • VD: fetch logs | filter loglevel == "ERROR" — đây là cấu trúc cơ bản nhất
  • Ngoài ra còn: sort, limit, summarize, fields, join…

2. “Communicates directly with Grail” ✅

  • DQL query trực tiếp truy vấn Grail (data lakehouse)
  • Grail chứa TẤT CẢ observability data (logs, metrics, traces, events)
  • DQL → Grail → results. Không qua trung gian nào khác

Tại sao các lựa chọn khác sai?

  • “Must be Administrator to use DQL” ❌: Bất kỳ user nào có quyền truy cập Dynatrace đều có thể viết và chạy DQL queries (tùy thuộc data access permissions). Không cần quyền Administrator. DQL được thiết kế cho mọi user — từ operators đến analysts.

  • “Cannot be used on Dashboards” ❌: Ngược lại — Dashboards mới dựa hoàn toàn trên DQL! Mỗi tile trong Dashboard chạy một DQL query bên dưới. DQL là foundation của Dashboards, chắc chắn có thể dùng trên Dashboards.

💡 Lời khuyên thi: DQL = fetch + filter + pipe → query Grail trực tiếp. Dùng được ở mọi nơi (Dashboards, Notebooks, Logs App, Traces App). KHÔNG cần admin rights.
