Phần 1: Tại Sao Dynatrace Tồn Tại?

Application Observability là gì?

Application = phần mềm thực hiện các tác vụ hỗ trợ business (website, hệ thống nội bộ, mobile app…).

Observability = khả năng hiểu được tình trạng, hiệu suất, và hành vi của ứng dụng từ bên trong ra ngoài.

NOTE

Monitoring vs Observability:

MonitoringObservability
Cho biếtTriệu chứng (response time chậm, error rate tăng)Tại sao triệu chứng xảy ra
Ví dụ”CPU 95%""CPU 95% vì query SQL chưa tối ưu gây full table scan”
Ví vonSmartwatch hiển thị nhịp tim caoBác sĩ nói “nhịp tim cao vì thiếu nước, cần uống nhiều hơn”

→ Monitoring = xem số liệu. Observability = hiểu ý nghĩa và hành động.

Tool Consolidation — Gộp Nhiều Tool Thành Một

Vấn đề: Truyền thống cần nhiều tool riêng biệt:

  • 1 tool cho infrastructure monitoring
  • 1 tool cho log collection
  • 1 tool cho network performance
  • 1 tool cho user experience
  • → Phải cài, cấu hình, cập nhật, quản lý license cho TỪNG tool

Giải pháp: Dynatrace gộp tất cả vào một nền tảng duy nhất (tool consolidation).

Lợi ích:

  • ✅ Ít tool hơn → giảm complexity và chi phí vận hành
  • ✅ Team tập trung vào cải thiện performance & user experience thay vì quản lý tool
  • ✅ Giảm licensing, maintenance, setup
  • ✅ Một giao diện duy nhất — không phải nhảy giữa nhiều dashboards

TIP

Ví von: Dynatrace giống như smartphone — thay thế camera, GPS, máy tính, đồng hồ… tất cả trong một thiết bị. Dynatrace gộp logs, metrics, traces, insights vào một platform duy nhất.

Phần 2: Dynatrace Hoạt Động Như Thế Nào?

Dynatrace giúp hiểu những gì đang xảy ra bên trong ứng dụng, hạ tầng, và trải nghiệm số — tự động và real-time. Để làm được điều này, Dynatrace cần thu thập data qua nhiều cách:

OneAgent — Bộ Thu Thập Dữ Liệu

OneAgent là phần mềm cài trên mỗi host để thu thập tất cả telemetry data:

OneAgent thu thập:
  ├── Metrics   (CPU, RAM, response time, error rate...)
  ├── Logs      (application logs, system logs)
  ├── Traces    (distributed traces / PurePath)
  ├── Events    (security, business, deployment...)
  └── Topology  (process, service, dependency discovery)

Đặc điểm:

  • Cài đặt đơn giản: download → chạy installer → tự động bắt đầu thu thập
  • Auto-instrumentation: không cần thay đổi code ứng dụng
  • Gửi data về Dynatrace platform qua HTTPS

ActiveGate — Điểm Trung Chuyển An Toàn

Vấn đề: OneAgent gửi data trực tiếp

Nếu mỗi OneAgent kết nối trực tiếp đến Dynatrace qua internet → cần mở firewall rule cho từng server. Với 5, 10, hay hàng trăm servers → quản lý firewall trở nên phức tạp.

Giải pháp: ActiveGate làm proxy

KHÔNG có ActiveGate:
  Server 1 (OneAgent) ──firewall──→ Internet → Dynatrace
  Server 2 (OneAgent) ──firewall──→ Internet → Dynatrace
  Server 3 (OneAgent) ──firewall──→ Internet → Dynatrace
  → Cần 3 firewall rules riêng biệt

CÓ ActiveGate:
  Server 1 (OneAgent) ──→ ┐
  Server 2 (OneAgent) ──→ ├→ ActiveGate ──firewall──→ Dynatrace
  Server 3 (OneAgent) ──→ ┘
  → Chỉ cần 1 firewall rule cho ActiveGate

TIP

Ví von bưu điện:

  • Không có ActiveGate = mỗi người tự đặt vé máy bay gửi thư ra nước ngoài → tốn kém, phức tạp
  • Có ActiveGate = mọi người gửi thư đến bưu điện → bưu điện gom, sắp xếp, gửi hàng loạt an toàn

ActiveGate = bưu điện của Dynatrace

Lợi ích của ActiveGate:

Lợi íchChi tiết
Bảo mậtChỉ traffic một chiều đi ra, server không bị expose
Hiệu suấtGiảm traffic, gom data trước khi gửi
Dễ quản lýChỉ cần 1 firewall rule cho ActiveGate
Kiểm soátQuyết định data nào được gửi, khi nào gửi
Mở rộngThêm server mới chỉ cần trỏ đến ActiveGate sẵn có

Phần 3: Ba Trụ Cột Của Observability

Metrics — Số Liệu Đo Lường

Metrics là các phép đo thu thập từ hệ thống theo thời gian.

Ví dụÝ nghĩa
CPU usage: 85%Server đang chịu tải cao
Response time: 2.5sỨng dụng phản hồi chậm
Error rate: 5%5% requests gặp lỗi
Active users: 1,2001,200 người đang dùng

→ Metrics cho bức tranh tổng quan về tình trạng hệ thống. Khi số liệu tăng/giảm đột ngột → tín hiệu đầu tiên cho thấy có vấn đề.

Logs — Nhật Ký Sự Kiện

Logs ghi lại các sự kiện xảy ra theo thời gian — ai làm gì, khi nào, và kết quả thế nào.

[10:32:15] INFO  - User "john" logged in successfully
[10:32:18] INFO  - User "john" added item #4521 to cart
[10:32:45] ERROR - Payment failed: timeout connecting to payment gateway
[10:33:01] WARN  - Retry payment attempt #2 for order #9876

→ Logs cho câu chuyện chi tiết — ghi lại mọi thứ đang xảy ra bên trong ứng dụng.

Traces — Theo Dõi Hành Trình Request

Traces theo dõi đường đi của một request xuyên suốt toàn bộ hệ thống.

User click "Buy Now"
  │
  ├── Web Server:        1 giây  ✅
  ├── Middleware Server:  1 giây  ✅
  └── Database Server:   4 giây  ⚠️ ← BOTTLENECK!
                         ────────
                  Tổng:  6 giây

→ Nhờ trace, biết ngay database là điểm nghẽn

→ Traces cho biết ở đâu thời gian bị tốn và tại sao request chậm.

Tổng Hợp Ba Trụ Cột

Trụ cộtTrả lời câu hỏiVí von
Metrics”Có gì bất thường?”Nhiệt kế — cho biết có sốt
Logs”Chuyện gì đã xảy ra?”Bệnh án — ghi chi tiết diễn biến
Traces”Vấn đề ở đâu?”X-ray — chỉ ra đúng chỗ bị tổn thương

IMPORTANT

Dynatrace thu thập cả 3 trụ cột TỰ ĐỘNG (out of the box) sau khi cài OneAgent.

Ngoài ra, Dynatrace còn thu thập thêm:

  • Security events — phát hiện vulnerabilities
  • Business events — tracking hoạt động kinh doanh
  • Deployment events — ghi nhận các lần deploy

Phần 4: Root Cause Determination — Tìm Nguyên Nhân Gốc

Vấn đề

Biết website chậm thì tốt, nhưng biết TẠI SAO chậm mới thực sự hữu ích.

Có rất nhiều nguyên nhân có thể:

  1. Update gần đây gây ra bug
  2. Traffic tăng đột biến, quá nhiều người truy cập cùng lúc
  3. Lỗi mạng làm gián đoạn giao tiếp giữa các hệ thống

Dynatrace Root Cause Analysis

Dynatrace không chỉ cảnh báo có vấn đề — mà còn chỉ ra nguyên nhân gốc.

Ví dụ thực tế:

Bạn chạy khuyến mãi “Mua kính thiên văn tặng bản đồ sao”. Vài phút sau, Dynatrace báo website chậm.

Bạn hoảng: “Có phải khuyến mãi làm hỏng gì không? Có nên gỡ xuống?”

Nhưng khi xem alert, bạn thấy nguyên nhân thực sự: traffic tăng đột biến — khuyến mãi quá thành công, quá nhiều người mua cùng lúc.

Giải pháp: Thêm servers để xử lý tải. Không cần gỡ khuyến mãi. Không cần đoán mò.

TIP

Ví von bác sĩ:

  • Monitoring = bạn biết mình bị sổ mũi (triệu chứng)
  • Root Cause Analysis = bác sĩ nói “đây là cảm lạnh thường, uống thuốc 3 ngày là khỏi” (nguyên nhân + giải pháp)

Davis AI của Dynatrace chính là “bác sĩ” — tự động tìm root cause thay vì chỉ báo triệu chứng.

Knowledge Check

Q1: What is the purpose of root cause analysis in Dynatrace?

  • A. To generate traffic for a website
  • B. To suggest design improvements
  • C. To identify WHY an issue is occurring
  • D. To collect metrics

Đáp án: C — To identify WHY an issue is occurring (Xác định TẠI SAO vấn đề đang xảy ra).

Tại sao C đúng?

Root cause analysis (RCA) là khả năng cốt lõi phân biệt Dynatrace với monitoring truyền thống:

  • Monitoring thông thường: CPU 95% → alert → bạn tự đi tìm nguyên nhân
  • Dynatrace RCA: CPU 95% → tìm thấy query SQL chưa tối ưu gây full table scan → chỉ ra đúng chỗ cần fix

Davis AI sử dụng topology mapping (Smartscape) để traverse dependency chain → tìm entity gốc gây ra vấn đề, không chỉ báo triệu chứng.

Giải thích các lựa chọn sai:

  • A. Generate traffic: Dynatrace không tạo traffic — nó giám sát traffic. Synthetics tạo simulated traffic để test, nhưng đó không phải purpose của RCA.
  • B. Suggest design improvements: Dynatrace tìm performance issues, không phải đề xuất cải tiến thiết kế UI/UX. Design improvements là việc của product team.
  • D. Collect metrics: Thu thập metrics là việc của OneAgent, không phải RCA. RCA sử dụng metrics đã thu thập để tìm nguyên nhân.

💡 Lời khuyên thi: RCA = WHY (tại sao). Monitoring = WHAT (cái gì xảy ra). Dynatrace làm cả hai, nhưng RCA là giá trị khác biệt chính.

Q2: How does ActiveGate simplify OneAgent traffic? (Select all that apply)

  • ✅ It collects data from multiple OneAgents
  • ✅ It reduces the number of firewall rules needed
  • ❌ It manages user logins for applications
  • ❌ ActiveGate never interacts with OneAgents

Đáp án: “Collects data from multiple OneAgents” + “Reduces firewall rules”

Tại sao 2 đáp án trên đúng?

ActiveGate = proxy trung gian giữa OneAgents và Dynatrace cloud:

  1. Collects from multiple OneAgents ✅: Tất cả OneAgents trong network gửi data đến ActiveGate thay vì gửi trực tiếp ra internet. ActiveGate gom data, compress, rồi forward đến Dynatrace.

  2. Reduces firewall rules ✅: Không cần mở firewall cho từng server — chỉ cần 1 rule cho ActiveGate. Với 100 servers → thay vì 100 rules → chỉ cần 1 rule.

Giải thích các lựa chọn sai:

  • Manages user logins: ActiveGate xử lý monitoring data traffic, không phải application user authentication. Login management thuộc application logic.
  • Never interacts with OneAgents: Hoàn toàn ngược — ActiveGate tương tác trực tiếp với OneAgents. OneAgents gửi data ĐẾN ActiveGate. Đây là chức năng chính của ActiveGate.

💡 Lời khuyên thi: ActiveGate = proxy/relay cho OneAgent traffic. 2 keywords: collect (gom data) + reduce firewall (giảm rules). ActiveGate KHÔNG phải load balancer hay reverse proxy cho user traffic.

Q3: What does a trace do in Dynatrace?

  • A. It monitors CPU and memory usage over time
  • B. It follows a specific request through all parts of an application to identify delays or errors
  • C. It stores user feedback for analysis
  • D. It collects static configuration data from an application

Đáp án: B — It follows a specific request through all parts of an application to identify delays or errors.

Tại sao B đúng?

Trong Dynatrace, trace (gọi là PurePath) theo dõi hành trình end-to-end của một request:

User click "Buy Now"
  → Web Server (1s) → App Server (1s) → Database (4s)
                                          ↑ BOTTLENECK

Trace cho thấy ở đâu thời gian bị tốn → pinpoint delay chính xác đến service/method level. Đây là distributed tracing — theo dõi request xuyên suốt nhiều services và technologies.

Giải thích các lựa chọn sai:

  • A. CPU and memory over time: Đây là metrics, không phải traces. Metrics đo lường tổng quan; traces theo dõi từng request riêng lẻ.
  • C. Stores user feedback: Dynatrace không thu thập “user feedback” (ý kiến người dùng). Session Replay ghi lại interactions nhưng không phải purpose của traces.
  • D. Static configuration data: Traces ghi dynamic request flow (runtime), không phải static config. Configuration discovery thuộc về OneAgent auto-detection.

💡 Lời khuyên thi: Nhớ 3 trụ cột: Metrics = đo lường tổng quan, Logs = ghi sự kiện, Traces = theo dõi request journey. Traces = PurePaths trong Dynatrace.

Q4: What are the benefits of tool consolidation? (Select all that apply)

  • ✅ Fewer tools reduce complexity and operational costs
  • ❌ Multiple specialized tools are needed for full observability
  • ✅ Teams can focus on improving performance and user experience
  • ✅ Licensing, maintenance, and setup are simplified with a single solution

Đáp án: 3 lựa chọn đúng (Fewer tools + Teams focus + Licensing simplified)

Tại sao 3 đáp án trên đúng?

Tool consolidation = gộp nhiều monitoring tools riêng lẻ vào 1 nền tảng duy nhất (Dynatrace). Lợi ích:

  1. Fewer tools → less complexity ✅: Thay vì manage 5-6 tools riêng biệt (infrastructure, APM, logs, RUM, synthetics), chỉ cần 1 platform → giảm complexity, training, vendor management.

  2. Teams focus on value ✅: Không tốn thời gian cài đặt, cấu hình, cập nhật nhiều tools → dành thời gian cải thiện products và user experience.

  3. Simplified licensing ✅: 1 vendor, 1 contract, 1 license model thay vì negotiate nhiều vendors → giảm chi phí tổng, dễ budget.

Giải thích lựa chọn sai:

  • Multiple specialized tools needed: Ngược lại — đây chính là vấn đề mà tool consolidation giải quyết. Dynatrace cung cấp full observability (metrics + logs + traces + RUM + synthetics + security) trong 1 platform, không cần multiple tools.

💡 Lời khuyên thi: Tool consolidation = core value proposition của Dynatrace. Keywords: single platform, reduce complexity, focus on value.
