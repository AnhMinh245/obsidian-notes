What role does Grail play for Davis AI?

  • A. Kho training data để fine-tune Davis AI model
  • B. Filter layer loại bỏ Davis AI alert trước khi chúng đến tay người dùng

Davis AI đọc từ Grail tại runtime. Grail lưu trữ telemetry, Smartscape lưu trữ topology, và Davis AI suy luận xuyên cả hai.

What role do buckets play inside Grail?

Câu hỏi 3 — fields vs filter command

What is the difference between the fields command and the filter command in DQL?

  • A. fields kích hoạt data ingestion còn filter kích hoạt data export ra file
  • B. fields loại bỏ row khỏi result set còn filter project các column cần hiển thị
  • C. fields chỉ hợp lệ ở cuối query còn filter chỉ hợp lệ ở đầu query
  • D. fields project hoặc trim các column hiển thị của mỗi record, còn filter loại bỏ các record không khớp với điều kiện
  • E. fields và filter là synonym trong DQL, tạo ra output giống hệt nhau trong mọi ngữ cảnh

💡 Đáp án & Giải thích

✅ Đáp án đúng: D

#Kết quảGiải thích
A❌DQL là read-only language trên dữ liệu Grail. Cả hai command không ingest hay export dữ liệu; chúng định hình query result trong memory.
B❌Đây là đảo ngược nghĩa đúng. fields định hình column và filter định hình row, không phải ngược lại.
C❌Cả hai command có thể xuất hiện tại nhiều vị trí trong pipeline. filter thường được áp dụng sớm cho hiệu quả, nhưng không có rule cố định về vị trí.
D✅Đúng. fields hoạt động trên column (như SQL SELECT’s column list); filter hoạt động trên row (như SQL WHERE).
E❌Chúng là hai command riêng biệt với hiệu ứng khác nhau. fields hoạt động trên column (projection); filter hoạt động trên row (selection).

Giải thích tổng thể:
fields định hình column (projection), filter định hình row (selection). Các command liên quan bao gồm fieldsAdd, fieldsRemove, và fieldsKeep.

Câu hỏi 6 — DQL time range keywords

  • B. lastMinute và lastHour

  • D. start và end

Giải thích tổng thể:

Câu hỏi 7 — DQL vs USQL

How does DQL compare to the older USQL query language in Dynatrace?

  • A. DQL là unified query language xuyên tất cả Grail data type, trong khi USQL nhắm vào data model user-session hẹp hơn
  • B. Cả DQL và USQL đang bị deprecated để chuyển sang standard SQL trên toàn platform
  • C. USQL có thể query Grail natively mà không cần translation hay compatibility layer nào
  • D. DQL đơn giản là bản đổi tên của USQL, với syntax giống hệt và query semantic được giữ nguyên

💡 Đáp án & Giải thích

✅ Đáp án đúng: A

#Kết quảGiải thích
A✅Đúng. USQL được scoped cho user-session analytics trên một dataset cụ thể, trong khi DQL span logs, metrics, traces, events, và nhiều hơn trong Grail.

Giải thích tổng thể:
USQL query legacy user-sessions data model; DQL query toàn bộ Grail lakehouse. DQL là unified language xuyên tất cả data type.

  • Mặc định restrictive — cần explicit policy mới được read
  • Policy scope được xuống: bucket, data type, field-level condition (DQL-expressed predicate)
  • API token đi qua IAM check — không có bypass
  • OS firewall ≠ Grail access control; IAM quản lý Grail access

🔄 Grail + Davis AI + OpenPipeline

  • Davis AI đọc từ Grail tại runtime — Grail không train Davis AI models
  • OpenPipeline nằm TRƯỚC Grail: parse → enrich → mask → sample → route vào bucket đúng
    • Field redaction/PII masking tại ingest (không phải tại query time)
    • Routing khác nhau: security logs → long retention bucket; dev logs → short retention bucket
  • Extended Retention for DQL: mở rộng DQL-queryable horizon vượt default window — hỗ trợ trend, seasonality, year-over-year analysis

🔗 OpenTelemetry + Grail

  • OTel logs, metrics, traces ingest first-class vào Grail
  • Query bằng cùng DQL, sống cạnh OneAgent-collected data
  • OTel ≠ storage layer; Grail mới là nơi lưu trữ

⚡ Các điểm hay nhầm lẫn

  • filter ≠ where (SQL) — DQL dùng filter
  • fetch ≠ select — DQL dùng fetch để bắt đầu query
  • summarize ≠ aggregate hay group — DQL dùng summarize
  • parse với DPL là cách extract structured fields từ unstructured log — không phải split() hay extractJson()
  • Cross-signal correlation TRONG một query là lợi thế chính của unified storage — không phải latency hay deduplication
  • Business events = first-class Grail data type (không cần convert thành metrics để store)
