Câu hỏi 1 — Signals OneAgent đóng góp

Which of the following signals does OneAgent contribute to Dynatrace? (Select all that apply)

  • A. Distributed traces with propagated request context
  • B. Logs collected from files and container stdout on the host
  • C. Git commit history from the organization’s source-code server
  • D. Markdown runbooks stored in the team wiki
  • E. Host and process metrics such as CPU, memory, and disk

💡 Đáp án & Giải thích

✅ Đáp án đúng: A, B, E

#Kết quảGiải thích
A✅Đúng. Distributed trace với context propagation tự động là một trong những tín hiệu nổi bật của OneAgent.
B✅Đúng. Module log của OneAgent có thể thu thập log từ file trên host và stdout của container, tùy cấu hình.
C❌Lịch sử Git thuộc công cụ phát triển, không phải dữ liệu telemetry từ agent.
D❌Nội dung runbook nằm trong wiki/knowledge base, không phải tín hiệu observability.
E✅Đúng. Đây là metrics nền tảng mà OneAgent thu trên mọi host được monitor.

Giải thích tổng thể:
OneAgent đóng góp metrics, trace, log cùng topology và ngữ cảnh entity. Runbook và lịch sử Git không phải tín hiệu telemetry.

Liên kết: OneAgent · Distributed Tracing · Grail

Câu hỏi 2 — Xác nhận OneAgent cài đặt và báo cáo

How can an operator confirm that OneAgent is installed and reporting from a given host?

  • A. By inspecting the cloud provider’s billing console for agent line items
  • B. Through the Hosts view in the UI, cross-checked against the OS service list
  • C. By opening a support ticket and asking Dynatrace to confirm agent state remotely
  • D. Exclusively through a mobile app view, since the web UI does not surface agent state

💡 Đáp án & Giải thích

✅ Đáp án đúng: B

#Kết quảGiải thích
A❌Console billing chỉ hiển thị chi phí, không phản ánh health của agent. OneAgent báo cáo lên Dynatrace, không qua billing cloud provider.
B✅Đúng. UI có trạng thái OneAgent theo host; trên host có thể thấy service OneAgent (daemon Linux hoặc Windows service) khi agent đang chạy.
C❌Ticket support không phải lối xác minh chuẩn. Operator có visibility trực tiếp từ UI và từ host.
D❌Web UI có hiển thị trạng thái agent; app mobile chỉ mirror. Giới hạn chỉ mobile là sai.

Giải thích tổng thể:
Xác minh OneAgent kết hợp kiểm tra phía platform (Hosts view trong UI) và phía host (service/process list OS). Hai phía khớp nhau thì agent đang healthy và reporting.

Liên kết: OneAgent · Hosts

Câu hỏi 3 — Metrics là tín hiệu gì

Which description matches metrics as an observability signal?

  • A. Structured spans that form a parent-child tree of operations over a request
  • B. Security findings from vulnerability scans run against applications each week
  • C. Numeric measurements over time, such as CPU, latency, and error rate
  • D. Unstructured text messages emitted by applications at various runtime moments

💡 Đáp án & Giải thích

✅ Đáp án đúng: C

#Kết quảGiải thích
A❌Cây span cha-con mô tả trace. Metrics là loại tín hiệu khác, không có cấu trúc cây đó.
B❌Kết quả quét bảo mật là loại dữ liệu riêng. Metrics là chuỗi thời gian số, độc lập với security tooling.
C✅Đúng. Metrics là đo lường số có timestamp theo thời gian; chúng là nền cho SLO, dashboard và alerting.
D❌Text không cấu trúc mô tả log, không phải metrics. Metrics là số và gắn thời gian.

Giải thích tổng thể:
Metrics là đo lường số theo thời gian. Chúng hỗ trợ phân tích xu hướng, alerting và tính SLO, và kết hợp gọn với các tín hiệu khác trong Grail.

Liên kết: Metrics · Grail · Logs · Distributed Tracing

Câu hỏi 4 — Distributed tracing và service graph

How does OneAgent support distributed tracing across a service graph?

  • A. Only the initial browser click is captured, with nothing stitched on the server side
  • B. Developers must pass trace IDs manually in every request header themselves
  • C. Tracing is limited to database queries, ignoring application code paths entirely
  • D. By propagating trace context across service boundaries and stitching spans
  • E. Spans are emitted as flat log lines instead of a structured trace tree

💡 Đáp án & Giải thích

✅ Đáp án đúng: D

#Kết quảGiải thích
A❌Thu phía browser thuộc RUM. Giá trị trace của OneAgent chủ yếu ở server-side xuyên service và dependency.
B❌Không cần gắn trace-id thủ công; OneAgent instrumentation truyền context tự động.
C❌Trace bao phủ luồng request xuyên service và dependency, không chỉ tầng database.
D✅Đúng. OneAgent xử lý context propagation để span từ nhiều service ghép thành một distributed trace — nền tảng phân tích kiểu PurePath.
E❌OneAgent phát span có cấu trúc và ghép thành cây trace, không phải log phẳng.

Giải thích tổng thể:
OneAgent thu span và propagate context tự động, nhờ đó các service trong hệ phân tán nằm trong một trace end-to-end thống nhất.

Liên kết: OneAgent · Distributed Tracing · PurePath

Câu hỏi 5 — Triển khai classic trên OS

In its classic host deployment, what form does OneAgent take on the operating system?

  • A. A browser extension installed by each end user on their own workstation
  • B. A SaaS-only feature with nothing actually installed on the host itself
  • C. An OS-level agent installed as a service or daemon on the host
  • D. A Kubernetes-only sidecar container that cannot run outside a cluster

💡 Đáp án & Giải thích

✅ Đáp án đúng: C

#Kết quảGiải thích
A❌Extension chạy trong browser. OneAgent chạy trên server nơi workload thực thi.
B❌SaaS mô tả nơi platform chạy; OneAgent vẫn là thành phần cài trên host.
C✅Đúng. Cài dưới dạng systemd trên Linux hoặc Windows service, rồi attach vào process được monitor.
D❌OneAgent hỗ trợ host/VM/container cổ điển, không chỉ sidecar Kubernetes.

Giải thích tổng thể:
OneAgent chạy như service cấp OS trên host. Trên Kubernetes, Dynatrace Operator đặt agent lên từng node, vẫn là thành phần cấp OS.

Liên kết: OneAgent · Dynatrace Operator · Kubernetes

Câu hỏi 6 — Trách nhiệm chính của OneAgent

What is Dynatrace OneAgent primarily responsible for on the systems where it runs?

  • A. Rendering dashboards and generating PDF reports from ingested telemetry
  • B. Replacing the cloud provider’s IAM and cost-management console
  • C. Auto-instrumenting workloads and shipping metrics, traces, and logs
  • D. Orchestrating CI/CD pipelines across the environments it observes

💡 Đáp án & Giải thích

✅ Đáp án đúng: C

#Kết quảGiải thích
A❌Dashboard và báo cáo thuộc UI. OneAgent là tầng thu thập bên dưới.
B❌IAM và billing là phạm vi nhà cung cấp/platform, ngoài phạm vi OneAgent.
C✅Đúng. OneAgent instrument process trên host và stream telemetry cùng ngữ cảnh entity lên platform.
D❌Điều phối pipeline thuộc Jenkins/GitHub Actions… OneAgent quan sát triển khai, không chạy pipeline.

Giải thích tổng thể:
OneAgent là agent thu thập và auto-instrumentation phía host: discover process, bắt telemetry đa tín hiệu, gắn entity context trước khi gửi dữ liệu lên platform.

Liên kết: OneAgent · Grail

Câu hỏi 7 — Vai trò ActiveGate

Which of these are valid roles ActiveGate can play in the Dynatrace architecture? (Select all that apply)

  • A. Host for extensions and integrations that pull metrics from external systems
  • B. Proxy that lets OneAgents in a private network reach the Dynatrace cluster
  • C. Replacement for Grail as the primary storage layer for long-horizon telemetry data
  • D. Workstation-side component installed on analyst laptops to cache dashboard renders locally

💡 Đáp án & Giải thích

✅ Đáp án đúng: A, B

#Kết quảGiải thích
A✅Đúng. Extension trên ActiveGate kéo metrics/event từ SNMP, cloud API, database và nguồn tương tự.
B✅Đúng. ActiveGate thường dùng làm proxy và điểm tổng hợp cho OneAgent trong mạng riêng hoặc bị hạn chế egress.
C❌Grail là tầng lưu trữ. ActiveGate là gateway và host tích hợp, không thay storage.
D❌ActiveGate là gateway phía server, không phải tiện ích trên laptop. Render dashboard diễn ra trên tenant, không cache local kiểu đó.

Giải thích tổng thể:
ActiveGate thường là proxy trong mạng cho OneAgent và là nơi chạy extension. Nó không phải storage layer hay component phía client workstation.

Câu hỏi 8 — Best practice ingest ở quy mô lớn

Which of these are recommended practices when enabling data ingestion across a large production estate? (Select all that apply)

  • A. Apply per-bucket retention so hot data stays short while rare data stays long
  • B. Use OpenPipeline to enrich, mask, or route data before it lands in Grail
  • C. Raise OneAgent sampling to the highest available rate on every host so downstream analytics always see the most detailed picture of each workload
  • D. Filter obviously irrelevant events (debug noise from dev namespaces) before ingest
  • E. Sample high-volume log sources at ingest to drop predictable low-value lines
  • F. Pin topology discovery to a nightly scan cadence so Smartscape reflects a consistent daily snapshot rather than updating continuously as entities come and go

💡 Đáp án & Giải thích

✅ Đáp án đúng: A, B, D, E

#Kết quảGiải thích
A✅Đúng. Retention theo bucket là lever chuẩn để cân bằng chi phí lưu trữ và giá trị phân tích.
B✅Đúng. OpenPipeline là chỗ được hỗ trợ để parse, enrich, mask, sample và route trước khi dữ liệu vào Grail.
C❌Sampling tối đa đồng loạt phá economics ingest ở quy mô lớn và tạo chi tiết dư thừa. Nên sample có chọn lọc nguồn high-volume tại ingest.
D✅Đúng. Lọc sự kiện giá trị thấp ở nguồn hoặc pipeline giúp giữ signal-to-noise.
E✅Đúng. Sample log high-volume, low-value tại ingest là practice kiểm soát chi phí phổ biến.
F❌Smartscape thiết kế để topology cập nhật liên tục. Chỉ quét đêm làm ngữ cảnh cũ đúng lúc autoscale/deploy cần dữ liệu mới.

Giải thích tổng thể:
Ở quy mô lớn, chiến lược ingest kết hợp retention theo bucket, sampling, lọc phía nguồn và xử lý OpenPipeline. Ingest tất cả không lọc và “đóng băng” topology là anti-pattern.

Liên kết: OpenPipeline · Grail · Grail Buckets · OneAgent · Smartscape

Câu hỏi 9 — Cập nhật OneAgent

Which statement about OneAgent updates is accurate?

  • A. Availability is restricted to Windows hosts, with no Linux or container support
  • B. Reinstalling the host operating system from scratch is required for each update
  • C. Central management from the Dynatrace environment with phased rollout support
  • D. Recompiling every monitored application with a new agent SDK is required

💡 Đáp án & Giải thích

✅ Đáp án đúng: C

#Kết quảGiải thích
A❌Cập nhật OneAgent có trên mọi nền tảng được hỗ trợ, không giới hạn Windows.
B❌Không cần cài lại OS. Cập nhật agent là gói/cách triển khai chuẩn, không phải rebuild host.
C✅Đúng. Chính sách cập nhật và rollout theo giai đoạn điều khiển từ environment — cách các fleet lớn giữ phiên bản agent đồng bộ.
D❌Không cần biên dịch lại ứng dụng. OneAgent attach vào runtime đang chạy, không link tĩnh vào build.

Giải thích tổng thể:
Cập nhật OneAgent quản lý tập trung với hỗ trợ phased rollout. Platform team chuẩn hóa phiên bản fleet mà không reinstall OS hay recompile app.

Liên kết: OneAgent

Câu hỏi 10 — Giao thức export OpenTelemetry

Which protocol does OpenTelemetry use to export telemetry to a backend such as Dynatrace?

  • A. SNMPv3 polling from the Dynatrace cluster back to the application hosts
  • B. SMTP over TLS, reusing the mail-server transport across hops
  • C. OTLP, carried over gRPC or HTTP with Protobuf payloads
  • D. FTP with batched trace files uploaded during overnight windows only

💡 Đáp án & Giải thích

✅ Đáp án đúng: C

#Kết quảGiải thích
A❌SNMP dùng quản trị hạ tầng, không phải transport cho dữ liệu OpenTelemetry.
B❌SMTP là giao thức mail, không liên quan telemetry export.
C✅Đúng. OTLP là định dây của OpenTelemetry; endpoint ingest Dynatrace nhận OTLP cho trace, metrics và logs.
D❌OpenTelemetry không dùng FTP batch qua đêm; export là real-time hoặc gần real-time qua OTLP.

Giải thích tổng thể:
OTLP là wire format OpenTelemetry, chạy trên gRPC hoặc HTTP với payload Protobuf. Dynatrace nhận OTLP trực tiếp và qua OpenTelemetry Collector.

Liên kết: OpenTelemetry · OTLP · Grail

Câu hỏi 11 — OneAgent vs OpenTelemetry Collector

What is the key difference between Dynatrace OneAgent and the OpenTelemetry Collector?

  • A. The Collector writes to its own proprietary storage that Dynatrace cannot read back
  • B. OneAgent handles only logs, while the OTel Collector handles only metrics exclusively
  • C. The OTel Collector runs only inside web browsers as a JavaScript library at page load
  • D. OneAgent is Dynatrace-native deep instrumentation; the Collector is a neutral pipeline
  • E. They are functionally identical and fully interchangeable in every deployment pattern

💡 Đáp án & Giải thích

✅ Đáp án đúng: D

#Kết quảGiải thích
A❌Collector không lưu trữ dữ liệu; nó là thành phần pipeline chuyển tiếp telemetry tới backend.
B❌Cả hai đều xử lý nhiều loại tín hiệu. Giới hạn mỗi bên một loại là sai vai trò.
C❌Collector là service độc lập, thường là sidecar, DaemonSet hoặc gateway — không phải thư viện trong browser.
D✅Đúng. OneAgent nhắm độ sâu và auto-instrumentation thuộc Dynatrace; Collector là pipeline trung lập cho dữ liệu dạng OTel giữa nguồn và backend.
E❌Hai thành phần đáp ứng nhu cầu khác nhau. Coi chúng hoàn toàn thay thế nhau là bỏ qua độ sâu OneAgent và tính trung lập của Collector.

Giải thích tổng thể:
OneAgent và OpenTelemetry Collector bổ sung nhau: OneAgent cung cấp instrumentation sâu native Dynatrace; Collector mang pipeline vendor-neutral. Nhiều khách hàng chạy cả hai.

Liên kết: OneAgent · OpenTelemetry · OpenTelemetry Collector

Câu hỏi 12 — Ingest OpenTelemetry traces vào Dynatrace

Which of these are supported ways to ingest OpenTelemetry traces into Dynatrace? (Select all that apply)

  • A. Configure OneAgent to wrap its telemetry as OTLP and tunnel through the OTel stack
  • B. Run an OpenTelemetry Collector that forwards OTLP to the Dynatrace endpoint
  • C. Write spans to a shared filesystem volume and let the Dynatrace cluster read them asynchronously
  • D. Configure a nightly batch job that re-ingests spans from yesterday through the Metrics Ingest API
  • E. Export OTLP directly from an instrumented app to a Dynatrace OTLP endpoint

💡 Đáp án & Giải thích

✅ Đáp án đúng: B, E

#Kết quảGiải thích
A❌OneAgent gửi telemetry theo cơ chế native của Dynatrace, không phải OTLP exporter hay tunnel qua stack OTel.
B✅Đúng. Collector ở giữa có thể batch, enrich, retry và sample trước khi dữ liệu vào platform — pattern rất thường gặp.
C❌Filesystem drop không phải đường ingest. Trace tới cluster qua endpoint OTLP chuẩn, không qua shared volume.
D❌Metrics Ingest dành cho metrics, không nhận trace payload. Span đi qua OTLP; Metrics API không thay thế.
E✅Đúng. OTLP trực tiếp từ app đã instrument là một trong hai pattern ingest phổ biến.

Giải thích tổng thể:
Trace OpenTelemetry vào Dynatrace hoặc trực tiếp từ ứng dụng qua OTLP, hoặc qua OpenTelemetry Collector chuyển tiếp OTLP tới endpoint Dynatrace.

Liên kết: OpenTelemetry · OTLP · OpenTelemetry Collector

Câu hỏi 13 — Ingest logs vào Dynatrace

Which of these are supported ways to ingest logs into Dynatrace? (Select all that apply)

  • A. The Log Monitoring API (Log Ingest API v2) accepting JSON over HTTP
  • B. OneAgent’s log module collecting files and container stdout on the host
  • C. Writing logs onto a shared NFS volume mounted inside the cluster
  • D. A SQL INSERT statement from the application’s primary transactional database
  • E. A reverse-DNS lookup from the monitored host that encodes log lines into the response
  • F. Fluent Bit or Fluentd forwarding logs to a Dynatrace output plugin

💡 Đáp án & Giải thích

✅ Đáp án đúng: A, B, F

#Kết quảGiải thích
A✅Đúng. Log Monitoring API v2 là HTTP ingest endpoint gửi log lập trình (JSON).
B✅Đúng. Module log của OneAgent đọc file log và stdout container rồi chuyển lên platform.
C❌Filesystem chia sẻ không phải kênh ingest. Cần cơ chế đưa log tới endpoint Dynatrace.
D❌CSDL ứng dụng không phải nguồn ingest. Log đi qua đường ingest chuyên dụng, không qua SQL.
E❌DNS không phải transport log. Ingest chạy qua HTTP endpoint định nghĩa, không qua phân giải tên.
F✅Đúng. Fluent Bit và Fluentd là shipper log phổ biến, có output/plugin gửi về Dynatrace.

Giải thích tổng thể:
Các đường ingest log thường gặp: module log OneAgent, Log Ingest API v2 qua HTTP, và pipeline Fluent Bit/Fluentd. Filesystem chia sẻ hay SQL không phải kênh hợp lệ.

Liên kết: OneAgent · Grail · Log Ingest API

Câu hỏi 14 — Vai trò Dynatrace extensions trong ingest

What role do Dynatrace extensions play in data ingest?

  • A. Replacements for the Dynatrace Hub’s catalog of apps and integrations
  • B. Lightweight UI widgets that render additional charts on Dashboard tiles at query time
  • C. Ingest metrics and events from technologies OneAgent cannot auto-instrument
  • D. Extensions act as full replacements for OneAgent on hosts that support them
  • E. Custom colour schemes and layout templates applied to Dashboards at tenant level

💡 Đáp án & Giải thích

✅ Đáp án đúng: C

#Kết quảGiải thích
A❌Extension xuất hiện trong Hub; không thay Hub. Hub là bề mặt khám phá tích hợp.
B❌Extension trong Dynatrace là thành phần tầng ingest, không phải widget chart trong UI. Dashboard cấu hình riêng.
C✅Đúng. Extension bù “đuôi dài” (SNMP, database, Prometheus endpoint, script…) qua Extension Framework 2.0.
D❌Extension bổ sung OneAgent, không thay thế. OneAgent vẫn phụ trách host và code instrumentation.

Giải thích tổng thể:
Extension lấp khoảng trống mà auto-instrumentation của OneAgent không phủ. Chúng kéo metrics và event từ SNMP, WMI, Prometheus hay script tùy chỉnh vào cùng platform.

Liên kết: Dynatrace Extensions · OneAgent · Dynatrace Hub

Câu hỏi 15 — Traces vs logs trong pipeline

Which statement best contrasts traces with logs in an observability pipeline?

  • A. Traces describe request flow and timing; logs capture event and message detail
  • B. Traces and logs are the same data type and differ only in their display label
  • C. Traces are raw text messages, while logs are structured request-flow graphs
  • D. Logs always contain trace IDs that link each line to exactly one matching span

💡 Đáp án & Giải thích

✅ Đáp án đúng: A

#Kết quảGiải thích
A✅Đúng. Trace cho luồng và timing của request; log ghi chi tiết sự kiện và message. Kết hợp tốt khi log mang trace context.
B❌Hai loại khác cấu trúc và mục đích. Gom một loại là mất phân biệt.
C❌Đảo ngược định nghĩa. Trace là luồng request có cấu trúc; log là bản ghi sự kiện (text hoặc structured).
D❌Một số log có trace ID khi runtime enrich, nhưng đó là bổ sung, không phải luôn luôn đúng mọi dòng.

Giải thích tổng thể:
Trace cho hình dạng request xuyên service. Log bắt sự kiện theo thời gian. Correlate qua trace ID dùng chung tạo một mặt điều tra thống nhất.

Liên kết: Distributed Tracing · Logs · Grail

NOTE

Phần này tổng hợp các điểm kiến thức cốt lõi được rút ra từ toàn bộ câu hỏi trong file. Dùng để ôn nhanh trước khi thi.

🤖 OneAgent — Core Concepts

  • Định nghĩa: OS-level agent cài dưới dạng service/daemon — auto-discover process và instrument liên tục
  • Primary role: auto-instrument workloads, stream metrics/traces/logs/entity context
  • Signals đóng góp: distributed traces (với context propagation), logs (file + container stdout), host/process metrics (CPU, memory, disk)
    • ❌ KHÔNG: git commit history, markdown runbooks
  • Instrumentation approach: automatic process discovery + hands-off continuous instrumentation — không cần SDK call thủ công
  • Khi process mới khởi động: OneAgent detect tự động, không cần operator đăng ký hay reboot
  • Restart requirement: host/process data chảy ngay; deep code instrumentation có thể cần restart tùy runtime
  • Updates: quản lý tập trung từ environment, hỗ trợ phased rollout — không cần reinstall OS hay recompile app

ModeCó gì

Full-StackInfrastructure + code-level instrumentation + distributed tracing

  • Telemetry tự động gắn với: cluster, namespace, workload, pod, node entities trong Smartscape
  • ❌ KHÔNG: cài tay từng pod, chỉ monitor control plane, nhúng binary vào image

🔌 ActiveGate

  • Roles:
    • Proxy cho OneAgent trong private/restricted network
    • Host extensions kéo metrics từ SNMP, cloud API, database, Prometheus…
  • ❌ KHÔNG phải: storage layer (đó là Grail), laptop/workstation component

🏗️ Ingest Best Practices ở Quy mô lớn

  • ✅ Per-bucket retention (cân bằng cost và analytical value)
  • ✅ OpenPipeline: enrich, mask, route trước khi vào Grail
  • ✅ Filter sự kiện giá trị thấp (dev namespace noise)
  • ✅ Sample log sources high-volume tại ingest
  • ❌ KHÔNG: sampling tối đa đồng loạt mọi host
  • ❌ KHÔNG: “freeze” Smartscape topology discovery (phải liên tục)

📐 Observability Signal Taxonomy

SignalĐịnh nghĩa
MetricsNumeric measurements over time (CPU, latency, error rate)
LogsRecords of events, errors, messages (text/structured)
TracesStructured spans forming request flow tree across services
  • Data in context: mọi signal gắn với entity và dependencies → pivot giữa signals tức thì
  • Unified ingest: heterogeneous sources hội tụ vào một normalized model trong Grail

⚡ HTTP Response codes

  • 2xx (200 OK / 202 Accepted) = ingest thành công
  • 4xx = lỗi phía client (payload sai, auth thiếu)
  • 5xx = lỗi phía server/platform
