DQL — Cú pháp & Kiến trúc Query

Mức độ: Người mới bắt đầu
Mục tiêu: Hiểu cấu trúc cơ bản của DQL query, cách pipeline hoạt động, và các quy tắc viết lệnh.

1. Mô hình Pipeline — Trái sang Phải

Mọi DQL query đều hoạt động theo mô hình pipeline: dữ liệu chảy từ trái sang phải, qua từng bước, mỗi bước biến đổi dữ liệu trước khi chuyển sang bước tiếp theo.

flowchart LR
    A["fetch logs<br/>10,000 rows"] -->|pipe| B["filter<br/>500 rows"]
    B -->|pipe| C["fields<br/>500 rows"]
    C -->|pipe| D["sort<br/>500 rows"]
    D -->|pipe| E["limit<br/>10 rows"]

    style A fill:#e53e3e,stroke:#c53030,color:#fff
    style B fill:#dd6b20,stroke:#c05621,color:#fff
    style C fill:#d69e2e,stroke:#975a16,color:#fff
    style D fill:#38a169,stroke:#276749,color:#fff
    style E fill:#3182ce,stroke:#2b6cb0,color:#fff

Ký hiệu pipe | ngăn cách các bước:

TIP

Đọc query DQL như đọc một câu chuyện: “Lấy logs → chỉ lấy ERROR → chỉ hiện timestamp và content → sắp xếp mới nhất trước → lấy 10 cái đầu”

2. Cấu trúc tổng quát

command parameter, parameter, ... [, thamso_tuy_chon:giatri], ...
| command ...
| command ...

2.1 Command — Lệnh

Mỗi bước trong pipeline là một command (lệnh). DQL có nhiều nhóm lệnh:

NhómLệnh phổ biếnCông dụng
Nguồn dữ liệufetch, timeseries, dataLấy dữ liệu đầu vào
Lọcfilter, filterOut, search, dedupGiảm số lượng record
Fieldsfields, fieldsAdd, fieldsRemove, fieldsRenameChọn/biến đổi cột
ParseparseTrích xuất dữ liệu từ text
Sắp xếpsort, limitThứ tự và giới hạn
Tổng hợpsummarize, makeTimeseriesGom nhóm, tính toán
Joinjoin, lookup, appendKết hợp nhiều nguồn

2.2 Tham số bắt buộc và tùy chọn

Quy tắc tham số tùy chọn:

  • Tham số tùy chọn phải được đặt tên (ví dụ: from:, to:, samplingRatio:)
  • Tham số bắt buộc thường đứng đầu, không cần đặt tên

5. Thứ tự thực thi

Query DQL thực thi từ trên xuống, từ trái sang phải. Thứ tự viết lệnh ảnh hưởng đến kết quả và hiệu năng:

6. Một số ký hiệu quan trọng

Ký hiệuTênDùng khi nào
|PipeNgăn cách các bước trong pipeline
{}Curly bracesNhóm tham số (by:, parameter groups)
[]Square bracketsTruy cập phần tử array hoặc record field
\“BacktickBao quanh tên field có ký tự đặc biệt
""Double quoteString literal
//Double slashComment một dòng
==EqualsSo sánh bằng (phân biệt hoa thường)
~TildeTìm kiếm (search với wildcard)
@AtTime alignment (làm tròn thời gian)

7. Ví dụ thực hành trên Playground

Mở Notebooks trong Dynatrace Playground và thử từng query sau:

Ví dụ 1 — Query đơn giản nhất

Kết quả: 5 log records đầu tiên với tất cả các field

Ví dụ 2 — Pipeline 3 bước

Kết quả: 10 error logs

Ví dụ 3 — Dùng tham số tùy chọn

Kết quả: 20 error logs trong 30 phút gần nhất, chỉ hiện 3 cột quan trọng

Ví dụ 4 — Parameter group {}

Kết quả: Bảng đếm số log theo mức độ (ERROR, INFO, WARN…)

NOTE

Nếu Playground chưa có data, thêm data record(...) để test cú pháp:

Khái niệmNhớ gì

CommandMỗi bước là một lệnh (fetch, filter, summarize…)
