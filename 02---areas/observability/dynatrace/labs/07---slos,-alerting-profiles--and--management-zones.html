Cách học lab này

Lab này kết nối 3 ý tưởng khác nhau: scope, reliability, và routing

  • Management Zone trả lời câu hỏi “mình đang nhìn phần nào của hệ thống”; SLO trả lời “phần đó có đang đáng tin cậy không”; Alerting Profile trả lời “ai cần biết khi phần đó có vấn đề”.
  • Nếu bạn thấy một SLO có vẻ không hợp lý, hãy quay lại kiểm tra định nghĩa SLI, denominator, và cửa sổ thời gian trước khi nghi ngờ UI.
  • Dynatrace thường cho cảm giác “đã gom sẵn context”, nhưng lab này là chỗ tốt để phân biệt đâu là context để hiển thị, đâu là logic đo reliability, và đâu là logic gửi thông báo.

1. Management Zones — Phân Nhóm Logical

1.1. Concept

💡 Management Zone là gì?

Management Zone = logical grouping của entities (hosts, services, processes) — tương tự “filter preset” áp dụng cho toàn bộ Dynatrace UI.

ConceptAnalogyVí dụ
Management Zone”Lens” nhìn vào infrastructureEasyTrade, Production, Team-Alpha
Tags”Labels” gắn vào entitiesenv:lab, team:trading

Khác biệt với Tags:

FeatureTagsManagement Zones
ScopeIndividual entityGrouping + RBAC
FilterAd-hoc filteringPersistent filtering cho toàn UI
RBACKhôngCó — giới hạn visibility per zone
AlertingKhôngCó — alerting profile per zone

1.2. Tạo Management Zone

  1. Vào Settings → Preferences → Management zones
  2. Click Add management zone
  3. Cấu hình:
    • Name: EasyTrade
    • Rules: Click Add new rule
      • Rule type: Process group
      • Condition: Process group name contains easytrade
      • (Hoặc dùng tag: app:easytrade nếu đã tag trong Lab 01)
  4. Click Preview → verify đúng entities hiện
  5. Save

1.3. Sử dụng Management Zone

  1. Trên navigation bar (top), tìm Management Zone selector
  2. Chọn EasyTrade
  3. Toàn bộ Dynatrace UI filter chỉ hiện EasyTrade entities:
    • Hosts → chỉ hosts chạy EasyTrade
    • Services → chỉ EasyTrade services
    • Problems → chỉ problems liên quan
    • Dashboards → chỉ data từ EasyTrade

💡 Tại sao quan trọng trong production?

Imagine company có 100+ services, 5 teams. Mỗi team chỉ muốn thấy services của mình. Management Zones + RBAC = mỗi team chỉ thấy zone của họ.

🔗 Fundamentals: Concept này không có equivalent trực tiếp trong Fundamentals, nhưng liên quan đến Ch.08 — Organizational context. Datadog dùng Tags + RBAC để đạt mục đích tương tự, nhưng không có dedicated “zone” concept.

2. SLOs — Service Level Objectives

2.1. Nhắc lại concept

🔗 Fundamentals: Ch.06

  • SLI (Indicator) = metric đo chất lượng (ví dụ: % requests thành công)
  • SLO (Objective) = target cho SLI (ví dụ: 99.9% availability)
  • Error Budget = khoảng lỗi cho phép (100% - SLO target = 0.1%)

2.2. Tạo Availability SLO

  1. Vào Service-level objectives (tìm trong navigation)
  2. Click Create SLO
  3. Cấu hình:

Step 1 — Define SLO:

  • Name: EasyTrade Broker Availability
  • Description: Availability of broker-service — the main entry point

Step 2 — Define SLI (khuyến nghị):

  • Ưu tiên chọn SLO template / built-in service availability template nếu tenant hiển thị
  • Scope vào service broker-service
  • Chỉ fallback sang metric expression thủ công nếu tenant của bạn không có template và bạn đã verify metric preview trên UI

Step 3 — Set target:

  • Target: 99.5% (cho lab — production thường 99.9%)
  • Warning: 99.8% (threshold cảnh báo sớm)
  • Timeframe: Rolling 7 days
  1. Click Create

2.3. 🔍 Quan Sát: SLO Dashboard

Sau khi tạo, SLO page hiện:

ElementHiển thị
Current SLI valueVí dụ: 99.87%
Target99.5%
Status✅ Met / ⚠️ At Risk / ❌ Breached
Error budgetRemaining % (ví dụ: 0.37% remaining)
Error budget chartBurn rate over time
SLI trendSLI value chart over timeframe

2.4. Hiểu Error Budget trên Dynatrace

💡 Error Budget visualization:

Target: 99.5% over 7 days

Total requests in 7 days: ~50,000
Allowed failures: 50,000 × 0.5% = 250 requests
Actual failures:   45 requests
Error budget used:  45/250 = 18%
Error budget left:  82%  ← ĐÂY LÀ SỐ QUAN TRỌNG!

Ý nghĩa:

  • Error budget > 50% → Safe, có thể deploy changes
  • Error budget 20-50% → Caution, monitor closely
  • Error budget < 20% → Freeze deploys, focus on reliability
  • Error budget = 0% → SLO breached!

🔗 Fundamentals: Ch.06 — Error Budget. Concept error budget từ theory → trực tiếp map vào Dynatrace SLO visualization.

2.5. Tạo Performance SLO

Thêm SLO thứ 2 cho performance:

  1. Create SLO mới
  2. Cấu hình:
    • Name: EasyTrade Broker Performance
    • SLI: Percentage of requests dưới ngưỡng latency bạn chọn
    • Ưu tiên dùng service performance / latency template nếu tenant hỗ trợ
    • Target: 95% (95% requests phải nhanh hơn 500ms)
    • Timeframe: Rolling 7 days

💡 2 loại SLO phổ biến:

SLO TypeSLITypical Target
Availability% requests thành công99.5% - 99.99%
Performance% requests < X ms90% - 99%

3. SLO + Alerting Integration

3.1. SLO-based alerts

Dynatrace có thể alert dựa trên SLO status:

  • Alert khi error budget burn rate cao (consuming too fast)
  • Alert khi SLO sắp breach (approaching target)

3.2. Cấu hình SLO alert

  1. Từ SLO page → click SLO vừa tạo
  2. Tìm section Alerting hoặc Burn rate alert
  3. Cấu hình:
    • Alert when: Error budget < 20% remaining
    • Or: Burn rate > 2x normal

3.3. Test với problem pattern

🔍 Quan sát: Error budget chart sẽ hiện “dip” tại thời điểm problem active.

4. Alerting Profile + Management Zone

4.1. Gắn Alerting Profile với Management Zone

  1. Vào Settings → Alerting → Alerting profiles
  2. Edit profile EasyTrade - All Problems (từ Lab 05)
  3. Thêm filter: Management zone = EasyTrade
  4. Save

Bây giờ profile này chỉ nhận problems từ EasyTrade zone — không nhận problems từ entities ngoài zone.

4.2. Tổng hợp: MZ + AP + Notification

Management Zone: "EasyTrade"
  → contains: all EasyTrade entities
  → used by: Alerting Profile "EasyTrade - All Problems"
     → sends to: Email notification (bạn)
     → filters: All severities

Management Zone: (default - all)
  → used by: Alerting Profile "EasyTrade - Critical Only"
     → sends to: (khác email/PagerDuty)
     → filters: Availability + Error only

🔗 Fundamentals: Ch.07 — Alert Routing. This is the complete pipeline: detection → filtering → routing → notification.

5. So Sánh: Dynatrace SLO vs Datadog SLO

FeatureDynatrace SLODatadog SLO
SLI sourceMetrics, Services (built-in)Metrics, Monitors
Error budget✅ Built-in visualization✅ Built-in visualization
Burn rate alerts✅✅
Management Zone scoping✅❌ (uses tags)
Calendar windows✅ (rolling + calendar)✅
AI/context integrationCó thể kết hợp với Problems, workflows, zonesChủ yếu qua monitors/workflows riêng

⚠️ Troubleshooting

SLO shows “No data”

  • Verify broker-service đang nhận traffic (docker compose ps | grep loadgen)
  • Kiểm tra entity selector — service name phải match chính xác
  • Thử dùng metric preview trước khi save SLO

Management Zone empty

  • Check rules — “contains” condition có match process group names?
  • Preview rule → phải thấy entities
  • Luôn save sau khi thay đổi rules

✅ Verify Checklist

  • Management Zone EasyTrade tạo thành công, preview hiện entities
  • Management Zone selector hoạt động — UI filter theo zone

  • SLO Performance tạo (optional)
