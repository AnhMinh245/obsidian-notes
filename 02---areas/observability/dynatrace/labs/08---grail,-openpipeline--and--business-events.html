1. Grail — “Data Lakehouse” Của Dynatrace

1.1. Concept: Tại sao cần Grail?

Trước Grail:

Metrics → Metrics storage (separate)
Logs → Log storage (separate)
Traces → Trace storage (separate)
Events → Event storage (separate)
Entities → Entity storage (separate)

Vấn đề: 5 storage systems → phải JOIN data cross-system
          → chậm, phức tạp, giới hạn query capabilities

Với Grail:

Metrics ─┐
Logs ────┤
Traces ──┤──→ GRAIL (unified lakehouse) ──→ DQL queries
Events ──┤                                    (1 query language,
Entities ┘                                     tất cả data types)

💡 Data Lakehouse = Data Lake + Data Warehouse:

  • Data Lake: Lưu mọi thứ, mọi format, cost-effective
  • Data Warehouse: Structured, fast queries, indexes
  • Grail: Kết hợp cả hai — lưu mọi thứ VÀ query nhanh

1.2. Grail vs Traditional Metrics Store

FeatureTraditional (Prometheus-style)Grail
Data typesChỉ metricsMetrics + Logs + Traces + Events + Entities
QueryPromQL (chỉ metrics)DQL (tất cả data types)
RetentionFixed (15d metrics, 3d logs)Flexible per data type
ContextData trong siloContext-aware (entity relationships)
SchemaFixed schemaSchema-on-read (flexible)

🔗 Fundamentals: Ch.09 — Data Platforms. Grail là implementation thực tế của concept “unified observability platform” — 1 nơi lưu tất cả telemetry data.

3. OpenPipeline — Data Processing

3.1. Concept

OpenPipeline = processing rules áp dụng lên data trước khi lưu vào Grail.

Raw data → [OpenPipeline] → Processed data → Grail
              │
              ├── Parsing (extract fields)
              ├── Filtering (drop unwanted data)
              ├── Enrichment (add context)
              ├── Routing (send to different buckets)
              └── Masking (hide PII)

3.2. Mở OpenPipeline

  1. Vào Settings → OpenPipeline (hoặc tìm trong navigation)
  2. Bạn sẽ thấy pipelines cho:
    • Logs
    • Events
    • Business Events
    • Metrics (nếu dùng OpenTelemetry ingestion)

3.3. Xem Log Pipeline

  1. Click vào Logs pipeline
  2. Quan sát processing rules:
    • Parsing rules: Extract fields từ unstructured logs
    • Processing rules: Transform data (rename fields, add attributes)
    • Routing rules: Send logs đến different storage buckets

3.4. Tạo Processing Rule (demo)

  1. Trong Logs pipeline → click Add processing rule
  2. Rule name: EasyTrade Log Enrichment
  3. Matching condition: matchesPhrase(content, "trade")
  4. Action: Add attribute business.domain = trading
  5. Save (có thể chỉ preview, không cần deploy)

💡 Tại sao OpenPipeline quan trọng?

BenefitVí dụ
Cost reductionDrop debug logs → lưu ít hơn → tiền ít hơn
Data qualityParse messy logs → structured fields
ComplianceMask PII (credit card numbers, emails)
RoutingLogs quan trọng → long retention, logs debug → short retention

🔗 Fundamentals: Concept pipeline processing liên quan đến Ch.02 — Log Processing. Datadog dùng Log Pipelines (tương tự) — cả hai giải quyết cùng vấn đề: process logs before storage.

4. Business Events — Beyond Technical Observability

4.1. Concept: Technical vs Business Observability

Traditional Observability:
  "Response time = 245ms, error rate = 0.5%"
  → Technical team hiểu, business team KHÔNG hiểu

Business Observability:
  "13 trades executed, $4,500 volume, 2 orders blocked"
  → AI HAI ĐỀU hiểu → better decision making

💡 Business Events = observability data được frame theo business language:

  • “Trade executed” (không phải “HTTP 200 on /api/trade”)
  • “Credit card order placed” (không phải “POST request to payment-service”)
  • “User login failed” (không phải “401 from auth-service”)

4.2. EasyTrade Business Events

EasyTrade repo được thiết kế để showcase business events, nhưng upstream README cũng nói rõ phần capture rules thường được áp dụng qua Monaco hoặc cấu hình Dynatrace tương ứng. Nghĩa là:

  • Nếu bạn chỉ mới docker compose up + cài OneAgent, fetch bizevents có thể hoàn toàn empty và đó là trạng thái hợp lệ
  • Nếu tenant/repo của bạn đã apply Monaco project hoặc business-event capture rules, query dưới đây mới có khả năng trả dữ liệu

Source of truth

Xem upstream easytrade/README.md và easytrade/monaco/README.md nếu bạn muốn business events xuất hiện chắc chắn. Repo có sẵn Monaco configs cho bizevents capture rules.

5. Data Retention & DDU

5.1. Hiểu DDU (Davis Data Units)

Dynatrace tính phí theo DDU — đơn vị đo data consumption.

Data typeRelative cost trendGhi chú
MetricsThường thấp hơn logs/tracesPhù hợp charting và alerting dài hạn
LogsTrung bình đến caoTốn ingest/retention hơn nếu volume lớn
TracesTrung bình đến caoQuery/retention phụ thuộc capability của tenant
Business EventsTrung bìnhGiá trị cao cho analytics nhưng vẫn cần quản lý volume
Entities / topology metadataThấpChủ yếu phục vụ context và discovery

Không hardcode retention numbers

Retention thực tế phụ thuộc license/capability/bucket settings của environment. Hãy xem trực tiếp ở Usage and billing và các storage settings của tenant thay vì assume một số ngày cố định.

5.2. Kiểm tra consumption

  1. Vào Settings → Usage and billing → Data usage
  2. Quan sát:
    • DDU consumption per data type
    • Projected monthly usage

💡 Tại sao quan trọng cho trial accounts?

Trial accounts có DDU limit. Nếu consume quá nhiều:

  • Data bị throttled (giới hạn ingestion)
  • Một số features disabled

Tips tiết kiệm DDU:

  • Disable debug-level log collection
  • Dùng ingest rules / OpenPipeline để drop hoặc route dữ liệu không cần thiết
  • Review buckets/retention trước khi tăng ingest volume

🔗 Fundamentals: Ch.09 — Observability Cost. Quản lý cost là phần quan trọng của production observability. Datadog cũng tính phí per metric, log, trace — cả hai platforms đều cần cost management.

⚠️ Troubleshooting

DQL queries return “Not authorized”

  • DQL trong Notebooks/Dashboards dùng quyền user account — không cần token
  • Nếu gọi DQL qua API: cần Access token (tìm “Access tokens” trong tenant)
  • Token cần scopes: storage:events:read, storage:logs:read, storage:metrics:read
  • Xem Section 3.3 — Token cho API labs để tạo token

Business events empty

  • Nếu bạn chưa apply Monaco/business-event capture rules thì fetch bizevents rỗng là bình thường
  • Xem easytrade/monaco/README.md để deploy các bizevents configs upstream đã chuẩn bị sẵn
  • Alternative: Tạo rule/capture config thủ công hoặc tạo events qua API

OpenPipeline không hiện

  • Feature có thể cần enable: Settings → OpenPipeline → Enable
  • Trial accounts thế hệ mới nên có sẵn
