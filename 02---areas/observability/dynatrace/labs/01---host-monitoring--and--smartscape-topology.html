Lab 01 — Host Monitoring & Smartscape Topology

⏱️ Thời gian: ~45 phút
📋 Prerequisites: Lab 00 hoàn thành, EasyTrade đang chạy, OneAgent connected
🔗 Source: Dynatrace/easytrade

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Đọc và hiểu Host metrics (CPU, memory, disk, network) trên Dynatrace
  • Hiểu khái niệm Process Group — cách Dynatrace nhóm processes
  • Khám phá Smartscape Topology — bản đồ 4 tầng dependency
  • Hiểu Technologies page — auto-detection capabilities
  • So sánh được Infrastructure monitoring trên Dynatrace vs concepts Fundamentals

📚 Kiến Thức Nền

Fundamentals

  • Ch.01 — Request Lifecycle
    → Smartscape hiển thị trực quan request flow qua các services
  • Ch.08 — Infrastructure Monitoring
    → USE method (Utilization, Saturation, Errors) maps trực tiếp vào Host metrics

Dynatrace Theory

  • Ch.01 — Kiến trúc Dynatrace — OneAgent, Smartscape, entities
  • Ch.03 — Topology — Smartscape layers

Cách học lab này

Hãy dùng lab này để học mô hình entity của Dynatrace

  • Điều quan trọng không chỉ là đọc CPU hay memory, mà là hiểu cách Dynatrace nối host, process group, service, và dependency topology lại thành một investigation graph.
  • Smartscape không chỉ là một hình đẹp. Nó hữu ích khi bạn đang lần từ triệu chứng hạ tầng sang ảnh hưởng ứng dụng, hoặc ngược lại từ service lỗi quay xuống process/host gây ra vấn đề.
  • Nếu bạn thấy topology khá “mượt” hơn Datadog ở cùng bài toán, hãy cố giải thích vì sao: đó là do entity model, auto-discovery, hay do bạn đang nhìn một stack nhỏ và ổn định.

🔄 Account Rotation Note

Lab này chỉ cần OneAgent connected + EasyTrade đang chạy. Nếu rotate account, cài lại OneAgent → EasyTrade tự động được phát hiện lại.

1. Host Details — “Bức Tranh Tổng Thể Của Server”

1.1. Mở Host page

  1. Trên Dynatrace UI, vào Infrastructure → Hosts
  2. Click vào host ThinkPad (tên host hiện là hostname của lab machine)

1.2. 🔍 Quan Sát: Host Overview

Bạn sẽ thấy dashboard tổng quan gồm:

SectionHiển thị gìÝ nghĩa
CPU% usage over timeBao nhiêu processing power đang dùng
MemoryUsed vs availableRAM consumption
DiskI/O throughput, queue lengthStorage performance
NetworkTraffic in/out (bytes/s)Network utilization
ProcessesList of running processesMọi thứ OneAgent phát hiện

💡 Tại sao Host page quan trọng?

Trong production, khi users phàn nàn “app chậm”, bước đầu tiên luôn là:

  1. Check CPU — có bị saturated (100%) không?
  2. Check Memory — có bị swap không?
  3. Check Disk I/O — có bottleneck không?
  4. Check Network — có packet loss không?

Đây chính là USE method từ Fundamentals:

🔗 Fundamentals: Ch.03 — USE Method

  • Utilization → CPU %, Memory %
  • Saturation → Disk queue length, Memory swap
  • Errors → Network errors, Disk errors

1.3. Deep dive: CPU

  1. Click vào CPU chart
  2. Quan sát:
    • CPU usage % — tổng usage
    • CPU user vs CPU system — user-space vs kernel-space

💡 Tại sao phân biệt user vs system?

  • User CPU cao → Apps đang xử lý nhiều (EasyTrade services)
  • System CPU cao → Kernel đang bận (I/O, networking, context switching)
  • Cả hai cao → Machine bị overloaded

Với ThinkPad i5-6300U chạy EasyTrade, bạn sẽ thấy CPU usage khá cao (50-80%) — đây là bình thường vì 15 containers trên 2C/4T.

1.4. Deep dive: Network

  1. Quan sát Network chart
  2. Tìm:
    • Connectivity — connections giữa processes
    • Retransmission rate — packet loss indicator

💡 Tại sao Network quan trọng cho microservices?
EasyTrade có ~15 services gọi nhau qua HTTP/gRPC. Nếu network có vấn đề (latency, packet loss), tất cả services đều bị ảnh hưởng — hiệu ứng domino.

2. Processes & Process Groups

2.1. Xem danh sách processes

Trên Host page, scroll xuống section Processes (hoặc vào tab Processes and containers).

🔍 Quan sát: OneAgent phát hiện MỌI process đang chạy — bao gồm:

  • Java processes (Login Service, Engine)
  • .NET processes (Pricing, Account, Offer, Credit Card)
  • Go processes (Broker, Feature Flag Service)
  • Docker daemon
  • Nginx (reverse proxy)
  • MSSQL Server
  • RabbitMQ

2.2. Khái niệm Process Group

💡 Process Group là gì?

Dynatrace tự động nhóm các process giống nhau thành 1 Process Group.

Ví dụ:

Process Group: "broker-service"
├── PID 1234 (container instance 1)
└── PID 5678 (container instance 2, nếu scale up)

Tại sao nhóm?

  • Trong production, 1 service có thể chạy nhiều instances (scaling)
  • Nhóm chúng lại → bạn nhìn performance tổng thể thay vì từng instance

2.3. Khám phá 1 Process Group

  1. Click vào 1 process group, ví dụ broker-service (Go)
  2. Bạn sẽ thấy:
    • Technology: Go (tự phát hiện!)
    • Properties: Command line, environment variables
    • Resource usage: CPU, memory riêng process này
    • Connections: Process này gọi process nào, ai gọi nó

💡 Tại sao Dynatrace biết đây là Go service?

OneAgent phân tích binary signature và runtime characteristics:

  • Java → detect JVM
  • .NET → detect CLR
  • Go → detect Go runtime
  • Node.js → detect V8 engine
  • Python → detect Python interpreter

Đây là deep code-level instrumentation — khác hoàn toàn với Docker labels mà Datadog Agent dùng.

🔗 Fundamentals: Ch.05 — Auto-Instrumentation. OneAgent = instrumentation ở OS level, không cần thay đổi code. So sánh với OTel agent (library level) hoặc Datadog Agent (container level).

3. Technologies — Auto-Detection

3.1. Mở Technologies page

  1. Vào Infrastructure → Technologies and processes
  2. Bạn sẽ thấy danh sách technologies OneAgent phát hiện

🔍 Quan sát: Danh sách sẽ include:

TechnologyDetected fromEasyTrade service
JavaJVM runtimeLogin Service, Engine
.NETCLR runtimePricing, Account, Offer, Credit Card, Third Party
GoGo binaryBroker, Feature Flag Service
DockerDocker daemonContainer runtime
NginxNginx binaryFrontend reverse proxy
SQL ServerMSSQL processDatabase
RabbitMQErlang/BEAM VMMessage queue

💡 Zero-config magic

Bạn không cần khai báo technology stack cho Dynatrace. OneAgent tự phát hiện tất cả. Trong production, điều này cực kỳ giá trị — bạn không cần biết trước team dùng gì, OneAgent sẽ tự phát hiện mọi technology trên host.

4. Smartscape Topology — “Bản Đồ Sống” Của Hệ Thống

Đây là feature signature của Dynatrace — không có equivalent trên Datadog

4.1. Mở Smartscape

  1. Vào Smartscape topology (tìm trong navigation menu)
  2. Bạn sẽ thấy bản đồ 3D/interactive

4.2. Hiểu 4 tầng Smartscape

Smartscape có 4 tầng từ dưới lên:

Layer 4: Services (top)
  ↑  HTTP calls, gRPC calls
Layer 3: Process Groups
  ↑  runs on
Layer 2: Hosts
  ↑  hosted at
Layer 1: Datacenter/Cloud (bottom)

🔍 Quan sát từng tầng:

TầngBạn thấy gìÝ nghĩa
DatacenterInfrastructure node (1 node vì lab)Physical/VM layer
HostThinkPad T460Machine đang chạy
Process Groupsbroker-service, pricing-service, …Applications/containers
ServicesHTTP endpoints, database callsBusiness transactions

4.3. Khám phá connections

  1. Click vào 1 service (ví dụ: broker-service)
  2. Quan sát các đường nối đến services khác
  3. Mỗi đường nối = thực sự có HTTP call giữa 2 services (không phải config, không phải assumptions)

💡 Tại sao Smartscape không giống Service Map thông thường?

FeatureDatadog Service MapDynatrace Smartscape
Data sourceAPM traces (sampling)Runtime observation từ OneAgent + process/network relationships
LayersServices only (1 layer)4 layers (datacenter → host → process → service)
DiscoveryBased on trace propagationBased on network calls + binary analysis
CoverageDepends on trace propagation + samplingThường đầy đủ hơn topology chỉ dựa trên traces
Infrastructure linkSeparate viewsIntegrated in 1 topology

🔗 Fundamentals: Nhớ Ch.01 — Request Lifecycle? Smartscape hiển thị chính xác đường đi: User → Nginx → Frontend → Broker → Pricing → MSSQL. Đây là lý thuyết trở thành trực quan.

4.4. Trace a request path

  1. Trong Smartscape, click broker-service (tầng Services)
  2. Quan sát:
    • Calls TO this service (ai gọi nó?) → Frontend
    • Calls FROM this service (nó gọi ai?) → Pricing, Account, MSSQL
  3. Đây chính là dependency graph thực tế — không phải config, mà được phát hiện từ traffic thật

5. Host Properties & Metadata

5.1. Xem Host Properties

  1. Quay lại Host page
  2. Click Properties and tags

🔍 Quan sát:

  • Host name, IP addresses — auto-detected
  • OS type/version — Fedora (auto-detected)
  • CPU model — i5-6300U (auto-detected)
  • Cloud provider — None (bare metal)
  • OneAgent version — version đang chạy

💡 Properties vs Tags:

  • Properties = facts tự động phát hiện (không thể thay đổi)
  • Tags = labels bạn tự gắn (key:value, dùng cho filtering)

5.2. Thêm custom tags

  1. Trên Host page → Properties and tags → Add tag
  2. Thêm tags:
    • env:lab
    • team:observability
    • app:easytrade

💡 Tại sao tags quan trọng?
Tags cho phép bạn filter và group entities — đặc biệt hữu ích khi có nhiều hosts/services. Trong production, tags như env:prod, region:us-east giúp tách biệt monitoring views.

🔗 Fundamentals: Concept tags/labels này giống hệt Ch.08 — Datadog cũng dùng tags, nhưng Datadog tags mạnh hơn (tag inheritance, unified tagging). Dynatrace dùng management zones cho phân nhóm nâng cao hơn (Lab 07).

⚠️ Troubleshooting

Host không xuất hiện

Processes thiếu

Smartscape trống

  • Smartscape cần traffic để phát hiện connections
  • Verify loadgen đang chạy: docker compose ps | grep loadgen
  • Chờ 10-15 phút cho đủ data

🔗 Kết Nối Fundamentals

Concept (Fundamentals)Dynatrace Implementation
USE Method (Ch.08)Host page → CPU (Utilization), Disk queue (Saturation), Network errors (Errors)
Request Lifecycle (Ch.01)Smartscape → trace request path từ Frontend → Backend services → DB
Auto-Instrumentation (Ch.05)Technologies page — OneAgent tự phát hiện Java, .NET, Go, Docker
Service Discovery (Ch.08)Process Groups — tự nhóm similar processes, không cần config
Infrastructure as Context (Ch.08)Smartscape 4 layers = infrastructure context cho mọi telemetry

✅ Verify Checklist

  • Host page hiện CPU, memory, disk, network metrics
  • Processes tab hiện đầy đủ EasyTrade containers (~15 processes)
  • Technologies page phát hiện Java, .NET, Go, Docker, Nginx, MSSQL, RabbitMQ
  • Smartscape hiện 4 tầng với connections giữa services
  • Custom tags đã thêm (env:lab, team:observability)
