Lab 03 — Log Monitoring & Log Viewer

⏱️ Thời gian: ~45 phút
📋 Prerequisites: Lab 02 hoàn thành
🔗 Source: Dynatrace/easytrade

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu cách OneAgent thu thập logs từ Docker containers
  • Sử dụng Log Viewer để tìm kiếm, filter logs
  • Viết DQL queries cơ bản cho log analysis
  • Thực hiện Log → Trace correlation
  • Tạo Log metrics (chuyển logs thành metrics)

Fundamentals

Cách học lab này

Với Dynatrace logs, bước đầu tiên luôn là kiểm tra ingest path

  • Nếu logs chưa xuất hiện, hãy giả định trước rằng bạn đang có vấn đề về ingest rules, storage, permissions, hoặc field parsing, chứ chưa phải DQL khó.
  • Trong quá trình query, hãy để ý field nào có thật trong log record của tenant bạn. Cùng một ý tưởng “lọc lỗi” nhưng field có thể khác nhau nếu parsing hoặc ingest processing khác nhau.
  • Correlation trong lab này mạnh nhất khi bạn dùng logs để quay về entity, service, hoặc trace cụ thể. Chỉ tìm theo message text sẽ giúp bạn thấy symptom, nhưng khó giúp bạn xác định impact và root cause.

1. Log Ingestion — OneAgent Thu Thập Logs Bằng Cách Nào?

1.1. Kiến trúc log collection

Docker container (broker-service)
  │ stdout/stderr
  ▼
Docker log driver → /var/lib/docker/containers/<id>/<id>-json.log
  │
  ▼
OneAgent (on host) → reads container log files
  │
  ▼ HTTPS
Dynatrace Cloud → Log Storage (Grail)
  │
  ▼
Log Viewer (UI) / DQL queries

💡 Tại sao host-side setup khá gọn?

OneAgent tự:

  1. Detect Docker containers đang chạy
  2. Tìm log files của mỗi container
  3. Tail logs real-time
  4. Enrich logs với metadata (host, process group, container name)
  5. Gửi lên Dynatrace Cloud

Bạn thường không cần sidecar hay log driver riêng cho lab này. Tuy vậy, log visibility trên tenant vẫn phụ thuộc vào:

  • OneAgent có quyền đọc log content
  • Tenant đang cho phép log ingest / storage
  • Ingest rules không drop mất source bạn cần

🔗 Fundamentals: So sánh với Ch.02 — Log Aggregation. Dynatrace dùng agent-based collection (giống Filebeat model) — OneAgent = combined metrics/traces/logs agent.

1.2. Verify logs đang được thu thập

1.3. Enable Log Ingest / Storage (nếu chưa thấy logs)

Latest Dynatrace vs classic UI

Tenant mới thường hiển thị Logs powered by Grail với ingest rules / storage settings. Tenant cũ hoặc hybrid có thể vẫn dùng path Settings → Log Monitoring → Log sources and storage.

  1. Trong Dynatrace global search, tìm một trong các mục sau:
    • Logs
    • Ingest rules
    • Log sources and storage
  2. Đảm bảo tenant không chặn ingest cho logs từ OneAgent / Docker containers
  3. Nếu vừa đổi setting, chờ vài phút để OneAgent bắt đầu gửi logs mới

Source of truth

Nếu tenant của bạn hiển thị wording khác note, ưu tiên terminology ngay trên UI. Dynatrace đã đổi khá nhiều giữa Log Monitoring classic và Logs powered by Grail.

2. Log Viewer — Khám Phá Logs

2.1. Mở Log Viewer

  1. Trên Dynatrace UI → Observe and explore → Logs
  2. Bạn sẽ thấy log stream từ tất cả sources

2.2. 🔍 Quan Sát: Log Overview

ElementMô tả
Log entriesDanh sách log lines, mới nhất trên cùng
TimestampThời điểm log được tạo
Status/LevelINFO, WARN, ERROR, DEBUG
ContentNội dung log message
SourceContainer/process tạo log

2.3. Filter logs

Thử các filter:

# Filter theo status/level
status == "ERROR"

# Filter theo container/source
dt.entity.container_group_instance == "<broker-service-id>"

# Filter theo nội dung
matchesPhrase(content, "trade")

# Kết hợp
status == "ERROR" and matchesPhrase(content, "database")

💡 Filter syntax là DQL-based — Dynatrace dùng DQL (Dynatrace Query Language) cho tất cả data queries, bao gồm cả log filtering.

2.4. Log details

  1. Click vào 1 log entry
  2. Quan sát các attributes tự động extracted:
    • dt.entity.host — host nào
    • dt.entity.process_group_instance — process nào
    • dt.entity.container_group_instance — container nào
    • log.source — log file path
    • timestamp — thời điểm chính xác

💡 So sánh: Datadog vs Dynatrace log attributes

DatadogDynatraceÝ nghĩa
servicedt.entity.serviceService tạo log
hostdt.entity.hostHost chạy container
container_namedt.entity.container_group_instanceContainer cụ thể
@http.status_codeAuto-parsed (nếu structured)HTTP status
dd.trace_idtrace_id / related trace link (khi correlation khả dụng)Link đến trace

3. DQL — Dynatrace Query Language

3.1. Mở Notebooks (DQL workspace)

  1. Vào Observe and explore → Notebooks (hoặc Logs)
  2. Switch sang Advanced mode hoặc mở Notebooks app
  3. Bạn có thể viết DQL queries trực tiếp

3.2. DQL cơ bản cho logs

3.3. 💡 Hiểu DQL syntax

DQL giống pipe-based processing — data chảy qua từng step:

fetch <data_type>     ← nguồn data (logs, metrics, events, ...)
| filter <condition>  ← lọc
| fields <fields>     ← chọn columns
| sort <field> desc   ← sắp xếp
| summarize ...       ← aggregate
| limit N             ← giới hạn results

🔗 Fundamentals: Nhớ concept query language từ logs chapter? DQL là Dynatrace’s proprietary query language — khác với Datadog (dùng query bar UI-driven) và khác Grafana (dùng LogQL/PromQL). Advantage: DQL dùng cho MỌI data types (logs, metrics, traces, entities, events) — unified language.

3.4. So sánh: DQL vs Datadog Log queries

FeatureDatadogDynatrace DQL
InterfaceClick-based UI + text barText-based (pipe syntax)
ScopeLogs only (separate syntax cho metrics)Unified cho tất cả data types
AggregationFacets + group bysummarize + by:
Learning curveDễ hơn (UI-driven)Khó hơn (phải học syntax)
FlexibilityTốt cho common casesTốt cho complex analysis

4. Log → Trace Correlation

4.1. Tìm correlated traces

  1. Trong Log Viewer, tìm 1 log entry từ broker-service
  2. Click vào log entry
  3. Tìm section Related traces hoặc PurePath
  4. Click → jump sang PurePath view

💡 Dynatrace có thể tự hỗ trợ correlation tốt hơn, nhưng không phải lúc nào cũng “magic”

Đây là điểm khác biệt lớn:

  • Datadog / OTel-style flows: thường rely nhiều vào trace/span IDs trong log payload hoặc enrichment pipeline
  • Dynatrace: OneAgent có thể enrich và connect log data với traces nếu logs đến từ monitored process và tenant đang bật đúng capability

Trong lab này, click-through log ↔ trace hoạt động tốt nhất khi:

  1. Logs đến từ process mà OneAgent đang monitor
  2. Trace tương ứng vẫn còn retention/quyền truy cập
  3. Tenant có log/trace connectivity enabled

🔗 Fundamentals: Ch.02 — Correlation IDs. Concept correlation ID (trace/span IDs trong logs) vẫn đúng cho OTel/Datadog. Với Dynatrace, OneAgent có thể tự làm nhiều phần enrichment/connectivity hơn, nhưng vẫn phụ thuộc capability và ingest path của tenant.

4.2. Từ Trace → Logs

Ngược lại:

  1. Mở 1 PurePath (từ Services → broker-service → requests)
  2. Trong PurePath detail, tìm tab Logs
  3. Bạn sẽ thấy logs emitted chính xác trong thời gian request đó

5. Log Metrics — Chuyển Logs Thành Metrics

5.1. Concept

💡 Tại sao cần log metrics?

  • Logs = chi tiết nhưng tốn storage (DDU - Davis Data Units)
  • Metrics = nhẹ, lưu trữ lâu, tốt cho dashboards và alerts
  • Log metric = “đếm pattern X trong logs, biến thành metric Y”

Ví dụ: Đếm số lần “error” xuất hiện trong logs → tạo metric log.error_count → alert khi > 10/min

5.2. Tạo Log metric

  1. Tìm Log metrics hoặc mở phần metric extraction / log metrics mà tenant của bạn cung cấp
  2. Click Add log metric
  3. Cấu hình:
    • Key: log.easytrade.errors
    • Query: status == "ERROR"
    • Measure: Count
  4. Save

5.3. Sử dụng Log metric

Sau khi tạo, metric mới xuất hiện trong Data Explorer:

  • Có thể dùng trong Dashboards
  • Có thể tạo Alerts
  • Lưu trữ lâu hơn raw logs

🔗 Fundamentals: Concept Metrics from Logs từ Ch.03. Đây là pattern phổ biến: giữ logs cho investigation, tạo metrics cho monitoring & alerting.

⚠️ Troubleshooting

Logs không xuất hiện

DQL query trả về empty

  • Data retention phụ thuộc environment plan / bucket settings, không assume cố định
  • Kiểm tra time range selector trên UI — đảm bảo đang xem đúng khoảng thời gian
  • Kiểm tra syntax DQL và field suggestions ngay trong editor

Không thấy Log → Trace correlation

  • OneAgent cần restart containers sau khi cài hoặc sau khi mới bật log ingest:
  • Chờ 5-10 phút cho OneAgent inject và correlate
