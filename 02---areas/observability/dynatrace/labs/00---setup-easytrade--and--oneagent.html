Lab 00 — Setup EasyTrade & OneAgent

⏱️ Thời gian: ~30 phút
📋 Prerequisites: ThinkPad T460 đã setup (Lab Environment Setup), Dynatrace trial account (Credentials)
🔗 Source: Dynatrace/easytrade

🎯 Mục Tiêu

Sau lab này, bạn sẽ:

  • Hiểu kiến trúc EasyTrade (microservices polyglot: Go, .NET, Java)
  • Cài đặt Dynatrace OneAgent trên ThinkPad
  • Khởi động EasyTrade trên Docker Compose
  • Verify OneAgent tự phát hiện tất cả services
  • Hiểu sự khác biệt cơ bản giữa OneAgent và Datadog Agent

📚 Kiến Thức Nền

Fundamentals

  • Ch.05 — Auto-Instrumentation
    → OneAgent = deep code-level instrumentation, inject vào process memory — khác hoàn toàn Agent-based approach
  • Ch.08 — Container Monitoring
    → OneAgent nhìn thấy mọi container process trên host

Dynatrace Theory

  • Ch.01 — Kiến trúc Dynatrace — OneAgent, ActiveGate, Cluster
  • Dynatrace Architecture — Deployment model

Cách học lab này

Giá trị lớn nhất của lab này là quan sát mức độ auto-discovery của Dynatrace

  • Hãy chú ý xem sau khi OneAgent được cài ở host, bao nhiêu thứ xuất hiện mà bạn chưa cần sửa code hay chạm vào từng container riêng lẻ. Đó là điểm cốt lõi trong trải nghiệm Dynatrace.
  • Đừng vội đánh giá nếu UI chưa hiện đủ dữ liệu ngay. Với OneAgent và tenant mới, luôn có độ trễ discovery, process grouping, và initial baselining.
  • Nếu host đã connect nhưng services chưa lên UI như kỳ vọng, hãy nghĩ theo thứ tự: OneAgent install đúng chưa, tenant URL/token có đúng không, containers có đang chạy đủ lâu không, rồi mới kết luận tới bug của app.

🔄 Account Rotation Note

Khi rotate Dynatrace trial account:

  1. Gỡ OneAgent cũ: /opt/dynatrace/oneagent/agent/uninstall.sh
  2. Cài OneAgent mới (URL + token từ trial mới)
  3. Restart EasyTrade: docker compose down && docker compose up -d
  4. Chờ 5-10 phút để data xuất hiện

Sự khác biệt kiến trúc: OneAgent vs Datadog Agent

AspectDatadog AgentDynatrace OneAgent
DeploymentContainer riêng trong Docker ComposeCài trên host OS (ngoài Docker)
InstrumentationLibrary-level (inject tracing library)Code-level (inject vào process memory)
DiscoveryDựa vào Docker socket + labelsTự phát hiện mọi process trên host
ConfigurationPhải configure integrationsZero-config — tự phát hiện technologies
OverheadNhẹ (chỉ collect telemetry)Nặng hơn (deep monitoring)
TopologyService map (passive)Smartscape (active, real-time dependency map)

💡 Tại sao OneAgent cài trên host?

  • OneAgent cần truy cập vào process memory để inject instrumentation code
  • Nó “nhìn” ở system-call level, nên phát hiện được mọi thứ mà container-level agent bỏ qua
  • Kết quả: zero-config monitoring — bạn không cần thay đổi gì trong application code

🔗 Fundamentals: So sánh với OTel auto-instrumentation (Ch.05). OTel inject tại library level, OneAgent inject tại OS process level — sâu hơn 1 tầng.

3. Cài Đặt OneAgent

3.1. Tại sao cài sau khi start app?

Bạn có thể cài OneAgent trước hoặc sau khi start EasyTrade. Nhưng cài sau có lợi:

  • Bạn có thể quan sát OneAgent tự phát hiện containers đang chạy (ấn tượng hơn!)
  • Verify app hoạt động trước, rồi thêm monitoring sau

3.2. Lấy installation command từ Dynatrace UI

  1. Đăng nhập Dynatrace environment
  2. Sidebar trái → Infrastructure & Operations (hoặc search “deploy”)
  3. Chọn Deploy Dynatrace → Start installation → Linux
  4. Dynatrace hiện lệnh install hoàn chỉnh — copy toàn bộ. Dạng:

Tenant URL

Tuỳ environment generation, tenant của bạn dùng domain *.apps.dynatrace.com hoặc *.live.dynatrace.com. Copy đúng URL mà Dynatrace UI cung cấp.

URL chứa sẵn token

URL download mà Dynatrace cung cấp đã chứa sẵn authentication token — bạn không cần tạo PaaS Token riêng.

Lệnh copy từ UI là source of truth. Một số tenant/version có thể prefill thêm flags khác; nếu vậy hãy ưu tiên lệnh Dynatrace cung cấp thay vì hardcode lại theo note.

💡 Giải thích từng parameter:

ParameterÝ nghĩa
--set-app-log-content-access=trueCho phép OneAgent đọc nội dung log files. Có thể đổi lại sau install qua OneAgent CLI nếu cần
--set-infra-only=falseMode full-stack — monitor cả infrastructure VÀ application code

infra-only vs full-stack

  • --set-infra-only=true: Chỉ monitor CPU, memory, disk, network (nhẹ, ít data)
  • --set-infra-only=false: Monitor mọi thứ — app performance, traces, code-level insights

Cho labs, luôn dùng full-stack để thấy đầy đủ capabilities.

4. 🔍 Verify — Kiểm Tra Trên Dynatrace UI

Sau khi cài OneAgent, chờ 5-10 phút rồi kiểm tra trên Dynatrace UI.

4.1. Host monitoring

  1. Trên Dynatrace UI, vào Infrastructure → Hosts
  2. Bạn sẽ thấy host ThinkPad xuất hiện (hostname của máy)
  3. Click vào host → xem:
    • CPU, memory, disk usage
    • Processes: tất cả container processes đang chạy
    • Containers: Docker containers detected

4.2. Services auto-discovered

  1. Vào Services & transactions (hoặc Services)
  2. Bạn sẽ thấy EasyTrade services tự động xuất hiện — KHÔNG cần cấu hình gì!
    • broker-service
    • pricing-service
    • loginservice
    • accountservice
    • …

💡 Tại sao tuyệt vời?
Bên phía application runtime của EasyTrade, bạn không cần thêm label/annotation/manual instrumentation để thấy services cơ bản. OneAgent tự:

  1. Phát hiện Docker containers đang chạy
  2. Nhận dạng technology (Go, .NET, Java)
  3. Inject instrumentation phù hợp
  4. Tạo Smartscape topology (ai gọi ai, qua port nào)

Phạm vi của "zero-config"

Zero-config ở đây chủ yếu áp dụng cho host/process/service discovery và tracing. Các capabilities khác như log ingest rules, business-event capture rules, routing, retention, hoặc notification workflows vẫn có thể cần cấu hình thêm ở các lab sau.

🔗 Fundamentals: So sánh với concept Service Discovery từ Ch.08. Dynatrace Smartscape là built-in service discovery — không cần Consul hay service mesh.

4.3. Smartscape preview

  1. Vào Smartscape topology
  2. Bạn sẽ thấy dependency map 3D:
    • Datacenter → Host → Process Groups → Services
    • Các đường nối giữa services = real HTTP calls được phát hiện

Đây là Smartscape — unique feature của Dynatrace mà Datadog không có equivalent.

5. 🔍 Khám Phá Feature Flags

EasyTrade có built-in problem patterns toggle bằng feature flags.

Xem danh sách flags

Bạn sẽ thấy 4 patterns:

  • db_not_responding — Database throws errors
  • ergo_aggregator_slowdown — Traffic slowdown
  • factory_crisis — Credit card processing blocked
  • high_cpu_usage — CPU spike

Chưa bật flag nào — bạn sẽ dùng chúng trong Lab 04 và Lab 05.

⚠️ Troubleshooting

OneAgent không xuất hiện trên Dynatrace UI

Services không xuất hiện

  • OneAgent cần restart container processes để inject instrumentation
  • Restart EasyTrade: docker compose down && docker compose up -d
  • Chờ 5-10 phút

EasyTrade frontend trả về 502

🧹 Clean Up

Stop EasyTrade (giữ images)

Gỡ OneAgent (khi cần rotate account)
