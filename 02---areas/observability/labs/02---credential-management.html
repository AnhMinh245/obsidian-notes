🔑 Credential Management — Quản Lý Tài Khoản Trial

Mục tiêu

Hướng dẫn tạo trial accounts, lấy API keys, và rotate credentials khi trial hết hạn — không cần rebuild toàn bộ lab.

Cách học note này

  • Hãy xem file này như “control plane” của cả bộ labs. Nếu credentials hoặc region/tenant sai, phần còn lại của labs rất dễ tạo cảm giác platform không ingest gì dù app vẫn chạy bình thường.
  • Điều quan trọng không chỉ là có secret đúng, mà còn là đúng loại secret và đúng endpoint/site. DD_API_KEY khác DD_APP_KEY; DT_API_TOKEN có thể là platform token hoặc classic access token tùy API; DD_SITE và DT_TENANT_URL sai sẽ làm data đi nhầm chỗ hoặc agent không connect đúng tenant.
  • Khi rotate account, mục tiêu không phải “sửa cho chạy lại bằng mọi giá”, mà là giữ một quy trình lặp lại được: cập nhật source-of-truth, apply vào app config cục bộ, restart đúng thành phần, rồi verify bằng tín hiệu cụ thể.

1. Nguyên Tắc Thiết Kế

Labs được thiết kế theo 3 nguyên tắc để hỗ trợ rotating trial accounts:

  1. Source of truth tập trung: Mỗi platform có 1 file .env riêng trong ~/.observability-labs/; các file .env ở repo app chỉ là bản copy/apply từ đây
  2. Idempotent: Mỗi lab có thể chạy lại từ đầu với account mới
  3. Quick swap: Đổi account = sửa 2-4 dòng + restart containers
~/.observability-labs/
├── .env.datadog        ← DD_API_KEY, DD_APP_KEY, ...
└── .env.dynatrace      ← DT_TENANT_URL, DT_API_TOKEN, ...

2. Datadog — Tạo Account & Lấy Keys

2.1. Tạo trial account

  1. Truy cập datadoghq.com/free-datadog-trial
  2. Đăng ký bằng email (dùng alias email cho mỗi trial, ví dụ: yourname+dd1@gmail.com)
  3. Sau khi tạo xong, nhìn URL trên browser khi đăng nhập để xác định Region của bạn:
    • app.datadoghq.com → US1 (DD_SITE=datadoghq.com)
    • us3.datadoghq.com → US3 (DD_SITE=us3.datadoghq.com)
    • us5.datadoghq.com → US5 (DD_SITE=us5.datadoghq.com)
    • app.datadoghq.eu → EU (DD_SITE=datadoghq.eu)
    • ap1.datadoghq.com → AP1 (DD_SITE=ap1.datadoghq.com)
  4. Trial kéo dài 14 ngày, full features

Email aliases

Gmail cho phép dùng + để tạo alias: user+dd1@gmail.com, user+dd2@gmail.com… Tất cả đều về cùng inbox nhưng Datadog coi là email khác nhau.

2.2. Lấy API Key

  1. Đăng nhập vào app.datadoghq.com
  2. Vào Organization Settings → API Keys
  3. Copy API Key (đã có sẵn 1 key)

2.3. Lấy Application Key

  1. Vẫn trong Organization Settings → Application Keys
  2. Click New Key → đặt tên thinkpad-lab
  3. Copy Application Key

Khi nào thật sự cần DD_APP_KEY?

  • Cần khi bạn gọi Datadog APIs, dùng Terraform/API automation, export/import qua API, hoặc chạy các script quản trị
  • Không phải lúc nào cũng cần chỉ để xem UI, nhận telemetry, hay làm các lab chỉ xoay quanh Agent + browser UI

Vì bộ labs này vẫn có một số phần tham chiếu API/export workflow, cứ lưu DD_APP_KEY trong source-of-truth là tiện nhất, nhưng đừng nhầm nó với thứ Agent cần để gửi data.

2.4. (Optional) Tạo RUM Application

Nếu muốn dùng Real User Monitoring (Storedog có Puppeteer tạo browser traffic):

  1. Vào Digital Experience → Applications → New Application
  2. Chọn JavaScript (JS)
  3. Copy Application ID và Client Token

Puppeteer traffic không tự động đồng nghĩa với RUM data

Puppeteer chỉ tạo browser traffic. Để thấy dữ liệu trong Datadog RUM, frontend của Storedog còn phải có browser SDK/config đúng (Application ID, Client Token, site, và init code).

2.5. Tạo file credentials

DD_SITE sai gây lỗi 403 Invalid API key — dù key đúng

Agent gửi data đến US1 (datadoghq.com) mặc định nếu không có DD_SITE. Nếu account của bạn ở US3/US5/EU, máy chủ US1 sẽ trả về 403 Forbidden vì nó không tìm thấy key của bạn ở đó.

Ngoài ra, docker-compose.dev.yml của Storedog phải chứa dòng - DD_SITE=${DD_SITE} trong phần environment của service dd-agent mới có hiệu lực. Nếu thiếu dòng này, agent container sẽ không nhận biến dù file .env đúng. Xem hướng dẫn chi tiết trong Lab 00 — Bước 3.

Sai DD_SITE là lỗi lab rất hay gặp

Symptom thường là:

  • Agent có vẻ chạy bình thường nhưng data không lên tenant bạn đang mở
  • RUM/browser side gọi sai domain
  • UI tenant trống dù containers vẫn healthy

Luôn kiểm tra lại region/site thật của account trước khi kết luận “Agent lỗi”.

2.6. Áp dụng vào Storedog

Storedog vẫn cần file .env riêng trong repo. File ~/.observability-labs/.env.datadog chỉ nên là source of truth để bạn copy các giá trị credentials/RUM site vào project-local .env khi setup hoặc rotate account.

Không symlink ~/.observability-labs/.env.datadog thành ~/labs/storedog/.env

storedog/.env.template còn nhiều biến cấu hình app khác ngoài credentials. Symlink trực tiếp sẽ làm thiếu các defaults của ứng dụng.

Chỉ 2 keys BẮT BUỘC

  • DD_API_KEY — Agent dùng để gửi data
  • DD_APP_KEY — API access cho các bước automation/API, không phải ingestion key của Agent

Các keys khác (RUM, etc.) là optional.

3. Dynatrace — Tạo Account & Lấy Tokens

3.1. Tạo trial account

  1. Truy cập dynatrace.com/trial
  2. Đăng ký bằng email (dùng alias tương tự: user+dt1@gmail.com)
  3. Chọn cluster region — tenant thường có URL dạng https://abc12345.apps.dynatrace.com hoặc https://abc12345.live.dynatrace.com
  4. Trial kéo dài 15 ngày, full features

3.2. Ghi nhận Environment URL

Sau khi tạo account, bạn sẽ có URL dạng:

https://abc12345.apps.dynatrace.com
# hoặc
https://abc12345.live.dynatrace.com

Đây là tenant URL — bạn sẽ cần nó cho mọi API calls và OneAgent installation.

3.3. (Optional) Tạo token cho terminal/API labs

DT_API_TOKEN không bắt buộc cho các labs dùng UI trực tiếp

Bạn chỉ cần token này khi gọi Dynatrace APIs từ terminal hoặc khi làm các labs cuối có dùng DQL/API.

Cách nghĩ dễ nhất là chia Dynatrace thành 2 họ API/token:

  • Latest platform services: ưu tiên Platform token
  • Classic environment APIs: vẫn có thể cần Access token classic

Personal Access Token (PAT) không nên được dùng như “default token cho mọi thứ”, vì phạm vi hỗ trợ hẹp hơn.

  1. Nếu lab/API bạn định gọi thuộc latest platform services:

    • Mở My platform tokens trong Account Management
    • Tạo Platform token

  2. Nếu một API cụ thể ghi rõ cần Access token:

    • Mở Access tokens trong tenant
    • Generate token với scopes phù hợp

  3. Đặt tên token kiểu thinkpad-lab, expiration tùy nhu cầu/trial duration

  4. Chọn scopes theo lab bạn định chạy. Ví dụ:

    • settings.read, settings.write nếu muốn automate settings
    • storage:events:read, storage:logs:read, storage:metrics:read khi tới các labs DQL/API
    • Các scope entity/topology/settings khác chỉ bật khi lab thật sự dùng tới

Personal Access Token không thay thế được access token cho mọi API

Dynatrace docs xem PAT là classic/legacy và chỉ phù hợp với một phần classic APIs. Với các tenant/latest platform flows, hãy dùng Access token / Platform token cho API automation.

  1. Xem Selected scopes ở dưới danh sách → click Generate token

Token chỉ hiển thị 1 lần

Sau khi generate, copy token ngay! Bạn sẽ không thể xem lại token value.

  1. Copy token → lưu vào file credentials

3.4. OneAgent Installation Token

OneAgent installation token được lấy từ Deploy flow (không phải Access tokens hay Personal Access Tokens):

  1. Sidebar trái → Infrastructure & Operations (hoặc tìm Deploy)
  2. Chọn Deploy Dynatrace → Start installation → Linux
  3. Dynatrace sẽ tự generate download URL chứa sẵn token
  4. Copy toàn bộ lệnh wget + install

Không cần PaaS Token riêng

Trong Dynatrace mới, bước Deploy → Install OneAgent tự cung cấp lệnh install hoàn chỉnh — không cần tạo PaaS token riêng như trước.

6. Security Notes

Bảo mật credentials

  • KHÔNG commit .env files vào Git
  • KHÔNG share API keys trên internet
  • Trial accounts sẽ tự disable sau khi hết hạn
  • Nếu dùng Git cho lab notes, thêm vào .gitignore: 
    .env
.env.*
