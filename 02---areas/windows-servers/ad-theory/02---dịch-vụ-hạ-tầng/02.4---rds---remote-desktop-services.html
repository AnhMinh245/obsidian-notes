RDS - Remote Desktop Services

Tóm tắt nhanh

  • RDS cung cấp remote access đến desktops và applications — từ session-based (chia sẻ OS) đến VDI (mỗi user 1 VM riêng)
  • 6 role services phối hợp: RDSH (host sessions), RDCB (điều phối), RDG (gateway HTTPS), RDWA (web portal), RDL (licensing), RDVH (VDI)
  • Connection flow: User → RD Web/Client → RD Gateway → RD Connection Broker → RD Session Host (hoặc RDVH)
  • Licensing yêu cầu RDS CAL riêng biệt (Per User hoặc Per Device) — không bao gồm trong Windows Server license
  • RemoteApp cho phép publish individual applications, User Profile Disks/FSLogix quản lý profiles
  • Azure Virtual Desktop (AVD) là cloud equivalent nhưng không thay thế on-premises RDS

Tổng quan

RDS (trước đây là Terminal Services, đổi tên từ Windows Server 2008 R2) cho phép:

  • Nhiều user cùng truy cập remote vào 1 server (session-based) — tiết kiệm resource
  • Publish ứng dụng individual (RemoteApp) thay vì full desktop — user experience tốt hơn
  • Cung cấp VDI (Virtual Desktop Infrastructure) — mỗi user có VM riêng cho isolation hoàn toàn
  • Truy cập an toàn từ internet qua RD Gateway (HTTPS tunnel, không cần VPN)
  • Tương tự như một toà nhà văn phòng chung: mỗi user thuê 1 phòng (session) trong toà nhà (RDSH), chia sẻ hạ tầng nhưng có không gian riêng

RD Session Host (RDSH)

  • Core component — nơi user sessions thực sự chạy
  • Multi-session: nhiều user cùng logon vào 1 server, chia sẻ OS nhưng có session riêng biệt
    • Mỗi session có desktop riêng, clipboard riêng, application space riêng
    • Sessions cách ly ở session boundary — không phải VM boundary
  • Chạy RemoteApp programs hoặc full desktop sessions
  • Resources (CPU, RAM, disk) được chia sẻ giữa các sessions — sizing cực kỳ quan trọng
  • Profile management: Roaming Profiles, User Profile Disks (UPD), hoặc FSLogix Profile Containers (modern)
  • Khi install ứng dụng trên RDSH, phải dùng Install Mode: change user /install → install → change user /execute
    • Hoặc install qua Control Panel/SCCM (tự activate install mode)

RD Connection Broker (RDCB)

  • Bộ não điều phối của RDS deployment — giống như bộ phận lễ tân phân bổ phòng họp
  • Chức năng:
    • Load balancing — phân phối new sessions đến RDSH ít tải nhất (weight-based)
    • Reconnection — khi user disconnect rồi reconnect → broker tìm session cũ trên đúng RDSH host
    • Collection management — quản lý Session Collections và Virtual Desktop Collections
  • Lưu trữ session state trong internal database (Windows Internal Database - WID) hoặc SQL Server (bắt buộc cho HA)
  • Mọi connection đều đi qua RDCB — không connect trực tiếp đến RDSH
    • Ngoại trừ admin RDP session (mstsc /admin) — bypass RDCB

RD Gateway (RDG)

  • HTTPS tunnel cho RDP traffic — thay thế việc mở port 3389 ra internet (rất nguy hiểm)
  • Hoạt động:
    • Client kết nối HTTPS (port 443) đến RD Gateway
    • RDG authenticate user (AD credentials, MFA nếu có)
    • Kiểm tra Connection Authorization Policy (CAP) — ai được phép connect
    • Kiểm tra Resource Authorization Policy (RAP) — user được phép truy cập resource nào
    • Tunnel RDP traffic qua HTTPS đến internal RDSH/RDCB
  • RPC over HTTPS (legacy) hoặc HTTP Transport (Windows Server 2012+, UDP support cho better performance)
  • Yêu cầu: SSL certificate trusted bởi clients (thường dùng public CA cert cho external access)
  • Tương tự: RDG là “cổng bảo vệ” của toà nhà — kiểm tra thẻ (CAP), xác nhận bạn được vào phòng nào (RAP), rồi đưa vào đúng phòng (tunnel đến RDSH)

CAP và RAP chi tiết

PolicyKiểm tra gìĐiều kiện có thể set

RAP (Resource Authorization)User được phép truy cập resource nào bên trong?AD group membership, allowed computer groups, specific RDSH names
  • NAP integration (Network Access Protection) — RD Gateway có thể kiểm tra health state của client device (deprecated từ Windows Server 2016)
  • Device Authorization — yêu cầu client device thuộc AD group cụ thể hoặc có certificate

RD Web Access (RDWA)

  • Web portal — user truy cập https://rdweb.corp.com/RDWeb để thấy danh sách RemoteApp và desktops
  • Chức năng:
    • Liệt kê RemoteApp programs user được phép truy cập (theo AD group membership)
    • Launch RemoteApp hoặc full desktop session
    • Tích hợp RD Gateway settings vào .rdp file tải về
  • Có thể customise branding (logo, colors, thông báo)
  • Từ Windows Server 2016+: RD Web Client — HTML5 client chạy trong browser, không cần cài MSTSC
    • Hỗ trợ: Edge, Chrome, Firefox, Safari
    • Hạn chế: không hỗ trợ tất cả features (vd: không redirect USB devices, limited clipboard)

RD Licensing (RDL)

  • Quản lý RDS Client Access Licenses (CALs)
  • Mỗi user hoặc device kết nối đến RDSH phải có RDS CAL (ngoài Windows Server CAL)
  • License server phải được activated với Microsoft Clearinghouse
  • Nếu không có license server → grace period 120 ngày → sau đó từ chối connections
    • Trừ admin RDP session trên console (session 0)

RD Virtualization Host (RDVH)

  • Tích hợp Hyper-V để cung cấp VDI (Virtual Desktop Infrastructure)
  • RDCB quản lý pool VM, gán VM cho user khi connect
  • VM chạy full Windows desktop OS (Windows 10/11 Enterprise)
  • Yêu cầu: VDA (Virtual Desktop Access) license cho VDI machines
    • VDA license included trong Microsoft 365 E3/E5 hoặc mua riêng

Deployment Models

Session-based Desktop

  • Nhiều user chia sẻ cùng 1 server OS (RDSH)
  • Mỗi user có session riêng, cách ly ở mức session (không phải VM)
  • Ưu điểm:
    • Tiết kiệm resource: 1 server phục vụ 20-50 users
    • Quản lý tập trung: patching 1 server = affect tất cả users
    • Cost-effective: không cần VDI infrastructure
  • Nhược điểm:
    • App compatibility: không phải mọi app support multi-session
    • Resource contention: 1 user chạy heavy app → ảnh hưởng users khác
    • Limited customization: users không install apps riêng

VDI - Virtual Desktop Infrastructure

  • Mỗi user được gán 1 VM riêng chạy desktop OS
  • Personal VDI: VM gán cố định cho 1 user — user có thể customize, install apps
    • VM persistent across sessions — data/settings giữ lại
  • Pooled VDI: VM từ pool, user nhận VM bất kỳ khi login, VM reset về golden image sau khi logout
    • Non-persistent: changes mất sau logout
    • Cần profile solution (FSLogix) để giữ user data
  • Ưu điểm: full isolation, app compatibility tốt (mọi desktop app), user experience gần giống PC
  • Nhược điểm: tốn resource hơn nhiều (mỗi VM = 1 OS instance), quản lý phức tạp, licensing đắt hơn

Khi nào dùng RemoteApp:

  • Power users cần full environment access
  • Help desk cần troubleshoot trong remote desktop context

User Profile Management

Vấn đề

Profile management là **pain point 1 trong RDS — profile corruption, bloat, slow logon là những vấn đề phổ biến nhất.

  • Session-based: user logon vào bất kỳ RDSH → cần profile nhất quán
  • Non-persistent VDI: VM reset sau logout → cần giữ user data ở nơi khác
  • Profile size lớn → logon chậm (copy profile qua network)

FSLogix chi tiết

  • Profile Container: mount VHDX chứa toàn bộ profile (C:\Users\<username>) tại logon
  • Office Container: VHDX riêng cho Office cache (Outlook OST, Teams cache, OneDrive) — tách khỏi profile chính
    • Tại sao tách: Office cache rất lớn (5-20 GB), change frequently, gây profile bloat
  • Storage: file share (SMB) hoặc Azure Files / Azure NetApp Files
  • Concurrent access: khi user có session trên nhiều RDSH → profile container Read-Write trên session đầu, Read-Only trên sessions sau
  • Cloud Cache: replicate profile container đến nhiều storage locations → HA

Chọn Per User hay Per Device:

  • Per User: khi users dùng nhiều devices (PC, laptop, phone, tablet)
  • Per Device: khi 1 device dùng chung cho nhiều users (kiosk, call center, factory terminal)
  • Không được mix Per User và Per Device trên cùng 1 license server

License Server Discovery

RDSH tìm license server theo thứ tự:

  1. Group Policy — chỉ định license server cụ thể (khuyến nghị, reliable nhất)
  2. Active Directory — license server publish thông tin vào AD
  3. Registry — cấu hình thủ công trên RDSH

Grace Period

  • 120 ngày từ khi RDSH nhận connection đầu tiên mà không có license server
  • Trong grace period: tất cả connections được phép, không cần CAL
  • Sau 120 ngày: RDSH từ chối mọi connection (trừ admin RDP session trên console)
  • Grace period không reset khi thêm license server — phải add server trước khi hết hạn
  • Grace period trap: nhiều tổ chức deploy RDS trong phase test, quên mua CAL. 120 ngày sau = tất cả users bị lock out.

  • Nhiều RDG servers đặt sau NLB (Network Load Balancer) hoặc hardware load balancer

  • Session affinity không bắt buộc (RDG stateless sau khi tunnel established)
  • Certificate SAN phải include farm DNS name (vd: rdg.corp.local)

Lưu ý quan trọng trong flow:

Printing trong RDS

Vấn đề

  • User in từ remote session → print ra printer tại local desk
  • RDSH server cần printer driver → driver mismatch, driver conflict, driver crash
  • Nhiều users = nhiều printers = driver management nightmare

Easy Print (mặc định, recommended)

  • Easy Print = RDP printer redirection không cần install driver trên RDSH
  • Client redirect local printer qua RDP session
  • RDSH dùng Easy Print driver (XPS-based) → render tại client side
  • Ưu điểm: không cần install printer driver trên RDSH, giảm conflict
  • Nhược điểm: một số printer-specific features không available, chất lượng in phụ thuộc XPS rendering

GPO cho Printing

  • Use Remote Desktop Easy Print printer driver first — ưu tiên Easy Print
  • Do not allow client printer redirection — tắt redirect
  • Redirect only the default client printer — chỉ redirect default printer (giảm clutter)
  • Use printer redirection — enable/disable specific redirections

RDS Security Hardening

Network Level Authentication (NLA)

  • NLA yêu cầu authentication trước khi establish full RDP session
  • Không có NLA: client connect → server allocate resources → rồi mới authenticate → DDoS risk
  • Có NLA: client authenticate (CredSSP) → nếu thành công → mới establish session
  • Luôn enable NLA — mặc định từ Windows Server 2012

TLS Configuration

  • RDP session mặc định encrypt bằng RDP security layer — yếu, nên upgrade
  • TLS (SSL) encryption: mạnh hơn, yêu cầu certificate trên RDSH
  • GPO: Set client connection encryption level = High + Require use of specific security layer = SSL
  • Minimum TLS version: TLS 1.2 — disable TLS 1.0/1.1

  • Windows Hello for Business: certificate-based, passwordless — tương lai của RDS authentication

Restricted Admin Mode và Remote Credential Guard

  • Restricted Admin: admin connect mà không gửi credentials đến RDSH → chống credential theft
    • mstsc /restrictedAdmin
    • Hạn chế: không access network resources từ RDSH (double-hop bị block)
  • Remote Credential Guard (Windows 10/Server 2016+): credentials stay trên client device, redirect Kerberos requests
    • Tốt hơn Restricted Admin: vẫn access network resources
    • mstsc /remoteGuard

MultiPoint Services

Tổng quan

  • MultiPoint Services = nhiều users chia sẻ 1 physical computer qua USB hubs (zero clients, monitors connected directly)
  • Khác với RDSH: MultiPoint kết nối trực tiếp qua USB/video, không qua network RDP
  • Use case: classroom, library, small office — nơi cần nhiều workstations nhưng budget thấp
  • Mỗi station: 1 monitor + 1 keyboard + 1 mouse connected qua USB hub
  • OS: Windows Server with MultiPoint Services role

On-premises RDS vs Azure Virtual Desktop (AVD)

So sánh

Khi nào dùng cái nào

Chọn On-premises RDS khi:

  • Data phải ở on-premises (compliance, regulation)
  • Existing infrastructure đã có, đã paid off
  • Low latency required (LAN apps, real-time systems)
  • Predictable load — không cần auto-scale
  • Internet connectivity unreliable

Chọn AVD khi:

  • Cloud-first strategy
  • Need Windows 10/11 multi-session (cost savings)
  • Variable load — cần scale up/down
  • Remote workforce distributed globally
  • Want Microsoft-managed infrastructure
  • Rapid deployment needed

Hybrid approach: RDS on-prem cho core apps, AVD cho burst capacity hoặc remote workers

Câu hỏi thường gặp

Q: RDS CAL khác Windows Server CAL?
A: Hoàn toàn khác. Windows Server CAL cho phép access Windows Server services (file share, print, AD). RDS CAL là CAL riêng biệt, bắt buộc thêm khi dùng RDSH/VDI. Cần cả 2: Windows Server CAL + RDS CAL.

Q: FSLogix có miễn phí không?
A: Có, nếu bạn có RDS CAL, Microsoft 365 E3/E5, hoặc Windows Enterprise license. Không cần mua riêng. Tải từ Microsoft website.

Q: Có thể dùng RDS mà không có RD Gateway không?
A: Có, cho internal access (LAN). Nhưng cho external access, RD Gateway là must-have — không bao giờ expose port 3389 ra internet.

Q: Roaming Profiles có còn dùng được không?
A: Technically có, nhưng strongly discouraged. Roaming Profiles copy toàn bộ profile qua network mỗi logon/logoff → chậm, bloat, corruption risk. FSLogix Profile Containers tốt hơn mọi mặt.

Q: RDSH có chạy được trên Windows Server Core không?
A: Có từ Windows Server 2019+. Nhưng management phức tạp hơn (no GUI). Phù hợp cho large-scale deployments nơi servers managed qua PowerShell/SCCM.

Q: Có thể dùng RDS trên Azure IaaS VMs?
A: Có, nhưng đó là “lift-and-shift” RDS lên Azure, khác với AVD. Bạn vẫn cần self-manage tất cả RDS components. Cân nhắc AVD nếu đã quyết định lên cloud.

Lưu ý quan trọng

CAUTION

Grace period trap — nhiều tổ chức deploy RDS rồi quên mua CAL. 120 ngày sau = tất cả users bị lock out. Luôn plan licensing từ đầu, activate license server ngay khi deploy.

  • Sizing RDSH — rule of thumb: 4-6 light users hoặc 2-3 heavy users per vCPU core. RAM: 2-4 GB base OS + 1-2 GB per session. Luôn load test trước production
  • User Profile management — profile corruption hoặc bloat là vấn đề #1 trong RDS. FSLogix Profile Containers (miễn phí với RDS CAL) là giải pháp hiện đại, thay thế Roaming Profiles và UPD
  • Printer redirection — Easy Print driver (mặc định) giảm vấn đề driver mismatch. Tránh cài printer driver trên RDSH trừ khi thực sự cần
  • Security:
    • Luôn enable NLA (Network Level Authentication)
    • RD Gateway nên đặt trong DMZ, không exposed trực tiếp
    • Cân nhắc MFA cho RD Gateway (Azure MFA NPS extension hoặc third-party)
    • Restrict admin RDP: dùng Restricted Admin mode hoặc Remote Credential Guard
    • Minimum TLS 1.2 cho tất cả RDS components
  • Windows Server 2025 — RDS vẫn là technology chính cho on-premises remote desktop. AVD là cloud complement, không replacement
