AD 2025 - DHCP và RDS Migration

Tóm tắt nhanh

  • DHCP Migration theo mô hình Export → Import → Parallel Run → Cutover — đảm bảo zero downtime cho IP assignment
  • DHCP Failover phải break partnership cũ trước, rồi mới cấu hình failover mới trên DC 2025
  • RDS deployment trên hạ tầng mới — ưu tiên Session-based cho đơn giản, migrate RemoteApp và profile
  • Certificate cho RDS Gateway/Broker/Web Access phải cấp từ CA 2025 mới — phụ thuộc hoàn tất CA migration trước
  • Cơ hội tốt để consolidate DHCP scope và upgrade RDS profile sang FSLogix

Superscope: nhóm nhiều scope thành 1 logical unit khi:

  • Multinetting: nhiều subnet trên cùng physical network
  • Scope gốc hết IP → tạo thêm scope → nhóm vào superscope

Khi migration: migrate toàn bộ superscope cùng lúc — không migrate từng scope riêng lẻ trong superscope.

DHCP Failover Migration

DHCP Failover cho phép 2 DHCP server chia sẻ scope — đảm bảo high availability.

Quy trình chuyển đổi Failover

  1. Break Failover cũ: huỷ partnership giữa 2 DHCP server cũ

    • Chọn: giữ scope trên server nào (thường server primary)
    • Server kia mất scope → sẵn sàng decommission
    • Quan trọng: break failover trước khi deauthorize server cũ

  2. Import vào DHCP mới: import scope configuration (từ export file)

  3. Configure Failover mới: thiết lập partnership giữa 2 DHCP 2025

    • Chọn mode: Hot Standby hoặc Load Balance
    • Configure shared secret (strong password)
    • Set Maximum Client Lead Time (MCLT) — default 1 giờ
    • Sync scope configuration

Khuyến nghị cho dự án:

  • Trong cùng site (2 DC/site): dùng Load Balance (50/50) — tận dụng cả 2 server
  • Giữa các site: mỗi site chạy DHCP riêng cho subnet của mình — không failover cross-site (vì subnet khác nhau)

DNS Dynamic Update Credential

DHCP server có thể thực hiện DNS Dynamic Update thay mặt client (đặc biệt cho client cũ không tự register DNS):

  • DnsUpdateProxy group: DHCP server account nên thuộc group này
    • Nhưng không nên nếu DHCP chạy trên DC — vì DC account có quá nhiều quyền
  • Dedicated credentials: tạo user account riêng cho DHCP dynamic update
    • Account này cần quyền update DNS zone
    • Khi migrate DHCP → cấu hình credential mới trên DHCP 2025 trỏ đến cùng account (hoặc tạo account mới)
    • Quan trọng: không để credential cũ sở hữu DNS record → record trở thành “orphan” khi decommission account cũ

Rollback DHCP

  • Nếu DHCP mới có vấn đề → reauthorize và reactivate scope trên DHCP cũ
  • Client sẽ tự liên hệ DHCP cũ khi renew (nếu DHCP mới không respond)
  • Rollback nhanh vì DHCP cũ vẫn giữ config (chỉ deactivate scope, chưa xoá)
  • Thời gian rollback: 5-10 phút (authorize + activate scope)

Chi tiết từng RDS Component

RD Connection Broker

  • Vai trò: điều phối session — quyết định user đến RDSH nào, load balance giữa RDSH
  • Placement: trên dedicated server (khuyến nghị cho production), không trên DC
  • High Availability: Connection Broker HA yêu cầu SQL Server database (SQL Express cho small, SQL Standard cho production)
  • Migration: cấu hình lại collection, session settings trên Broker mới — không có export/import tự động

RD Session Host (RDSH)

  • Vai trò: host user session — đây là nơi user thực sự chạy ứng dụng
  • Placement: server riêng, không chung với DC hay Broker (security + performance)
  • Sizing: phụ thuộc số concurrent user và loại ứng dụng (xem bảng sizing ở trên)
  • Migration: cài đặt ứng dụng trên RDSH mới, cấu hình session collection

RD Gateway

  • Vai trò: tunnel RDP traffic qua HTTPS — cho phép truy cập từ internet an toàn
  • Placement: DMZ hoặc edge network
  • Certificate: cần SSL certificate trust bởi external client — cấp từ CA 2025 mới (hoặc public CA nếu external user không join domain)
  • Migration: cấu hình Connection Authorization Policy (CAP) và Resource Authorization Policy (RAP) trên Gateway mới

RD Web Access

  • Vai trò: web portal cho user truy cập RemoteApp và desktop collection
  • Placement: co-located với Gateway hoặc server riêng
  • Certificate: cần SSL certificate cho web portal (cùng cert với Gateway nếu co-located)
  • Migration: publish RemoteApp program list lên Web Access mới

RD Licensing

  • Vai trò: quản lý RDS CAL (Client Access License) — bắt buộc cho production
  • Placement: trên DC hoặc dedicated server
  • Migration:
    • Per-User CAL: license theo user → migrate license server, user CAL tự track
    • Per-Device CAL: license theo device → cần reissue CAL trên server mới
  • Grace period: 120 ngày — phải activate Licensing server và install CAL trước khi hết

Lưu ý quan trọng

DHCP

  • Không authorize 2 DHCP server cấp cùng 1 scope cùng lúc (trừ khi failover) → gây IP conflict — đây là sai lầm phổ biến nhất
  • DHCP trên DC: chấp nhận được nhưng không best practice — nếu DC restart (patch), mất DHCP service trong khi reboot
  • Lease time: nếu lease time ngắn (4-8 giờ), cutover nhanh vì client renew sớm. Nếu lease dài (8 ngày), phải đợi lâu hơn hoặc force renew (ipconfig /renew trên client hoặc DHCP scope option change)
  • IP conflict detection: bật tính năng conflict detection trên DHCP mới — DHCP ping IP trước khi lease → tránh conflict với static IP
  • DHCP relay/helper: nếu dùng IP helper trên router → update helper address trỏ đến DHCP 2025 mới khi cutover

RDS

  • RDS trên DC: Microsoft không khuyến nghị cài RD Session Host trên DC — security concern và resource contention
  • Grace period: RDS có 120-day grace period cho licensing — phải setup Licensing server trước khi hết. Countdown bắt đầu từ khi user đầu tiên connect
  • Printer redirection: kiểm tra driver printer trên RDSH mới — driver cũ có thể không compatible với Server 2025. Dùng Universal Print Driver hoặc Easy Print
  • RemoteApp compatibility: test mỗi RemoteApp trên Server 2025 — không phải mọi app đều compatible. Đặc biệt legacy 32-bit app
  • NLA (Network Level Authentication): Server 2025 default enable NLA — client cũ không support NLA sẽ không connect được

Câu hỏi thường gặp

Q: DHCP export/import có bao gồm lease data không?

A: Export bằng Export-DhcpServer bao gồm scope config, reservations, options, policies. Lease data có thể include hoặc exclude. Thường không cần import lease — client sẽ tự renew lease khi contact DHCP mới.

Q: Có thể chạy 2 DHCP server cùng scope mà không failover?

A: Không nên — 2 DHCP cùng scope mà không failover → cả 2 cấp cùng IP → IP conflict. Luôn dùng failover relationship hoặc split scope (80/20 rule) nếu cần 2 server.

Q: FSLogix có cần license riêng không?

A: FSLogix license đi kèm Microsoft 365 E3/E5, Microsoft 365 Business Premium, hoặc RDS SAL. Nếu tổ chức có M365 E3+ → đã có quyền dùng FSLogix miễn phí.
