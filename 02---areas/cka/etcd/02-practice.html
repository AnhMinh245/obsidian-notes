Mục tiêu

Không dừng ở “service đã chạy.” Phải tự tay thao tác để hiểu rõ:

  • key-value hoạt động ra sao

  • lease/TTL dùng để làm gì
  • snapshot/restore ảnh hưởng ra sao
  • compact/defrag liên quan gì đến vận hành

Nếu ít thời gian

Chỉ cần làm 5 bài này: put/get/del → prefix → watch → lease + keepalive → snapshot + restore

Lab 1 — Key-Value Store cơ bản

Mục tiêu: Hiểu CRUD cho key-value.

Rút ra gì?

  • etcd lưu dữ liệu theo cặp key → value
  • put ghi đè giá trị cũ
  • del xóa key khỏi current state

Lab 2 — Prefix như “thư mục logic”

Mục tiêu: Hiểu cách tổ chức key theo namespace.

Rút ra gì?

  • Prefix giúp nhóm dữ liệu theo namespace logic
  • Kubernetes lưu object theo path dạng /registry/<resource>/<namespace>/<name>

Lab 3 — Revision và Versioning

Mục tiêu: Hiểu cơ chế version tracking của etcd.

Giải thích các fields

FieldÝ nghĩa
create_revisionRevision khi key được tạo lần đầu
mod_revisionRevision của lần sửa gần nhất
versionSố lần key bị update

→ Đây chính là nền tảng trực giác cho resourceVersion trong Kubernetes.

Lab 5 — So sánh State qua Revision

Mục tiêu: Thấy rõ revision tăng theo từng write operation.

Rút ra gì?

  • Current value là v3, nhưng revision đã tăng qua từng lần sửa
  • Mỗi update tạo ra phiên bản logic mới trên toàn cluster

Lab 6 — Transaction (Compare-and-Swap)

Mục tiêu: Hiểu atomicity và conditional write.

Mở transaction interactive:

etcd sẽ hiện 3 prompt theo thứ tự. Nhập như sau (mỗi section kết thúc bằng một dòng trống):

compares:                                ← prompt tự hiện, không cần gõ
value("/lab/txn/count") = "1"
                                         ← Enter trống → chuyển sang section tiếp

success requests (get, put, del):        ← prompt tự hiện
put /lab/txn/result success
                                         ← Enter trống

failure requests (get, put, del):        ← prompt tự hiện
put /lab/txn/result failed
                                         ← Enter trống → thực thi

Lưu ý

Không gõ cmp, then, else. Ba prompt là tự động hiện ra — chỉ cần nhập nội dung và Enter trống để chuyển section.

Kiểm tra kết quả:

Thử case fail — thay đổi value rồi chạy lại transaction:

Rút ra gì?

  • etcd hỗ trợ compare-and-swap style logic
  • Đây là nền tảng cho distributed lock, leader election, coordination

Lab 7 — Lease và TTL

Mục tiêu: Hiểu khái niệm ephemeral data.

Rút ra gì?

  • Lease là “thời gian sống” gắn với key
  • Dùng cho session, heartbeat, ephemeral registration
  • Trực giác: “nếu không renew thì coi như chết”

  • Keepalive giống heartbeat
  • Khi process chết, lease hết → key tự xóa
  • Cơ chế này dùng cho leader election và service registration

Mục tiêu: Xem thông tin cluster runtime.

Rút ra gì?

  • Single-node vừa là member duy nhất vừa là leader
  • Sau này 3-node sẽ thấy rõ leader/follower distinction

Lab 12 — Snapshot Backup và Restore

Mục tiêu: Nắm vững quy trình backup/restore — bắt buộc cho vận hành thật.

Restore thật trong production

Muốn restore thật:

  1. systemctl stop etcd
  2. Backup data-dir cũ
  3. etcdutl snapshot restore ra data-dir mới
  4. systemctl start etcd

Rút ra gì?

  • Snapshot là backup logic
  • Restore sinh ra data-dir mới
  • Không bao giờ restore đè lên data-dir đang chạy

Lab 13 — Compact (Dọn lịch sử revision)

Mục tiêu: Hiểu tại sao cần compact và nó làm gì.

Rút ra gì?

  • Compact dọn revision history cũ
  • Current value vẫn còn nguyên
  • Thứ bị dọn là lịch sử, không phải giá trị hiện tại

Lab 14 — Defrag (Thu hồi storage vật lý)

Mục tiêu: Hiểu sự khác nhau giữa DB size và in-use size.

Compact vs Defrag

CompactDefrag
Làm gìDọn logical historyThu hồi storage vật lý
Khi nào cầnKhi revision tích lũy quá nhiềuSau khi compact hoặc xóa nhiều key
Ảnh hưởngGiảm số revision lưu trữGiảm DB SIZE trên disk

Lab 20 — Self-Assessment Checklist

Sau khi làm xong, tự trả lời 10 câu này:

  • put/get/del trong etcd hoạt động ra sao?
  • Prefix key giúp tổ chức dữ liệu thế nào?
  • revision, version, create_revision, mod_revision khác nhau thế nào?
  • watch dùng để làm gì?
  • lease + keepalive mô hình hóa heartbeat ra sao?
  • Transaction giúp điều phối thế nào?
  • lock và elect có tác dụng gì?
  • snapshot khác restore thế nào?
  • compact khác defrag thế nào?
  • Tại sao Kubernetes cần etcd chứ không dùng database thông thường?

Cách học đúng chất SRE

Với mỗi lab, ghi lại 3 dòng:

  • Tôi vừa làm gì
  • etcd phản ứng thế nào
  • Trong Kubernetes điều này tương ứng với cái gì

Ví dụ với watch:

  • Tôi vừa watch một key
  • etcd stream event khi key đổi
  • Trong K8S, controller watch object thay đổi để reconcile
