1. Quota và NOSPACE Alarm

etcd có giới hạn dung lượng

etcd mặc định giới hạn database 2 GB (--quota-backend-bytes). Khi đầy:

etcdserver: mvcc: database space exceeded

Hậu quả: Cluster chuyển sang read-only → K8S không thể tạo/update bất kỳ object nào.

Cluster sẽ chết

apiserver ghi object vào etcd. etcd read-only = apiserver lỗi = không thể schedule pods, update deployments, tạo services.

Phát hiện NOSPACE

Output khi có alarm:

memberID:17047539645383733244 alarm:NOSPACE

Kiểm tra dung lượng hiện tại

CộtÝ nghĩa
DB SIZETổng dung lượng file trên disk
IN USEPhần đang chứa data thật

Khi DB SIZE → quota limit → NOSPACE alarm.

Xử lý NOSPACE — Step by step

Thứ tự quan trọng

Phải compact → defrag → disarm. Nếu chỉ disarm mà không compact/defrag, alarm sẽ lại trigger ngay.

2. Compact — Dọn dẹp lịch sử

Tại sao cần compact?

Mỗi write operation tạo một revision mới. etcd giữ tất cả lịch sử cho đến khi bạn compact. Sau vài tuần, lịch sử revision có thể chiếm rất nhiều dung lượng.

3. Defrag — Thu hồi disk space

Compact ≠ Defrag

CompactDefrag
Làm gìXóa logical revision historyThu hồi physical disk space
Khi nàoThường xuyên (auto)Định kỳ hoặc sau compact lớn
Ảnh hưởngKhông downtimeBlock I/O trong vài giây
Kết quảQuorum cho historyDB SIZE giảm

Chạy defrag

Defrag block I/O

Defrag sẽ block etcd I/O trong thời gian chạy (thường vài giây, có thể lâu hơn với DB lớn). Trong HA cluster, defrag từng node một, bắt đầu từ follower, leader cuối cùng.

Disk là yếu tố quan trọng nhất

5. WAL và Snapshot — Hiểu internal storage

Write-Ahead Log (WAL)

/var/lib/etcd/member/wal/
  • Mọi write operation ghi vào WAL trước khi apply vào database
  • Đảm bảo durability: mất điện giữa chừng → etcd replay WAL khi start lại
  • WAL files có kích thước cố định (~64 MB mỗi file)

Snapshot files

/var/lib/etcd/member/snap/
  • Snapshot lưu toàn bộ state tại một thời điểm
  • Sau khi tạo snapshot, WAL cũ được dọn
  • Tần suất: mỗi --snapshot-count write operations

Database file

/var/lib/etcd/member/snap/db
  • Đây là BoltDB file chứa actual data
  • File này là thứ mà etcdctl endpoint status report là “DB SIZE”

6. Checklist vận hành production

Hàng ngày

  • Kiểm tra endpoint health trên mọi node
  • Kiểm tra alarm list — phải trống
  • Kiểm tra DB SIZE vs quota

Hàng tuần

  • Verify auto-compaction đang chạy
  • Kiểm tra disk latency (wal_fsync_duration)
  • Review snapshot backup schedule

Hàng tháng

  • Chạy defrag (từng node, follower trước)
  • Review DB SIZE trend
  • Test restore từ backup (để chắc backup hoạt động)

Khi có incident

  • alarm list — NOSPACE?
  • endpoint status -w table — leader ổn định?
  • member list -w table — thiếu member?
  • journalctl -u etcd -n 100 hoặc kubectl logs — error message?
