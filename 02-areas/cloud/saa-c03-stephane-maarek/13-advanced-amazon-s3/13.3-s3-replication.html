Replication là gì?

S3 Replication tự động copy object từ source bucket → destination bucket — asynchronous, one-way.

Hai loại Replication

Loại Ý nghĩa Use Case
CRR (Cross-Region Replication) Source & Destination khác region Compliance, DR, giảm latency đọc cho user xa
SRR (Same-Region Replication) Source & Destination cùng region Log aggregation, replicate prod → test/staging

Điều kiện bắt buộc

  1. ✔ Bật Versioning ở cả source và destination bucket.
  2. ✔ Có IAM Role cho phép S3 thực hiện replication (AWS tự tạo hoặc bạn tạo).
  3. ❗ Replication là asynchronous — không real-time, có độ trễ nhỏ.

Buckets có thể ở:

  • Khác region.
  • Khác AWS account (hay dùng cho compliance).

5 Điều quan trọng về Replication (hay ra thi)

1. Chỉ áp dụng cho object MỚI

  • Object upload sau khi bật rule → ✔ được replicate.
  • Object tồn tại trước khi bật rule → ❌ KHÔNG tự replicate.

Muốn replicate object cũ? → Dùng S3 Batch Replication.

2. DELETE và Versioning

Hành động Có replicate không?
Delete không có version ID Tạo delete marker → Có thể replicate (nếu bật option)
Delete có version ID cụ thể ❌ KHÔNG replicate — tránh malicious delete lan rộng

3. Không có Replication chaining

Object tạo ở A → KHÔNG tự sang C dù B→C có rule.

4. Replication là ONE-WAY

  • Destination không biết về source, không trigger ngược lại.
  • Thay đổi ở destination không quay về source.

5. IAM và cơ chế bên trong

  • AWS gán IAM Role cho S3 với quyền read source + write destination.
  • S3 service tự chạy replication.
  • Bạn không cần Lambda, cron, hay event thêm.

Use Cases

CRR:

  • Compliance (data phải lưu ở nhiều region).
  • Disaster Recovery multi-region.
  • Giảm latency đọc cho user ở region khác.

SRR:

  • Log aggregation (gom log từ nhiều bucket → 1).
  • Replicate production → test/staging.
  • Phân tách dữ liệu trong cùng region (separation of concerns).

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"compliance, lưu data ở region khác" CRR
"gom log từ nhiều bucket cùng region" SRR
"replicate cả object đã tồn tại từ trước" S3 Batch Replication
"xoá object có version ID cụ thể có replicate không?" Không — chặn malicious delete
"A→B, B→C, upload vào A có sang C không?" Không — không có chaining
"sửa ở destination có ảnh hưởng source không?" Không — one-way, không trigger ngược

Điểm hay ra thi

  • Versioning bắt buộc ở CẢ hai bucket — quên 1 bên là không hoạt động.
  • Object cũ KHÔNG tự replicate — dùng S3 Batch Replication.
  • Delete có version ID → KHÔNG replicate (bảo vệ chống xóa ác ý).
  • Không có chaining: A→B + B→C ≠ A→C.
  • Replication là ONE-WAY — destination không trigger ngược về source.

Takeaway cá nhân

  • CRR = multi-region DR + compliance; SRR = isolation prod/test trong cùng region.
  • Replication không phải sync/mirror — asynchronous one-way copy.
  • Bật Versioning trước, sau đó mới tạo Replication Rule.
