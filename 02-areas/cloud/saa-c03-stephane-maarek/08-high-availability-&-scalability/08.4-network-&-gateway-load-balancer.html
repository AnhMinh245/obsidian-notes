8.4 – Network Load Balancer (NLB) & Gateway Load Balancer (GWLB)

Cách đọc note này: NLB và GWLB là 2 dịch vụ khác hẳn nhau dù cùng "họ ELB" — NLB phục vụ hiệu năng cao (TCP/UDP + static IP), GWLB phục vụ security appliance (firewall/IDS/IPS inline). Đừng nhầm 2 use case này.

Network Load Balancer (NLB) — Layer 4

NLB là gì?

NLB hoạt động ở Layer 4 (TCP/UDP/TLS), được thiết kế cho workload cần:

  • Hiệu năng cực cao — xử lý hàng triệu request/giây.
  • Độ trễ cực thấp — microsecond latency.
  • Static IP — 1 IP tĩnh cho mỗi AZ.

Khác với ALB, NLB không đọc nội dung HTTP — nó chỉ nhìn vào TCP/UDP packet headers để forward.

Đặc điểm quan trọng

  • Static IP cho mỗi AZ → rất tiện khi cần whitelist IP (firewall doanh nghiệp, banking, partner API).
  • Có thể gán Elastic IP cho mỗi AZ nếu muốn IP cố định hoàn toàn.
  • Hỗ trợ TCP, UDP, TLS (TLS offloading tùy chọn).
  • Failover cực nhanh và ổn định hơn ALB trong các workload network-intensive.

Target Groups của NLB

NLB hỗ trợ 3 loại target:

Target Type Mô tả Use case
EC2 Instances Đăng ký trực tiếp instance App server thông thường
IP Addresses Private IP (bao gồm on-premise qua DX/VPN) Hybrid architecture
Application Load Balancer NLB phía trước → ALB phía sau Cần static IP + Layer 7 routing

Mô hình NLB + ALB rất phổ biến: NLB cung cấp IP tĩnh (cho whitelist firewall), ALB xử lý routing thông minh Layer 7.

Health Check của NLB

NLB hỗ trợ:

  • TCP health check — nhanh và nhẹ nhất.
  • HTTP/HTTPS health check — phù hợp nếu backend là web service.

Lưu ý: NLB không đọc HTTP header, health check HTTP chỉ để kiểm tra trạng thái backend.

Gateway Load Balancer (GWLB) — Layer 3

GWLB là gì?

Gateway Load Balancer giúp triển khai, mở rộng và quản lý các thiết bị mạng ảo (virtual security appliances) của bên thứ ba, ví dụ:

  • Firewall (Check Point, Palo Alto, Fortinet…)
  • IDS/IPS (Intrusion Detection/Prevention)
  • Deep Packet Inspection (DPI)
  • Network analytics / Traffic inspection

Nói đơn giản: GWLB là điểm chặn duy nhất để đẩy toàn bộ traffic qua hệ thống security appliance, đảm bảo scale + high availability mà ứng dụng không biết có firewall ở giữa.

GWLB hoạt động ở Layer 3 (Network Layer)

Khác với ALB (L7) hoặc NLB (L4), GWLB xử lý IP packets — cho phép firewall/IPS nhìn thấy traffic nguyên bản để phân tích chuyên sâu.

GWLB = 2 chức năng trong 1

Chức năng Mô tả
Transparent Network Gateway Điểm đi/về duy nhất, ứng dụng/client không biết có appliance đứng giữa, không thay đổi IP
Load Balancer Phân phối traffic đến nhiều virtual appliances, tự scale out/in, đảm bảo HA

GENEVE Protocol — Port 6081

Tại sao cần GENEVE? Vì nó giữ nguyên gói tin gốc bên trong — firewall/IPS cần thấy raw traffic để phân tích.

Target Group của GWLB

Chỉ hỗ trợ 2 loại:

  • EC2 Instances — chạy firewall software.
  • IP Addresses (private IP bắt buộc) — appliance on-prem hoặc VM custom.

Luồng hoạt động điển hình

Khi nào dùng GWLB?

  • Cần inline firewall/IPS/DPI với traffic.
  • Muốn scale-out security layer.
  • Cần tách lớp security khỏi application (security VPC riêng).
  • Dùng firewall từ marketplace và muốn HA + auto scaling.
  • Triển khai security inspection trong mô hình multi-VPC.

So sánh ALB – NLB – GWLB

Tiêu chí ALB NLB GWLB
Layer OSI Layer 7 (HTTP) Layer 4 (TCP/UDP) Layer 3 (IP)
Use case chính Web app, microservices, routing HTTP High performance TCP/UDP, static IP Firewall, IDS/IPS, security appliance
Protocol HTTP, HTTPS, gRPC TCP, UDP, TLS IP (GENEVE port 6081)
Routing thông minh Path, Host, Header, Query ❌ Không ❌ Không
X-Forwarded-For ✔ Có ❌ Không ❌ Không
Static IP ❌ Không ✔ 1 IP/AZ + Elastic IP Thông qua GWLB Endpoint
TLS Termination ✔ Có ✔ Có (L4) ❌ Không
Target Types Instance, IP, Lambda, ALB Instance, IP, ALB Instance, IP (private only)
Health Check HTTP/HTTPS TCP/HTTP/HTTPS GENEVE
Sticky Session ✔ ✔ (TCP only) ❌
Phù hợp Web, API, microservices Game, VoIP, DB proxy, IoT Inline security appliance

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Cần IP tĩnh để whitelist firewall đối tác" NLB (static IP per AZ, có thể gán Elastic IP)
"Hàng triệu request/giây, microsecond latency" NLB
"Deploy firewall/IDS/IPS bên thứ 3 inline với traffic" GWLB
"Traffic phải được inspect trước khi tới app, app không biết" GWLB (Transparent Network Gateway)
"Encapsulation protocol port 6081" GENEVE (GWLB)
"TLS passthrough, không muốn terminate tại LB" NLB (không phải ALB)

Điểm hay ra thi

  • NLB có static IP → khi đề hỏi "cần IP cố định để whitelist" → chọn NLB (hoặc NLB + ALB).
  • GWLB dùng GENEVE port 6081 — keyword quan trọng trong câu hỏi security appliance.
  • NLB cũng hỗ trợ SNI (thường bị bỏ sót) — NLB có thể terminate TLS với nhiều cert.
  • GWLB target group chỉ nhận private IP — không public.
  • NLB + ALB là combo khi cần cả static IP lẫn L7 routing.

Takeaway cá nhân

  • NLB là lựa chọn khi hiệu năng > flexibility (game server, financial trading, VoIP).
  • GWLB giải quyết bài toán "security appliance as a service" — không cần tự lo scale/HA cho firewall.
  • Khi đề thi hỏi về "firewall/IDS/IPS inline traffic" → GWLB là câu trả lời.
