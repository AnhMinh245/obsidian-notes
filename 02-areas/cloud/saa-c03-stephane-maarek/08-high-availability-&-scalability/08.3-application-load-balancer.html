8.3 – Application Load Balancer (ALB)

Cách đọc note này: ALB là loại LB phổ biến nhất trong đề thi. Trọng tâm cần nhớ: 4 loại routing rule, 4 loại target, và cơ chế X-Forwarded-For (vì ALB terminate TCP connection nên backend không thấy IP thật).

ALB là gì?

Application Load Balancer (ALB) là Load Balancer thế hệ v2 của AWS, hoạt động ở Layer 7 (HTTP/HTTPS/WebSocket) của mô hình OSI. Đây là Load Balancer phổ biến nhất trong các ứng dụng web hiện đại.

Khác với NLB (chỉ nhìn TCP/UDP), ALB hiểu được nội dung HTTP:

  • HTTP headers, path, hostname, query string, method (GET/POST…), cookies.
  • Từ đó thực hiện smart routing — định tuyến thông minh đến đúng backend.

Những tính năng nổi bật

1. Routing thông minh theo nhiều tiêu chí

ALB định tuyến traffic dựa trên 4 loại rule:

Loại Rule Ví dụ Dùng cho
Path-based /api/* → TG-API, /images/* → TG-Images Microservices theo path
Host-based api.example.com → TG-API, shop.example.com → TG-Shop Multi-domain trên 1 ALB
Query String ?platform=mobile → TG-Mobile A/B testing, multi-platform
Header-based User-Agent: Mobile → TG-Mobile Device-specific routing

2. Hỗ trợ nhiều ứng dụng và nhiều backend

  • Một ALB có thể phục vụ nhiều ứng dụng thông qua nhiều target group.
  • Mỗi target group có health check riêng.
  • Thay thế được hàng chục CLB → tiết kiệm chi phí đáng kể.

3. Hỗ trợ giao thức hiện đại

  • HTTP/1.1 — chuẩn truyền thống.
  • HTTP/2 — cải thiện tốc độ web (multiplexing, compression).
  • WebSocket — giao tiếp real-time (chat, dashboard live).

4. HTTP → HTTPS Redirect

ALB hỗ trợ tự động redirect HTTP → HTTPS, không cần cấu hình trong backend.

5. Tích hợp authentication

  • OIDC (OpenID Connect).
  • Amazon Cognito.
  • Social providers (Google, Facebook, Amazon).

Target Groups — tại sao ALB không route trực tiếp vào EC2?

Target Group là lớp trừu tượng giữa ALB và backend. Xem chi tiết: Tại sao ALB phải dùng Target Groups?

ALB hỗ trợ 4 loại target:

Target Type Mô tả Use case
EC2 Instances Kết hợp với Auto Scaling Group Web/App server thông thường
ECS Tasks Dynamic port mapping, tự đăng ký Container (Fargate/EC2 launch type)
Lambda Functions ALB chuyển HTTP request → JSON event Serverless backend
IP Addresses Private IP (on-premise qua VPN/DX) Hybrid architecture

Health check được cấu hình tại cấp target group, không phải tại ALB.

X-Forwarded Headers — quan trọng với developer

ALB chấm dứt kết nối TCP từ client (connection termination):

  • Connection từ client → dừng tại ALB.
  • ALB mở connection mới → backend.
  • Backend không thấy IP thật của client.

AWS giải quyết bằng cách thêm header vào request:

Header Giá trị
X-Forwarded-For IP thật của client
X-Forwarded-Port Port client đang dùng
X-Forwarded-Proto Protocol (http hoặc https)

Backend cần đọc X-Forwarded-For thay vì IP trong socket connection để lấy IP thật của user.

Hostname của ALB là cố định (không có IP tĩnh)

ALB không có IP cố định — nó dùng nhiều IP (để tự scale). Hostname dạng:

my-alb-123456789.ap-southeast-1.elb.amazonaws.com

Thực hành tốt nhất: Dùng Route 53 Alias Record trỏ vào hostname này — không dùng IP trực tiếp.

Khi nào chọn ALB thay vì NLB?

Use case Chọn
HTTP/HTTPS web app ALB
Routing theo path, host, query, header ALB
Microservices ALB
ECS/Fargate containers ALB
Cần IP tĩnh (whitelist firewall) NLB
TCP/UDP low-latency NLB
TLS passthrough (không muốn terminate TLS tại LB) NLB

Khi ALB không phù hợp

  • Không xử lý TCP/UDP thuần.
  • Không cho phép TLS passthrough (ALB luôn terminate TLS).
  • Không phù hợp workload yêu cầu hàng triệu request/sec với microsecond latency → dùng NLB.

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Route theo path /api/*, /images/*" Path-based routing
"Route theo api.example.com vs shop.example.com" Host-based routing
"Backend cần biết IP thật của client" Đọc header X-Forwarded-For
"ALB làm backend cho Lambda serverless" Target Group loại Lambda Function
"Cần route tới server on-premise qua VPN/DX" Target Group loại IP Addresses
"1 ALB phục vụ nhiều domain HTTPS" SNI — xem 08.5 - ELB Advanced Features

Điểm hay ra thi

  • ALB tốt nhất cho microservices và container (ECS/EKS).
  • Target Group có thể chứa Lambda — ALB làm gateway serverless.
  • X-Forwarded-For là cách lấy IP thật của client khi dùng ALB.
  • ALB hostname cố định nhưng IP thay đổi → luôn dùng DNS (Route 53 Alias), không hardcode IP.
  • 1 ALB có thể thay thế nhiều CLB → tiết kiệm chi phí.

Takeaway cá nhân

  • ALB là lựa chọn mặc định cho hầu hết web app hiện đại vì routing Layer 7 linh hoạt.
  • Kiến trúc microservice chuẩn: Route 53 → ALB (path routing) → nhiều Target Groups → nhiều ECS services.
  • Backend phải đọc X-Forwarded-For để lấy IP client thật.
