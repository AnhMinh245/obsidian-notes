12.3 – S3 Bucket Policy & Access Control

Cách đọc note này: Trọng tâm là "4 kịch bản truy cập S3" bên dưới — đề thi gần như luôn hỏi dưới dạng tình huống, không hỏi lý thuyết suông. Đối chiếu thêm ở 3.1 - Storage Solutions - S3, EBS, EFS, FSx.

Hai nhóm phân quyền S3

1. User-based — IAM Policies

  • Gắn policy vào IAM user / group / role.
  • Định nghĩa user đó được phép gọi API S3 nào (s3:GetObject, s3:PutObject…) trên resource nào.

IAM policy = "User biết làm gì"

2. Resource-based — Bucket Policy & ACL

Bucket Policy:

  • Gắn lên bucket (JSON) — áp dụng cho cả bucket + mọi object bên trong.
  • Dùng cho: public access, cross-account access, bắt buộc encryption.

Object ACL:

  • Gắn trên từng object — granular rất nhỏ.
  • Nhiều nơi disable ACL để đơn giản (S3 Object Ownership).

Bucket ACL:

  • ACL cho cả bucket — ít dùng, có thể disable hoàn toàn.

Quy tắc "Được truy cập hay không?"

Một IAM principal chỉ truy cập được khi đồng thời thỏa:

  1. IAM Allow hoặc Resource Policy Allow
  2. Không có Deny nào (Deny luôn thắng Allow)
IAM Policy Bucket Policy Kết quả
Allow (không có) ✅ Cho phép
(không có) Allow ✅ Cho phép
Allow Deny ❌ Từ chối
Deny Allow ❌ Từ chối
(không) (không) ❌ Từ chối (default deny)

Bucket Policy — Cấu trúc

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "PublicRead",
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::examplebucket/*"
  }]
}
Field Mô tả
Effect Allow hoặc Deny
Principal Ai áp dụng (* = tất cả; ARN cụ thể)
Action API S3 được phép/từ chối
Resource Bucket và/hoặc object (ARN)
Condition Điều kiện tùy chọn (IP, MFA, SecureTransport…)

4 Kịch bản truy cập S3

Kịch bản 1: Public Access (Static Website)

  • Người truy cập là anonymous (không có IAM user).
  • Chỉ hoạt động khi Bucket Policy cho phép Principal: * làm s3:GetObject.
  • Phải tắt Block Public Access trước.

Kịch bản 2: IAM User Access (Dev/Ops)

  • Dev dùng AWS CLI hoặc Console.
  • Cấp quyền qua IAM Policy gắn vào user hoặc group.
  • Không cần bucket policy nếu không có yêu cầu đặc biệt.

Kịch bản 3: EC2 Access

  • EC2 KHÔNG dùng access key hardcode (không an toàn).
  • Dùng IAM Role gắn vào EC2 instance → AWS tự cấp temporary credentials.

Thi hay hỏi: "EC2 cần đọc ghi S3, cách nào secure nhất?" → IAM Role, không phải access key.

Kịch bản 4: Cross-Account Access

  • IAM User ở account B muốn vào bucket của account A.
  • Account A cần viết Bucket Policy với Principal là ARN của user/role account B.

Cross-account S3 → Bucket Policy là bắt buộc.

Block Public Access

Lớp bảo vệ "ngoài cùng" — chặn mọi public access kể cả khi Bucket Policy có Allow.

Setting Ý nghĩa
Block all public access Chặn tất cả
Block public ACLs Chặn ACL grant public
Block public bucket policy Chặn bucket policy tạo public

Có thể set:

  • Ở cấp Account → áp cho tất cả bucket trong account.
  • Ở cấp Bucket → từng bucket riêng.

Best practice: Luôn bật Block Public Access. Tắt chỉ khi thực sự cần public (static website, public dataset).

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Ai cũng đọc được object, không cần đăng nhập" Bucket Policy với Principal: "*" (+ tắt Block Public Access)
"Dev/Ops thao tác S3 qua CLI/Console hàng ngày" IAM Policy gắn vào user/group
"EC2 cần đọc/ghi S3, không muốn hardcode key" IAM Role gắn vào EC2 Instance Profile
"User ở account khác cần truy cập bucket của mình" Bucket Policy với Principal là ARN account kia (IAM Role của account B không đủ)
"IAM Allow nhưng vẫn bị từ chối" Có Deny ở đâu đó (IAM/Bucket Policy/Block Public Access) — Deny luôn thắng
"Bật Bucket Policy Allow Public nhưng vẫn 403" Block Public Access đang bật — override tất cả

Điểm hay ra thi

  • Deny luôn thắng Allow — dù IAM Allow hay Bucket Policy Allow.
  • Default = Deny khi không có policy nào.
  • Cross-account → Bucket Policy bắt buộc (không chỉ IAM policy của account kia).
  • EC2 truy cập S3 → IAM Role, không hardcode access key.
  • Block Public Access override Bucket Policy — nếu bật thì không có gì public được.
  • Object ACL hay bị disable trong setup mới — Bucket Policy là cách chuẩn.

Takeaway cá nhân

  • IAM Policy = "identity biết làm gì"; Bucket Policy = "resource cho phép ai".
  • Deny luôn thắng — nhớ điều này là đủ để trả lời đa số câu hỏi về S3 access.
  • Block Public Access là lớp override cuối cùng — kiểm tra nó trước khi debug 403.
