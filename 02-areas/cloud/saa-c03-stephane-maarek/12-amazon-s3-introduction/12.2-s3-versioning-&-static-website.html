12.2 – S3 Versioning & Static Website

Cách đọc note này: 2 tính năng độc lập của S3 nhưng hay đi cùng nhau trong đề thi: Versioning bảo vệ dữ liệu khỏi xoá nhầm, Static Website là cách dùng S3 làm web hosting giá rẻ. Xem thêm 3.1 - Storage Solutions - S3, EBS, EFS, FSx.

S3 Versioning

Versioning cho phép lưu nhiều phiên bản của cùng một object trong cùng một bucket.

Cách bật

Bật ở bucket level — áp dụng cho toàn bộ bucket, không phải từng object.

Cách hoạt động

Tại sao nên bật Versioning?

  • Chống xóa nhầm — xóa object chỉ tạo "delete marker", không mất dữ liệu thật.
  • Rollback về phiên bản cũ bất cứ lúc nào.
  • Bắt buộc để dùng S3 Replication (xem S3 Replication).
  • Quan trọng cho Backup, Compliance, MFA Delete.

Các gotcha hay bị nhầm

Tình huống Thực tế
File tồn tại trước khi bật versioning Version ID là null
Suspend versioning ❌ KHÔNG xóa version cũ; chỉ ngừng tạo version mới
Xóa object (không chỉ định version) Tạo delete marker — object vẫn tồn tại, chỉ bị ẩn đi
Xóa delete marker Object "hiện lại" — như chưa bị xóa
Xóa có version ID cụ thể Xóa vĩnh viễn phiên bản đó

Điểm thi: Suspend ≠ Delete versions. Xóa object tạo delete marker — không phải xóa thật.

Versioning + Lifecycle Rules

Lifecycle Rules có thể scope vào non-current versions để tự động chuyển class hoặc xóa. Xem S3 Lifecycle Rules.

S3 Static Website Hosting

S3 có thể host static website — chỉ gồm HTML, CSS, JavaScript, ảnh. Không chạy được server-side code (PHP, Node, Python…).

Cách kích hoạt

  1. Vào bucket → Properties → Static website hosting → Enable.
  2. Đặt tên file index (vd: index.html) và error page (vd: error.html).
  3. Bucket Policy phải cho phép public read.

URL website

http://bucket-name.s3-website-aws-region.amazonaws.com
http://bucket-name.s3-website.aws-region.amazonaws.com

Ví dụ:

http://my-site.s3-website-us-east-1.amazonaws.com

Yêu cầu bắt buộc

  • Bucket phải cho phép public read (Bucket Policy Principal: "*" Allow s3:GetObject).
  • Tắt Block Public Access trước khi gán public bucket policy.
  • Nếu không → 403 Forbidden.

Điểm thi: Static website endpoint bắt buộc bucket public. Khác với CloudFront + OAC (Origin Access Control) — dùng CloudFront thì bucket có thể private.

Tại sao nên dùng CloudFront thay vì S3 Website endpoint trực tiếp?

Tiêu chí S3 Website Endpoint CloudFront + S3
HTTPS ❌ Chỉ HTTP ✔ HTTPS
CDN / Edge caching ❌ Không ✔ Có
Bucket public? Bắt buộc Không cần (OAC)
Custom domain Cần CNAME/Alias Hỗ trợ tốt hơn
Chi phí Rẻ hơn Tốt hơn cho lưu lượng lớn

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Xoá nhầm object, muốn khôi phục được" Bật Versioning trước khi sự cố xảy ra
"Tắt versioning có mất data cũ không?" Không — Suspend chỉ ngừng tạo version mới
"Object trước khi bật versioning có version ID gì?" null
"Host web tĩnh (HTML/CSS/JS) rẻ nhất trên AWS" S3 Static Website Hosting
"Website S3 trả 403 Forbidden" Kiểm tra Block Public Access và Bucket Policy
"Cần HTTPS cho static site" Bắt buộc thêm CloudFront phía trước (S3 endpoint chỉ HTTP)

Điểm hay ra thi

  • Suspend versioning KHÔNG xóa versions cũ.
  • File cũ (trước khi bật versioning) có version = null.
  • Delete object → delete marker, không mất data thật.
  • Static website → 403 Forbidden khi Block Public Access bật hoặc thiếu bucket policy.
  • S3 website endpoint chỉ hỗ trợ HTTP, không phải HTTPS.
  • Muốn HTTPS cho static site → cần CloudFront phía trước.

Takeaway cá nhân

  • Versioning = bảo vệ dữ liệu khỏi xóa nhầm — luôn bật cho bucket production.
  • Static website S3 = cách nhanh nhất host web tĩnh, nhưng cần public bucket; CloudFront + S3 là cách production-ready.
