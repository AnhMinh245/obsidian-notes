16 – Storage Extras

Snow Family, FSx, Storage Gateway, Transfer Family, DataSync — các dịch vụ storage “ngoài” EBS/EFS/S3 core nhưng rất hay ra thi vì dễ nhầm use case.

AWS Snow Family

Snow Family = thiết bị vật lý bảo mật cao, di động để:

  • Thu thập / xử lý data tại edge
  • Migrate data vào hoặc ra AWS (offline)
  • Phù hợp khi mạng quá chậm / đắt / không ổn định

Quy mô thiết bị (hay hỏi trong thi)

Thiết bị Quy mô data (order of magnitude) Ghi chú
Snowcone Vài TB Nhỏ, nhẹ, có thể chạy compute nhẹ
Snowball Edge Tới mức PB (nhiều device) Storage Optimized / Compute Optimized
Snowmobile Tới mức EB (exabyte) “Container truck” — migrate data center lớn

Nhớ theo bậc: Snowcone (TB) → Snowball (PB) → Snowmobile (EB).

Khi nào dùng Snow thay vì transfer qua mạng?

Thách thức của transfer online:

  • Connectivity hạn chế / không ổn định
  • Bandwidth hẹp hoặc shared (không maximize được đường truyền)
  • Chi phí mạng cao (egress / dedicated line đắt)

Rule of thumb (Stephane): Nếu transfer qua mạng > 1 tuần → dùng thiết bị Snow (offline).

Flow migrate điển hình (import vào AWS)

  • Data trên device được encrypt (keys quản lý qua KMS trong quy trình AWS).
  • Có thể export ngược: lấy data từ S3 ra device rồi ship về on-premises.

Edge Computing với Snowball Edge

Edge Computing = xử lý data ngay nơi data được tạo, trước khi (hoặc thay vì) gửi về cloud.

Ví dụ vị trí: xe tải, tàu biển, trạm khai thác dưới lòng đất — Internet kém / không có compute tại chỗ.

Thiết bị Mục đích
Snowball Edge Compute Optimized Edge compute (ưu tiên CPU/GPU)
Snowball Edge Storage Optimized Edge storage dung lượng lớn

Trên Snowball Edge có thể chạy:

  • EC2 instances
  • Lambda functions (compute tại device)

Use cases: preprocess data (lọc/nén trước khi gửi cloud), machine learning tại chỗ, transcoding media.

Snowball → Glacier: không import trực tiếp

  • Snowball không import thẳng vào Glacier.
  • Phải vào S3 trước, rồi dùng S3 Lifecycle Policy transition sang Glacier.

Điểm thi: “Migrate petabyte rồi archive Glacier” → Snowball → S3 → Lifecycle → Glacier. Không chọn “Snowball trực tiếp Glacier”.

Amazon FSx – Overview

Amazon FSx = launch file system third-party hiệu năng cao trên AWS — fully managed (patch, backup, HA tùy loại).

FSx Protocol / hệ Use case nổi bật
Windows File Server SMB, NTFS Share Windows, AD, DFS
Lustre Parallel FS (Linux/cluster) HPC, ML, video, finance
NetApp ONTAP NFS, SMB, iSCSI Migrate ONTAP/NAS, multi-OS
OpenZFS NFS v3/v4.x Migrate ZFS, clone nhanh

Khác EFS thế nào?

  • EFS = NFS managed “thuần AWS”, đơn giản, multi-AZ, cho Linux POSIX share thông thường.
  • FSx = khi cần semantics của Windows / Lustre / NetApp / ZFS (AD, DFS, parallel HPC, dedup, clone…).

Amazon FSx for Windows File Server

Fully managed Windows file share — thay thế Windows File Server tự quản.

Đặc điểm:

  • Protocol: SMB + Windows NTFS
  • Tích hợp Microsoft Active Directory, ACLs, user quotas
  • Mount được từ Linux EC2 (không chỉ Windows)
  • Hỗ trợ DFS Namespaces (gộp nhiều FS thành 1 namespace logic)
  • Scale: hàng chục GB/s, hàng triệu IOPS, hàng trăm PB
Storage Khi nào
SSD Latency-sensitive: DB, media processing, analytics
HDD Workload phổ thông: home directory, CMS

Kiến trúc / hybrid:

  • Truy cập từ on-premises qua VPN hoặc Direct Connect
  • Có thể cấu hình Multi-AZ (HA)
  • Backup hàng ngày sang S3

Điểm thi: Cần shared storage Windows + AD + ACL/NTFS → FSx for Windows, không chọn EFS (EFS là NFS/Linux-centric).

Amazon FSx for Lustre

Lustre = parallel distributed file system cho large-scale computing
(tên từ “Linux” + “cluster”).

Use cases: Machine Learning, HPC, video processing, financial modeling, EDA.

  • Scale: hàng trăm GB/s, hàng triệu IOPS, latency sub-ms
Storage Khi nào
SSD Low-latency, IOPS-intensive, file nhỏ / random
HDD Throughput-intensive, file lớn / sequential

Tích hợp S3 (điểm hay hỏi)

  • “Đọc S3 như file system” qua FSx (object S3 hiện ra dạng file/folder).
  • Ghi kết quả compute ngược lại S3.
  • Truy cập từ on-premises qua VPN / Direct Connect.

Deployment options: Scratch vs Persistent

Scratch Persistent
Mục đích Temporary storage Long-term storage
Replication ❌ Không replicate (mất nếu file server fail) ✔ Replicate trong cùng AZ
Hiệu năng Burst cao (6x, ~200 MB/s per TiB) Ổn định hơn; thay server hỏng trong vài phút
Chi phí Thường rẻ hơn cho job ngắn Cao hơn (có durability trong AZ)
Dùng khi Short-term processing, tối ưu chi phí Long-term, data nhạy cảm

Điểm thi: Job HPC ngắn, dataset có thể lấy lại từ S3 → Scratch. Data phải sống lâu trên FS → Persistent.

Amazon FSx for NetApp ONTAP

Managed NetApp ONTAP trên AWS — giữ feature set quen thuộc của NetApp.

  • Protocol: NFS, SMB, iSCSI (linh hoạt nhất trong nhóm FSx về protocol)
  • Migrate workload đang chạy ONTAP / NAS lên AWS với ít đổi app
  • Tương thích: Linux, Windows, macOS, VMware Cloud on AWS, WorkSpaces, AppStream 2.0, EC2, ECS, EKS
  • Storage tự co giãn (shrink/grow)
  • Snapshots, replication, compression, deduplication, chi phí thấp
  • Point-in-time instantaneous cloning — clone FS gần như tức thì để test workload mới (không copy full data)

Khi nào chọn ONTAP: Đề bài nhấn NetApp, deduplication, iSCSI + NFS + SMB cùng lúc, hoặc instant clone cho môi trường test.

Amazon FSx for OpenZFS

Managed OpenZFS trên AWS.

  • Protocol: NFS (v3, v4, v4.1, v4.2)
  • Migrate workload ZFS lên AWS
  • Tương thích: Linux, Windows, macOS, VMware Cloud on AWS, WorkSpaces, AppStream 2.0, EC2, ECS, EKS
  • Tới 1,000,000 IOPS, latency < 0.5 ms
  • Snapshots, compression, chi phí thấp
  • Point-in-time instantaneous cloning (giống ONTAP — dùng cho test)

FSx — chọn nhanh

Nhu cầu Chọn
Windows share + AD + SMB / NTFS / DFS FSx for Windows
HPC / ML / parallel FS + gắn S3 FSx for Lustre
NFS + SMB + iSCSI, dedup, ONTAP feature FSx for NetApp ONTAP
NFS + ZFS semantics, clone nhanh, IOPS cực cao FSx for OpenZFS
Linux POSIX shared FS đơn giản, multi-AZ EFS

Hybrid Cloud for Storage

AWS đẩy mô hình hybrid cloud: một phần infra trên cloud, một phần on-premises.

Lý do thường gặp: migration dài dở, security, compliance, IT strategy (“cloud dần”).

Vấn đề cốt lõi: S3 là object storage proprietary (không mount NFS thuần như EFS). Làm sao app on-premises “thấy” S3 như file share quen thuộc?

→ AWS Storage Gateway

AWS Storage — cloud-native options (nhắc lại)

AWS Storage Gateway

Cầu nối giữa data on-premises và data trên cloud — user/app on-prem dùng protocol quen (NFS/SMB/iSCSI/VTL), phía sau là AWS.

Use cases:

  • Disaster recovery
  • Backup & restore
  • Tiered storage (nóng on-prem cache, lạnh trên S3)
  • On-premises cache + low-latency file access
Loại Protocol phía on-prem Backend AWS “Nhìn” như
S3 File Gateway NFS / SMB S3 objects File share
Volume Gateway iSCSI Volumes → EBS snapshots trên S3 Đĩa block
Tape Gateway iSCSI VTL Virtual tapes → S3 / Glacier Tape library

Gateway thường chạy dạng VM (VMware / Hyper-V / KVM) hoặc hardware appliance, có local cache; kết nối Internet hoặc Direct Connect, encrypt in-transit.

Amazon S3 File Gateway

  • Bucket S3 truy cập qua NFS hoặc SMB như file share thường
  • Data dùng gần đây cache tại gateway → đọc nóng nhanh
  • Storage class hỗ trợ “ghi trực tiếp”: Standard, Standard-IA, One Zone-IA, Intelligent-Tiering
  • Sang Glacier / Deep Archive bằng Lifecycle Policy (không mount Glacier như folder hot)
  • Mỗi File Gateway dùng IAM Role để access bucket
  • SMB tích hợp Active Directory cho user authentication

Ví dụ đề bài: “On-premises cần NFS/SMB vào object trên S3, giữ cache local” → S3 File Gateway.

Volume Gateway

Block storage qua iSCSI, backed bởi S3 (qua EBS snapshots).

  • Backup thành EBS snapshots → restore volume on-premises hoặc tạo EBS volume trên AWS (DR rất tiện)
Mode Dataset chính nằm đâu? Hành vi Khi nào
Cached volumes AWS (S3) On-prem chỉ cache data nóng On-prem disk ít, muốn mở rộng gần như unlimited trên cloud
Stored volumes On-premises (full) Toàn bộ data local; backup định kỳ lên S3 Cần latency local tuyệt đối + vẫn muốn backup cloud

Mẹo nhớ: Cached = “não ở cloud, cache ở nhà”. Stored = “não ở nhà, backup lên cloud”.

Tape Gateway

Cho công ty vẫn backup bằng quy trình physical tape (và không muốn đổi backup software ngay).

  • Giữ cùng quy trình backup, tape trở thành ảo trên cloud
  • Virtual Tape Library (VTL) backed bởi S3 và Glacier
  • Interface iSCSI; tương thích nhiều backup software phổ biến
  • Workflow: backup → virtual tape trên S3 → “eject” → archive Glacier / Deep Archive

Điểm thi nhanh:

  • File share NFS/SMB ↔ S3 → File Gateway
  • iSCSI disk + Cached/Stored / EBS snapshot DR → Volume Gateway
  • Thay thế tape library → Tape Gateway

AWS Transfer Family

Fully managed file transfer vào/ra Amazon S3 hoặc Amazon EFS qua giao thức FTP-family — khi đối tác/hệ thống cũ chỉ nói SFTP/FTP/FTPS.

Protocol Ý nghĩa
FTP File Transfer Protocol (không mã hóa — hạn chế dùng)
FTPS FTP over SSL
SFTP Secure File Transfer Protocol (chạy trên SSH)

Đặc điểm:

  • Managed infrastructure, scalable, reliable, HA multi-AZ
  • Pricing: endpoint provisioned / giờ + data transfer (GB)
  • Quản lý user credential trong service, hoặc integrate IdP có sẵn:
    • Microsoft Active Directory, LDAP, Okta, Amazon Cognito, custom identity provider
  • Use cases: chia sẻ file với partner, public datasets, tích hợp CRM / ERP vẫn dùng SFTP

Điểm thi: “Partner upload bằng SFTP vào S3, không muốn quản lý FTP server” → Transfer Family.
Không chọn Storage Gateway (không phải SFTP endpoint) và không chọn DataSync (không phải giao thức FTP-family cho partner).

AWS DataSync

Di chuyển / đồng bộ lượng data lớn, có thể lên lịch, giữ metadata & permissions — tối ưu hơn tự viết rsync/script.

Chiều transfer Cần agent?
On-premises / cloud khác → AWS (NFS, SMB, HDFS, S3 API…) ✔ Cần agent (deploy gần nguồn)
AWS → AWS (giữa các storage services) ❌ Không cần agent

Có thể sync tới:

  • Amazon S3 (mọi storage class, kể cả Glacier)
  • Amazon EFS
  • Amazon FSx (Windows, Lustre, NetApp, OpenZFS…)

Đặc điểm vận hành:

  • Schedule: hourly / daily / weekly (hoặc one-time)
  • Giữ file permissions & metadata (NFS POSIX, SMB…)
  • Transfer incremental sau lần đầu (chỉ file đổi)
  • 1 agent task tới ~10 Gbps; có thể set bandwidth limit để không “bóp” mạng production

DataSync vs các dịch vụ “chuyển data” khác

Nhu cầu Chọn Vì sao
Online sync lớn, schedule, giữ metadata DataSync Tối ưu throughput + incremental
On-prem cần mount liên tục (NFS/SMB/iSCSI/tape) Storage Gateway Access ongoing, có cache local
Client/partner dùng SFTP/FTP/FTPS Transfer Family Protocol FTP-family managed
Offline, petabyte, mạng > 1 tuần Snow Family Ship thiết bị vật lý
Continuous file share Windows trên AWS FSx for Windows Không phải công cụ migrate

Kết hợp thực tế: DataSync (online, phần còn lại / delta hàng ngày) + Snowball (bulk ban đầu quá lớn) — đề thi đôi khi mô tả đúng pattern này.

Storage Comparison (tóm tắt toàn cảnh)

Dịch vụ Bản chất “Một câu” nhớ
S3 Object storage API object, không mount POSIX thuần
S3 Glacier Object archival Rẻ, retrieve chậm hơn
EBS Block network — gắn EC2 Thường 1 instance / volume
Instance Store Disk vật lý ephemeral IOPS cực cao, mất khi stop/terminate
EFS NFS Linux managed Multi-AZ share POSIX đơn giản
FSx for Windows Windows file server managed SMB + AD
FSx for Lustre HPC parallel FS Gắn S3, Scratch/Persistent
FSx for NetApp ONTAP NetApp managed NFS/SMB/iSCSI + dedup/clone
FSx for OpenZFS ZFS managed NFS + clone + IOPS cao
Storage Gateway Hybrid bridge File / Volume / Tape
Transfer Family FTP-family managed SFTP vào S3/EFS
DataSync Bulk / scheduled sync Agent on-prem; AWS↔AWS không agent
Snowcone / Snowball / Snowmobile Physical migration TB → PB → EB
Database Structured + query Không thay storage file/object

Tình huống thi — chọn dịch vụ nào?

Đề bài (rút gọn) Đáp án
80 TB, mạng chỉ xong sau 3 tuần Snowball
5 EB data center lift-and-shift Snowmobile
Import Snowball rồi lưu Glacier lâu dài Snowball → S3 → Lifecycle
Windows home directories + AD ACL FSx for Windows
1000 node ML đọc dataset từ S3 FSx for Lustre (+ S3)
Job HPC 2 ngày, tối ưu tiền, data tái tạo được Lustre Scratch
On-prem NFS trỏ vào objects S3, có cache S3 File Gateway
iSCSI volume, data full ở on-prem, backup cloud Volume Gateway Stored
iSCSI, on-prem disk nhỏ, primary data trên AWS Volume Gateway Cached
Backup software tape → cloud Tape Gateway
Đối tác bắt buộc SFTP upload vào S3 Transfer Family
Sync NFS on-prem → EFS mỗi đêm DataSync (+ agent)
Copy EFS region A → FSx/EFS region B DataSync (không agent)

Điểm hay ra thi

  • Snow scale: Snowcone (TB) / Snowball (PB) / Snowmobile (EB); > 1 tuần qua mạng → Snow.
  • Snowball không vào Glacier trực tiếp — luôn S3 + Lifecycle.
  • Windows + AD + SMB → FSx for Windows (không EFS).
  • HPC/ML + S3-as-filesystem → FSx for Lustre; Scratch vs Persistent.
  • NFS/SMB hybrid liên tục → File Gateway; iSCSI → Volume Gateway (Cached vs Stored); tape → Tape Gateway.
  • SFTP/FTPS/FTP → Transfer Family.
  • Sync lớn có schedule / AWS↔AWS → DataSync; đừng nhầm với Storage Gateway (mount ongoing).

Takeaway cá nhân

  • Bốn “cổng chuyển data”: Gateway = sống hybrid; DataSync = copy/sync; Transfer Family = FTP-family; Snow = xe tải offline.
  • FSx = khi EFS/EBS thiếu semantics (Windows AD, Lustre HPC, ONTAP/ZFS).
  • Cached vs Stored của Volume Gateway dễ mất điểm — đọc kỹ đề xem data “não” nằm đâu.
  • Snowball → Glacier = nhớ thêm bước Lifecycle.
