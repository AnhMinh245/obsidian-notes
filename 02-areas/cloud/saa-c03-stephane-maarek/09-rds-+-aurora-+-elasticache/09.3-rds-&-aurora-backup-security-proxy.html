9.3 – RDS & Aurora: Backup, Security, RDS Proxy

1. RDS Backups

Automated Backups (Tự động)

  • RDS tự động tạo daily full backup trong "backup window".
  • Transaction logs được backup mỗi 5 phút → cho phép Point-in-Time Recovery (PITR) đến 5 phút trước hiện tại.
  • Retention: 1–35 ngày (đặt = 0 thì tắt).

Manual Snapshots (Thủ công)

  • Người dùng chủ động tạo.
  • Lưu giữ vĩnh viễn cho đến khi bạn xóa.

Trick quan trọng trong thi: Khi Stop RDS instance, bạn vẫn phải trả tiền storage. Nếu định dừng lâu → snapshot → xóa instance → restore khi cần để tiết kiệm chi phí.

2. Aurora Backups

Điểm khác quan trọng nhất so với RDS:

  • Automated Backup của Aurora KHÔNG thể disable — luôn bật.
  • Retention 1–35 ngày.
  • PITR gần như realtime (dựa trên shared storage layer).

Manual Snapshots: giống RDS — lưu vĩnh viễn cho đến khi xóa.

3. Restore Options

Restore từ Automated Backup / Snapshot

  • Kết quả luôn là một DB mới — không overwrite DB cũ.

Restore MySQL RDS từ S3 (Migration on-prem → AWS)

  1. Backup DB on-premise.
  2. Upload vào S3.
  3. RDS đọc file từ S3 để tạo instance mới.

Restore MySQL Aurora từ S3 (dùng Percona XtraBackup)

  1. Backup on-prem bằng Percona XtraBackup.
  2. Upload vào S3.
  3. Aurora cluster mới được restore từ file đó.

4. Aurora Database Cloning

Mục đích: Tạo một Aurora cluster mới từ cluster hiện có — nhanh hơn snapshot/restore.

Cơ chế Copy-On-Write:

  • Bản clone ban đầu dùng chung storage với DB gốc → không cần copy dữ liệu.
  • Khi cluster mới ghi dữ liệu → phần đó mới được tách riêng.

Ưu điểm:

  • Cực nhanh (không copy data).
  • Tiết kiệm chi phí.
  • Không ảnh hưởng production.
  • Phù hợp cho staging, testing, analytics.

5. RDS & Aurora Security

Mã hóa dữ liệu lưu trữ (At-Rest Encryption)

  • RDS/Aurora dùng AWS KMS để mã hóa từ lúc tạo DB.
  • Master encrypted → replicas bắt buộc cũng encrypted.
  • Master không encrypted → replicas không thể encrypted.
  • Muốn mã hóa DB đang chạy mà chưa encrypted → snapshot → restore với encryption.

Exam trick: Không thể bật encryption trực tiếp trên DB đang chạy — phải đi qua snapshot.

Mã hóa khi truyền (In-Transit Encryption)

  • Tất cả RDS/Aurora TLS-ready mặc định.
  • Client dùng AWS TLS certificates để kết nối.

IAM Authentication

Thay vì username/password truyền thống, dùng IAM Roles để login DB:

  • Hỗ trợ MySQL, PostgreSQL, Aurora tương ứng.
  • Password trở thành IAM token (valid trong 15 phút, được generate từ IAM).

Hay xuất hiện trong thi: "Giải pháp nào giảm rủi ro credential leak?" → IAM Database Authentication.

Security Groups

  • SG kiểm soát lưu lượng inbound/outbound vào DB.
  • Whitelist application tier, EC2, Lambda, VPC CIDR.

No SSH Access

  • RDS/Aurora không cho SSH vào instance.
  • Ngoại lệ: RDS Custom (Oracle/SQL Server) — cho phép SSH vào underlying EC2.

Audit Logs

  • Bật general logs, slow query logs, audit logs → gửi sang CloudWatch Logs để lưu lâu và phân tích.

6. Amazon RDS Proxy

RDS Proxy là gì?

Fully-managed database proxy nằm giữa application và RDS/Aurora:

Vấn đề mà RDS Proxy giải quyết:

  • Lambda scale mạnh → mỗi instance mở connection riêng → DB bị connection storm → timeout, crash.
  • RDS Proxy gộp và chia sẻ các DB connection → giảm stress lên DB.

Các lợi ích chính

Lợi ích Mô tả
Connection Pooling Giảm số lượng connection thật vào DB, tránh overload
Serverless, Auto-Scaling Proxy tự mở rộng theo tải
Multi-AZ built-in Không cần cấu hình HA riêng
Failover nhanh hơn Giảm failover time cho RDS & Aurora tới 66%
IAM Authentication Ép buộc IAM auth, credentials lưu trong Secrets Manager
Không sửa code Chỉ đổi endpoint sang proxy endpoint
Không public RDS Proxy luôn trong VPC — không thể từ internet

Engine hỗ trợ

  • RDS MySQL / PostgreSQL / MariaDB / SQL Server.
  • Aurora MySQL / PostgreSQL.

Khi nào cần dùng RDS Proxy?

  • Lambda + RDS — Lambda scale mạnh → connection storm → bắt buộc dùng Proxy.
  • Muốn failover nhanh hơn mà không sửa code.
  • Muốn tập trung quản lý IAM credentials qua Secrets Manager.

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Lambda gọi RDS/Aurora bị connection timeout khi scale mạnh" RDS Proxy
"Giảm rủi ro lộ credential khi kết nối DB" IAM Database Authentication
"Bật encryption cho DB đang chạy mà chưa mã hoá" Không làm trực tiếp được — phải snapshot → restore with encryption
"Tạo bản sao DB cho staging mà không ảnh hưởng production, không tốn storage ban đầu" Aurora Database Cloning (copy-on-write)
"Dừng DB lâu ngày để tiết kiệm chi phí" Snapshot → xoá instance → restore khi cần (Stop vẫn tính tiền storage)

Xem thêm góc nhìn "domain thi": 3.3 - Database - RDS, Aurora, DynamoDB · 1.4 - Data Protection - KMS, ACM, Encryption · 1.6 - Secrets và Credentials Management.

Điểm hay ra thi

  • Aurora Automated Backup không thể tắt (RDS có thể tắt).
  • Mã hóa RDS: không thể bật trực tiếp → phải snapshot → restore với KMS.
  • IAM token thay password — valid 15 phút.
  • RDS Proxy = câu trả lời khi đề hỏi về Lambda + RDS connection timeout.
  • RDS Proxy giảm failover time 66%.
  • Aurora Cloning dùng Copy-On-Write → nhanh và không tốn storage ban đầu.

Takeaway cá nhân

  • Backup strategy: Automated (PITR) + Manual Snapshot (long-term retention) → biết cả hai.
  • Security: KMS at-rest + TLS in-transit + IAM auth + Security Group = 4 lớp bảo vệ.
  • RDS Proxy là bắt buộc cho kiến trúc Serverless (Lambda) dùng RDS/Aurora.
