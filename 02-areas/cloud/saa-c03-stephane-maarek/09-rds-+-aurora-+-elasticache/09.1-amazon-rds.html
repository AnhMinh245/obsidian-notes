9.1 – Amazon RDS

Amazon RDS là gì?

Amazon RDS (Relational Database Service) là dịch vụ cơ sở dữ liệu quan hệ được AWS quản lý hoàn toàn (fully managed). RDS giúp tạo, vận hành và mở rộng database SQL trên cloud mà không phải lo việc cài OS, DB engine, backup, patch, failover...

Các engine được hỗ trợ

Engine Ghi chú
PostgreSQL Open-source, phổ biến trong enterprise
MySQL Phổ biến nhất cho web app
MariaDB Fork của MySQL, open-source
Oracle Enterprise DB, tốn phí license
Microsoft SQL Server Enterprise, Windows ecosystem
IBM DB2 Enterprise legacy
Amazon Aurora AWS proprietary, tương thích MySQL/PostgreSQL, hiệu năng cao

Tại sao dùng RDS thay vì tự cài DB trên EC2?

Tính năng EC2 + DB tự cài Amazon RDS
Cài đặt OS + DB Bạn lo AWS lo
Patching OS/DB Bạn lo AWS lo (trong maintenance window)
Automated Backup Bạn tự code ✔ Tích hợp sẵn
Point-in-Time Restore Bạn tự làm ✔ Tự động (mỗi 5 phút)
Monitoring Bạn tự setup ✔ CloudWatch, Performance Insights
Read Replica Bạn tự config ✔ 1 click
Multi-AZ Failover Bạn tự build ✔ Tự động
SSH vào DB server ✔ Có ❌ Không
Chi phí management Cao Thấp hơn

Hạn chế duy nhất của RDS: Không SSH được vào DB server (vì fully-managed). Nếu cần SSH → dùng RDS Custom (chỉ Oracle + SQL Server).

RDS Storage Autoscaling

RDS có thể tự động mở rộng storage khi database sắp đầy — tránh downtime do hết dung lượng.

Cách bật: Đặt Maximum Storage Threshold (giới hạn AWS được phép tự động tăng).

RDS sẽ tự scale khi đồng thời thỏa 3 điều kiện:

  1. Free storage < 10% dung lượng hiện tại.
  2. Tình trạng low-storage kéo dài ≥ 5 phút.
  3. Đã qua 6 giờ từ lần autoscale trước (tránh scale liên tục).

Hỗ trợ: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, Aurora.

RDS Read Replicas vs Multi-AZ — bẫy thi số 1

Đây là cặp khái niệm bị nhầm nhiều nhất trong SAA-C03.

Read Replica — Scale đọc (READ ONLY)

  • Mục đích: Tăng hiệu năng đọc, giảm tải cho DB chính.
  • Replication: ASYNC — có độ trễ nhỏ (eventual consistency).
  • Đọc được không? ✔ Có — chỉ SELECT, không INSERT/UPDATE/DELETE.
  • Failover tự động? ❌ Không — phải promote thủ công.
  • Số lượng: Tối đa 15 Read Replicas (MySQL, MariaDB, PostgreSQL).
  • Triển khai: Same AZ, Cross-AZ, Cross-Region (tính phí).
  • Promote: Có thể promote thành DB độc lập (DR hoặc migration).

Chi phí mạng:

  • Cùng Region (dù khác AZ) → Miễn phí.
  • Cross-Region → Tính phí (hay ra thi!).

Use cases:

  • Reporting / BI / Analytics → đọc replica thay vì DB chính.
  • Machine learning / Data processing.
  • Disaster Recovery (promote cross-region replica).

Multi-AZ — High Availability (STANDBY)

  • Mục đích: Đảm bảo High Availability, không dành cho scale đọc.
  • Replication: SYNC — zero data loss khi failover.
  • Đọc được không? ❌ Không — standby không phục vụ traffic.
  • Failover tự động? ✔ Có — AWS tự chuyển trong 30–120 giây.
  • Cơ chế: 1 DNS endpoint duy nhất; AWS update DNS sang standby khi primary fail.

Chuyển từ Single-AZ sang Multi-AZ (zero downtime):

  1. AWS tạo snapshot của DB hiện tại.
  2. Restore snapshot sang AZ mới → tạo Standby DB.
  3. Thiết lập SYNC replication.
  4. Không có downtime.

Bảng so sánh

Tính năng Read Replica Multi-AZ
Mục đích Scale đọc High Availability
Loại replication ASYNC SYNC
Đọc được? ✔ Yes (read-only) ❌ No (standby)
Failover tự động? ❌ Không ✔ Yes
Scope Same AZ, Cross-AZ, Cross-Region Cross-AZ (cùng Region)
Chi phí Free cùng Region, tốn tiền cross-region Không tính phí replication
Use case Reporting, BI, analytics HA, DR chống AZ failure

RDS Custom — khi cần SSH vào DB

RDS Custom là phiên bản đặc biệt dành cho:

  • Oracle Database (Custom for Oracle)
  • Microsoft SQL Server (Custom for SQL Server)

Điểm đặc biệt: Bạn có toàn quyền truy cập vào OS và DB layer — điều mà RDS thường không cho phép.

RDS Custom = RDS nhưng có quyền như EC2.

Khi nào dùng RDS Custom:

  • Cần cài thêm agent, plugin hỗ trợ.
  • Cần tùy chỉnh OS-level (kernel parameter, registry).
  • Cần bật native DB features bị giới hạn trong RDS thường (Oracle Data Guard, SQL Server features).
  • Ứng dụng legacy yêu cầu cấu hình DB/OS đặc biệt.

Automation Mode: Trước khi tùy chỉnh, phải tắt Automation Mode (AWS tự động phát hiện thay đổi lạ và rollback). Quy trình:

  1. Snapshot DB trước.
  2. Tắt Automation Mode.
  3. SSH/SSM vào server để tùy chỉnh.
  4. Bật lại Automation Mode sau khi xong.
RDS thường RDS Custom
Quản lý OS AWS Bạn
SSH vào EC2 ❌ ✔ SSH/SSM
Cài thêm phần mềm ❌ ✔
Engine hỗ trợ Tất cả Chỉ Oracle + SQL Server

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Giảm tải cho DB chính khi có nhiều truy vấn SELECT/report" Read Replica
"Đảm bảo DB không downtime khi mất cả một AZ" Multi-AZ
"Cross-region, chấp nhận tốn phí network" Read Replica cross-region
"Cần SSH vào OS của DB (Oracle/SQL Server)" RDS Custom
"Storage sắp đầy nhưng không muốn tự tay resize" RDS Storage Autoscaling (đặt Maximum Storage Threshold)
"Chuyển Single-AZ sang Multi-AZ mà không downtime" Có thể làm được — AWS tự snapshot + restore + sync ngầm

Xem thêm góc nhìn "domain thi": 3.3 - Database - RDS, Aurora, DynamoDB · Cost: 4.4 - Database Cost Optimization.

Điểm hay ra thi

  • Read Replica dùng để scale đọc (không phải HA).
  • Multi-AZ dùng để HA (standby không đọc được).
  • Cross-Region Read Replica tính phí network — trong cùng Region thì miễn phí.
  • Không thể SSH vào RDS thường → chỉ RDS Custom mới được.
  • Storage Autoscaling cần đặt Maximum Storage Threshold.
  • Chuyển Single-AZ sang Multi-AZ không có downtime.

Takeaway cá nhân

  • RDS là "EC2 cho database" — bạn không cần quản lý OS/DB, chỉ cần dùng endpoint.
  • Nhớ phân biệt rõ Read Replica (ASYNC, scale đọc) vs Multi-AZ (SYNC, HA) — đây là bẫy thi số 1 của section này.
  • RDS Custom chỉ dành cho Oracle và SQL Server khi cần deep customization.
