9.2 – Amazon Aurora

Aurora là gì?

Amazon Aurora là database engine do AWS tự phát triển (proprietary), không open-source, nhưng tương thích 100% với MySQL và PostgreSQL.

Ứng dụng, driver, ORM chạy MySQL/PostgreSQL đều hoạt động bình thường trên Aurora — không cần sửa code.

Điểm khác biệt cốt lõi:

Aurora không chỉ là database engine. Nó là DB + storage cluster được thiết kế từ đầu cho cloud.

Tại sao Aurora nhanh hơn RDS?

RDS truyền thống:

  • Mỗi DB instance có EBS storage riêng.
  • Replication phải copy dữ liệu giữa các instance qua network.

Aurora cloud-native:

  • Storage cluster dùng chung cho tất cả instance.
  • Storage được replicate 6 copies across 3 AZ tự động.
  • Replication không qua instance → replica lag < 10 ms.

Kết quả:

  • 5 lần nhanh hơn MySQL RDS
  • 3 lần nhanh hơn PostgreSQL RDS
  • Latency cực thấp, throughput rất cao.

Cơ chế lưu trữ Aurora (Aurora Storage Engine)

6 copies của dữ liệu trong 3 AZ:

  • Mỗi AZ có 2 copies.
  • Yêu cầu để tiếp tục hoạt động:
    • 4/6 copies → thực hiện writes (quorum write).
    • 3/6 copies → thực hiện reads (quorum read).

Tính năng storage:

  • Self-healing — tự phát hiện lỗi + tự sửa, không cần DBA.
  • Auto-expanding — tự tăng từ 10 GB → 128 TB.
  • Striped across 100s of volumes — throughput cực cao.

Kiến trúc Aurora Cluster

Thành phần Mô tả
Writer Instance (master) Chỉ 1 instance, thực hiện write (INSERT, UPDATE, DELETE)
Reader Instances Tối đa 15 replicas, dùng chung storage cluster
Writer Endpoint DNS trỏ luôn đến writer hiện tại
Reader Endpoint Load balancing read queries giữa tất cả replicas

Reader Endpoint = load balancer đọc tự động — ứng dụng không cần biết bao nhiêu replicas.

High Availability trong Aurora

Aurora được thiết kế HA mặc định:

  • Storage replicate across 3 AZ.
  • Writer failover sang một Reader trong dưới 30 giây.
  • Không mất dữ liệu (do shared storage — không cần replicate).
  • Reader tự động promote thành Writer.
Tính năng RDS Multi-AZ Aurora
Replication SYNC instance → instance Quorum (6 copies / 3 AZ)
Replica lag 100ms – vài giây < 10 ms
Failover time 30–120 giây < 30 giây
Read Replicas 5 15
Storage EBS (per instance) Shared cluster

Aurora Advanced Concepts

Auto Scaling Replicas

Aurora tự động thêm/bớt read replicas khi:

  • CPU hoặc connections tăng cao.
  • Nhiều SELECT queries.
  • Traffic đọc đột biến.

Replicas mới tự join vào Reader Endpoint — không cần chỉnh code ứng dụng.

Custom Endpoints

Mặc định có Writer + Reader Endpoint. Custom Endpoint cho phép phân nhóm subset replicas để chạy loại query riêng:

Khi đã có Custom Endpoints → Reader Endpoint chung ít được dùng hơn.

Aurora Serverless

Aurora tự động bật/tắt, auto-scale hoàn toàn theo tải — không cần quản lý instance:

  • Tự khởi tạo DB khi cần, tự pause khi idle.
  • Tính phí theo giây sử dụng — cực kỳ tiết kiệm.
  • Client kết nối qua Proxy Fleet do Aurora quản lý.

Dùng cho:

  • Workload không thường xuyên, unpredictable.
  • Dev/Test.
  • Web/app mùa vụ.

Global Aurora

Cách 1 — Cross-Region Read Replica:

  • Đơn giản, dễ thiết lập.
  • Replica ở region khác, lag < 1 giây.
  • Dùng cho DR hoặc giảm latency đọc toàn cầu.

Cách 2 — Aurora Global Database (Recommended):

  • 1 Primary Region + tối đa 10 Secondary Regions.
  • Replication < 1 giây.
  • Promoting secondary → RTO < 1 phút.
  • Cho global applications, giảm latency toàn cầu.

Aurora Machine Learning Integration

Aurora tích hợp trực tiếp với Amazon SageMaker và Amazon Comprehend — cho phép chạy ML prediction trực tiếp bằng SQL:

SELECT ml_predict('recommendation_model', user_profile) FROM users;

Use cases: Fraud detection, sentiment analysis, product recommendations, ads targeting.

Babelfish for Aurora PostgreSQL

Babelfish giúp Aurora PostgreSQL hiểu T-SQL (SQL của Microsoft SQL Server):

  • Chạy được T-SQL mà không đổi code.
  • Dùng SQL Server client driver trực tiếp.
  • Migration từ SQL Server sang Aurora với minimal code changes.

Các tính năng nổi bật của Aurora

  • ✔ Automatic failover.
  • ✔ Automatic backups + Point-in-Time Restore.
  • ✔ Encryption at rest & in transit.
  • ✔ Push-button scaling (vertical + horizontal).
  • ✔ Zero-downtime patching.
  • ✔ Aurora Backtrack — roll back dữ liệu trong quá khứ mà không cần restore snapshot.

Chi phí

Aurora đắt hơn RDS ~20%, nhưng hiệu năng cao hơn nhiều → chi phí/hiệu năng thực tế thấp hơn.

Bảng từ khoá đề thi

Từ khoá trong đề Chọn

Điểm hay ra thi

  • Aurora = 5x MySQL, 3x Postgres — do shared storage, không phải do instance mạnh hơn.
  • Storage quorum: 4/6 write, 3/6 read — có thể mất 2 AZ mà vẫn write được.
  • Failover < 30 giây (vs RDS Multi-AZ 30–120s).
  • Aurora Backtrack — keyword quan trọng cho câu hỏi "rollback không cần restore backup".
  • Aurora Serverless = không manage instance + tính theo giây.
  • Global Database: RTO < 1 phút khi promote secondary.
  • Aurora Automated Backup không thể disable (khác RDS có thể tắt).

Takeaway cá nhân

  • Aurora là "RDS premium" — chọn khi cần hiệu năng cao, HA tốt, hoặc multi-region.
  • Cơ chế shared storage là chìa khóa: không cần replicate data giữa instances → replica lag < 10ms.
  • Biết các tính năng nâng cao (Serverless, Global DB, Custom Endpoint, Backtrack) vì hay ra thi.
