10. Route 53

Cách đọc note này: Note đã khá đầy đủ về lý thuyết (8 Routing Policies, Health Check, Alias vs CNAME). Đối chiếu với 3.5 - Networking - VPC, Route 53, Direct Connect khi cần liên hệ Route 53 trong bức tranh networking tổng thể (VPC, Direct Connect).

DNS là gì?

DNS (Domain Name System) là hệ thống chuyển đổi tên miền thân thiện (google.com) thành địa chỉ IP mà máy tính hiểu được — hoạt động như "danh bạ điện thoại của Internet".

Cấu trúc phân cấp DNS:

.                    ← Root
└── .com             ← TLD (Top Level Domain)
    └── example.com  ← SLD (Second Level Domain)
        └── api.example.com  ← Subdomain

Các khái niệm DNS quan trọng

Khái niệm Mô tả
Domain Registrar Nơi mua domain (Route 53, GoDaddy, Namecheap)
DNS Record Dữ liệu trong DNS (A, AAAA, CNAME, NS, MX…)
Zone File File chứa toàn bộ DNS records của 1 domain
Name Server (NS) Server trả lời truy vấn DNS
TLD Phần đuôi domain (.com, .org, .vn)
FQDN Tên miền đầy đủ (api.www.example.com.)

DNS hoạt động như thế nào?

Amazon Route 53

Route 53 là dịch vụ DNS authoritative của AWS — bạn toàn quyền chỉnh sửa DNS records.

Đặc điểm nổi bật:

  • Dịch vụ duy nhất của AWS có SLA 100% uptime.
  • Đóng vai trò cả Domain Registrar và DNS Service.
  • Hỗ trợ health check và routing nâng cao.
  • Tên "Route 53" = port 53 (port chuẩn của DNS).

Các loại DNS Record quan trọng

Record Mô tả
A Hostname → IPv4
AAAA Hostname → IPv6
CNAME Hostname → hostname khác (không dùng ở zone apex)
NS Danh sách Name Servers của Hosted Zone
MX Mail exchange servers
TXT Text records (domain verification, SPF, DKIM)

Hosted Zones

Hosted Zone là "container" chứa các DNS records cho một domain.

Loại Mô tả Phạm vi
Public Hosted Zone Domain truy cập từ Internet Mọi người resolve được
Private Hosted Zone Domain chỉ trong VPC Chỉ EC2/services trong VPC liên kết

Chi phí: $0.50/tháng/Hosted Zone.

Ví dụ:

  • Public: app.mydomain.com → trỏ tới ALB, CloudFront, S3 website.
  • Private: db.internal.company, api.internal → chỉ resolve trong VPC.

TTL (Time To Live)

TTL = thời gian DNS resolver (client, ISP) được phép cache bản ghi.

TTL cao (ví dụ 24h) TTL thấp (ví dụ 60s)
Số query đến Route 53 Ít → rẻ hơn Nhiều → tốn hơn
Tốc độ cập nhật IP Chậm (khách hàng còn giữ cache) Nhanh
Dùng khi Ít thay đổi, ổn định Chuẩn bị đổi DNS record, migration

Lưu ý: Alias Record không cho đặt TTL — AWS tự quản lý.

CNAME vs Alias Record

Đây là một trong những điểm phân biệt quan trọng nhất của Route 53.

Tiêu chí CNAME Alias
Trỏ đến Hostname khác (bất kỳ) AWS resource (ALB, CloudFront, S3…)
Dùng ở zone apex (example.com)? ❌ Không ✔ Có
Phí query Tính phí Miễn phí
TTL Tự đặt AWS quản lý tự động
Health Check Không native ✔ Native

Alias Targets được hỗ trợ:

  • Elastic Load Balancers (ALB / NLB)
  • CloudFront Distribution
  • API Gateway
  • S3 Website hosting
  • Elastic Beanstalk
  • VPC Interface Endpoints
  • Global Accelerator
  • Record khác trong cùng Hosted Zone

KHÔNG được làm Alias target:

  • ❌ EC2 Public DNS hostname
  • ❌ External hostname ngoài AWS

8 Routing Policies

Routing Policy xác định Route 53 trả lời truy vấn DNS như thế nào.

Chú ý: DNS không route traffic — DNS chỉ trả về IP. Routing Policy là về cách chọn IP nào để trả về.

1. Simple Routing Policy

DNS truyền thống: 1 record → 1 hoặc nhiều IP.

  • Có thể có nhiều giá trị trong 1 record → client tự chọn ngẫu nhiên.
  • Không hỗ trợ health check.
  • Alias trong Simple chỉ trỏ được 1 AWS resource.

Dùng cho: Backend chỉ có 1 endpoint đơn giản.

Bẫy thi: "Simple có load balancing không?" → Không, client random, không có health check.

2. Weighted Routing Policy

Chia traffic theo tỷ lệ phần trăm — mỗi record được gán một weight.

  • Weight không cần cộng thành 100.
  • Weight = 0 → không nhận traffic.
  • Có thể kết hợp health check → tự loại endpoint fail.

Dùng cho: Canary deployment (test version mới với 10% traffic), chia tải giữa regions.

Công thức: traffic (%) = weight của record / tổng weight tất cả record. Weight không cần cộng thành 100 — ở ví dụ trên 70+20+10=100 chỉ là trùng hợp, có thể đặt 7/2/1 vẫn ra đúng tỷ lệ 70/20/10.

3. Latency-based Routing Policy

Chọn endpoint có độ trễ thấp nhất với user dựa trên bảng RTT toàn cầu của AWS.

  • Bạn phải gán region cho mỗi record (Route 53 không tự detect).
  • Có thể gắn health check.

Ví dụ: User ở Hà Nội → Route 53 đo RTT đến Singapore và Tokyo → chọn Singapore nếu thấp hơn.

Phân biệt: Geolocation = theo vị trí địa lý, Latency = theo tốc độ thực tế.

4. Failover Routing Policy (Active–Passive)

DR đơn giản nhất với DNS:

  • Primary bắt buộc phải có health check.
  • Khi Primary fail → Route 53 tự động trả về Secondary.

Dùng khi: Muốn DR đơn giản, không cần Multi-Region Active/Active.

5. Geolocation Routing Policy

Route traffic dựa trên vị trí địa lý của user — không phải latency.

  • Chọn theo: Continent → Country → US State.
  • Bắt buộc phải có Default record (cho user không match bất kỳ rule nào).

Dùng cho:

  • Website theo ngôn ngữ (vd: user France → French version).
  • Chặn user theo khu vực (geo-restriction).
  • Tuân thủ luật (GDPR, China, US law).

Khác Latency: User ở Đức nhưng server Singapore gần hơn → Geolocation vẫn gửi đến Germany record nếu cấu hình vậy.

6. Geoproximity Routing Policy

Nâng cấp của Geolocation: route dựa trên vị trí user + vị trí resource, có thể điều chỉnh bằng bias.

  • Bias +99 → kéo nhiều traffic hơn về resource này (mở rộng vùng phục vụ).
  • Bias -99 → giảm traffic về resource này (thu hẹp vùng phục vụ).
  • Bắt buộc dùng Route 53 Traffic Flow (visual editor).
  • Hỗ trợ cả AWS resource (region) và external resource (qua lat/long).

Dùng cho: Tối ưu multi-region dựa trên geography + điều chỉnh tải theo ý muốn.

Bias 0 = biên giới chia đôi đúng theo khoảng cách địa lý thực tế. Tăng bias của us-west-1 lên dương → đường phân chia (đường cam) dịch sang phải, kéo thêm user ở giữa nước Mỹ về phía Tây.

7. IP-based Routing Policy

Route traffic dựa trên địa chỉ IP của client (CIDR-based).

  • Bạn định nghĩa tập CIDR → gán endpoint tương ứng.
  • User thuộc CIDR nào → Route 53 trả endpoint đó.

Dùng cho:

  • Tối ưu chi phí giữa ISP (ISP A dùng endpoint A, ISP B dùng endpoint B).
  • Enterprise routing theo IP block nội bộ.

8. Multi-Value Answer Routing

Trả về tối đa 8 giá trị healthy cho mỗi DNS query.

  • Kết hợp health check → chỉ trả endpoint healthy.
  • Client chọn ngẫu nhiên trong số các IP trả về.
  • Không thay thế ELB — đây là DNS feature, không phải true load balancer.

Dùng cho: Phân phối traffic đơn giản với built-in health filtering.

Health Checks

Tổng quan

Route 53 Health Check giúp DNS tự động failover khi endpoint bị lỗi.

3 loại health check:

Loại Cách hoạt động Dùng khi
Monitor Endpoint Route 53 gửi request trực tiếp đến endpoint Public endpoint (EC2, ALB, on-prem public)
Calculated Kết hợp nhiều health checks bằng AND/OR/NOT App đa tầng
CloudWatch Alarm Monitor CloudWatch alarm thay vì endpoint Private resource (RDS, EC2 private)

Quan trọng: Health checker của Route 53 nằm ngoài VPC → không kiểm tra được private endpoint trực tiếp.

Monitor an Endpoint

  • ~15 health checker toàn cầu kiểm tra endpoint.
  • Mặc định cần 3 lần pass liên tiếp → healthy.
  • Hỗ trợ HTTP, HTTPS, TCP.
  • Pass khi server trả 2xx hoặc 3xx.
  • Phải mở firewall cho IP range của health checker.

Calculated Health Checks

Kết hợp nhiều child health checks:

  • AND / OR / NOT logic.
  • Tối đa 256 child health checks.
  • Đặt điều kiện: "N trong M child cần healthy".

Dùng khi: Đang bảo trì 1 server nhưng không muốn fail cả hệ thống.

Health Checks với Private Hosted Zone

Vì health checker không vào được VPC → cần giải pháp gián tiếp:

  1. Tạo CloudWatch metric giám sát private resource.
  2. Tạo CloudWatch Alarm khi metric bất thường.
  3. Tạo Health Check kiểu "Monitor CloudWatch Alarm".

Use case: Failover giữa 2 RDS private endpoints, Hybrid on-prem ↔ AWS.

Domain Registrar vs DNS Service

Registrar = nơi mua/đăng ký domain (GoDaddy, Namecheap, Route 53).

DNS Service = nơi quản lý DNS records (Route 53).

Hai cái này hoàn toàn có thể tách biệt.

Dùng GoDaddy + Route 53

Quy trình:

  1. Tạo Public Hosted Zone trong Route 53.
  2. Lấy 4 NS records Route 53 cung cấp.
  3. Vào GoDaddy → thay Nameserver bằng 4 NS này.

→ GoDaddy giữ domain; Route 53 là authoritative DNS.

Quan trọng: Route 53 chỉ hoạt động khi domain trỏ NS về Route 53.

Hybrid DNS — Route 53 Resolver

Route 53 Resolver cho phép EC2 trong VPC và on-premises resolve lẫn nhau.

Loại Endpoint Hướng Dùng khi
Inbound Endpoint On-prem → VPC On-prem resolve private domain của AWS
Outbound Endpoint VPC → On-prem EC2 resolve domain nội bộ của on-prem

Policy Health Check? Dùng cho Keyword nhận ra
Simple ❌ 1 endpoint đơn giản "No health check needed"
Weighted ✔ Canary, A/B test "Chia tỷ lệ %", "Blue/Green"
Latency ✔ Giảm latency toàn cầu "Lowest latency", "Closest region"

Multi-Value ✔ Multiple healthy endpoints "Up to 8 values", "Client-side LB"

Bảng từ khoá đề thi

Từ khoá trong đề Chọn
"Trỏ domain apex/naked domain (example.com) tới ALB/CloudFront" Alias Record (CNAME không hỗ trợ ở apex)
"Muốn miễn phí query DNS tới AWS resource" Alias Record
"Chia % traffic để test version mới / canary" Weighted Routing
"Chọn region có độ trễ thấp nhất cho user" Latency-based Routing
"User ở quốc gia X phải thấy nội dung/luật riêng" Geolocation Routing
"Dịch chuyển traffic giữa các region bằng bias" Geoproximity Routing (cần Traffic Flow)
"Route theo ISP/CIDR của client" IP-based Routing
"Primary/Secondary, Disaster Recovery đơn giản bằng DNS" Failover Routing
"Trả về nhiều IP healthy, client tự chọn" Multi-Value Answer (không phải ELB)
"Health check cho RDS/EC2 private trong VPC" CloudWatch Alarm-based Health Check (health checker Route 53 nằm ngoài VPC)
"On-premises cần resolve domain private của AWS và ngược lại" Route 53 Resolver (Inbound/Outbound Endpoint)

Điểm hay ra thi

  • Alias record dùng được ở zone apex (example.com) — CNAME thì không.
  • Alias trỏ tới ALB/NLB/CloudFront → miễn phí query.
  • Alias KHÔNG trỏ được tới EC2 Public DNS hay external hostname.
  • TTL cao = client cache lâu, khó đổi nhanh.
  • TTL thấp = tốn tiền query, nhưng đổi DNS nhanh.
  • Health check chỉ hoạt động cho public endpoint — private resource phải qua CloudWatch Alarm.
  • Geolocation ≠ Latency: Geolocation theo địa lý user; Latency theo RTT thực tế.
  • Geoproximity cần Traffic Flow — bias để shift traffic.
  • Multi-Value tối đa 8 healthy records — KHÔNG thay thế ELB.
  • Route 53 không cần là Registrar — chỉ cần domain trỏ NS về Route 53.
  • Route 53 = SLA 100% — dịch vụ duy nhất của AWS.

Takeaway cá nhân

  • Route 53 là "bộ não DNS" của AWS — mọi traffic đều qua đây.
  • CNAME vs Alias: nhớ Alias là "native AWS CNAME" — dùng được ở apex, miễn phí, HC native.
  • Chọn Routing Policy: Simple (1 endpoint) → Weighted (A/B) → Latency (perf) → Failover (DR) → Geolocation (compliance) → Geoproximity (advanced) → IP-based (ISP) → Multi-Value (distributed).
  • Health Check cho private resource: CloudWatch Alarm → HC "Monitor CloudWatch Alarm".
