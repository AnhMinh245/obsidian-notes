AWS EC2 - Mô phỏng kết nối Fibre Channel SAN

AWS EC2 - Mô phỏng kết nối Fibre Channel SAN

Question I am trying to answer

  • EC2 có thể kết nối đến vật lý FC SAN (qua SAN Switch) không?
  • Làm thế nào để mô phỏng FC SAN storage trên AWS?

TL;DR

  • AWS không hỗ trợ native Fibre Channel — FC là Layer 2 protocol, không route được qua IP.
  • EC2 không có HBA (Host Bus Adapter), không thể join FC fabric trực tiếp.
  • Có 3 hướng tiếp cận tuỳ vào bài toán: FC-to-iSCSI Bridge, AWS FSx ONTAP, hoặc Software SAN thuần AWS.
  • Cách phổ biến nhất cho hybrid: FC SAN on-prem → FC-to-iSCSI Gateway → Direct Connect/VPN → EC2.

Tại sao FC không chạy native trên AWS?

Yếu tố On-Premise FC AWS EC2
Protocol layer Layer 2 (non-routable) Chỉ hỗ trợ IP (Layer 3+)
HBA (Host Bus Adapter) Cần card vật lý 8/16/32Gbps Không có, EC2 là VM ảo hoá
FC Fabric / SAN Switch Brocade, Cisco MDS Không tồn tại trên AWS
Zoning Hardware zoning trên switch Không áp dụng
Latency μs (microsecond) ms (millisecond) qua network

Kết luận: EC2 không thể là FC Initiator kết nối trực tiếp vào FC SAN. Phải bridge qua protocol khác.

3 hướng tiếp cận

Hướng 1 — FC SAN On-Prem + Bridge sang iSCSI (Hybrid)

Dành cho: Có FC SAN vật lý tại data center, muốn EC2 dùng chung storage.

Physical FC SAN
    │ (FC 16Gbps)
    ▼
FC SAN Switch (Brocade/Cisco)
    │ (FC 16Gbps)
    ▼
FC-to-iSCSI Gateway (*)
    │ (iSCSI over Ethernet)
    ▼
Router/Firewall
    │ (AWS Direct Connect / Site-to-Site VPN)
    ▼
AWS VPC
    │ (Private Subnet)
    ▼
EC2 Instance (iSCSI Initiator)

(*) FC-to-iSCSI Gateway là thiết bị/software bridge FC LUN thành iSCSI target:

Gateway Loại Ghi chú
NetApp ONTAP Hardware + Software Expose FC LUN qua iSCSI natively
IBM Spectrum Virtualize Software FC → iSCSI gateway
Dell EMC PowerStore Hardware Hỗ trợ multi-protocol (FC + iSCSI + NVMe-oF)
Linux targetcli (LIO) Software (free) Tạo iSCSI target từ FC LUN qua /dev/sdX
StarWind Virtual SAN Software FC → iSCSI bridge

Cấu hình EC2 (iSCSI Initiator):

# Cài iscsid
sudo yum install -y iscsi-initiator-utils   # Amazon Linux
sudo apt install -y open-iscsi              # Ubuntu

# Discovery target từ Gateway IP
sudo iscsiadm -m discovery -t sendtargets -p <GATEWAY_IP>:3260

# Login vào target
sudo iscsiadm -m node --login

# Kiểm tra disk mới xuất hiện
lsblk

Hướng 2 — AWS FSx for NetApp ONTAP (Fully Managed)

Dành cho: Không có on-prem SAN, muốn SAN-like experience hoàn toàn trên AWS.

AWS FSx ONTAP là managed NetApp ONTAP — hỗ trợ iSCSI block storage (tương đương FC SAN về tính năng).

EC2 Instance (iSCSI Initiator)
    │
    ▼ (iSCSI over Private Network)
FSx for NetApp ONTAP
├── iSCSI LUNs (block storage như FC SAN)
├── NFS v3/v4.1
├── SMB/CIFS
└── NVMe-oF (roadmap)

Thiết lập FSx ONTAP iSCSI:

  1. AWS Console → FSx → Create file system → NetApp ONTAP
  2. Chọn Deployment type: Multi-AZ hoặc Single-AZ
  3. Chọn VPC và subnet
  4. Sau khi tạo xong → Storage Virtual Machines → tạo iSCSI LUN

Trên EC2:

# Cài open-iscsi
sudo yum install -y iscsi-initiator-utils

# Sửa initiator IQN (tuỳ chọn)
cat /etc/iscsi/initiatorname.iscsi

# Connect đến FSx ONTAP iSCSI target
sudo iscsiadm -m discovery -t sendtargets -p <FSx_iSCSI_IP>:3260
sudo iscsiadm -m node --login
lsblk  # thấy disk mới

Ưu điểm FSx ONTAP:

  • Hỗ trợ thin provisioning, deduplication, compression như SAN thật
  • Snapshots, cloning — giống NetApp truyền thống
  • Không cần quản lý infrastructure
  • Hỗ trợ multi-protocol: cùng 1 volume serve NFS + iSCSI

Chi phí tham khảo (ap-southeast-1):

  • SSD storage: ~$0.242/GB/tháng
  • Throughput: từ $0.036/MBps/tháng

Hướng 3 — Phần mềm SAN thuần trên EC2 (Lab/Dev)

Dành cho: Lab, học tập, test FC SAN workflow mà không cần hardware.

Dùng EC2 instance chạy phần mềm SAN target, EC2 khác là initiator:

EC2-A "SAN Target"          EC2-B "SAN Initiator"
(targetcli / TGT)    ←────────────────→   (open-iscsi)
Private IP: 10.0.1.10                      Private IP: 10.0.2.10

Cài đặt iSCSI Target trên EC2-A (Amazon Linux 2023):

sudo dnf install -y targetcli

# Tạo block device target
sudo targetcli

# Trong targetcli shell:
/> backstores/block create name=san_lun1 dev=/dev/nvme1n1
/> iscsi/ create iqn.2024-01.com.example:san-target
/> iscsi/iqn.2024-01.com.example:san-target/tpg1/luns create /backstores/block/san_lun1
/> iscsi/iqn.2024-01.com.example:san-target/tpg1/portals create 0.0.0.0 3260
/> saveconfig
/> exit

sudo systemctl enable --now target

Kết nối từ EC2-B (iSCSI Initiator):

sudo yum install -y iscsi-initiator-utils
sudo iscsiadm -m discovery -t sendtargets -p 10.0.1.10:3260
sudo iscsiadm -m node --login
lsblk  # thấy /dev/sdb hoặc /dev/nvme1n1

So sánh 3 hướng

Tiêu chí Hướng 1 (FC+Bridge) Hướng 2 (FSx ONTAP) Hướng 3 (SW SAN Lab)
FC SAN thật ✅ Có vật lý ❌ Không ❌ Không
Chi phí Cao (Direct Connect) Trung bình Thấp (chỉ EC2)
Latency ~1-5ms (VPN/DC) ~1ms <1ms (same VPC)
Phù hợp Production hybrid Production AWS-native Lab/Dev/Test
Quản lý Phức tạp AWS managed Thủ công
FC Protocol Có (on-prem) Không Không

Lưu ý thực tế

  • MPIO (Multipath I/O): Trên on-prem FC, MPIO là bắt buộc cho HA. Với iSCSI trên AWS, có thể dùng dm-multipath với multiple ENI.
  • Security: iSCSI không mã hoá by default → dùng CHAP authentication + Security Group chặt (chỉ mở port 3260 giữa các instance cần thiết).
  • Performance gap: FC 32Gbps ≈ 3.2 GB/s. iSCSI trên EC2 bị giới hạn bởi network bandwidth của instance type (t3.xlarge = up to 5 Gbps shared).
  • EBS thay thế tốt hơn: Nếu mục tiêu là block storage cho EC2, EBS io2 Block Express (64,000 IOPS, sub-millisecond latency) thực tế tốt hơn iSCSI SAN cho hầu hết workload.
