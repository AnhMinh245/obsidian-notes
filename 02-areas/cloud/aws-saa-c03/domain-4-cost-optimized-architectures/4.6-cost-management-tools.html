Cost Management Tools

Cost Management Tools

Tầm quan trọng

AWS Cost Management Tools là nền tảng xuyên suốt cả 4 task statements trong Domain 4. Hiểu rõ từng tool, use case, và sự khác biệt giữa chúng là điều kiện tiên quyết để trả lời đúng các câu hỏi cost optimization trong kỳ thi SAA-C03.

Tổng quan Cost Management Tools

1. AWS Cost Explorer

AWS Cost Explorer là gì?

AWS Cost Explorer là dịch vụ visualization và analysis cho phép bạn xem, hiểu, và quản lý chi phí AWS theo thời gian. Đây là tool đầu tiên bạn nên nghĩ đến khi đề bài nói "analyze", "visualize", "understand" costs.

1.1. Tính năng chính

Tính năng Chi tiết
Time range Xem dữ liệu 12 tháng trước + dự báo 12 tháng tới
Granularity Monthly, Daily, Hourly (chỉ EC2)
Filters Service, Linked Account, Tag, AZ, Instance Type, Purchase Option, API Operation
Grouping Service, Instance Type, Tag, Usage Type, Region, Linked Account
RI Reports RI Utilization report, RI Coverage report
SP Reports Savings Plans Utilization, Savings Plans Coverage
Forecasting ML-based forecast dựa trên historical usage patterns
API access GetCostAndUsage, GetCostForecast — cho phép query programmatic
Right-sizing Recommendations cho EC2 instances (resize hoặc terminate)

1.2. Filters & Dimensions

1.3. RI Utilization & Coverage Reports

Exam tip — RI Reports trong Cost Explorer
  • RI Utilization Report: cho biết bạn đã sử dụng bao nhiêu % RI đã mua → phát hiện RI lãng phí
  • RI Coverage Report: cho biết bao nhiêu % usage được cover bởi RI → phát hiện cơ hội mua thêm RI
  • Cả hai đều hiển thị trong Cost Explorer, KHÔNG phải Trusted Advisor

1.4. Forecasting

# Cost Explorer Forecast
- Sử dụng: Machine Learning models
- Dựa trên: Historical usage patterns (up to 12 months)
- Dự báo: Up to 12 months into the future
- Accuracy: Dependent on data consistency
- Use case: Budget planning, capacity planning
- API: GetCostForecast
Giới hạn Cost Explorer
  • Dữ liệu mất 24 giờ để xuất hiện trong Cost Explorer (không real-time)
  • Hourly granularity chỉ có cho EC2 (các service khác chỉ daily/monthly)
  • Forecast accuracy phụ thuộc vào tính nhất quán của usage patterns
  • Cần enable Cost Explorer trước khi sử dụng lần đầu (mất ~24h để populate data)

2. AWS Budgets

AWS Budgets là gì?

AWS Budgets cho phép bạn đặt ngân sách tuỳ chỉnh để theo dõi chi phí và usage, nhận alerts khi vượt ngưỡng, và tự động thực hiện actions (apply IAM policy, stop instances).

2.1. Budget Types

Budget Type Theo dõi gì Ví dụ
Cost Budget Chi phí thực tế vs budget "Tổng AWS spend không quá $10,000/tháng"
Usage Budget Lượng usage (hours, GB, requests) "EC2 usage không quá 500 instance-hours"
Reservation Budget RI utilization hoặc coverage "RI utilization phải > 80%"
Savings Plans Budget SP utilization hoặc coverage "SP coverage phải > 70%"

2.2. Alerts & Thresholds

2.3. Budget Actions

Budget Actions — điểm mới quan trọng

Budget Actions cho phép tự động remediation khi budget bị vượt:

Action Type Tác dụng Scope
Apply IAM Policy Deny specific actions (e.g., deny ec2:RunInstances) Single account
Apply SCP Organization-level restriction AWS Organizations
Stop EC2 instances Dừng running EC2 instances Single account
Stop RDS instances Dừng running RDS instances Single account

Actions có thể set để chạy automatically hoặc require approval (approval workflow).

2.4. Pricing & Limits

# AWS Budgets Pricing
Free tier:
  - First 2 budgets: FREE
After free tier:
  - Each additional budget: $0.02/day (~$0.62/month)
Limits:
  - Maximum: 62,000 budgets per account
  - Alert subscribers: up to 10 email addresses per alert
  - SNS topic: 1 per alert
Budget reports:
  - Schedule: daily, weekly, monthly
  - Delivery: email
Exam tip — Budgets vs Cost Explorer
  • "Muốn được alert khi chi phí vượt ngưỡng" → AWS Budgets
  • "Muốn phân tích chi phí theo service/tag/account" → Cost Explorer
  • "Muốn tự động stop instances khi vượt budget" → AWS Budgets Actions
  • "Muốn forecast chi phí 12 tháng tới" → Cost Explorer

3. AWS Cost and Usage Report (CUR)

CUR là gì?

AWS Cost and Usage Report (CUR) cung cấp bộ dữ liệu chi phí chi tiết nhất của AWS — đến từng line item, từng resource, từng giờ. CUR được deliver đến S3 bucket và có thể query bằng Athena, Redshift, hoặc QuickSight.

3.1. Tính năng chi tiết

Tính năng Chi tiết
Granularity Hourly, Daily, Monthly
Delivery Tự động deliver đến S3 bucket (bạn chỉ định)
Format CSV hoặc Parquet (recommended cho Athena)
Detail level Line-item: mỗi resource, mỗi giờ, mỗi API call
Resource IDs Bao gồm individual resource IDs (e.g., i-1234567890abcdef0)
Tag detail Hiển thị cost allocation tags ở level từng resource
RI/SP detail Amortized costs, effective costs, recurring/non-recurring
Auto table creation Tích hợp Athena — auto tạo table + Glue crawler

3.2. Architecture — CUR Analysis Pipeline

3.3. CUR vs Cost Explorer

Tiêu chí Cost Explorer CUR
Detail level Service/account/tag level Line-item level (từng resource)
Granularity Hourly (EC2 only), Daily, Monthly Hourly, Daily, Monthly (mọi service)
Access Console UI + API S3 file (CSV/Parquet) → Athena/Redshift
Best for Quick visualization, trends Deep analysis, custom reporting
Resource IDs ❌ ✅
Custom queries Limited filters/groups Full SQL (Athena)
Cost Free Free (chỉ trả S3 storage + Athena queries)
Exam tip — CUR
  • Đề nói "most detailed" hoặc "line-item level" hoặc "resource-level cost data" → CUR
  • CUR + Athena là combo phổ biến cho custom cost analysis
  • Dùng Parquet format khi query bằng Athena (compression + columnar = faster + cheaper)
  • CUR có thể include resource IDs — Cost Explorer thì KHÔNG

4. AWS Trusted Advisor

Trusted Advisor là gì?

AWS Trusted Advisor là service cung cấp real-time guidance để giúp bạn provision resources theo AWS best practices trên 5 danh mục: Cost Optimization, Performance, Security, Fault Tolerance, và Service Limits.

4.1. 5 Categories

4.2. Support Plan Tiers

Tính năng Basic / Developer Business / Enterprise
Core checks 7 checks (6 security + 1 service limits) ✅ Full checks (tất cả categories)
Cost Optimization checks ❌ ✅
Performance checks ❌ ✅
Fault Tolerance checks ❌ ✅
Programmatic API access ❌ ✅
CloudWatch integration ❌ ✅
Refresh frequency Manual only Every 15 minutes (some checks)
AWS Support API ❌ ✅

4.3. Cost Optimization Checks (Business/Enterprise only)

Trusted Advisor — Cost Optimization Checks
Check Phát hiện gì
Low Utilization EC2 Instances với CPU avg < 10% trong 14 ngày
Idle Load Balancers Load balancers không có backend instances hoặc traffic rất thấp
Unassociated Elastic IPs EIPs không gắn vào running instance (bị charge $0.005/hour)
Underutilized EBS Volumes Volumes với IOPS < 100/day trong 14 ngày
Idle RDS DB Instances RDS instances không có connection trong 7 ngày
Amazon Redshift Cluster Optimization Clusters underutilized
RI Lease Expiration RIs sắp hết hạn trong 30 ngày
RI Optimization Recommend mua thêm hoặc modify RIs
Savings Plans Unused Savings Plans commitment
Trusted Advisor ≠ Compute Optimizer
  • Trusted Advisor: broad checks, 5 categories, rule-based, có/không recommendation
  • Compute Optimizer: chỉ focus vào right-sizing, ML-based, chi tiết hơn cho EC2/EBS/Lambda/ASG
  • Đề hỏi "right-sizing recommendation" cho EC2 → Compute Optimizer
  • Đề hỏi "phát hiện idle resources" tổng quát → Trusted Advisor

5. AWS Compute Optimizer

Compute Optimizer là gì?

AWS Compute Optimizer sử dụng machine learning để phân tích CloudWatch metrics và đưa ra right-sizing recommendations cho EC2 instances, Auto Scaling Groups, EBS volumes, Lambda functions, và ECS on Fargate.

5.1. Resources được hỗ trợ

Resource Metrics phân tích Recommendations
EC2 Instances CPU, Memory, Disk I/O, Network Instance type/size thay đổi
Auto Scaling Groups Group-level metrics ASG configuration changes
EBS Volumes IOPS, Throughput, Latency Volume type/size changes
Lambda Functions Duration, Memory utilization Memory size adjustments
ECS on Fargate CPU, Memory Task size recommendations

5.2. Finding Types

5.3. Enhanced Infrastructure Metrics

# Compute Optimizer — Enhanced Infrastructure Metrics
Default:
  - Lookback period: 14 days of CloudWatch data
  - Cost: FREE
  
Enhanced (paid):
  - Lookback period: Up to 93 days (3 months)
  - Better accuracy: More data points = better ML predictions
  - Memory metrics: Requires CloudWatch Agent for memory utilization
  - Cost: Varies based on resources monitored
Exam tip — Compute Optimizer
  • "Right-sizing recommendations" → Compute Optimizer (không phải Trusted Advisor)
  • Compute Optimizer cần CloudWatch Agent để có memory metrics (CloudWatch mặc định chỉ có CPU, disk, network)
  • Enhanced Metrics (93 days) cho recommendations chính xác hơn 14-day default
  • FREE cho basic recommendations; paid cho enhanced

6. Cost Allocation Tags

Cost Allocation Tags

Cost Allocation Tags cho phép bạn phân bổ chi phí theo project, team, environment, hoặc bất kỳ dimension nào bạn muốn. Tags xuất hiện trong Cost Explorer, CUR, và Budgets.

6.1. Hai loại tags

Loại Prefix Ai tạo Ví dụ
AWS-generated aws: AWS tự tạo aws:createdBy (ai tạo resource)
User-defined user: User tạo user:Environment, user:Project, user:CostCenter

6.2. Activation & Usage

Lưu ý quan trọng về Tags
  • Tags phải được activated trong Billing Console trước khi xuất hiện trong cost reports
  • Activation mất tối đa 24 giờ
  • Tags không retroactive — chỉ áp dụng cho usage SAU khi tag được gắn
  • Dùng AWS Config rules để enforce tag compliance (detect untagged resources)
  • Tag policies trong AWS Organizations để standardize tag keys/values

6.3. Best Practices

# Recommended Tag Strategy
Required tags (enforce via SCP/Config):
  - Environment: dev | staging | prod
  - Project: project-name
  - CostCenter: cost-center-id
  - Owner: team-email
  - Application: app-name

Optional tags:
  - Compliance: pci | hipaa | none
  - DataClassification: public | internal | confidential
  - AutoShutdown: "true" | "false" (for dev environments)

7. AWS Organizations — Consolidated Billing

Consolidated Billing

Khi sử dụng AWS Organizations, Management Account nhận và thanh toán bills cho tất cả member accounts. Đây cung cấp một số lợi ích cost optimization quan trọng.

7.1. Lợi ích chi phí

Lợi ích Chi tiết
Volume Discounts Tổng usage của tất cả accounts được cộng gộp → reach volume pricing tiers nhanh hơn
RI Sharing RI mua trong 1 account có thể shared cho account khác trong org (nếu enabled)
SP Sharing Savings Plans cũng shared tương tự RI
Single bill 1 invoice, 1 payment method — đơn giản hoá accounting
Free Data Transfer Data transfer between accounts cùng AZ = FREE

7.2. RI & SP Sharing

Exam tip — Consolidated Billing
  • S3 volume discount: Nếu Account A dùng 50TB và Account B dùng 50TB → bill tính trên 100TB → giá per-GB rẻ hơn
  • RI sharing có thể tắt cho từng account (Settings → RI sharing preferences)
  • Blended rate: các accounts chia sẻ pricing rates dựa trên tổng combined usage
  • Đề hỏi "how to get volume discounts across multiple AWS accounts" → Consolidated Billing trong Organizations

8. AWS Pricing Calculator

AWS Pricing Calculator

AWS Pricing Calculator (thay thế Simple Monthly Calculator cũ) cho phép bạn estimate chi phí AWS trước khi deploy. Accessible tại calculator.aws.

8.1. Tính năng

Tính năng Chi tiết
Estimate creation Tạo estimate cho individual service hoặc entire architecture
Region comparison So sánh giá giữa các regions
Instance comparison So sánh instance types/sizes
Scenario modeling "What if" scenarios (e.g., thêm/bớt resources)
Share & export Share estimate via link, export CSV/PDF
Group resources Nhóm resources theo service, team, environment
Pricing Calculator ≠ Cost Explorer
  • Pricing Calculator: estimate trước khi deploy (planning)
  • Cost Explorer: analyze sau khi deploy (actual costs)
  • Đề hỏi "estimate costs before migration" → Pricing Calculator
  • Đề hỏi "analyze current spending patterns" → Cost Explorer

9. Savings Plans — Chi tiết

Savings Plans — kiến thức trọng tâm

Savings Plans là commitment-based discount model thay thế và bổ sung cho Reserved Instances. Bạn commit spend 1 lượng $/hour nhất định trong 1 hoặc 3 năm, đổi lại nhận discount.

9.2. So sánh Savings Plans vs Reserved Instances

Tiêu chí Compute Savings Plans EC2 Instance SP Standard RI Convertible RI
Max discount 66% 72% 72% 66%
Instance family flexibility ✅ Any 🔒 Specific 🔒 Specific ✅ Can convert
Region flexibility ✅ Any 🔒 Specific 🔒 Specific 🔒 Specific
OS flexibility ✅ Any ✅ Any 🔒 Specific ✅ Can convert
Tenancy flexibility ✅ Any ✅ Any 🔒 Specific ✅ Can convert
Size flexibility ✅ Any ✅ Any ✅ (Regional) ✅
Applies to Fargate ✅ ❌ ❌ ❌
Applies to Lambda ✅ ❌ ❌ ❌
Sell on Marketplace ❌ ❌ ✅ ❌

9.3. Payment Options

Payment Discount level Cash flow
All Upfront Highest discount Trả hết trước
Partial Upfront Medium discount Trả 1 phần trước + monthly
No Upfront Lowest discount Chỉ trả monthly
Exam tip — Savings Plans
  • "Most flexible savings option across EC2, Fargate, Lambda" → Compute Savings Plans
  • "Maximum discount cho EC2 trong cùng instance family" → EC2 Instance Savings Plans (72%)
  • "Muốn thay đổi instance family sau khi commit" → Compute Savings Plans (không phải EC2 Instance SP)
  • Savings Plans cannot be sold on Marketplace (chỉ Standard RI mới bán được)
  • Savings Plans áp dụng trước On-Demand pricing — usage vượt commitment = On-Demand rate

11. AWS Cost Anomaly Detection

Cost Anomaly Detection

Dịch vụ sử dụng Machine Learning để liên tục giám sát chi phí và lượng sử dụng của bạn nhằm phát hiện các khoản chi tiêu bất thường.

  • Vấn đề: Budgets chỉ cảnh báo khi vượt ngưỡng tổng (VD: vượt $1000). Nhưng nếu hôm nay EC2 vọt lên bất thường ngốn $100 (bình thường chỉ $10) mà chưa chạm mốc $1000, Budgets sẽ không cảnh báo ngay.
  • Giải pháp: Anomaly Detection phát hiện sự kiện bất thường này ngay lập tức (dựa trên pattern lịch sử) và gửi cảnh báo (SNS, Slack, Email) để chặn đứng hóa đơn tăng vọt.

12. Case Study: Ngăn chặn vượt ngân sách tự động (Budgets Actions)

Bối cảnh: Môi trường Sandbox của Dev được cấp ngân sách $500/tháng. Tuy nhiên, các Dev thường xuyên quên tắt EC2 lớn vào cuối tuần, khiến hóa đơn hay bị lố.

Giải pháp: Sử dụng AWS Budgets Actions. Khi chi tiêu vượt 100% ngân sách ($500), Budgets kích hoạt một Action tự động:

  1. Thực thi một SSM Document (Systems Manager) hoặc áp dụng một IAM Policy cấm chạy EC2.
  2. SSM Document sẽ lập tức chạy lệnh StopInstances trên tất cả EC2 có tag Environment=Sandbox.
  3. Nhờ đó, máy tự động tắt, ngăn chặn hóa đơn chảy máu tiếp.

13. CLI & JSON Policy Snippets

Service Control Policy (SCP) Ngăn chặn tạo EC2 đắt tiền (p3, x1): Dùng SCP ở mức Organization Root để ngăn tất cả tài khoản con khởi tạo các dòng EC2 siêu đắt.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RequireMicroInstanceType",
      "Effect": "Deny",
      "Action": "ec2:RunInstances",
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "StringNotEquals": {
          "ec2:InstanceType": [
            "t2.micro",
            "t3.micro"
          ]
        }
      }
    }
  ]
}
