Compute Cost Optimization

Task 4.2: Design Cost-Optimized Compute Solutions

📊 Tiến độ học tập: Compute Cost Optimization

Status: Đã hoàn thành chuyên sâu Tầm quan trọng: Rất Cao (Chi phí Compute luôn chiếm tỷ trọng lớn nhất trong bất kỳ dự án Cloud nào).

Chi phí tính toán (Compute) thường chiếm phần lớn nhất trong hóa đơn AWS. Việc tối ưu hóa compute không chỉ đòi hỏi chọn đúng mô hình mua sắm mà còn phải ứng dụng linh hoạt các kiến trúc hiện đại (Serverless, Containers), "Right-sizing" (chọn đúng kích cỡ máy), và xử lý tốt các giới hạn của hệ thống.

1. Lý Thuyết Chuyên Sâu: Các Mô Hình Mua Sắm Amazon EC2 (Purchasing Options)

AWS cung cấp 5 cách mua EC2 cơ bản. Đây là kiến thức BẮT BUỘC có mặt trong bài thi.

Mô hình mua sắm Đặc điểm cốt lõi Mức giảm giá Use Case lý tưởng
On-Demand Trả tiền theo từng giây (Pay-by-the-second), không cam kết, tắt/bật tùy ý. Giá đắt nhất. 0% (Giá gốc) Ứng dụng ngắn hạn, workload biến động không thể đoán trước, giai đoạn Dev/Test.
Reserved Instances (RI) Cam kết sử dụng 1 năm hoặc 3 năm. Trả trước càng nhiều, giảm giá càng sâu. Có 2 loại: Standard (không đổi được OS/Instance family) và Convertible (đổi được, nhưng giảm giá ít hơn). Lên đến 72% Ứng dụng Production chạy ổn định 24/7 (VD: Master Database, Backend cốt lõi).
Savings Plans Cam kết mức chi tiêu ($/giờ) trong 1 hoặc 3 năm thay vì cam kết cấu hình máy cụ thể. Vô cùng linh hoạt (Compute Savings Plans áp dụng được cả cho Fargate và Lambda). Lên đến 72% Workload dài hạn nhưng công ty có kế hoạch thay đổi Instance Types hoặc chuyển sang Serverless trong tương lai.
Spot Instances Đấu thầu các EC2 dư thừa của AWS. CỰC KỲ QUAN TRỌNG: AWS có thể đòi lại máy bất kỳ lúc nào với cảnh báo 2 phút (2-minute warning). Lên đến 90% Batch processing, Image rendering, CI/CD, Workload stateless (có thể bắt đầu lại nếu bị ngắt quãng).
Dedicated Hosts Thuê trọn nguyên một máy chủ vật lý, bạn kiểm soát được socket/core vật lý. Rất đắt Mang giấy phép phần mềm riêng (BYOL - Bring Your Own License) bị ràng buộc theo socket vật lý, hoặc yêu cầu bảo mật cao nhất (Compliance).
Mẹo làm bài thi

AWS rất thích hỏi "workload can be interrupted" hoặc "jobs that can be resumed without failure" → Auto chọn Spot Instances.

2. Burstable Performance Instances (T-Family) và Cạm Bẫy Chi Phí

Các dòng EC2 như t2, t3, t4g được gọi là Burstable Instances. Chúng được thiết kế với giá cực rẻ để phục vụ các website có mức độ sử dụng CPU trung bình thấp, nhưng thỉnh thoảng cần "burst" (bùng nổ) lên 100%.

  • Cơ chế CPU Credits: Hoạt động như tích điểm thẻ tín dụng. Khi CPU nhàn rỗi (ví dụ chạy < 20%), máy tích luỹ credit. Khi có khách truy cập, tải vọt lên 100%, máy tiêu thụ credit. Hết credit, hiệu năng CPU bị bóp nghẹt (throttle) về baseline, máy trở nên giật lag.
  • T-Unlimited Mode (Cạm bẫy): Mặc định bật trên t3 và t4g. Khi hết Credit, máy không bị lag, hệ thống cho phép bạn "vay mượn" năng lực CPU. TUY NHIÊN, AWS sẽ tính thêm tiền cho lượng CPU vượt ngưỡng này (Surplus credits). Nếu chạy 100% CPU liên tục 24/7 trên T3 Unlimited, hóa đơn sẽ đắt hơn việc mua một máy m5 to đùng!

3. Các Chiến Lược "Vắt Kiệt" (Utilization Optimization)

EC2 Auto Scaling

Đừng chạy cố định 10 máy EC2 nếu ban đêm không ai dùng.

  • Dynamic Scaling: Scale dựa trên CloudWatch Metrics (VD: CPU > 70% thì đẻ thêm máy, CPU < 30% thì tắt bớt).
  • Scheduled Scaling: Rất tiết kiệm chi phí. Nếu biết 9AM sáng thứ Hai nhân viên mới đi làm, hãy hẹn giờ bật máy lúc 8h45AM và tắt toàn bộ vào 6h00PM thứ Sáu.

Right-sizing (Chọn đúng kích thước)

Dùng dịch vụ Machine Learning AWS Compute Optimizer. Nó theo dõi hệ thống 14 ngày, nếu thấy EC2 của bạn có CPU lúc nào cũng < 10%, nó sẽ đưa ra báo cáo khuyến nghị bạn hạ size (downgrade) từ c5.2xlarge xuống c5.large.

EC2 Hibernation (Ngủ Đông)

Thay vì Stop/Start tốn thời gian boot hệ điều hành rề rà, Hibernation ghi toàn bộ dữ liệu trên RAM (in-memory state) vào ổ cứng EBS Root Volume. Lúc ngủ đông, bạn KHÔNG bị tính tiền Compute, chỉ bị tính tiền lưu trữ EBS. Phù hợp cho ứng dụng cần khởi động (Warm up) mất nhiều thời gian.

4. Limits, Quotas & Constraints Cần Lưu Ý

  1. AWS Lambda:
    • Timeout giới hạn: Tối đa 15 phút. Nếu script xử lý video của bạn chạy mất 20 phút, BẮT BUỘC phải chuyển sang AWS Fargate hoặc EC2. Lambda không thể chạy quá 15 phút.
    • Memory và CPU: Tối đa 10 GB RAM. AWS tự động cấp phát CPU tỷ lệ thuận với RAM. Muốn Lambda chạy nhanh hơn, hãy tăng RAM (chi phí/ms đắt hơn nhưng thời gian chạy ngắn lại, đôi khi tổng tiền rẻ hơn).
  2. EC2 Spot Instances:
    • Nếu AWS thu hồi Spot instance trong giờ đầu tiên (First hour), bạn KHÔNG bị tính phí cho giờ đó.
    • Nếu Bạn tự Terminate Spot instance, bạn sẽ bị tính phí đến từng giây cuối cùng.
  3. AWS Fargate:
    • Fargate là Serverless Containers. Tính tiền trên số vCPU và GB Memory bạn đăng ký cho Task. Rẻ hơn EC2 nếu traffic lác đác, nhưng nếu traffic cực khủng chạy 24/7, EC2 tĩnh có thể rẻ hơn.

5. ARM Processors: AWS Graviton

Đây là chiêu "đổi chip giảm tiền". AWS tự chế tạo chip Graviton (c6g, m6g, t4g) dựa trên kiến trúc ARM thay vì dùng Intel/AMD (x86).

  • Lợi ích: Hiệu năng tính toán (Price/Performance) tốt hơn tới 40% so với chip Intel. Rẻ hơn rõ rệt.
  • Constraint (Trở ngại): Không phải bê ứng dụng vào là chạy được. Code (C/C++, Go) hoặc Docker image phải được biên dịch lại (re-compile) cho kiến trúc ARM. Riêng các ngôn ngữ thông dịch như Python, Node.js, Java hầu như chạy được ngay.

6. Case Study Thực Tế: Auto Scaling Group với Mixed Instances Policy

Bối cảnh: Công ty có ứng dụng xử lý ảnh phi trạng thái (stateless worker nodes). Traffic tăng mạnh vào ban ngày, tắt hẳn ban đêm. Yêu cầu: Không bao giờ được sập hệ thống (cần Base capacity), nhưng chi phí scale-out phải cực rẻ.

Giải pháp Cost-Optimized:

  1. Cấu hình Auto Scaling Group sử dụng Mixed Instances Policy.
  2. Đặt OnDemandBaseCapacity = 2. ASG sẽ luôn giữ 2 máy On-Demand để đảm bảo ứng dụng sống sót.
  3. Đặt SpotAllocationStrategy = capacity-optimized. Mọi máy sinh ra thêm do scale-out (khi traffic tăng) sẽ là 100% Spot Instances (rẻ hơn 90%).
  4. AWS sẽ chọn nhóm Spot pool rảnh rỗi nhất để đẻ máy, giảm rủi ro bị thu hồi tập thể. Nếu AWS thu hồi 1 máy Spot, ứng dụng có 2 phút để xử lý graceful shutdown, sau đó ASG đẻ 1 máy Spot khác đắp vào.

7. Troubleshooting & Lỗi Ngốn Tiền Phổ Biến

Vấn đề (Issue) Nguyên nhân (Root Cause) Khắc phục (Resolution)
Phí Elastic IP nhàn rỗi Xóa (Terminate) EC2 nhưng quên trả lại IP tĩnh. Thực hiện lệnh release-address ngay sau khi Terminate EC2. Nếu EIP đang gắn vào máy chạy, nó miễn phí.
Máy Spot tắt rụp, hỏng Data Ứng dụng không bắt (catch) tín hiệu Interruption của AWS. Cấu hình ứng dụng hoặc cài script liên tục check HTTP Metadata của AWS. Nếu trả về status 200, lập tức lưu data vào S3 và exit an toàn.
Mua Reserved Instance nhưng không thấy giảm giá Mua nhầm Region hoặc nhầm Instance Family (VD: máy chạy m5 mà đi mua RI cho c5). Đọc kỹ báo cáo trong Cost Explorer. Nâng cấp lên Savings Plans để tránh tình trạng "mua hớ" (vì SP áp dụng cho mọi instance family).

8. CLI & JSON Policy Snippets

Lệnh kiểm tra cảnh báo Spot Interruption (Chạy cronjob liên tục trên EC2):

# Lệnh check Instance Metadata Service (IMDS). 
# Nếu HTTP status trả về 200, tức là máy này sẽ "bốc hơi" trong đúng 2 phút nữa!
curl -H "X-aws-ec2-metadata-token: $TOKEN" -s http://169.254.169.254/latest/meta-data/spot/instance-action

JSON Snippet Cấu hình Mixed Instances Policy cho ASG:

{
  "AutoScalingGroupName": "web-worker-asg",
  "MixedInstancesPolicy": {
    "InstancesDistribution": {
      "OnDemandBaseCapacity": 2,
      "OnDemandPercentageAboveBaseCapacity": 0,
      "SpotAllocationStrategy": "capacity-optimized"
    },
    "LaunchTemplate": {
      "LaunchTemplateSpecification": {
        "LaunchTemplateName": "WorkerTemplate",
        "Version": "$Default"
      },
      "Overrides": [
        { "InstanceType": "c5.large" },
        { "InstanceType": "c5a.large" },
        { "InstanceType": "m5.large" }
      ]
    }
  }
}

9. Cảnh Báo & Mẹo Thi (Exam Tips)

Mẹo từ khóa SAA-C03
  • "Spiky, unpredictable traffic, cost-effective container deployment" → Chọn AWS Fargate (Đỡ phải duy trì EC2 nền).
  • "Machine Learning models processing data, can be interrupted" → Spot Instances.
  • "Company commits to $10/hour spend, needs flexibility across Lambda/Fargate/EC2" → Compute Savings Plans.
  • "Save money on non-production environment at night" → Auto Scaling Scheduled Actions (Tắt máy lúc 6PM, bật lúc 8AM).
  • "Migrate C++ app to cloud, lowest compute cost" → Nếu app có thể re-compile, chọn AWS Graviton instances (t4g, m6g).
Exam Trap: Lambda Timeout

Nếu đề bài nói: "A script runs once a day, processes data for 30 minutes. Most cost-effective way?" ĐỪNG CHỌN AWS Lambda vì Lambda bị Limit ở 15 phút. Bạn phải chọn AWS Batch chạy với Spot Instances hoặc dùng AWS Fargate.

10. Checklist Ôn Tập Cuối Cùng

  • Hiểu quy tắc Spot: AWS thu hồi trong giờ đầu = không tính phí. Mình tự tắt = tính phí bình thường.
  • Sự khác nhau giữa Standard RI (không đổi loại máy được) và Compute Savings Plans (đổi đủ thứ).
  • Phân biệt lúc nào nên dùng EC2 On-Demand (ngắn hạn) vs Serverless Lambda (dựa trên event, lác đác).
  • Nhớ giới hạn cứng của Lambda: 15 phút, 10GB RAM, 10GB ổ /tmp.
  • Tránh bẫy hóa đơn của dòng T-family: Chế độ Unlimited gây tăng phí khủng khiếp nếu tải cao liên tục.
