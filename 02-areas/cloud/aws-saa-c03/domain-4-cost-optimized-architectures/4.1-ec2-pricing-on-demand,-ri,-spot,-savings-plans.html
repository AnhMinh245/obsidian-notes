EC2 Pricing - On-Demand, RI, Spot, Savings Plans

EC2 Pricing — On-Demand, RI, Spot, Savings Plans

Tầm quan trọng trong thi

EC2 pricing models là chủ đề ra đề thi nhiều nhất trong Domain 4. Bạn cần hiểu rõ từng pricing option, khi nào sử dụng, và cách kết hợp chúng để tối ưu chi phí. Đây là nền tảng cho Task 4.2 — Design Cost-Optimized Compute Solutions.

Tổng quan EC2 Pricing Models

1. On-Demand Instances

On-Demand là gì?

On-Demand Instances cho phép bạn trả tiền theo giây (Linux/Ubuntu) hoặc theo giờ (Windows/RHEL) mà không cần cam kết dài hạn. Đây là pricing model đắt nhất nhưng linh hoạt nhất.

1.1. Đặc điểm

Đặc điểm Chi tiết
Billing Per-second (minimum 60 seconds) cho Linux; Per-hour cho Windows
Commitment Không cần cam kết
Discount Không có discount (baseline pricing)
Availability Luôn available (subject to capacity)
Stop/Start Có thể stop/start/terminate bất kỳ lúc nào
Billing khi stopped KHÔNG bị charge EC2 compute; VẪN bị charge EBS volumes

1.2. Use Cases phù hợp

  • ✅ Short-term, irregular workloads không thể bị interrupt
  • ✅ Applications đang develop/test lần đầu trên AWS
  • ✅ Workloads không thể predict usage pattern
  • ✅ Ứng dụng cần chạy liên tục nhưng chưa sẵn sàng commit 1/3 năm
  • ✅ Baseline check — dùng On-Demand trước, sau đó analyze usage rồi mua RI/SP

1.3. On-Demand Capacity Reservations (ODCR)

On-Demand Capacity Reservations

ODCR cho phép bạn reserve EC2 capacity trong một AZ cụ thể mà không cần cam kết dài hạn. Bạn bị charge On-Demand rate dù có dùng hay không — nhưng guarantee có capacity khi cần.

# ODCR Details
- Reserve capacity: specific instance type + AZ
- Billing: On-Demand rate (used or not)
- Commitment: NONE — create/cancel anytime
- Discount: NONE (combine with RI or SP for discount)
- Best combo: ODCR + Savings Plans = guaranteed capacity + discount
Exam tip — On-Demand
  • On-Demand là default pricing — mọi instance launch đều On-Demand trừ khi chỉ định khác
  • ODCR + Savings Plans = best of both worlds (capacity guarantee + discount)
  • Stopped instances: không charge compute nhưng vẫn charge EBS
  • Billing per-second = minimum 1 minute (60 seconds)

2. Reserved Instances (RI)

Reserved Instances

Reserved Instances cung cấp significant discount (lên tới 72%) so với On-Demand pricing bằng cách commit sử dụng instance type cụ thể trong 1 hoặc 3 năm. RI không phải là instance vật lý — mà là billing discount áp dụng cho matching On-Demand instances.

2.1. Hai loại RI chính

2.2. So sánh Standard vs Convertible RI

Tiêu chí Standard RI Convertible RI
Max discount 72% 66%
Change instance family ❌ ✅ (convert)
Change instance type ❌ (chỉ size flexibility nếu Regional) ✅ (convert)
Change OS ❌ ✅ (convert)
Change tenancy ❌ ✅ (convert)
Change scope ✅ (Regional ↔ Zonal) ✅
Sell on Marketplace ✅ ❌
Merge/Split ✅ ✅
Size flexibility ✅ (Regional scope) ✅
Best for Biết chính xác cần gì Cần flexibility + long-term

2.3. Payment Options

Payment Option Discount Cash Flow
All Upfront (AURI) Highest (72% Standard) Trả hết ngay đầu kỳ
Partial Upfront (PURI) Medium 50% upfront + monthly
No Upfront (NURI) Lowest 100% monthly
Quy tắc discount: 3-year > 1-year; All Upfront > Partial > No Upfront

Maximum discount = 3-year term + All Upfront + Standard RI = 72%

2.5. RI Size Flexibility (Regional scope)

Size Flexibility

Với Regional scope RIs, AWS sử dụng normalization factor để apply discount cho instances cùng family nhưng khác size. Ví dụ: 1x m5.xlarge RI có thể cover 2x m5.large hoặc 0.5x m5.2xlarge.

# Normalization Factors (relative to xlarge = 8)
nano:      1      # m5.nano
micro:     1      # m5.micro  
small:     1      # m5.small
medium:    2      # m5.medium
large:     4      # m5.large
xlarge:    8      # m5.xlarge ← baseline
2xlarge:   16     # m5.2xlarge
4xlarge:   32     # m5.4xlarge
8xlarge:   64     # m5.8xlarge
12xlarge:  96     # m5.12xlarge
16xlarge:  128    # m5.16xlarge
24xlarge:  192    # m5.24xlarge
metal:     192    # m5.metal

# Example:
# Bought: 1x m5.xlarge RI (factor = 8)
# Can cover: 2x m5.large (factor = 4 × 2 = 8) ✅
# Can cover: 4x m5.medium (factor = 2 × 4 = 8) ✅
# Can cover: 0.5x m5.2xlarge (factor = 16 × 0.5 = 8) ✅

2.6. RI Modifications

Modification Cho phép? Cách làm
Change AZ (within Region) ✅ Standard + Convertible Modify RI
Change scope (Regional ↔ Zonal) ✅ Modify RI
Change network platform ✅ Modify RI
Split RI (1x xlarge → 2x large) ✅ Modify RI
Merge RI (2x large → 1x xlarge) ✅ Modify RI
Change instance family ❌ Standard / ✅ Convertible Exchange (Convert)
Change OS ❌ Standard / ✅ Convertible Exchange
Change tenancy ❌ Standard / ✅ Convertible Exchange
Convertible RI Exchange Rules
  • Khi exchange Convertible RI, new RI value phải ≥ old RI value
  • Bạn không thể downgrade — chỉ equal or upgrade
  • Exchange tạo RI mới với remaining term của RI cũ
  • Convertible RI KHÔNG THỂ bán trên Marketplace

3. Spot Instances

Spot Instances là gì?

Spot Instances cho phép bạn sử dụng unused EC2 capacity với discount lên tới 90% so với On-Demand. Trade-off: AWS có thể lấy lại instance bất kỳ lúc nào với thông báo trước 2 phút.

3.1. Đặc điểm chính

Đặc điểm Chi tiết
Discount Lên tới 90% so với On-Demand
Pricing Giá thay đổi theo supply/demand (nhưng stable hơn trước)
Interruption AWS có thể reclaim với 2-minute warning
Interruption notice EC2 metadata endpoint + CloudWatch Events/EventBridge
Max price Bạn set max price; nếu spot price > max → instance terminated
Availability Phụ thuộc spare capacity — không guarantee

3.2. Spot Request Types

Persistent Spot Request — Trap question

Để thực sự terminate một Persistent Spot Instance:

  1. Cancel the Spot request FIRST
  2. Then terminate the instance

Nếu chỉ terminate instance mà không cancel request → AWS sẽ tự động launch instance mới!

Nếu chỉ cancel request mà không terminate instance → Instance vẫn chạy và charge On-Demand!

3.3. Spot Fleet

Spot Fleet

Spot Fleet là tập hợp Spot Instances + (optional) On-Demand Instances được quản lý như một đơn vị. Bạn define target capacity và Spot Fleet tự động launch/maintain instances.

Allocation Strategies

Strategy Mô tả Best for
lowestPrice Chọn pool có giá thấp nhất Cost optimization thuần tuý
diversified Phân tán across nhiều pools Availability — giảm risk tất cả bị interrupt cùng lúc
capacityOptimized Chọn pool có capacity available cao nhất Workloads cần availability cao
priceCapacityOptimized ⭐ Kết hợp price + capacity (AWS recommended) Best default choice — balance cost và availability

3.5. Use Cases — Spot vs NOT Spot

✅ Phù hợp cho Spot ❌ KHÔNG phù hợp cho Spot
Batch processing jobs Databases (stateful)
Data analysis / Big Data (EMR) Critical production web servers
CI/CD pipelines Applications cần 100% uptime
Image/video rendering Workloads không thể checkpoint/retry
Machine learning training Single-instance applications
Stateless web servers (behind ALB + ASG) Real-time transaction processing
Scientific computing Healthcare/financial critical systems
Testing/QA environments
Exam tip — Spot Instances
  • Keywords trong đề: "fault-tolerant", "can be interrupted", "flexible start/stop", "batch", "stateless" → Spot
  • Keywords không phải Spot: "critical", "cannot be interrupted", "database", "persistent state"
  • Spot Fleet priceCapacityOptimized = AWS recommended default strategy
  • Spot + ASG: set Mixed Instances Policy → On-Demand base + Spot for scale-out

4. Savings Plans — Chi tiết

Savings Plans vs Reserved Instances

Savings Plans là newer, more flexible alternative cho RI. Thay vì commit specific instance type, bạn commit $/hour spend — và usage matching commitment nhận discount.

4.1. Compute Savings Plans

# Compute Savings Plans
Applies to:
  - EC2 instances (any family, size, Region, OS, tenancy)
  - AWS Fargate (ECS + EKS)
  - AWS Lambda
  
Max discount: 66% off On-Demand
Term: 1-year or 3-year
Payment: No Upfront / Partial Upfront / All Upfront

Flexibility:
  ✅ Change instance family (m5 → c5)
  ✅ Change instance size (xlarge → 2xlarge)
  ✅ Change Region (us-east-1 → eu-west-1)
  ✅ Change OS (Linux → Windows)
  ✅ Change tenancy (shared → dedicated)
  ✅ Switch from EC2 to Fargate/Lambda

4.2. EC2 Instance Savings Plans

# EC2 Instance Savings Plans
Applies to:
  - EC2 instances ONLY
  - Specific instance family (e.g., M5)
  - Specific Region (e.g., us-east-1)
  
Max discount: 72% off On-Demand
Term: 1-year or 3-year
Payment: No Upfront / Partial Upfront / All Upfront

Flexibility:
  ✅ Change instance size (m5.xlarge → m5.2xlarge)
  ✅ Change OS (Linux → Windows)
  ✅ Change tenancy (shared → dedicated)
  ❌ Cannot change family (m5 → c5) ← locked
  ❌ Cannot change Region (us-east-1 → eu-west-1) ← locked
  ❌ Does NOT apply to Fargate/Lambda

5. Dedicated Hosts

Dedicated Hosts

Dedicated Host là physical server được dedicated riêng cho bạn. Bạn có full visibility vào physical sockets, cores, và host ID — cần thiết cho BYOL (Bring Your Own License) và compliance requirements.

5.1. Đặc điểm

Đặc điểm Chi tiết
Physical server Entire server cho 1 AWS account
Visibility Sockets, cores, host ID
BYOL Hỗ trợ per-socket, per-core, per-VM licenses
Pricing On-Demand hoặc RI (1y/3y)
Cost Đắt nhất trong tất cả options
Use case Compliance (HIPAA, SOX), licensing (Oracle, SQL Server, Windows Server)
Instance placement Bạn control instances chạy trên host nào
Auto-placement Có thể enable/disable

5.2. Dedicated Hosts vs Dedicated Instances

Tiêu chí Dedicated Hosts Dedicated Instances
Physical server Dedicated cho bạn Dedicated cho bạn
Visibility ✅ Sockets, cores, host ID ❌ Không thấy
Instance placement control ✅ ❌
BYOL ✅ ❌
Per-host billing ✅ (charged per host) ❌ (charged per instance)
Affinity ✅ (instance stays on same host) ❌
Pricing Đắt hơn Rẻ hơn (so với Dedicated Host)
Use case BYOL, compliance cần visibility Compliance cần isolation
Exam tip — Dedicated
  • "BYOL" hoặc "bring your own license" → Dedicated Hosts (vì cần visibility vào sockets/cores)
  • "Hardware isolation" mà KHÔNG cần BYOL → Dedicated Instances (rẻ hơn)
  • "Compliance requires dedicated hardware" → depends on details, nhưng nếu cần host visibility → Dedicated Hosts
  • Cả hai đều compliance-friendly, nhưng Dedicated Hosts đắt hơn

6. Capacity Reservations

On-Demand Capacity Reservations

Capacity Reservations cho phép bạn reserve compute capacity trong AZ cụ thể cho instance type cụ thể. Không có billing discount — nhưng guarantee capacity sẽ available khi bạn cần.

6.1. Đặc điểm

# On-Demand Capacity Reservations
Create/Cancel: anytime (no commitment)
Billing: On-Demand rate (dù dùng hay không)
Discount: NONE — phải combine với RI hoặc SP
Scope: specific instance type + AZ
Capacity guarantee: YES — reserved capacity always available

# Best combination:
ODCR + Savings Plans = guaranteed capacity + billing discount
# This replaces the deprecated "Scheduled RI" use case

6.2. Use Cases

Scenario Solution
Cần capacity guarantee + discount ODCR + Savings Plans
Disaster Recovery — cần capacity sẵn sàng ODCR (không cần chạy instances)
Seasonal peaks — biết trước thời điểm ODCR created before peak
Compliance — phải chạy trong AZ cụ thể ODCR + RI/SP

7. EC2 Pricing Decision Tree

8. Bảng tổng hợp — Tất cả EC2 Pricing Options

Option Max Discount Commitment Flexibility Interruption Best Use Case
On-Demand 0% None Highest No Short-term, unpredictable
Standard RI 72% 1y/3y Low (same type+region) No Steady-state, known workload
Convertible RI 66% 1y/3y Medium (can convert) No Long-term, may change
Compute SP 66% 1y/3y Very High (any family/region/compute) No Multi-service, flexible
EC2 Instance SP 72% 1y/3y High (same family+region) No EC2-focused, max discount
Spot 90% None High YES Batch, fault-tolerant
Dedicated Hosts RI pricing available Optional (1y/3y) Low No BYOL, compliance
Dedicated Instances On-Demand or RI Optional Low No Hardware isolation
ODCR 0% (combine w/ SP/RI) None Medium No Capacity guarantee

9. EC2 Cost Optimization Strategies

9.1. Mixed Instance Strategy (Auto Scaling)

9.2. Right-Sizing với Compute Optimizer

# Right-sizing workflow
1. Enable Compute Optimizer
2. Wait 14 days (minimum data collection)
3. Review recommendations:
   - Over-provisioned → downsize
   - Under-provisioned → upsize
   - Optimized → no action
4. Implement changes during maintenance window
5. Monitor post-change performance
6. Enable Enhanced Monitoring (93 days) for better accuracy

9.3. Scheduled Start/Stop

# Scheduled start/stop for dev/test environments
Tools:
  - AWS Instance Scheduler (CloudFormation solution)
  - Lambda + EventBridge rules
  - AWS Systems Manager Automation

Example schedule:
  - Start: Mon-Fri 8:00 AM
  - Stop: Mon-Fri 7:00 PM
  - Weekend: stopped
  
Savings: ~65% cho dev/test environments
  - 24*7 = 168 hours/week (full cost)
  - 11*5 = 55 hours/week (scheduled)
  - Savings: (168-55)/168 = ~67%

9.4. EC2 Hibernate vs Stop vs Terminate

Action RAM state EBS root EBS data Billing Resume time
Stop Lost Preserved Preserved EBS only 30s-2min (boot)
Hibernate Saved to EBS Preserved Preserved EBS only (larger root) Seconds (resume from RAM)
Terminate Lost Deleted (default) Depends on DeleteOnTermination Nothing N/A
Exam tip — Hibernate
  • Hibernate = nhanh hơn restart vì RAM được restore từ EBS
  • Root EBS volume phải encrypted và đủ lớn để chứa RAM dump
  • RAM size limit: 150 GB
  • Supported: On-Demand, RI (không hỗ trợ Spot nữa — deprecated)
  • Use case: applications khởi động lâu (JVM warm-up, large in-memory cache)

10. EC2 Pricing — Region Impact

Giá EC2 khác nhau giữa các Regions

Cùng instance type, giá có thể chênh 10-30% giữa các regions. Ví dụ:

  • us-east-1 (N. Virginia): thường rẻ nhất
  • ap-southeast-1 (Singapore): ~10-15% đắt hơn
  • sa-east-1 (São Paulo): ~20-30% đắt hơn

Nếu đề bài nói "reduce costs" và workload không yêu cầu specific region → xem xét deploy ở Region rẻ hơn

  • Phân biệt On-Demand vs RI vs Spot vs Savings Plans — discount, commitment, flexibility
  • Hiểu Standard RI vs Convertible RI — exchange rules, marketplace
  • Nắm 3 payment options — All/Partial/No Upfront
  • Hiểu Regional vs Zonal RI scope — size flexibility, capacity reservation
  • Biết Spot Fleet strategies — lowestPrice, diversified, capacityOptimized, priceCapacityOptimized
  • Hiểu Spot interruption handling — 2-min notice, persistent vs one-time
  • So sánh Compute SP vs EC2 Instance SP — flexibility vs discount
  • Phân biệt Dedicated Hosts vs Dedicated Instances — BYOL requirement
  • Hiểu ODCR + SP combo — capacity guarantee + discount
  • Nắm Mixed Instances Policy trong ASG — On-Demand base + Spot scale
  • Biết Hibernate vs Stop vs Terminate — RAM state, billing, resume time
  • Hiểu RI Size Flexibility và normalization factors
