AWS EC2 - Gán Multiple ENI và Elastic IP qua Console (GUI)

AWS EC2 - Gán Multiple ENI và Elastic IP qua Console (GUI)

Xem thêm: AWS EC2 - Multiple IPs và Elastic IP trên Multi-Subnet VPC (phiên bản CLI)

TL;DR

  • t3.xlarge hỗ trợ tối đa 4 ENI → dùng cho 1 public + 3 private subnet.
  • Toàn bộ thực hiện qua AWS Management Console, không cần CLI.
  • Quy trình: Launch EC2 → Tạo ENI → Attach ENI → Gán Elastic IP.

Kiến trúc với t3.xlarge

EC2 t3.xlarge
├── eth0 → Public Subnet  (10.0.1.0/24) ← Elastic IP gắn ở đây
├── eth1 → Private Subnet 1 (10.0.2.0/24)
├── eth2 → Private Subnet 2 (10.0.3.0/24)
└── eth3 → Private Subnet 3 (10.0.4.0/24)

Lưu ý: Tất cả ENI và instance phải cùng 1 Availability Zone (vd: ap-southeast-1a).

PHẦN A — Launch EC2 Instance

Bước 1 — Mở EC2 Launch Wizard

  1. Vào AWS Console → thanh tìm kiếm gõ EC2 → chọn EC2
  2. Sidebar trái → Instances → nút Launch instances (cam/vàng góc trên phải)

Bước 2 — Điền thông tin cơ bản

Name and tags

  • Name: multi-subnet-instance

Application and OS Images (AMI)

  • Chọn Amazon Linux 2023 (hoặc Ubuntu 24.04 LTS tuỳ preference)
  • Kiến trúc: 64-bit (x86)

Instance type

  • Gõ vào ô tìm kiếm: t3.xlarge → chọn t3.xlarge
    • 4 vCPU · 16 GiB · Max 4 ENI · Max 15 IPs/ENI

Key pair

  • Chọn key pair đã có, hoặc Create new key pair nếu chưa có

Bước 3 — Network Settings (quan trọng)

Click Edit ở góc phải của phần Network settings

Field Giá trị
VPC Chọn VPC đã tạo
Subnet Chọn Public Subnet (10.0.1.0/24)
Auto-assign public IP Disable ← quan trọng, sẽ gắn EIP thủ công sau
Firewall (Security group) Chọn SG đã có (hoặc tạo mới)

Chỉ cần cấu hình eth0 (primary) ở đây. Các ENI phụ sẽ attach sau khi instance chạy.

Advanced network configuration (tuỳ chọn):

  • Primary IP: nhập 10.0.1.10 để đặt IP tĩnh thay vì DHCP ngẫu nhiên

Bước 4 — Configure Storage

  • Giữ mặc định 8 GiB gp3 hoặc tăng nếu cần

Bước 5 — Launch

  • Click Launch instance → chờ status chuyển sang 2/2 checks passed
  • Ghi lại Instance ID (dạng i-0abc123def456789)

PHẦN B — Tạo và Attach ENI cho Private Subnets

Bước 6 — Tạo ENI cho Private Subnet 1

  1. Sidebar EC2 → mục Network & Security → Network Interfaces
  2. Click Create network interface (góc trên phải)

Điền form: | Field | Giá trị | |---|---| | Description | eni-private-subnet-1 | | Subnet | Chọn Private Subnet 1 (10.0.2.0/24) | | Private IPv4 address | Custom → nhập 10.0.2.10 | | Security groups | Chọn cùng SG với instance |

→ Click Create network interface

Ghi lại Network Interface ID (dạng eni-0abc123...)

Bước 7 — Tạo ENI cho Private Subnet 2 và 3

Lặp lại Bước 6 hai lần nữa:

ENI thứ 2: | Field | Giá trị | |---|---| | Description | eni-private-subnet-2 | | Subnet | Private Subnet 2 (10.0.3.0/24) | | Private IPv4 address | 10.0.3.10 |

ENI thứ 3: | Field | Giá trị | |---|---| | Description | eni-private-subnet-3 | | Subnet | Private Subnet 3 (10.0.4.0/24) | | Private IPv4 address | 10.0.4.10 |

Bước 8 — Attach ENI vào Instance

Thực hiện lần lượt cho từng ENI vừa tạo:

  1. Tại trang Network Interfaces → tick chọn ENI cần attach
  2. Menu Actions (góc trên phải) → Attach
  3. Cửa sổ popup:
    • Instance: tìm và chọn multi-subnet-instance
    • Device index: AWS tự điền (1, 2, 3 tăng dần)
  4. Click Attach

Làm đủ 3 lần cho 3 ENI private. Sau đó vào Instances → chọn instance → tab Networking → kiểm tra thấy đủ 4 network interfaces.

PHẦN C — Gán Elastic IP

Bước 9 — Kiểm tra Elastic IP đã có

  1. Sidebar → Network & Security → Elastic IPs
  2. Xác nhận có EIP chưa được gán (cột Associated instance ID trống)

Nếu chưa có: Allocate Elastic IP address → Region pool → Allocate

Bước 10 — Associate Elastic IP vào Primary ENI

  1. Tick chọn EIP cần gán
  2. Actions → Associate Elastic IP address
  3. Điền form:
Field Giá trị
Resource type Network interface
Network interface Chọn ENI của Public Subnet (eth0 — có Private IP 10.0.1.10)
Private IP address 10.0.1.10
  1. Click Associate

Sau bước này, instance có thể truy cập từ internet qua Elastic IP.

PHẦN D — Xác minh trong Console

Bước 11 — Kiểm tra trên tab Networking của Instance

  1. Instances → chọn multi-subnet-instance → tab Networking
  2. Kéo xuống phần Network interfaces → phải thấy:
eth0  |  10.0.1.10  |  <Elastic IP>    |  Public Subnet
eth1  |  10.0.2.10  |  —               |  Private Subnet 1
eth2  |  10.0.3.10  |  —               |  Private Subnet 2
eth3  |  10.0.4.10  |  —               |  Private Subnet 3

Bước 12 — Kiểm tra kết nối SSH vào instance

# SSH qua Elastic IP (eth0)
ssh -i <key.pem> ec2-user@<ELASTIC_IP>

# Bên trong instance, kiểm tra interfaces
ip addr show

Phải thấy 4 interfaces: eth0, eth1, eth2, eth3 với IP tương ứng.

PHẦN E — Cấu hình Policy Routing trong OS (bắt buộc)

Sau khi attach ENI, OS cần biết route traffic ra đúng interface. Mặc định Linux chỉ dùng 1 default route.

Amazon Linux 2023

SSH vào instance, chạy script sau:

# Tạo routing table cho mỗi ENI phụ
# eth1 - Private Subnet 1
echo "101 eth1rt" >> /etc/iproute2/rt_tables
ip route add 10.0.2.0/24 dev eth1 table 101
ip route add default via 10.0.2.1 dev eth1 table 101
ip rule add from 10.0.2.10 table 101 priority 100

# eth2 - Private Subnet 2
echo "102 eth2rt" >> /etc/iproute2/rt_tables
ip route add 10.0.3.0/24 dev eth2 table 102
ip route add default via 10.0.3.1 dev eth2 table 102
ip rule add from 10.0.3.10 table 102 priority 101

# eth3 - Private Subnet 3
echo "103 eth3rt" >> /etc/iproute2/rt_tables
ip route add 10.0.4.0/24 dev eth3 table 103
ip route add default via 10.0.4.1 dev eth3 table 103
ip rule add from 10.0.4.10 table 103 priority 102

Để persistent qua reboot, tạo systemd service hoặc thêm vào /etc/rc.local.

Lưu ý quan trọng

  • t3.xlarge = 4 ENI max → chỉ đủ cho 1 public + 3 private (không phải 4 private như ban đầu).
  • ENI và instance phải cùng AZ — nếu tạo ENI ở AZ khác sẽ không attach được.
  • Elastic IP tính phí $0.005/giờ khi không gắn vào running instance → associate ngay sau khi allocate.
  • Security Group của ENI phụ có thể khác SG của eth0 — thiết kế SG rule theo đúng traffic flow cần thiết.
  • Khi detach ENI phụ (eth1–eth3): interface trong OS sẽ biến mất, nhưng ENI vẫn tồn tại trên AWS (không bị xoá).
  • Để delete ENI, phải detach trước rồi mới delete được.
