Tổng quan Categories — Mindmap

1. Analytics

Service Mô tả Domain liên quan Mức độ
Amazon Athena Query trực tiếp data trong S3 bằng SQL (serverless, pay per query). Dùng cho ad-hoc analysis, log analysis, querying data lake D3, D4 🟡 Important
AWS Data Exchange Marketplace để subscribe và sử dụng third-party data sets trong AWS. Hỗ trợ S3, Redshift, API-based data D3 🟢 Good to know
AWS Data Pipeline Orchestration service để move và transform data giữa AWS compute/storage services. Đang dần bị thay thế bởi Glue/Step Functions D3 🟢 Good to know
Amazon EMR Managed Hadoop/Spark cluster cho big data processing. Chạy trên EC2 hoặc EKS. Dùng cho ETL, machine learning, log analysis quy mô lớn D3 🟡 Important
AWS Glue Serverless ETL (Extract, Transform, Load) service. Tự động discover schema (Glue Crawler), tạo data catalog. Tích hợp tốt với Athena, Redshift, S3 D3 🟡 Important
Amazon Kinesis Real-time streaming data platform. 4 services con: Data Streams (custom consumers, shard-based), Data Firehose (auto delivery to S3/Redshift/OpenSearch), Data Analytics (SQL on streams), Video Streams D3 🔴 Critical
AWS Lake Formation Xây dựng và quản lý data lake trên S3. Centralized access control, fine-grained permissions, data cataloging D1, D3 🟢 Good to know
Amazon MSK Managed Apache Kafka. Dùng khi cần Kafka ecosystem (producers/consumers API, Kafka Connect). So sánh thường gặp với Kinesis D3 🟢 Good to know
Amazon OpenSearch Service Managed OpenSearch (fork từ Elasticsearch). Full-text search, log analytics, real-time application monitoring. Tích hợp với CloudWatch Logs, Kinesis D3 🟡 Important
Amazon QuickSight Serverless BI (Business Intelligence) dashboards. ML-powered insights. Pay-per-session pricing model D3 🟢 Good to know
Amazon Redshift Cloud data warehouse (petabyte-scale). Columnar storage, MPP (Massively Parallel Processing). Dùng Redshift Spectrum để query S3 data D3, D4 🟡 Important
Kinesis vs MSK — phân biệt nhanh
  • Kinesis: AWS-native, tự động scale (Firehose), pay per shard/throughput, dễ dùng
  • MSK: Managed Kafka, dùng khi team đã có Kafka expertise hoặc cần Kafka ecosystem (Connect, Streams API)
  • Trong đề thi, nếu không nói "existing Kafka" → chọn Kinesis

2. Application Integration

Service Mô tả Domain liên quan Mức độ
Amazon AppFlow Managed integration service để transfer data giữa SaaS apps (Salesforce, SAP, Slack) và AWS services (S3, Redshift). No-code/low-code D3 🟢 Good to know
AWS AppSync Managed GraphQL và Pub/Sub API service. Real-time data sync cho mobile/web apps. Tích hợp DynamoDB, Lambda, HTTP datasources D3 🟡 Important
Amazon EventBridge Serverless event bus. Route events giữa AWS services, SaaS apps, custom apps. Event-driven architecture. Rules-based routing, schema registry D2, D3 🔴 Critical
Amazon MQ Managed message broker cho Apache ActiveMQ và RabbitMQ. Dùng khi migrate existing apps dùng standard messaging protocols (AMQP, MQTT, STOMP) D2 🟡 Important
Amazon SNS Pub/Sub messaging service. Push-based. Fan-out pattern: 1 message → nhiều subscribers (SQS queues, Lambda, HTTP, email, SMS). Standard & FIFO topics D2, D3 🔴 Critical
Amazon SQS Fully managed message queue. Pull-based. Decoupling producers và consumers. Standard (at-least-once, unlimited throughput) vs FIFO (exactly-once, 300/3000 msg/s). Dead-Letter Queue (DLQ) cho failed messages D2, D3 🔴 Critical
AWS Step Functions Serverless orchestration cho distributed applications. Visual workflow (state machine). Standard (long-running, up to 1 year) vs Express (high-volume, up to 5 min) D3 🟡 Important
SQS vs SNS vs EventBridge — thường bị nhầm
Feature SQS SNS EventBridge
Model Queue (pull) Pub/Sub (push) Event Bus (push)
Consumers 1 consumer per message Multiple subscribers Multiple targets
Use case Decouple, buffer Fan-out, notifications Event-driven, rules-based routing
Ordering FIFO available FIFO available Ordered per source
Filtering N/A Message filtering Content-based rules
Cross-account Yes Yes Yes

3. Cloud Financial Management (Cost Management)

Service Mô tả Domain liên quan Mức độ
AWS Budgets Set custom cost, usage, reservation budgets. Alert khi vượt threshold (email, SNS). Có thể auto-execute actions (stop EC2, apply SCP) D4 🔴 Critical
AWS Cost and Usage Report (CUR) Report chi tiết nhất về AWS spending. CSV/Parquet to S3. Dùng Athena/Redshift để analyze. Granularity: hourly/daily/monthly D4 🟡 Important
AWS Cost Explorer Visualize, understand, manage AWS costs & usage over time. Built-in forecasting (12 months). Right-sizing recommendations cho EC2 D4 🔴 Critical
Savings Plans Flexible pricing model — commit spend $/hour for 1 or 3 years. Compute SP (áp dụng mọi compute: EC2, Fargate, Lambda) vs EC2 Instance SP (specific instance family + region, giảm nhiều hơn) D4 🔴 Critical
So sánh Cost tools
  • Cost Explorer: xem retrospective + forecast → "Tôi đã/sẽ chi bao nhiêu?"
  • Budgets: set threshold + alerts → "Báo tôi khi vượt X USD"
  • CUR: raw data chi tiết → "Tôi cần analyze spending patterns"
  • Trusted Advisor: recommendations → "AWS gợi ý tôi tiết kiệm ở đâu?"

4. Compute

Service Mô tả Domain liên quan Mức độ
AWS Batch Managed batch computing. Tự động provision optimal EC2/Spot instances cho batch jobs. Dùng Docker containers. Không cần manage cluster D3, D4 🟡 Important
Amazon EC2 Virtual servers in the cloud. Core compute service. Instance types, AMIs, EBS, placement groups, user data, metadata, instance store. Pricing: On-Demand, Reserved, Savings Plans, Spot, Dedicated D1, D2, D3, D4 🔴 Critical
Amazon EC2 Auto Scaling Automatically adjust EC2 capacity. Launch templates, scaling policies (target tracking, step, simple, scheduled, predictive). Cooldown periods. Health checks D2, D3, D4 🔴 Critical
AWS Elastic Beanstalk PaaS — deploy apps (Java, .NET, Node.js, Python, Docker…) mà không cần manage infrastructure. Internally dùng EC2, ELB, Auto Scaling, RDS. "Platform as a Service" trên AWS D3 🟡 Important
AWS Outposts AWS infrastructure on-premises. Chạy AWS services tại data center khách hàng. Dùng cho low-latency, data residency requirements D2, D3 🟢 Good to know
AWS Serverless Application Repository Discover, deploy, publish serverless applications. Community-shared Lambda functions và SAM templates D3 🟢 Good to know
VMware Cloud on AWS Chạy VMware workloads trên AWS infrastructure. Dùng cho migration từ on-premises VMware environments D2 🟢 Good to know
AWS Wavelength Deploy apps tại 5G carrier network edge. Ultra-low latency cho mobile apps, IoT, real-time gaming. Tích hợp với Verizon, Vodafone D3 🟢 Good to know

5. Containers

Service Mô tả Domain liên quan Mức độ
Amazon ECS Anywhere Chạy ECS tasks trên on-premises hoặc customer-managed infrastructure. Register external instances vào ECS cluster D2 🟢 Good to know
Amazon EKS Anywhere Chạy Kubernetes clusters trên on-premises infrastructure (bare metal, VMware). Dùng EKS API/tooling D2 🟢 Good to know
Amazon EKS Distro Open-source Kubernetes distribution giống EKS. Self-managed, deploy ở bất kỳ đâu D2 🟢 Good to know
Amazon ECR Docker container registry. Store, manage, deploy container images. Integrated với ECS/EKS. Image scanning, lifecycle policies, cross-region replication D3 🟡 Important
Amazon ECS Container orchestration service (AWS-native). Task definitions, services, clusters. Launch types: EC2 (bạn manage instances) vs Fargate (serverless). Tích hợp ALB, service discovery D3 🔴 Critical
Amazon EKS Managed Kubernetes. Dùng khi cần Kubernetes ecosystem (Helm, kubectl, K8s API). Multi-AZ control plane. Launch types: EC2, Fargate, EKS Anywhere D3 🔴 Critical
ECS vs EKS — khi nào chọn cái nào?
  • ECS: AWS-native, đơn giản hơn, không cần Kubernetes expertise → chọn khi "least operational overhead"
  • EKS: Kubernetes ecosystem, portable, community tools → chọn khi "already using Kubernetes" hoặc "need portability"
  • Cả 2 đều support Fargate (serverless containers)

6. Database

Service Mô tả Domain liên quan Mức độ
Amazon Aurora MySQL/PostgreSQL-compatible relational DB. Up to 5x throughput MySQL, 3x throughput PostgreSQL. Auto-scaling storage (10GB → 128TB). 6 copies data across 3 AZs. Aurora Serverless v2, Global Database, Multi-Master D2, D3 🔴 Critical
Amazon Aurora Serverless On-demand auto-scaling Aurora. Scale to zero khi không dùng. Dùng cho infrequent/unpredictable workloads. v1 (scale to 0) vs v2 (instant scaling, production-ready) D3, D4 🟡 Important
Amazon DocumentDB MongoDB-compatible document database. Managed, scalable. Dùng khi migrate MongoDB workloads lên AWS hoặc cần document model D3 🟡 Important
Amazon DynamoDB Serverless key-value & document database. Single-digit ms latency at any scale. On-demand vs provisioned capacity. Global Tables (multi-region). DynamoDB Streams, TTL, DAX (caching). Partition key design quan trọng D2, D3, D4 🔴 Critical
Amazon ElastiCache Managed in-memory cache/data store. Redis (complex data types, persistence, replication, pub/sub, geospatial) vs Memcached (simple caching, multi-threaded, no persistence). Dùng cho session store, leaderboards, real-time analytics D3 🔴 Critical
Amazon Keyspaces Managed Apache Cassandra-compatible database. Serverless. Dùng khi migrate Cassandra workloads hoặc cần wide-column store D3 🟢 Good to know
Amazon Neptune Graph database. Dùng cho social networks, recommendation engines, fraud detection, knowledge graphs. Supports Gremlin, SPARQL, openCypher D3 🟢 Good to know
Amazon QLDB Quantum Ledger Database. Immutable, cryptographically verifiable transaction log. Dùng cho audit trail, supply chain, financial transactions cần chứng minh không bị tamper D3 🟢 Good to know
Amazon RDS Managed relational database. Engines: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server. Multi-AZ (HA, sync replication), Read Replicas (read scaling, async). Automated backups, snapshots D2, D3 🔴 Critical
Amazon Redshift Cloud data warehouse (listed lại ở Database cho convenience). Petabyte-scale, columnar, MPP. Redshift Spectrum query S3. RA3 instances tách compute/storage D3, D4 🟡 Important
RDS Multi-AZ vs Read Replicas — bẫy phổ biến nhất
Feature Multi-AZ Read Replica
Mục đích High Availability Read Scaling
Replication Synchronous Asynchronous
Failover Automatic (DNS switch) Manual (promote to standalone)
Read traffic ❌ Không serve reads ✅ Serve read queries
Cross-region ❌ Same region ✅ Cross-region available
Số lượng 1 standby Up to 5 (MySQL/MariaDB/PostgreSQL), 15 (Aurora)
Database selection decision tree cho đề thi
Relational + complex queries → RDS / Aurora
Key-value / document + massive scale → DynamoDB
In-memory caching → ElastiCache (Redis/Memcached)
Data warehouse / OLAP → Redshift
MongoDB compatibility → DocumentDB
Cassandra compatibility → Keyspaces
Graph relationships → Neptune
Immutable ledger → QLDB
Full-text search → OpenSearch
Time-series → Timestream (not in scope, but good to know)

ML services trong SAA-C03

Bạn không cần biết sâu về ML services. Chỉ cần biết service nào làm gì để match với use case trong đề bài:

  • Chatbot → Lex
  • Search documents → Kendra
  • Text from image → Textract
  • Speech to text → Transcribe
  • Text to speech → Polly
  • Image analysis → Rekognition
  • NLP/sentiment → Comprehend
  • Custom ML → SageMaker

10. Management & Governance

Service Mô tả Domain liên quan Mức độ
AWS Auto Scaling Unified scaling cho nhiều resource types (EC2, ECS, DynamoDB, Aurora). Scaling plans. Khác với EC2 Auto Scaling (chỉ EC2) D2, D4 🟡 Important
AWS CloudFormation Infrastructure as Code (IaC). JSON/YAML templates. Stacks, stack sets (multi-account), change sets, drift detection. Nested stacks. Key service cho Operational Excellence pillar D1, D2 🔴 Critical
AWS CloudTrail API call logging. Who did what, when, from where. Management events (free, 90 days) vs data events (paid). Multi-region trail, organization trail. CloudTrail Lake cho querying D1 🔴 Critical
Amazon CloudWatch Monitoring & observability. Metrics, Logs, Alarms, Dashboards, Events (→ EventBridge), Insights, Contributor Insights. Custom metrics, detailed monitoring (1-min), basic (5-min) D1, D2, D3 🔴 Critical
AWS CLI Command-line interface cho AWS services. Programmatic access, scripting, automation D1 🟢 Good to know
AWS Compute Optimizer ML-based recommendations cho right-sizing EC2, EBS, Lambda, ECS on Fargate. Analyze utilization metrics → recommend optimal resources D4 🟡 Important
AWS Config Track configuration changes. Configuration history, compliance rules (managed & custom). Remediation actions. "What changed and when?" — audit và compliance D1 🔴 Critical
AWS Control Tower Setup và govern multi-account AWS environment. Landing zone, guardrails (preventive + detective), account factory. Built on Organizations, SSO, Config D1 🟡 Important
AWS Health Dashboard Service health information. Service Health (global AWS status) vs Your Account Health (events affecting your resources). EventBridge integration cho automation D2 🟢 Good to know
AWS License Manager Track và manage software licenses (BYOL, enterprise agreements). Enforce licensing rules, prevent overages D4 🟢 Good to know
Amazon Managed Grafana Managed Grafana cho dashboards. Integrates với CloudWatch, Prometheus, X-Ray, OpenSearch. Enterprise-ready với SSO D3 🟢 Good to know
Amazon Managed Service for Prometheus Managed Prometheus cho container monitoring. Collect, query, alert on container metrics. PromQL compatible D3 🟢 Good to know
AWS Management Console Web-based GUI cho AWS services D1 🟢 Good to know
AWS Organizations Multi-account management. Organization Units (OUs), Service Control Policies (SCPs), consolidated billing, member accounts. Central governance D1, D4 🔴 Critical
AWS Proton Managed delivery service cho container và serverless deployments. Templates cho infrastructure provisioning. Self-service cho developers D3 🟢 Good to know
AWS Service Catalog Create và manage catalogs of approved IT services. CloudFormation-based products. Governance, compliance, self-service provisioning D1 🟡 Important
AWS Systems Manager Quản lý fleet of servers (EC2, on-premises). Session Manager (no SSH needed), Patch Manager, Parameter Store (config/secrets), Run Command, Automation, Inventory D1, D2 🔴 Critical
AWS Trusted Advisor Best practices recommendations: cost optimization, performance, security, fault tolerance, service limits. Basic (core checks, free) vs Business/Enterprise Support (full checks) D1, D4 🟡 Important
AWS Well-Architected Tool Review workloads against Well-Architected Framework 6 pillars. Generate improvement plans, track progress. Free service D1, D2, D3, D4 🟢 Good to know
CloudTrail vs Config vs CloudWatch — phân biệt
Service Trả lời câu hỏi Ví dụ
CloudTrail "Ai đã làm gì?" User X deleted S3 bucket at 10:30 AM
Config "Resource cấu hình thế nào và đã thay đổi gì?" Security Group SG-123 added port 22 yesterday
CloudWatch "Resource đang hoạt động ra sao?" CPU utilization 85%, 500 errors increased

12. Migration & Transfer

Service Mô tả Domain liên quan Mức độ
AWS Application Discovery Service Discover on-premises servers, dependencies, performance data. Agent-based vs agentless. Planning cho migration D2 🟢 Good to know
AWS Application Migration Service (MGN) Lift-and-shift migration (formerly CloudEndure). Automated replication, testing, cutover. Minimal downtime migration D2 🟡 Important
AWS Database Migration Service (DMS) Migrate databases to AWS. Homogeneous (MySQL → RDS MySQL) & heterogeneous (Oracle → Aurora PostgreSQL, cần SCT). Continuous replication, CDC (Change Data Capture) D2, D3 🔴 Critical
AWS DataSync Data transfer service. On-premises ↔ AWS (S3, EFS, FSx). Automated, scheduled, encrypted. Up to 10 Gbps. Online transfer (qua internet hoặc Direct Connect) D2 🟡 Important
AWS Migration Hub Central tracking cho migration projects. Integrates với MGN, DMS, partner tools. Visualize migration progress D2 🟢 Good to know
AWS Snow Family Offline data transfer devices. Snowcone (8-14TB, nhỏ, portable), Snowball Edge (80TB, compute + storage), Snowmobile (100PB, xe tải container). Dùng khi bandwidth limited hoặc data > 10TB D2, D4 🔴 Critical
AWS Transfer Family Managed SFTP, FTPS, FTP server cho S3 và EFS. Dùng khi cần file transfer protocol compatibility (legacy systems, partners) D2 🟢 Good to know
Khi nào dùng Snow Family vs DataSync?
  • Data < 10TB + bandwidth tốt → DataSync (online, nhanh hơn)
  • Data > 10TB + bandwidth hạn chế → Snowball Edge
  • Data > 100TB + tight deadline → nhiều Snowball Edge song song
  • Data > 10PB → Snowmobile (literally xe tải)
  • Nhớ: "Nếu transfer qua internet mất > 1 tuần → dùng Snow Family"

13. Networking & Content Delivery

Service Mô tả Domain liên quan Mức độ
AWS Client VPN Managed VPN cho remote access. OpenVPN-based. Users connect từ laptop/phone vào VPC. Certificate-based hoặc AD authentication D1, D2 🟡 Important
Amazon CloudFront Global CDN. Edge locations, caching, HTTPS, Origin Access Control/Identity (OAC/OAI), Lambda@Edge, CloudFront Functions, geo-restriction, signed URLs/cookies, field-level encryption D3 🔴 Critical
AWS Direct Connect Dedicated network connection từ on-premises → AWS. 1/10/100 Gbps. Consistent latency, private connectivity. NOT encrypted by default — cần VPN on top cho encryption. Lead time: weeks to months D1, D2 🔴 Critical
Elastic Load Balancing (ELB) Distribute traffic across targets. ALB (Layer 7, HTTP/HTTPS, path/host routing), NLB (Layer 4, TCP/UDP, ultra-low latency, static IP), GLB (Layer 3, third-party appliances, GENEVE), CLB (legacy, Layer 4/7) D2, D3 🔴 Critical
AWS Global Accelerator Improve global application performance. Static anycast IPs, AWS global network. Failover < 30 seconds. So sánh thường gặp với CloudFront D2, D3 🟡 Important
AWS PrivateLink Private connectivity từ VPC đến AWS services hoặc third-party services. Không qua internet. Interface VPC Endpoints. Giữ traffic trong AWS network D1 🔴 Critical
Amazon Route 53 Managed DNS + domain registration. Routing policies: Simple, Weighted, Latency, Failover, Geolocation, Geoproximity, Multi-Value Answer. Health checks, alias records D2, D3 🔴 Critical
AWS Site-to-Site VPN VPN tunnel giữa on-premises network và AWS VPC. Encrypted over internet. Customer Gateway (on-premises) + Virtual Private Gateway / Transit Gateway (AWS side). Quick setup (minutes vs Direct Connect weeks) D1, D2 🔴 Critical
AWS Transit Gateway Hub-and-spoke network cho connect multiple VPCs, on-premises networks, VPN connections. Regional, inter-region peering. Simplify complex network topologies. Route tables per attachment D1, D2 🔴 Critical

18. Service Limits, Quotas & Advanced Concepts

Hard Limits vs Soft Limits

AWS có hai loại giới hạn:

  • Soft Limits (Adjustable Quotas): Có thể yêu cầu tăng thông qua Service Quotas console hoặc AWS Support. VD: số lượng EC2 instances tối đa per region (mặc định 20 vCPUs cho On-Demand).
  • Hard Limits (Unadjustable Quotas): Giới hạn vật lý hoặc kiến trúc, không thể tăng. Đề thi rất hay hỏi về cách vượt qua rào cản này bằng kiến trúc thay thế.

18.1. Các Limits & Constraints quan trọng cần nhớ

Service Limit / Quota Loại Cách giải quyết / Ghi chú
VPC 5 VPCs per Region Soft Xin tăng limit.
VPC Peering Không có transitive peering Hard Dùng Transit Gateway nếu cần hub-and-spoke.
Security Group Tối đa 5 SGs per ENI, 60 Inbound + 60 Outbound rules per SG Soft Gộp CIDR, hoặc dùng nhiều ENI (nhưng bị giới hạn OS).
Lambda 15 phút execution timeout Hard Dùng Step Functions + ECS Fargate hoặc EC2/Batch.
SQS Retention tối đa 14 ngày Hard Nếu cần lưu lâu hơn, Lambda đọc SQS ghi vào S3 / DynamoDB.
S3 Max object size: 5TB Hard File lớn hơn 5TB phải chia nhỏ. Khuyên dùng Multipart Upload cho file > 100MB.
IAM Tối đa 10 managed policies per User/Role Soft Gộp chính sách (Inline policy), dùng Groups thay vì assign trực tiếp vào User.

18.2. Under the Hood: Control Plane vs Data Plane

Thiết kế kiến trúc Cloud luôn yêu cầu hiểu về 2 mặt phẳng này:

  • Control Plane: Nơi tạo, cấu hình, xóa resource (VD: RunInstances EC2 API, tạo S3 bucket, đổi Route 53 record). Thường có SLA thấp hơn (99.9%) và dễ bị API throttling.
  • Data Plane: Nơi thực tế phục vụ traffic / workload (VD: EC2 instance running, tải file từ S3, DNS query resolution). Data Plane được AWS thiết kế để "always on" (SLA lên đến 99.99% hoặc 100%).
    Best Practice

    Trong trường hợp DR (Disaster Recovery), đừng phụ thuộc vào Control Plane để phục hồi hệ thống. Hãy "pre-provision" resource hoặc sử dụng Data Plane mechanisms (ví dụ: failover routing) vì Control Plane API có thể bị quá tải trong lúc Region có sự cố.

18.3. Troubleshooting: Lỗi API / Limit phổ biến

Lỗi (Error Code) Nguyên nhân Khắc phục
InstanceLimitExceeded Vượt quá số vCPU cho phép ở Region Request limit increase qua AWS Support / Service Quotas.
InsufficientInstanceCapacity AWS hết máy chủ vật lý ở AZ đó (Rất hiếm) Đợi một lúc rồi thử lại, thử AZ khác, đổi instance family khác.
ThrottlingException (429) Gọi API quá nhanh vượt rate limit Áp dụng Exponential Backoff và Jitter trong code SDK.
AccessDenied (403) Thiếu IAM Permission hoặc resource policy (S3/KMS) block Dùng IAM Policy Simulator để debug, kiểm tra SCP ở Organization.
S3 503 Slow Down Ghi/đọc quá mức 3500 PUT / 5500 GET per prefix Rải prefix (randomized key names) thay vì ghi tập trung vào một thư mục gốc.

18.4. CLI Snippets: Kiểm tra Service Quotas

# Xem danh sách các services và quota codes (VD: cho ec2)
aws service-quotas list-service-quotas --service-code ec2 --query "Quotas[*].{Name:QuotaName,Value:Value}" --output table

# Yêu cầu tăng limit vCPU cho Standard Instances (L-1216C47A) lên 64
aws service-quotas request-service-quota-increase \
    --service-code ec2 \
    --quota-code L-1216C47A \
    --desired-value 64

18.5. Case Study: Hệ sinh thái Serverless (Tương tác giữa các Services)

Để làm quen với cách các services trong danh sách trên tương tác với nhau, đây là mô hình Serverless Data Ingestion pipeline kinh điển.

Luồng dữ liệu:

  1. API Gateway (App Integration) nhận telemetry data từ mobile apps.
  2. Lambda (Compute) được trigger, thực hiện validation, format data.
  3. Kinesis Data Firehose (Analytics) nhận dữ liệu từ Lambda, gộp (batching) và đẩy về S3. (Nếu dùng Kinesis Firehose, quá trình scale hoàn toàn tự động, vượt qua nút thắt cổ chai nếu dùng RDS).
  4. S3 (Storage) làm Data Lake lưu Raw Data theo cấu trúc thư mục dạng year/month/day.
  5. Athena & QuickSight (Analytics) query và visualize biểu đồ trực tiếp từ S3 mà không cần copy data ra ngoài.
