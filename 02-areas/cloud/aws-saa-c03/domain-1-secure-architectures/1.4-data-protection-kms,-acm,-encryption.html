Data Protection - KMS, ACM, Encryption

Data Protection trên AWS

Bảo vệ dữ liệu (Data Protection) là yêu cầu cốt lõi trong Domain 1 của AWS SAA-C03. Khái niệm này chia làm hai mảng chính: Encryption at Rest (Mã hóa khi lưu trữ) và Encryption in Transit (Mã hóa khi truyền tải).

1. AWS Key Management Service (KMS)

AWS KMS là dịch vụ quản lý vòng đời khóa mã hóa (Customer Master Keys - CMK). KMS tích hợp liền mạch với hầu hết các dịch vụ AWS (EBS, S3, RDS...).

Các loại CMK (Customer Master Keys)

  1. AWS Owned CMK: Khóa do AWS sở hữu và sử dụng nội bộ để mã hóa dữ liệu của bạn, không hiển thị trên console (không tính phí).
  2. AWS Managed CMK: Khóa do AWS tạo cho từng dịch vụ thay mặt bạn (VD: aws/s3, aws/rds). Bạn có thể xem nhưng không thể sửa policy. (Miễn phí, tự động xoay khóa 1 năm/lần).
  3. Customer Managed CMK: Khóa do BẠN tự tạo, tự định nghĩa Key Policy, tự quyết định thời gian rotate. Có thể bật Automatic Key Rotation (xoay khóa tự động mỗi 1 năm). Phải trả phí hàng tháng.

KMS APIs

  • Encrypt / Decrypt: Mã hóa/giải mã trực tiếp dữ liệu dung lượng nhỏ (Tối đa 4KB).
  • GenerateDataKey: Dùng để mã hóa dữ liệu lớn (Envelope Encryption). Trả về Data Key (bản rõ) và Data Key (đã mã hóa bằng CMK).

Envelope Encryption (Mã hóa phong bì)

AWS KMS không bao giờ gửi CMK ra khỏi server của nó. Khi mã hóa dữ liệu khổng lồ (VD file 100GB), AWS dùng phương pháp Envelope Encryption:

KMS Key Policies

KMS KHÔNG bị chi phối hoàn toàn bởi IAM Policies. Một IAM User có quyền AdministratorAccess VẪN KHÔNG THỂ sử dụng KMS Key nếu KMS Key Policy không tường minh cấp quyền cho IAM User đó. Key Policy điều khiển tất cả!

Cross-Region Key Replication

  • Bạn có thể tạo Multi-Region KMS Keys. AWS cho phép một Primary Key ở us-east-1 tự động đồng bộ (replicate) sang ap-southeast-1.
  • Lưu ý: Multi-Region key có cùng một material (ruột khóa), giúp giải mã dữ liệu được sao chép xuyên region cực kỳ dễ dàng (ví dụ Replicate một RDS Snapshot được mã hóa sang region khác).

2. CloudHSM

Trong khi KMS là dịch vụ dùng chung (multi-tenant), AWS CloudHSM cung cấp phần cứng bảo mật chuyên dụng (Hardware Security Module) theo chuẩn FIPS 140-2 Level 3 đặt ngay trong VPC của bạn.

  • Bạn có toàn quyền quản lý khóa (AWS không thể khôi phục khóa nếu bạn mất credentials).
  • Thường dùng cho chứng chỉ SSL/TLS offload, Oracle TDE, mã hóa chuẩn ngân hàng.
  • HA (High Availability): Triển khai nhiều HSM appliances vào các AZ khác nhau để tạo thành CloudHSM Cluster.
  • Có thể dùng CloudHSM làm Custom Key Store cho KMS.

3. Encryption at Rest (Mã hóa dữ liệu lưu trữ)

Mã hóa Amazon S3

Khi upload dữ liệu lên S3, có 4 cách mã hóa:

Phương pháp Quản lý khóa Ghi chú Bắt buộc gửi kèm Header
SSE-S3 S3 (Khóa AES-256) Mặc định hiện nay của mọi bucket. S3 tự quản lý toàn bộ. "x-amz-server-side-encryption": "AES256"
SSE-KMS AWS KMS Quản lý khóa tập trung qua KMS, cung cấp nhật ký audit (CloudTrail) mỗi lần key được dùng. "x-amz-server-side-encryption": "aws:kms"
SSE-C Khách hàng (Customer) Bạn tự quản lý key. Phải gửi khóa bí mật kèm theo MỖI request API HTTPS (S3 không lưu khóa này). Không có header riêng, gửi kèm khóa.
Client-Side Khách hàng Khách hàng mã hóa file trên máy tính của họ TRƯỚC KHI upload lên S3. N/A
Bắt buộc mã hóa bằng Bucket Policy

Nếu bạn muốn ép buộc tất cả file upload lên S3 phải dùng SSE-KMS, hãy viết Bucket Policy Deny hành động s3:PutObject nếu Condition s3:x-amz-server-side-encryption KHÔNG bằng aws:kms.

Mã hóa EBS Volume

  • Dữ liệu bên trong, Snapshot tạo ra, và dữ liệu luân chuyển giữa instance và EBS đều được mã hóa.
  • Bạn có thể mã hóa một unencrypted EBS Volume bằng cách: Tạo Snapshot → Copy Snapshot (bật encryption trong lúc copy) → Tạo Volume mới từ Encrypted Snapshot.

Mã hóa RDS và EFS

  • Bắt buộc phải bật mã hóa ngay lúc tạo mới (at creation time). Không thể đổi từ unencrypted sang encrypted trực tiếp mà phải thông qua Snapshot/Backup & Restore.
  • EFS encryption at rest sử dụng AWS KMS.

4. Encryption in Transit (Mã hóa đường truyền) & ACM

Bảo vệ dữ liệu đang bay (in-flight) trên môi trường mạng bằng giao thức HTTPS/TLS/SSL.

AWS Certificate Manager (ACM)

ACM chuyên cung cấp, quản lý và triển khai chứng chỉ SSL/TLS công cộng và nội bộ.

  • Public Certificates: Cấp miễn phí hoàn toàn. ACM tự động gia hạn (auto-renewal) trước khi hết hạn.
  • Private CA: Để tạo chứng chỉ cho mạng nội bộ (có phí khởi tạo lớn).
  • Tích hợp: Bạn KHÔNG THỂ cài chứng chỉ ACM trực tiếp lên EC2 instance. ACM chỉ được gắn trực tiếp vào:
    • Elastic Load Balancers (ALB, NLB).
    • Amazon CloudFront Distributions.
    • Amazon API Gateway.
Exam Tip - ALB HTTPS Termination

Thay vì để EC2 chịu tải việc giải mã SSL (rất tốn CPU), ALB (Load Balancer) kết hợp với ACM Certificate sẽ làm nhiệm vụ HTTPS Termination (giải mã HTTPS tại ALB, rồi đẩy gói tin chưa mã hóa qua HTTP vào EC2 trong private subnet để xử lý).

5. Phân loại dữ liệu (Data Classification) & Amazon Macie

Amazon Macie là dịch vụ phân tích học máy (Machine Learning) được thiết kế đặc biệt để quét các S3 Buckets.

  • Tự động phát hiện PII (Personally Identifiable Information - Thông tin định danh cá nhân) như thẻ tín dụng, hộ chiếu, khóa bí mật...
  • Phát hiện PHI (Personal Health Information - Dữ liệu y tế sức khỏe).
  • Cảnh báo nếu một bucket chứa dữ liệu PII bị set quyền public nhầm.

6. AWS Secrets Manager vs SSM Parameter Store

Mặc dù có note chuyên sâu, nhưng ở phạm vi Data Protection, bạn cần phân biệt nhanh 2 công cụ lưu trữ bí mật này:

Tính năng AWS Secrets Manager SSM Parameter Store
Đặc tính chính Dịch vụ cao cấp, tự động Rotate Lưu trữ cấu hình (config) cơ bản
Tính năng xoay khóa tự động (Auto Rotation) Tích hợp sẵn trực tiếp với RDS, Redshift, DocumentDB (dùng Lambda). KHÔNG có tính năng tự xoay tự động gốc. Phải tự code Lambda nếu cần.
Bảo mật Bắt buộc mã hóa bằng KMS. Hỗ trợ Plaintext (String) và Encrypted (SecureString dùng KMS).
Chi phí Mất phí cố định (~$0.40/secret/tháng). Hoàn toàn miễn phí (Standard tier).
Multi-Region Hỗ trợ Secret Replication tự động. Không hỗ trợ tự động replicate.
Use Case

Nếu đề bài yêu cầu "Lưu trữ cấu hình môi trường như URL của API Gateway hoặc API key của Stripe với chi phí rẻ nhất" → SSM Parameter Store. Nếu đề bài yêu cầu "Lưu trữ mật khẩu database và phải tự động thay đổi mật khẩu mỗi 30 ngày để tuân thủ bảo mật" → AWS Secrets Manager.

7. Service Limits, Quotas & Constraints

Đối tượng Giới hạn Loại Ghi chú
KMS CMKs 100,000 Symmetric keys per Region Soft Đa số không bao giờ chạm tới limit này.
KMS API Quota GenerateDataKey ~ 10,000 - 50,000 req/s Soft Có thể gây lỗi ThrottlingException khi hệ thống scale đột ngột.
ACM Certificates 2,500 certificates per account Soft Nếu dùng SAN (Subject Alternative Names), mỗi cert có thể gánh đến 100 domain.
EBS Encrypted Volumes Cần chia sẻ KMS Key nếu copy snapshot Hard Không thể copy snapshot được mã hóa bởi Default EBS Key sang account khác. Bạn MỚI copy bằng Customer Managed Key (CMK) và share key đó.

8. Troubleshooting & Common Errors

Tình huống Giải thích & Cách khắc phục
KMS AccessDeniedException khi tải file từ S3 S3 bucket đã cho phép bạn lấy file, nhưng file đó được mã hóa bằng KMS (SSE-KMS) mà KMS Key Policy không cho bạn quyền kms:Decrypt. Khắc phục: Yêu cầu chủ khóa cấp quyền Decrypt.
ACM Certificate không tự động Renew ACM cấp phát chứng chỉ bằng DNS Validation. Nếu bạn vô tình xóa bản ghi CNAME mà ACM tạo ra trong Route 53, ACM sẽ không thể xác thực lại domain và chứng chỉ sẽ hết hạn.
Không copy được RDS/EBS Snapshot sang Account khác Snapshot đang được mã hóa bằng "AWS Managed Key" (vd: aws/rds). Các khóa do AWS quản lý KHÔNG THỂ chia sẻ cross-account. Khắc phục: Phải tạo bản copy snapshot bằng CMK của bạn, sau đó share CMK và share bản copy đó.

9. CLI & JSON Snippets

9.1. Lệnh AWS CLI để giải mã (Decrypt) trực tiếp

(Lưu ý: KMS chỉ giải mã trực tiếp dữ liệu <= 4KB, ví dụ password).

aws kms decrypt \
    --ciphertext-blob fileb://encrypted-password.bin \
    --query Plaintext \
    --output text | base64 --decode

9.2. JSON S3 Bucket Policy: Ép buộc mã hóa SSE-KMS

Ngăn chặn bất kỳ ai upload file lên bucket nếu không gửi kèm header yêu cầu mã hóa KMS.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RequireKMSEncryption",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::my-secure-bucket/*",
      "Condition": {
        "StringNotEquals": {
          "s3:x-amz-server-side-encryption": "aws:kms"
        }
      }
    }
  ]
}

10. Case Study: Cross-Account S3 KMS Access

Đây là bài toán thực tế và câu hỏi kinh điển trong kỳ thi SAA-C03: Làm sao để Account B đọc được một object đã mã hóa SSE-KMS trong S3 của Account A?

Bí kíp cấu hình (Chìa khóa 3 ổ): Để quá trình này thành công, bạn cần cấu hình ĐỦ 3 NƠI:

  1. S3 Bucket Policy ở Account A: Cấp quyền s3:GetObject cho Role của Account B.
  2. KMS Key Policy ở Account A: Cấp quyền kms:Decrypt cho Role của Account B. (Nếu quên bước này, lấy file về sẽ là rác/báo lỗi).
  3. IAM Policy ở Account B: Phải cấp quyền Allow s3:GetObject và kms:Decrypt cho App EC2. (Vì truy cập Cross-Account luôn đòi hỏi sự đồng thuận của 2 bên).

Checklist Bảo vệ dữ liệu

  • Bật "Default Encryption" trên tất cả Amazon S3 buckets.
  • Sử dụng CMK với tính năng tự động xoay (Automatic Key Rotation) mỗi 1 năm để giảm chi phí so với xoay thủ công.
  • Chỉ định AWS ACM quản lý chứng chỉ trên ALB thay vì cài đặt cert bằng tay lên từng web server EC2.
  • Không lưu trữ thông tin nhạy cảm vào plaintext files (như docker-compose.yml), dùng Secrets Manager / Parameter Store kết hợp IAM Roles truy xuất khi chạy ứng dụng.
