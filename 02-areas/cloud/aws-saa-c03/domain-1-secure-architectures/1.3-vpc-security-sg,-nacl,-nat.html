VPC Security - SG, NACL, NAT

VPC Security & Connectivity

Amazon Virtual Private Cloud (VPC) cho phép bạn khởi chạy các tài nguyên AWS vào một mạng ảo do bạn định nghĩa. Việc thiết kế bảo mật cho VPC là nền tảng cốt lõi của Domain 1 - Secure Architectures.

Sơ đồ Kiến trúc VPC Cơ Bản

1. Security Groups (SG)

Security Group là bức tường lửa ảo (virtual firewall) hoạt động ở cấp độ Instance (giao diện mạng ENI) để kiểm soát lưu lượng Inbound và Outbound.

  • Stateful (Có trạng thái): Nếu bạn cho phép một request đi vào (Inbound), response trả về cho request đó sẽ tự động được phép đi ra (Outbound) bất kể rules Outbound cấu hình như thế nào.
  • Mặc định:
    • Khi tạo mới: Mặc định TỪ CHỐI tất cả Inbound (không có luật nào), và CHO PHÉP tất cả Outbound.
  • Rules:
    • Chỉ hỗ trợ ALLOW rules (Không thể viết rule DENY một IP nào đó trên SG).
    • Không có số thứ tự đánh giá, tất cả rules đều được đánh giá trước khi quyết định cấp quyền.
  • Chaining SGs (Tham chiếu SG):
    • Source của một luật Inbound có thể là 1 địa chỉ IP (192.168.1.0/24) HOẶC một Security Group khác.
    • Ví dụ: DB_SG có thể cho phép truy cập cổng 3306 chỉ từ Web_SG. Đây là best practice vô cùng quan trọng, giúp scale tự động mà không cần cập nhật IP tĩnh.
Exam Tip

Nếu đề bài yêu cầu "cấm một dải IP cụ thể tấn công EC2", bạn KHÔNG THỂ dùng Security Group. Bạn bắt buộc phải dùng Network ACL (NACL) hoặc WAF.

2. Network Access Control Lists (NACLs)

NACL là lớp bảo mật mạng tùy chọn đóng vai trò như tường lửa kiểm soát lưu lượng vào/ra khỏi Subnet.

  • Stateless (Không trạng thái): Bất kỳ lưu lượng Inbound được phép đi vào cũng phải được kiểm tra lại trên luật Outbound để xem có được đi ra hay không. Do đó, bạn phải cấu hình cả rule Inbound và Outbound.
  • Ephemeral Ports: Vì tính chất Stateless, khi client (ở ngoài) truy cập Web server (ở trong subnet) qua cổng 80, web server sẽ trả lại kết quả qua một cổng ngẫu nhiên (ephemeral ports: 1024-65535). Bạn PHẢI mở outbound trên các port này trong NACL.
  • Mặc định:
    • NACL mặc định của VPC: Cho phép TẤT CẢ Inbound và Outbound.
    • Custom NACL (tạo mới): Từ chối TẤT CẢ Inbound và Outbound cho đến khi bạn thêm luật.
  • Rules:
    • Hỗ trợ cả ALLOW và DENY rules.
    • Luật được đánh giá tuần tự theo số thứ tự (Rule number) từ thấp đến cao (vd: 100, 200). Rule nào match trước sẽ được thực thi ngay lập tức. (Best practice: Đánh số cách nhau 100 để dễ chèn luật sau này).

So Sánh Security Group vs NACL

Đặc điểm Security Group (SG) Network ACL (NACL)
Phạm vi áp dụng Gắn ở cấp độ Instance (ENI) Gắn ở cấp độ Subnet
Stateful / Stateless Stateful (Return traffic is automatically allowed) Stateless (Must explicitly allow return traffic)
Loại Rules hỗ trợ Chỉ ALLOW Cả ALLOW và DENY
Thứ tự đánh giá Không theo thứ tự, evaluate toàn bộ Tuần tự theo Rule Number (thấp nhất ưu tiên trước)
Mặc định (khi tạo mới) Chặn Inbound, Cho phép Outbound Chặn tất cả (Inbound & Outbound)

3. Quản lý lưu lượng ra Internet (NAT)

Khi EC2 nằm trong Private Subnet cần tải bản cập nhật, chúng cần truy cập Internet nhưng không muốn bị expose trực tiếp.

NAT Gateway

  • Là dịch vụ được AWS quản lý toàn diện (Managed service).
  • Băng thông scale tự động lên đến 45 Gbps.
  • Cực kỳ khả dụng (Highly Available) trong một Availability Zone (AZ).
  • Chi phí: Tính theo giờ sử dụng và số GB dữ liệu đi qua. Rất tốn kém nếu lưu lượng lớn.
  • Bắt buộc phải đặt trong Public Subnet và cần có Elastic IP (EIP).
  • EC2 ở Private Subnet trỏ route 0.0.0.0/0 về NAT Gateway.

NAT Instance (Legacy)

  • Là một EC2 instance thông thường được cấu hình làm router.
  • Cần tự quản lý OS, bản vá, scaling (khó cấu hình HA).
  • Băng thông phụ thuộc vào loại EC2 instance.
  • Bắt buộc: Phải Disable thuộc tính Source/Destination Check trên EC2 instance thì nó mới định tuyến được gói tin không thuộc về nó.
  • Có thể kết hợp làm Bastion Host.
Cảnh báo

NAT Gateway KHÔNG khả dụng chéo AZ. Nếu AZ chứa NAT Gateway sập, các private subnet ở AZ khác trỏ về NAT Gateway đó sẽ mất internet. → Kiến trúc HA tốt nhất: Triển khai 1 NAT Gateway trong mỗi AZ.

4. Bastion Hosts và Systems Manager Session Manager

Làm sao để admin SSH/RDP vào EC2 nằm trong Private Subnet một cách an toàn?

  1. Bastion Host (Jump box):
    • Một EC2 instance đặt trong Public Subnet. Admin SSH vào Bastion, từ Bastion SSH tiếp vào Private EC2.
    • Yêu cầu cấu hình SG chặt chẽ (chỉ nhận SSH/RDP từ IP công ty). Quản lý SSH keys khó khăn.
  2. AWS Systems Manager (SSM) Session Manager:
    • Giải pháp tốt nhất, hiện đại nhất.
    • Không cần mở port Inbound (không cần port 22/3389).
    • Không cần Bastion host, không quản lý SSH key.
    • EC2 chỉ cần cài SSM Agent và có kết nối Internet (hoặc VPC Endpoint) để liên lạc với AWS SSM Service. Truy cập trực tiếp qua AWS Console hoặc CLI.

5. VPC Endpoints và AWS PrivateLink

Khi một EC2 trong Private Subnet cần truy cập S3 hoặc DynamoDB, theo cách thông thường, lưu lượng phải đi qua NAT Gateway ra Internet rồi mới vào lại S3. Cách này tốn phí NAT và kém bảo mật.

VPC Endpoints cho phép lưu lượng đi hoàn toàn trong mạng nội bộ AWS (AWS Network), không bao giờ chạm tới Internet public.

Gateway Endpoints

  • Dùng miễn phí, định tuyến qua thay đổi trong Route Table.
  • Chỉ hỗ trợ: Amazon S3 và Amazon DynamoDB.
  • Không thể truy cập từ môi trường On-Premises qua VPN/Direct Connect (vì Gateway endpoint không có IP trong VPC).

Interface Endpoints (AWS PrivateLink)

  • Tạo một Elastic Network Interface (ENI) với Private IP bên trong subnet của bạn.
  • Hỗ trợ hầu hết các dịch vụ AWS (KMS, SNS, SQS, SSM...).
  • Phải trả phí theo giờ và GB data.
  • Có thể truy cập từ On-Premises (vì có IP cụ thể).
  • Sử dụng công nghệ AWS PrivateLink.
Chia sẻ ứng dụng riêng qua PrivateLink

Bạn có ứng dụng tự viết ở VPC A (Account A) và muốn chia sẻ cho VPC B (Account B) nhưng trùng dải IP (overlapping CIDR), không thể dùng VPC Peering. → Giải pháp: Cấu hình Network Load Balancer (NLB) + VPC Endpoint Service (PrivateLink) ở VPC A. Bên VPC B tạo Interface Endpoint. Kết nối cực kỳ an toàn và xử lý được lỗi IP Overlap.

6. Kết nối Hybrid Cloud: VPN & Direct Connect

Doanh nghiệp muốn kết nối Data Center nội bộ (On-premises) với AWS VPC.

AWS Site-to-Site VPN

  • Kết nối mã hóa qua Internet (IPsec).
  • Cài đặt nhanh (vài phút), chi phí thấp.
  • Thành phần:
    • Customer Gateway (CGW): Ở phía Data Center.
    • Virtual Private Gateway (VGW) hoặc Transit Gateway (TGW): Ở phía AWS.
  • Tốc độ giới hạn ~1.25 Gbps mỗi tunnel.

AWS Direct Connect (DX)

  • Đường truyền mạng cáp quang vật lý riêng biệt (Private, dedicated connection) cắm thẳng vào AWS. KHÔNG đi qua Internet.
  • Ưu điểm: Băng thông khổng lồ (1Gbps - 100Gbps), độ trễ cực thấp và ổn định. Chi phí data transfer out rẻ hơn.
  • Nhược điểm: Mất 1-2 tháng để kéo cáp.
  • Dedicated Connection: 1 Gbps, 10 Gbps, 100 Gbps. Do bạn tự làm việc với AWS.
  • Hosted Connection: < 1 Gbps. Thuê qua AWS Partner.
  • Chú ý: Dữ liệu qua Direct Connect MẶC ĐỊNH KHÔNG ĐƯỢC MÃ HÓA. Nếu cần mã hóa, phải chạy VPN over Direct Connect.

7. Các dịch vụ giám sát và bảo vệ khác mạng

VPC Flow Logs

  • Cho phép ghi lại thông tin về luồng IP (traffic) đi vào/ra các ENI trong VPC.
  • Giúp phân tích nguyên nhân tại sao EC2 không kết nối được (xem log xem bị SG hay NACL chặn "REJECT").
  • Đích lưu trữ: Amazon CloudWatch Logs, Amazon S3, hoặc Kinesis.
  • Lưu ý: Flow logs chỉ ghi siêu dữ liệu (metadata: Source IP, Dest IP, Port, Bytes, Allow/Reject). Nó không bắt (capture) nội dung gói tin (packet payload). Muốn bắt payload phải dùng tính năng Traffic Mirroring.

AWS Network Firewall

  • Dịch vụ tường lửa mạng cao cấp, hỗ trợ Stateful inspection, xâm nhập (IPS/IDS).
  • Hỗ trợ luật theo công nghệ Suricata.
  • Giám sát luồng traffic giữa các VPC, giữa VPC và Internet, hoặc On-premise.

Checklist Cấu hình Bảo Mật Mạng

  • Xóa luật 0.0.0.0/0 (Inbound) trên tất cả các Security Groups trừ Load Balancers/Bastion.
  • Chuyển sang sử dụng Systems Manager thay vì dùng Bastion host.
  • Đặt DB Instances hoàn toàn vào Private Subnets, khóa port Database (3306, 5432) chỉ cho phép từ Application Security Group.
  • Sử dụng VPC Endpoints (S3 Gateway) để tránh thất thoát dữ liệu ra public internet và tiết kiệm phí NAT.
  • Triển khai VPC Flow Logs để phục vụ mục đích audit và troubleshoot mạng.

8. VPC Limits & Quotas

Đối tượng Giới hạn Loại Ghi chú
VPC per Region 5 Soft Có thể request tăng.
Subnets per VPC 200 Soft
IPv4 CIDR block per VPC 5 Soft Bạn có thể add thêm Secondary CIDR block vào VPC.
NACLs per VPC 200 Soft
Rules per NACL 20 (Inbound) + 20 (Outbound) Soft Có thể tăng lên tối đa 40, nhưng AWS cảnh báo sẽ làm giảm network performance.
Security Groups per Region 2,500 Soft
SGs per ENI (Instance) 5 Soft Có thể xin tăng lên 16 (Tích rule limit sẽ thay đổi tương ứng).
Rules per SG 60 Inbound + 60 Outbound Soft Tích của (Số SGs per ENI) x (Số Rules per SG) không được vượt quá 1000 mặc định.

9. Under the Hood: Lỗi Mạng ở cấp độ TCP

Một mẹo cực kỳ quan trọng để debug lỗi mạng trong AWS (và có trong câu hỏi thi):

  1. Connection Timeout (Hết thời gian kết nối):
    • Client gửi SYN packet nhưng không nhận được gì phản hồi, đợi đến khi timeout.
    • Lỗi này 99% là do Security Group hoặc NACL chặn traffic (Drop packet âm thầm - silent drop).
  2. Connection Refused (Bị từ chối kết nối):
    • Client gửi SYN, server phản hồi bằng RST (Reset).
    • Mạng đã thông (SG/NACL mở đúng port), nhưng dịch vụ bên trong EC2 chưa chạy (ví dụ Nginx chưa start, hoặc lắng nghe sai địa chỉ IP).

10. Troubleshooting: Phân tích VPC Flow Logs

VPC Flow Logs giúp bạn biết chính xác gói tin bị chặn ở đâu. Format cơ bản: <version> <account-id> <interface-id> <srcaddr> <dstaddr> <srcport> <dstport> <protocol> <packets> <bytes> <start> <end> <action> <log-status>

Scenario: Không thể SSH vào EC2

  • Bạn thấy log: ... 192.168.1.5 10.0.1.10 54321 22 6 ... REJECT OK -> Gói tin đi VÀO (Inbound) cổng 22 bị chặn (REJECT). Có thể do Security Group Inbound không có port 22, hoặc NACL Inbound chặn port 22.
  • Bạn thấy log: ... 10.0.1.10 192.168.1.5 22 54321 6 ... REJECT OK -> Gói tin trả về (Outbound) từ EC2 về client bị chặn. Do Security Group là stateful, SG không bao giờ chặn return traffic. Lỗi 100% nằm ở NACL Outbound (Chưa mở Ephemeral ports 1024-65535).

11. CLI Snippets

11.1. Cập nhật Inbound Rule cho Security Group

# Cho phép SSH từ 1 IP cụ thể
aws ec2 authorize-security-group-ingress \
    --group-id sg-0123456789abcdef0 \
    --protocol tcp \
    --port 22 \
    --cidr 203.0.113.0/24

11.2. Xem thông tin VPC Flow Logs

aws ec2 describe-flow-logs \
    --filter "Name=resource-id,Values=vpc-0abcdef1234567890" \
    --query "FlowLogs[*].{ID:FlowLogId,Status:FlowLogStatus,LogGroup:LogGroupName}" \
    --output table

12. Case Study: Kiến trúc HA NAT Gateway & S3 Endpoint

Đây là kiến trúc chuẩn cho môi trường Production (Multi-AZ) để đảm bảo High Availability và Cost Optimization (Bằng S3 Gateway Endpoint).

Luồng xử lý:

  1. HA cho Internet Outbound: App EC2 A trỏ route 0.0.0.0/0 về NAT Gateway A nằm CÙNG AZ. Tương tự cho B. Nếu AZ A mất mạng hoàn toàn, AZ B vẫn hoạt động độc lập (Không trỏ chéo AZ để tránh phí Cross-AZ Data Transfer và tránh Single Point of Failure).
  2. Cost Optimization cho S3: Nếu EC2 tải file cực lớn từ S3, traffic đi qua NAT Gateway sẽ bị tính phí ~$0.045/GB (Phí xử lý NAT). Khi gắn thêm VPC Gateway Endpoint cho S3, traffic gọi tới S3 sẽ rẽ nhánh đi qua Endpoint này hoàn toàn MIỄN PHÍ. Route Table tự động thêm một prefix list (vd: pl-68a54001) trỏ vào Endpoint.
