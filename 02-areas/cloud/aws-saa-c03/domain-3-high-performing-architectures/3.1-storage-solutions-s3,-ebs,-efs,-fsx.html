Storage Solutions - S3, EBS, EFS, FSx

Storage Solutions: S3, EBS, EFS, FSx & Storage Gateway

Để đạt được kiến trúc hiệu năng cao trong phần Storage, bạn phải lựa chọn chuẩn xác giữa Object Storage, Block Storage và File Storage dựa trên IOPS, Throughput, và đặc điểm truy cập của workload.

1. Cây Quyết định Lưu trữ (Storage Decision Tree)

Sử dụng sơ đồ dưới đây để đưa ra quyết định nhanh khi gặp câu hỏi về thiết kế lưu trữ:

2. Amazon S3 (Simple Storage Service)

Amazon S3 là nền tảng Object Storage chủ lực. Để tối ưu hóa hiệu năng và chi phí, bạn cần nắm vững các khía cạnh sau:

2.1. Các Storage Classes và Bảng So Sánh

Việc đặt sai Storage Class không làm sập hệ thống nhưng sẽ khiến chi phí đội lên gấp nhiều lần.

S3 Storage Class Tính sẵn sàng (Avail.) Độ bền (Durability) Thời gian lưu tối thiểu Phí truy xuất Thời gian lấy dữ liệu Use Case
S3 Standard 99.99% 11 số 9 None Không Milliseconds Web hosting, dữ liệu truy cập nóng.
S3 Intelligent-Tiering 99.9% 11 số 9 None Không Milliseconds Dữ liệu không đoán trước được quy luật truy cập.
S3 Standard-IA 99.9% 11 số 9 30 days Có Milliseconds Backups, disaster recovery (cần truy xuất ngay).
S3 One Zone-IA 99.5% 11 số 9 30 days Có Milliseconds Bản sao chép thứ 2, dữ liệu có thể tái tạo.
Glacier Instant Retrieval 99.9% 11 số 9 90 days Có Milliseconds Archive nhưng thỉnh thoảng cần lấy ngay.
Glacier Flexible Retrieval 99.99% (AZs) 11 số 9 90 days Có 1 min - 12 hours Archive chi phí thấp, không cần gấp.
Glacier Deep Archive 99.99% (AZs) 11 số 9 180 days Có 12 hours - 48 hours Lưu trữ tuân thủ pháp lý lâu dài (7-10 năm).
Important

S3 Intelligent-Tiering tự động di chuyển objects giữa các tầng lưu trữ (Frequent, Infrequent, Archive Instant) mà không có retrieval fee, thay vào đó AWS thu một khoản phí giám sát (monitoring fee) hàng tháng.

2.2. Tính năng Bảo mật & Quản trị S3

  • Versioning: Lưu mọi phiên bản của object, bảo vệ khỏi việc vô tình xóa. Khi xóa, S3 tạo một "delete marker". Cần kết hợp với MFA Delete để ngăn hacker xóa hoàn toàn.
  • S3 Object Lock:
    • Tính năng WORM (Write Once Read Many).
    • Governance mode: Có thể sửa/xoá nếu user có quyền IAM đặc biệt (s3:BypassGovernanceRetention).
    • Compliance mode: KHÔNG MỘT AI (kể cả root account) có thể sửa/xóa cho đến khi hết thời hạn retention. Cần cho chuẩn pháp lý (SEC, HIPAA).
    • Legal Hold: Khóa object vô thời hạn bất chấp retention period cho đến khi được gỡ bỏ bằng tay.
  • Lifecycle Policies: Tự động chuyển data (Transition) từ Standard -> IA -> Glacier sau N ngày. Hoặc tự động xóa (Expiration) log files cũ.

2.3. Under the Hood: Tối ưu Hiệu Năng & Limits của S3

  • S3 Limits & Quotas:
    • Max kích thước của một Object: 5 TB.
    • Max kích thước cho 1 thao tác PUT đơn lẻ: 5 GB. (Nên dùng Multipart Upload cho file > 100MB).
    • Số lượng buckets mặc định: 100/account (có thể xin tăng lên 1000).
  • S3 Performance Guidelines:
    • Mỗi Prefix (tương đương với một "thư mục" ảo trong S3) hỗ trợ tối đa 3,500 PUT/COPY/POST/DELETE requests/second và 5,500 GET/HEAD requests/second.
    • Nếu cần TPS (Transactions Per Second) cao hơn, hãy phân tán dữ liệu ra nhiều Prefixes. S3 sẽ tự động scale hạ tầng đằng sau để phục vụ.
  • KMS Limits: Khi S3 kết hợp mã hoá bằng AWS KMS (SSE-KMS), hiệu năng có thể bị nghẽn do giới hạn API calls đến KMS thay vì S3. Bạn cần xin tăng quota của KMS nếu request rate quá cao.
  • S3 Byte-Range Fetches: Kéo từng phần (chunks) của file song song giúp tăng tốc độ download. Rất hữu ích khi chỉ cần đọc một phần header của file dữ liệu lớn.
  • S3 Select / Glacier Select: Cho phép chạy câu lệnh SQL trực tiếp trên S3 để trả về đúng kết quả cần thiết, thay vì download toàn bộ dữ liệu.
  • S3 Event Notifications: Tự động trigger Lambda function, SQS, SNS.

2.4. Troubleshooting & Common Errors (S3)

  • 403 Access Denied: Xảy ra rất thường xuyên. Nguyên nhân có thể do:
    1. IAM User/Role thiếu quyền truy cập (vd: s3:GetObject).
    2. Bucket Policy chặn request (vd: chặn truy cập từ ngoài VPC).
    3. Tính năng Block Public Access đang bật, trong khi bạn lại cố set object thành public (ACL hoặc Policy).
    4. Mã hoá KMS đang bật, nhưng IAM Role thiếu quyền decrypt (kms:Decrypt) với Customer Managed Key.
  • S3 Replication Fails: Tính năng Cross-Region Replication (CRR) yêu cầu cả hai bucket (source & destination) đều phải bật Versioning. Thêm nữa, IAM Role được S3 sử dụng phải có đủ quyền đọc source và ghi vào destination bucket.

2.5. CLI & JSON Policy Snippets

Snippet: Bucket Policy chặn truy cập nếu không dùng HTTPS Rất phổ biến trong yêu cầu compliance/security:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EnforceHTTPS",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": "arn:aws:s3:::my-secure-bucket/*",

3. Amazon EBS (Elastic Block Store)

EBS là ổ cứng mạng (network drive) gắn vào EC2 instance. Đặc trưng là Block Storage.

3.1. Các loại Volume và Giới hạn (Volume Types & Limits)

Volume Type Max Size Max IOPS Max Throughput Đặc tính nổi bật & Use Case
gp3 (General Purpose SSD) 16 TiB 16,000 1,000 MiB/s Bất kể dung lượng, luôn có baseline 3,000 IOPS & 125 MiB/s. Dễ dàng scale IOPS/throughput độc lập.
gp2 (General Purpose SSD) 16 TiB 16,000 250 MiB/s IOPS gắn liền với dung lượng (3 IOPS / GB). Dùng burst balance để tăng tạm thời lên 3000 IOPS cho volume < 1TB.
io2 Block Express 64 TiB 256,000 4,000 MiB/s Độ trễ sub-millisecond, độ bền 99.999%. Dành cho database tải siêu cao (SAP HANA).
io1 (Provisioned IOPS) 16 TiB 64,000 1,000 MiB/s Provision IOPS cố định. Tỷ lệ IOPS:GB tối đa là 50:1.
st1 (Throughput Optimized HDD) 16 TiB 500 500 MiB/s Big Data, Data Warehouses, Log processing, Kafka. (Không dùng làm boot volume)
sc1 (Cold HDD) 16 TiB 250 250 MiB/s Rẻ nhất. File server hiếm truy cập. (Không dùng làm boot volume)
Mẹo thi
  • Cost-effective cho database thông thường → Chọn gp3.
  • Mission-critical, latency-sensitive, >16000 IOPS → Chọn io1 / io2.
  • Big Data, MapReduce, Kafka, streaming workloads → Chọn st1.

3.2. Under the Hood & Advanced Configuration

  • EBS Burst Balance (gp2): Với gp2, nếu dung lượng volume nhỏ (dưới 1TB), bạn không có đủ IOPS cơ bản. Hệ thống cấp cho bạn I/O credits (Burst Balance). Khi dùng cạn credit này, hiệu năng volume sẽ tuột dốc không phanh. Giải pháp: Nâng cấp lên gp3 hoặc tăng dung lượng gp2 lên >1TB.
  • EBS Multi-Attach: Chỉ dành cho io1 / io2. Cho phép gắn cùng 1 volume vào nhiều EC2 instances (tối đa 16) trong CÙNG MỘT AZ. Bắt buộc OS phải dùng file system dạng cluster-aware (vd: GFS2). Không dùng cho ext4/xfs thông thường!
  • EC2 Instance Store: Ổ cứng cắm vật lý trực tiếp trên server chứa EC2. Đem lại hiệu năng khủng khiếp nhất (millions of IOPS). Nhưng là Ephemeral storage - Nếu instance Stop hoặc Terminate, dữ liệu sẽ bốc hơi hoàn toàn. Reboot thì giữ nguyên.

3.3. Troubleshooting Common Errors (EBS)

  • Volume Stuck in "attaching" hoặc "detaching": Thường do OS bên trong không nhả lock ổ đĩa (vd: process nào đó đang đọc/ghi liên tục) hoặc lỗi hạ tầng AWS. Bạn có thể thử Force Detach volume, nhưng cảnh báo có thể gây corrupt data.
  • Cannot mount volume in another AZ: EBS volumes bị ràng buộc vào một AZ cụ thể. Nếu EC2 nằm ở us-east-1a thì không thể gắn EBS nằm ở us-east-1b. Cách giải quyết: Chụp EBS Snapshot → Tạo Volume mới từ Snapshot đó ở us-east-1b → Gắn vào EC2.

4. Amazon EFS (Elastic File System)

Là NFS network file system, dùng được cho hàng ngàn EC2 instances mount vào cùng lúc. Tương thích chuẩn POSIX, Linux only. Phù hợp cho kiến trúc Serverless (EFS có thể mount thẳng vào Lambda hoặc ECS Fargate).

4.1. Hiệu năng, Thông lượng & Quotas

  • Limits:
    • Max concurrent EC2 connections: Lên tới vài chục ngàn. (Thực tế là không giới hạn, nhưng kết nối Native EFS driver tối ưu nhất cho hàng ngàn instance).
  • Performance Modes:
    • General Purpose (Mặc định): Độ trễ siêu thấp. Giới hạn 35,000 IOPS. Phù hợp cho 99% workloads.
    • Max I/O: Hỗ trợ 500,000+ IOPS nhưng đổi lại latency cao hơn một chút. Dùng cho Big Data, xử lý media. (Lưu ý: Bạn không thể đổi từ GP sang Max I/O sau khi đã tạo EFS).
  • Throughput Modes:
    • Elastic: Tự động scale lên xuống băng thông dựa vào tải thực tế, chỉ trả tiền cho phần đã dùng. Khuyên dùng hiện nay.
    • Provisioned: Cố định băng thông độc lập với dung lượng lưu trữ.
    • Bursting: Băng thông tăng giảm phụ thuộc vào dung lượng lưu trữ (rất dễ bị thắt cổ chai nếu lưu trữ ít nhưng truy cập nhiều).

4.2. Troubleshooting Common Errors (EFS)

  • EFS Mount Timeout: Thường gặp nhất khi chạy lệnh mount. Nguyên nhân 99% là do Security Group. Hãy đảm bảo SG của EFS cho phép Inbound traffic ở port 2049 (NFS) từ Security Group của EC2.
  • Read-Only File System: Nếu EFS mount thành công nhưng báo Read-only, có thể cấu hình mount của Linux bị sai cờ ro, hoặc quyền POSIX UID/GID của thư mục không cấp quyền ghi cho user hiện tại.
Cảnh báo

EFS chỉ hỗ trợ môi trường Linux. Nếu cần share file cho hệ thống Windows (SMB), PHẢI DÙNG Amazon FSx for Windows.

5. Amazon FSx Family

FSx cung cấp các file systems đầy đủ tính năng được quản lý (managed) cho các workloads chuyên biệt:

  1. FSx for Windows File Server:
    • Chạy trên nền Windows Server. Hỗ trợ giao thức SMB, NTFS.
    • Tích hợp sâu với Active Directory (AD).
    • Tùy chọn Single-AZ hoặc Multi-AZ.
  2. FSx for Lustre:
    • Dành riêng cho HPC (High-Performance Computing), Machine Learning, Video Processing. Tốc độ đọc/ghi cực nhanh (sub-millisecond, hàng trăm GB/s).
    • Tích hợp Directly với S3: FSxL có thể "lazy-load" file từ S3 xuống, xử lý nhanh như điện, rồi write lại kết quả lên S3.
  3. FSx for NetApp ONTAP: Đa giao thức (NFS, SMB, iSCSI), hỗ trợ deduplication, compression, SnapMirror.
  4. FSx for OpenZFS: ZFS file system siêu tốc độ cao, snapshot tức thì.

6. AWS Storage Gateway & AWS Backup

6.1. AWS Storage Gateway

Dùng để kết nối on-premises (hạ tầng tại chỗ) với AWS Cloud Storage.

  • S3 File Gateway: Trình bày như một thư mục chia sẻ NFS/SMB local. Nhưng phía sau đẩy object lên S3. Chứa local cache giúp truy cập file nóng tốc độ cao.
  • FSx File Gateway: Cho phép máy on-prem truy cập FSx for Windows qua SMB với local cache.
  • Volume Gateway (iSCSI):
    • Cached Volumes: Lưu toàn bộ data trên S3, chỉ giữ file nóng ở local.
    • Stored Volumes: Lưu FULL dữ liệu ở local (đảm bảo độ trễ = 0), âm thầm backup snapshot lên S3.
  • Tape Gateway (VTL): Cắm vào các phần mềm backup truyền thống (Veeam, Backup Exec) thay cho băng từ vật lý. Back data vào S3/Glacier.

6.2. AWS Backup

  • Dịch vụ tập trung (Centralized backup service). Quản lý chính sách backup (Backup Plans) cho EC2, EBS, EFS, RDS, DynamoDB.
  • Hỗ trợ backup liên Region (Cross-region) và liên Account (Cross-account bằng AWS Organizations).

7. Case Study Thực Tế

Case Study: Kiến trúc Xử lý Video (HPC) với S3 và FSx for Lustre

Bài toán: Một công ty media cần xử lý (render) hàng ngàn video gốc (lưu trên S3) mỗi ngày. Việc copy data từ S3 trực tiếp vào từng EC2 rất chậm và nghẽn cổ chai mạng.

Giải pháp: Sử dụng FSx for Lustre liên kết trực tiếp với bucket S3. Các EC2 instances chạy thuật toán render sẽ mount ổ Lustre này vào để lấy dữ liệu với tốc độ của siêu máy tính.
