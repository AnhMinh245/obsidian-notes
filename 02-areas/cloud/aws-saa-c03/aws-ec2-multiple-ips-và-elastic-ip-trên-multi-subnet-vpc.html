AWS EC2 - Multiple IPs và Elastic IP trên Multi-Subnet VPC

AWS EC2 - Multiple IPs và Elastic IP trên Multi-Subnet VPC

Question I am trying to answer

  • Làm thế nào để gán nhiều địa chỉ IP tĩnh trên nhiều subnet (1 public + 4 private) cho một EC2 instance?
  • Cách attach Elastic IP vào từng network interface?

TL;DR

  • Mỗi EC2 instance có 1 Primary Network Interface (eth0) gắn với subnet tại launch.
  • Để có IP trên nhiều subnet khác nhau, phải tạo thêm Elastic Network Interface (ENI) — mỗi ENI gắn với 1 subnet.
  • Mỗi ENI có thể có 1 hoặc nhiều Private IP (secondary IPs).
  • Elastic IP chỉ gắn vào Private IP của ENI (không gắn trực tiếp vào instance).
  • EC2 trong private subnet không có Elastic IP; chỉ public subnet ENI mới có thể gắn EIP.

Kiến trúc tổng quan

VPC (10.0.0.0/16)
├── Public Subnet  (10.0.1.0/24)   → eth0 (Primary ENI) + Elastic IP
├── Private Subnet 1 (10.0.2.0/24) → eth1
├── Private Subnet 2 (10.0.3.0/24) → eth2
├── Private Subnet 3 (10.0.4.0/24) → eth3
└── Private Subnet 4 (10.0.5.0/24) → eth4

Mỗi ENI (eth0–eth4) mang 1 Private IP tĩnh. EIP gắn vào eth0 để expose ra internet.

Deep Notes

Bước 1 — Chuẩn bị VPC và Subnets

Giả sử đã có VPC và 5 subnets. Kiểm tra:

aws ec2 describe-subnets \
  --filters "Name=vpc-id,Values=<VPC_ID>" \
  --query 'Subnets[*].{ID:SubnetId,CIDR:CidrBlock,AZ:AvailabilityZone,Public:MapPublicIpOnLaunch}' \
  --output table

Lưu ý: Tất cả ENI phải nằm trong cùng 1 Availability Zone với EC2 instance.

Bước 2 — Launch EC2 Instance với Primary ENI trên Public Subnet

aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type t3.medium \
  --subnet-id <PUBLIC_SUBNET_ID> \
  --private-ip-address 10.0.1.10 \
  --no-associate-public-ip-address \
  --key-name <KEY_PAIR_NAME> \
  --security-group-ids <SG_ID> \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=multi-subnet-instance}]'

Tắt auto-assign public IP (--no-associate-public-ip-address) — sẽ gắn Elastic IP thủ công sau.

Bước 3 — Tạo ENI cho mỗi Private Subnet

Chạy lần lượt cho 4 private subnets:

# ENI cho Private Subnet 1
aws ec2 create-network-interface \
  --subnet-id <PRIVATE_SUBNET_1_ID> \
  --private-ip-address 10.0.2.10 \
  --groups <SG_ID> \
  --description "eth1 - Private Subnet 1" \
  --tag-specifications 'ResourceType=network-interface,Tags=[{Key=Name,Value=eni-private-1}]'

# ENI cho Private Subnet 2
aws ec2 create-network-interface \
  --subnet-id <PRIVATE_SUBNET_2_ID> \
  --private-ip-address 10.0.3.10 \
  --groups <SG_ID> \
  --description "eth2 - Private Subnet 2" \
  --tag-specifications 'ResourceType=network-interface,Tags=[{Key=Name,Value=eni-private-2}]'

# ENI cho Private Subnet 3
aws ec2 create-network-interface \
  --subnet-id <PRIVATE_SUBNET_3_ID> \
  --private-ip-address 10.0.4.10 \
  --groups <SG_ID> \
  --description "eth3 - Private Subnet 3" \
  --tag-specifications 'ResourceType=network-interface,Tags=[{Key=Name,Value=eni-private-3}]'

# ENI cho Private Subnet 4
aws ec2 create-network-interface \
  --subnet-id <PRIVATE_SUBNET_4_ID> \
  --private-ip-address 10.0.5.10 \
  --groups <SG_ID> \
  --description "eth4 - Private Subnet 4" \
  --tag-specifications 'ResourceType=network-interface,Tags=[{Key=Name,Value=eni-private-4}]'

Lưu lại các NetworkInterfaceId trả về.

Bước 4 — Attach ENI vào EC2 Instance

# Attach với device index tăng dần (1, 2, 3, 4)
aws ec2 attach-network-interface \
  --network-interface-id <ENI_ID_PRIVATE_1> \
  --instance-id <INSTANCE_ID> \
  --device-index 1

aws ec2 attach-network-interface \
  --network-interface-id <ENI_ID_PRIVATE_2> \
  --instance-id <INSTANCE_ID> \
  --device-index 2

aws ec2 attach-network-interface \
  --network-interface-id <ENI_ID_PRIVATE_3> \
  --instance-id <INSTANCE_ID> \
  --device-index 3

aws ec2 attach-network-interface \
  --network-interface-id <ENI_ID_PRIVATE_4> \
  --instance-id <INSTANCE_ID> \
  --device-index 4

Giới hạn: Số ENI tối đa phụ thuộc instance type. t3.medium hỗ trợ tối đa 3 ENI. Cần dùng c5.xlarge (8 ENI) hoặc m5.large (3 ENI) cho 5 interfaces.

Kiểm tra giới hạn:

aws ec2 describe-instance-types \
  --instance-types t3.medium \
  --query 'InstanceTypes[*].NetworkInfo.{MaxENI:MaximumNetworkInterfaces,MaxIPs:Ipv4AddressesPerInterface}'

Bước 5 — Gán Elastic IP vào Primary ENI (Public Subnet)

# Kiểm tra Elastic IP đã có
aws ec2 describe-addresses --output table

# Gán EIP vào Private IP của eth0
aws ec2 associate-address \
  --allocation-id <EIP_ALLOCATION_ID> \
  --network-interface-id <PRIMARY_ENI_ID> \
  --private-ip-address 10.0.1.10

EIP chỉ có thể gán vào ENI thuộc public subnet (có Internet Gateway route). Private subnet ENI không route được internet qua EIP.

Bước 6 — Enable Source/Destination Check = false (nếu dùng instance làm router/NAT)

aws ec2 modify-network-interface-attribute \
  --network-interface-id <ENI_ID> \
  --no-source-dest-check

Bước 7 — Cấu hình OS bên trong EC2 (Amazon Linux 2 / Ubuntu)

Sau khi attach ENI, OS cần route đúng traffic ra đúng interface.

Amazon Linux 2 / RHEL — dùng nmcli hoặc ip rule

# Kiểm tra interfaces
ip addr show

# Thêm route rule cho từng interface (policy routing)
# Ví dụ eth1 = 10.0.2.10/24, gateway 10.0.2.1
ip route add 10.0.2.0/24 dev eth1 table 101
ip rule add from 10.0.2.10 table 101 prio 100

# Làm tương tự cho eth2, eth3, eth4

Để persistent qua reboot trên Amazon Linux 2:

# /etc/sysconfig/network-scripts/route-eth1
10.0.2.0/24 dev eth1 table 101

# /etc/sysconfig/network-scripts/rule-eth1
from 10.0.2.10 table 101 prio 100

Ubuntu — dùng Netplan

# /etc/netplan/51-eth1.yaml
network:
  version: 2
  ethernets:
    eth1:
      dhcp4: no
      addresses:
        - 10.0.2.10/24
      routes:
        - to: 0.0.0.0/0
          via: 10.0.2.1
          table: 101
      routing-policy:
        - from: 10.0.2.10
          table: 101
          priority: 100

netplan apply

Bước 8 — Verify kết nối

# Từ bên ngoài — ping EIP
ping <ELASTIC_IP>

# Từ trong instance — kiểm tra routing
ip route show table all
curl --interface eth1 https://ifconfig.me  # traffic ra qua eth1

# Kiểm tra ENI status trên AWS
aws ec2 describe-network-interfaces \
  --filters "Name=attachment.instance-id,Values=<INSTANCE_ID>" \
  --query 'NetworkInterfaces[*].{ENI:NetworkInterfaceId,IP:PrivateIpAddress,Subnet:SubnetId,Status:Status}'

Tradeoffs / Alternatives

Cách Ưu điểm Nhược điểm
Multi-ENI (cách trên) Isolation mạng thật sự, route riêng mỗi subnet Giới hạn ENI theo instance type, phức tạp OS config
Secondary Private IPs trên 1 ENI Đơn giản, không cần multi-ENI Tất cả IPs cùng 1 subnet, không đa subnet
Multiple Instances + Internal LB Scale tốt hơn Tốn chi phí, overkill cho use case đơn giản

Key Concepts

  • ENI (Elastic Network Interface): Virtual NIC gắn vào EC2. Mỗi ENI = 1 subnet, 1 Security Group set, 1+ Private IPs.
  • Elastic IP (EIP): Public IP tĩnh của AWS, gắn vào Private IP của ENI. Tính phí khi không gắn vào running instance.
  • Device Index: Thứ tự gắn ENI vào instance (0 = primary, 1–N = secondary).
  • Source/Dest Check: AWS mặc định drop packet nếu src/dst không phải IP của ENI — phải tắt nếu dùng làm NAT/router.
  • Policy Routing: Cơ chế Linux route traffic dựa theo IP nguồn, cần thiết khi có nhiều interface cùng gateway.
